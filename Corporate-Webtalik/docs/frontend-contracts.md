Keep media full bleed without adding the container gutter twice. Default to cover on ordinary internal pages; do not restore notched/type/launch/wide/craft. The current client allows services/contact-us/about-us plus every single service page from radmanct/services/specs; products receive no title. Populate label/description/shared CTA for every assigned public page through that one filter; reuse service specs for detail copy and preserve stored excerpts/privacy. Preserve local attachment APIs, content privacy, Hafez, shared buttons and existing guarded video behavior; Cover media loads its small page-title entry for desktop reference motion: shared smoother speed .4 on the inner wrapper and shared media-parallax zoom 1 to 1.15, scrub 1, on image/video. Do not let zoom and scroll effects write the same transform; retain static mobile/reduced-motion and all video guards. No-media/excluded routes need no title JS. See docs/architecture.md for the current assignment contract.

The custom website service supplies a subtitle below its H1 and two shared actions below the description. Cover stacks the copy when a subtitle is present. The two actions wrap on narrow screens, and the cover can grow when the copy needs more space. See the [service copy](content/services/custom-website/copy.md).

Dark page backgrounds use the shared flat --rdc-clr-dark (#0e0e0d). The footer is the approved exception: --rdc-clr-ink (#090908), retaining its existing decorative image, opacity and layering. Let other sections inherit the page background unless the owner explicitly requests a separate surface; do not add decorative gradients or noise by default. Preserve necessary media overlays and interactive surfaces. See the color contract in docs/architecture.md.

Approved Services artwork keeps a 1920×1080 canvas, with the original artwork reduced inside the asset (1440×810 at 0,50), without recoloring. Keep the hero at exactly 100svh (100vh fallback), never increase its height to fit the image. Rescale decorative node coordinates with the asset; do not resize the artwork via CSS transforms. Its legacy media_inset marker must not apply a thumbnail inset, zoom, crop, mask, fade or recoloring. Preserve shared smoother speed .4 on the inner wrapper: sizing changes must not disable the existing scroll parallax or separate nodes from the image. Only its four decorative nodes animate on existing image lines; preserve the original source. Other cover media retain their motion.

Before changing media mappings, inspect every consumer. Home offering-* keys are reserved for animated home artwork with image-specific orbit geometry; service-page replacement images must use separate services-* keys. Changing service imagery must not replace home base images or motion.

Internal hero decoration uses the shared title-art renderer and art-orbit runtime. Main home dots and internal fixed/moving nodes use the single --rdc-art-node-sz token; fixed nodes may be dimmer but not a different size. Visible contours must join exactly; motion uses those same paths. Keep image background correction in the asset, without CSS image blend/mask/filter.

## اسکرول، ورود و پذیرش حرکت

Performance work must preserve the selected design and animation. Treat audit suggestions as hypotheses: verify the current owner and change only demonstrated problems. Preserve menu roll hover, wave, stagger, duration/easing, dialog focus and scroll locking; do not replace them with CSS or simplify motion without explicit authorization. Do not change hero timing, parallax scrub, smoother intensity or resize thresholds merely because an audit proposes other values.

Sticky keyboard fallback must use :focus-visible, restore focus after pin reparenting, preserve the target's viewport position through the shared scroll owner, and re-enable on focus exit. Pointer focus must not unnecessarily disable the scene. Keep the session preloader gate separate from hero entrance gating, including denied storage and cached-page fallback. Keep unchanged orb visibility updates synchronous; async work belongs only to actual vendor loading. Register Vite static imports through native WordPress script modules without eagerly preloading dynamic imports.

Consume runtime/scroll-state.js for actual smooth/native mode, runtime/refresh.js for refresh ownership and runtime/observers.js for shared observers; do not add parallel schedulers or observers for the same targets. Keep immediate global refresh after a scene pin changes. Parallax changes scrub in place on rdc:scr-mode; reveal never re-hides already visible media and remains once-only. Only the home Hero selects the shorter entrance profile; shared timings, Persian shaping, RTL/LTR direction, long-text span limits and cleanup remain in text-motion.js. Preserve smooth:1.6 and the selected GSAP menu hover unless a measured issue justifies changing them.

For authorized local browser checks after a build, verify the page's hashed module URLs against the current manifest; fetch the manifest without cache. A throttled RAF/GSAP clock cannot establish FPS or animation duration: report the limitation instead of repeating long waits or tuning production motion to the test environment.

Keep the scroll content position:relative in initial CSS so the absolute header has the same containing block before and after ScrollSmoother startup, including the WordPress admin bar. See docs/architecture.md, Header initialization.

## دادهٔ مشتری، UI و ادامهٔ جزئیات

For UI work, consult `docs/shared-ui.md` at the project root before creating styles or behavior. That document owns the shared-component inventory; inspect the relevant live owner and its consumers, reuse it, and remove the superseded consumer rules. Section headings share only CSS: split heading and `rdc-heading--stack` beside FAQ; preserve semantic headings and keep Page Title independent. Do not copy the inventory into this skill, force different content into one renderer, or load all UI modules globally. Update the inventory when a shared ownership/consumption contract changes; focused doc-only edits need no runtime build or browser run.

For another customer, keep the Radman CT identity and replace the editorial callbacks in inc/client.php. Home data/offerings/selected work and service specs use their small native WordPress filters; footer keeps its existing filter and request cache. Generic owners must not hardcode this customer's name, contacts or attachment IDs. Preserve current rendered data and legacy meta/options; do not migrate or rename stored data as part of reuse work.

Prefer token/scoped CSS changes within existing build entries for styling differences. Use distinct page/layout templates for genuinely different markup. Extract shared renderers only for actual repeated use or independent responsibility; do not add a client registry, variant resolver, settings framework, Child dependency or duplicate animation runtime. Defer header modes, sidebar extraction and routing changes until a real second consumer requires them. For data-only refactors, compare the before/after output and verify unchanged frontend assets; a browser matrix or rebuilding unchanged JS/CSS is unnecessary.

Post/project singles share one continuation data/render/CSS owner (docs/architecture.md, Detail continuation): native same-type previous/next; public unprotected category matches with clearly labeled recent fallback. Reuse existing card renderers/base styles, preserve the main query, hide unavailable directions and locked content; do not duplicate per-page navigation or add a recommendation runtime.

The floating contact control is theme-owned via inc/ui/contact.php, template-parts/ui/contact.php and ui/contact CSS/JS. Channels belong to inc/client.php through radmanct/contact/data. Reuse the existing site bundles and static-root lifecycle; see docs/architecture.md, Floating contact. Preserve accessible panel behavior and GPL attribution; avoid restoring a plugin/settings dependency.

Design-library/client boundary: the library is the reusable reference; Webtalik is an independent customer implementation. Transfer only selected modules, remap media and inspect all consumers; no automatic cross-project sync or replacement of unrelated page imagery. For marquee comparisons, match pixels per second rather than copying a duration across different card counts; verify acceleration and deceleration separately.

## مالکیت SEO

SEO follows docs/wordpress.md: recognized SEO plugins own metadata, while the theme fallback yields. Preserve one plain content H1 when a route omits the media Page Title. Verification belongs to one owner; Analytics requires an explicitly configured single integration and must not be emitted twice.

Plugin metadata ownership also covers custom PHP pages: do not fill empty plugin descriptions from client copy or override plugin SEO fields. Template content may be absent from the plugin's editor analysis; keep its rendered semantics and media accessibility correct at their existing owners.
