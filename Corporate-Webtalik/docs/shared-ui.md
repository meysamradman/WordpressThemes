## دو مدل عنوان سکشن

- **دوطرفه:** `rdc-heading`، گروه `rdc-heading__inr` شامل برچسب p با `__lbl` و عنوان واقعی H2/H3 با `__ttl`، و توضیح p با `__desc` در سمت مقابل. مصرف‌های فعلی، بالای mosaic چهار زیرصفحهٔ خدمات و معرفی «راهکارهای ما» در صفحهٔ خدمات هستند. رنگ تدریجیِ ثابت عنوان با CSS روی کل متن اعمال می‌شود.
- **کناری:** همان کلاس‌ها همراه `rdc-heading--stack`؛ عنوان و توضیح زیر هم، کنار محتوای سکشن. FAQ همین مدل را در renderer مشترکش مصرف می‌کند؛ عنوان آن رنگ یکدست دارد و کنار آکاردئون است. در نمایش باریک، معرفی بالای سؤال‌ها قرار می‌گیرد.

توضیحات هر دو مدل از نقش متن ثانویهٔ `--rdc-mut` استفاده می‌کنند؛ رنگ عنوان یا سفید مستقیم برای توضیح تعریف نشود. فونت و رنگ از tokens/base، اندازهٔ عنوان از `--rdc-sz-section` و آیکون برچسب از catalog خوانده می‌شوند. حروف فارسی را جدا نکنید؛ برچسب و توضیح را برای ظاهر به heading تبدیل نکنید. Page Title و عنوان کارت‌ها خودکار وارد این دو مدل نمی‌شوند. `faq.css` این فایل مشترک را import می‌کند؛ در entryهای service/services دوباره import نشود. مصرف‌کنندهٔ دیگری که FAQ ندارد می‌تواند آن را یک‌بار در entry خودش وارد کند.

## قواعد تغییر و کارایی

1. قبل از ساخت کلاس، رنگ یا رفتار جدید، مالک و مصرف‌کننده‌های موجود را پیدا کنید. برای یک طراحی یکسان، همان کلاس یا گزینهٔ موجود را مصرف کنید؛ تغییر واقعی طراحی، modifier محدود خودش را دارد.
2. اشتراک CSS الزاماً اشتراک PHP/JS نیست. محتوای متفاوت را یکسان نکنید و برای دو ظاهر، registry، تنظیمات، renderer بزرگ یا وابستگی تازه نسازید.
3. هنگام انتقال یک مصرف به مالک مشترک، قانون قدیمیِ همان مصرف را حذف کنید؛ override تکراری یا alias موقت باقی نگذارید. بخش‌های نامرتبط را خودکار بازطراحی نکنید.
4. CSS/JS فقط از entry و مسیرهای مصرف فعلی انتخاب شود؛ سورس ماژولار به معنی درخواست HTTP مستقل برای هر قطعه نیست. خروجی dist را مستقیم ویرایش نکنید.
5. RTL/LTR، موبایل، معنای تگ‌ها، ابعاد تصویر، reduced-motion و cleanup حفظ شوند. بررسی کوتاه متناسب با تغییر کافی است؛ build اثبات FPS یا سرعت هاست نیست.
6. مالک مشترک یا قرارداد مصرف که تغییر کرد، همین فهرست را به‌روز کنید. AGENTS و skill به این سند ارجاع می‌دهند؛ فهرست کامل را در سه جا کپی نکنید. کتابخانهٔ طراحی و پروژه‌های مشتری runtime مستقل دارند؛ این سند مجوز همگام‌سازی خودکار بین پروژه‌ها نیست.

## عنوان جمع‌وجور صفحات بدون هیرو

`inc/compact-title.php` مالک تشخیص route و دادهٔ امن، `template-parts/layout/titles/compact.php` مالک markup، `src/css/layout/compact-title.css` مالک هندسه و پس‌زمینه است. خروجی `layout/page-title.php` برای آرشیوها، وبلاگ/جستجو و برگهٔ بدون هیرو قبل از ظرف محتوا به این مالک واگذار می‌شود؛ `content-heading.php` در این مسیرها عنوان دوم چاپ نمی‌کند؛ جزئیات نوشته و پروژه همان عنوان متنی قبلی را حفظ می‌کنند. رندر compact یک H1 با Hafez و اندازهٔ ۳۲ تا ۴۴px دارد؛ توضیح از نقش mut، برچسب p، بدون آمار یا تزئینات اضافه؛ CTA اختیاری از renderer مشترک دکمه. تصویر ثابت طلایی از کتابخانهٔ رسانه با کلید `compact-title` در `webtalik_media` با ابعاد ۲۱۷۲×۷۲۴ و رنگ پایهٔ `#0e0e0d` تمام پس‌زمینهٔ همین بخش را می‌پوشاند. CSS فقط هنگام مصرف بارگذاری می‌شود. طرح فعلی ثابت است.
