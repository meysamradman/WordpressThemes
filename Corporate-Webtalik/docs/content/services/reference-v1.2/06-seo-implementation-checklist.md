# چک‌لیست سئو و کنترل انتشار صفحات خدمات وبتالیک

این سند **دستور اجرا** است، نه محتوایی که باید در صفحه عمومی نمایش داده شود.

## A. کیفیت محتوا و اصالت

- [ ] هر صفحه یک هدف جست‌وجوی اصلی و مخاطب مشخص دارد.
- [ ] محتوای خدمات دیگر به‌جای توضیح همان خدمت تکرار نشده است.
- [ ] در هر صفحه تعریف دقیق، موارد کاربرد، قابلیت‌های واقعی، محدودیت‌ها، هزینه، فرایند و CTA مناسب وجود دارد.
- [ ] اعداد، نتایج، رضایت مشتری، فناوری پروژه، تاریخ و شرایط پشتیبانی فقط با سند ثبت شده‌اند.
- [ ] نمونه‌کارها دقیقاً سهم وبتالیک را توضیح می‌دهند؛ تجربه ساختگی یا متن «نمونه» منتشر نشده است.
- [ ] متن از رقبا کپی، بازنویسی نزدیک یا صرفاً با جابه‌جایی واژه‌ها تولید نشده است.
- [ ] نمونه‌گیری از جمله‌های غیرعمومی و بررسی تشابه احتمالی انجام شده؛ نتیجه به‌عنوان تضمین یکتایی کامل معرفی نشده است.
- [ ] توضیحات و مثال‌های هر خدمت با دامنه واقعی کار، تجربه وبتالیک و نمونه‌کارهای قابل اثبات منطبق شده‌اند.
- [ ] عنوان‌ها و متن‌ها بر مبنای نیت مخاطب نوشته شده‌اند، نه تقلید ترتیب محتوای سایت‌های رقیب.
- [ ] اصطلاحات تخصصی برای مشتری توضیح داده شده‌اند و از اغراق یا تضمین بی‌دلیل خبری نیست.
- [ ] ترجمه‌ها، توضیحات چندزبانه و عکس‌ها حق استفاده و کیفیت مناسب دارند.

## B. عنوان، متا و ساختار HTML

- [ ] برای هر URL یک `<title>` متمایز و سازگار با H1 ثبت شده است.
- [ ] Meta Description همان خدمت را خلاصه می‌کند؛ عبارت‌های نامرتبط و فهرست‌کردن کلمات کلیدی ندارد.
- [ ] در محتوای اصلی یک H1 روشن و ساختار معنادار H2/H3 وجود دارد؛ Heading فقط برای اندازه ظاهری استفاده نشده است.
- [ ] زیرعنوان Hero که نقش زیرعنوان دارد در `p` است، نه H2 تزئینی.
- [ ] لینک‌های CTA و خدمات به‌صورت `<a href>` واقعی قابل پیمایش هستند.
- [ ] آدرس Canonical هر صفحه با URL نهایی سازگار است؛ صفحات تکراری و نسخه‌های آزمایشی بررسی شده‌اند.
- [ ] اگر منوی Breadcrumb قابل مشاهده است، ساختار آن با URL و در صورت استفاده `BreadcrumbList` هماهنگ است.
- [ ] داده ساختاریافته فقط در صورتی اضافه شده که از محتوای قابل مشاهده و داده واقعی پشتیبانی کند.

## C. دسترسی به محتوا و سئوی فنی

- [ ] محتوای اصلی HTML قابل خواندن است و صرفاً با Hover، Scroll یا کلیک جاوااسکریپتی به وجود نمی‌آید.
- [ ] مسیرهای مهم در سورس/رندر نهایی قابل پیمایش‌اند؛ SPA از آدرس و وضعیت HTTP درست استفاده می‌کند.
- [ ] محیط پیش‌نمایش/استیجینگ به‌اشتباه ایندکس نمی‌شود و سایت اصلی به‌اشتباه `noindex` ندارد.
- [ ] تصاویر محتوایی Alt توصیفی و تصاویر صرفاً تزئینی Alt خالی دارند.
- [ ] افکت‌های Sticky، پارالاکس و Hover در موبایل و کیبورد قابل استفاده‌اند و حرکت کاهش‌یافته رعایت می‌شود.
- [ ] عملکرد واقعی در موبایل بررسی می‌شود: LCP، INP، CLS و مشکلات شبکه/حجم رسانه.
- [ ] لینک‌های داخلی و نمونه‌کارها به URLهای زنده و محتوای معتبر می‌رسند.
- [ ] صفحات خصوصی پنل مدیریت، داده‌های کاربری و محیط‌های لاگین نباید ناخواسته ایندکس شوند.
- [ ] FAQ برای پاسخ کاربر است؛ نمایش Rich Result FAQ برای وب‌سایت شرکتی معمولی انتظار نمی‌رود.

## D. انتقال سایت قدیمی به نسخه جدید

- [ ] Crawl و خروجی URLهای قدیمی، sitemap، GSC و در صورت دسترسی داده بک‌لینک آماده شده است.
- [ ] برای هر URL قدیمی وضعیت تصمیم‌گیری ثبت شده: حفظ، تغییر مقصد مرتبط، نگهداری، حذف اصولی.
- [ ] برای URLهای تغییرکرده نقشه `old_url -> new_url` تک‌به‌تک تدوین شده است.
- [ ] URL دوره‌های آموزشی قدیمی به صفحه خدمات نامرتبط یا صفحه اصلی ریدایرکت جمعی نمی‌شوند.
- [ ] ریدایرکت 301/308 فقط زمانی که انتقال دائمی است به مقصد واقعاً مرتبط انجام می‌شود.
- [ ] زنجیره ریدایرکت‌ها حذف شده و لینک‌های داخلی مستقیماً به URL نهایی اشاره می‌کنند.
- [ ] sitemap جدید تنها URLهای canonical و قابل ایندکس را در بر می‌گیرد.
- [ ] وضعیت 404/410، Canonical، robots و پاسخ سرور پس از انتقال تست شده است.
- [ ] قبل و بعد از انتشار عملکرد کلیک، نمایش، ایندکس و خطاهای Crawl پیگیری می‌شود.
- [ ] افت/نوسان احتمالی رتبه در دوره مهاجرت به‌عنوان ریسک واقعی ثبت شده؛ تضمین حفظ همه رتبه‌ها داده نشده است.

## E. اطلاعات باز و مالک تأیید

| مورد | نیازمند تأیید توسط |
|---|---|
| نام خدمت چهارم | وبتالیک |
| نام و URL نهایی سه صفحه خدمت | وبتالیک + مسئول فنی/سئو |
| نام و جزئیات نمونه‌کارها | وبتالیک |
| برآورد/تعرفه و شرایط درخواست پروژه | وبتالیک |
| قرارداد مالکیت، تحویل سورس و پشتیبانی | وبتالیک |
| داده‌های Search Console و URLهای قبلی | مالک سایت و مسئول سئو |
| ماژول‌های قابل نمایش پنل React+Vite | وبتالیک + بررسی امنیت |
