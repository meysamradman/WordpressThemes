# سناریوهای خدمات وب‌تالیک

در `/services/` چهار خدمت را با توضیح کوتاه و لینک به صفحهٔ مربوط معرفی می‌کنیم. معیار انتخاب برای بازدیدکننده نوع خروجی است. جزئیات پیاده‌سازی، نمونه‌کار و FAQ تخصصی در صفحهٔ همان خدمت می‌آیند.

| خدمت | خروجی و فناوری | شناسنامه |
| --- | --- | --- |
| طراحی و توسعه وب‌سایت اختصاصی | طراحی و کدنویسی رابط وب با Next.js و React. بک‌اند و API با Django یا FastAPI در صورت نیاز. محور صفحه، وب‌سایت عمومی و کار مخاطب در آن است. | [شناسنامه](custom-website/scenario.md) · [متن‌ها](custom-website/copy.md) |
| طراحی و توسعه تخصصی وردپرس | قالب، قابلیت و افزونهٔ سفارشی با WordPress و PHP. محور صفحه، توسعه در بستر وردپرس و مدیریت محتواست. | [شناسنامه](wordpress.md) |
| پنل مدیریت و سامانه‌های تحت وب | پنل با React و Vite، بک‌اند Django یا FastAPI، API و پایگاه داده. محور صفحه، داده، نقش‌ها و گردش کار عملیاتی است. | [شناسنامه](web-systems.md) |
| طراحی و توسعه اپلیکیشن موبایل | اپلیکیشن با React Native و Expo، متصل به بک‌اند و API. محور صفحه، تجربه و فرایندهای کاربر موبایل است. | [شناسنامه](mobile-app.md) |

آدرس و H1 فعلی هر خدمت در شناسنامهٔ خودش ثبت شده. اگر پروژه هم سایت عمومی دارد و هم پنل عملیات، هر صفحه دربارهٔ خروجی خودش توضیح می‌دهد و از متن مرتبط به خدمت مکمل لینک می‌دهد. معرفی راهکارهای آمادهٔ املاک، فروشگاه و وب‌سایت شرکتی در [محصولات](../products/README.md) پیگیری می‌شود.

### ترتیب تطبیق متن با طراحی

1. در بریف، مخاطب، تصمیم کاربر، خروجی و مرز خدمت را با شواهد واقعی روشن کنید. FAQ، هزینه، تحویل و پشتیبانی را مطابق دامنهٔ کار و قرارداد بنویسید. نمونه‌کار قابل انتشار باید نقش وبتالیک، مسئله، راهکار و فناوری تأییدشده را روشن کند.
2. متن پیشنهادی را با نسخهٔ موجود مقایسه کنید. از بخش محتوای عمومی بسته تنها متن بازبینی و تأییدشده را برداشت کنید. بریف، تحقیق و یادداشت پیش از انتشار در مستندات داخلی بمانند. موضوع‌های هر سند را کامل بررسی کنید و موارد ادغام‌شده، موکول‌شده یا نیازمند شاهد را در شناسنامهٔ صفحه ثبت کنید.
3. برای هر موضوع، H2/H3، متن و رسانه، سکشن موجود یا پیشنهادی و رفتار موبایل/دسکتاپ را تعیین کنید. Grid، Sticky و تایم‌لاین پس از مشخص شدن محتوای لازم انتخاب شوند. متن، لینک و اقدام اصلی در HTML اولیه در دسترس باشند.
4. در پایان، عنوان و متا را در مالک Yoast بررسی کنید. مقصد واقعی پیوندهای هاب، خدمات مکمل، نمونه‌کار و تماس را کنترل کنید. تغییر URL پس از بررسی نشانی قدیمی، canonical و نیاز به ریدایرکت در نقشهٔ انتقال انجام شود. [راهنمای آغاز سئوی گوگل](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)

## الگوی مشترک چهار صفحه

- معرفی روشن، انتخاب خدمت و خروجی قابل تحویل، قابلیت‌ها، نقش فناوری‌ها، مدرک، مراحل، پاسخ به سؤال‌های تصمیم‌ساز و مسیر تماس. تعداد موضوع‌ها تعداد سکشن‌های گرافیکی را تعیین نمی‌کند. چیدمان مشکی و طلایی فعلی مبنای تطبیق متن‌هاست.
- یک H1 با نام خدمت، H2 برای موضوع‌های اصلی و H3 برای زیرموضوع‌هایی مانند کارت‌ها و فناوری‌ها. متن عمومی و لینک‌های واقعی در HTML اولیهٔ PHP باشند. GSAP حرکت و نمایش عناصر را مدیریت می‌کند. طول متن را نیاز کاربر و فضای طرح تعیین می‌کند. [محتوای کاربرمحور گوگل](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).
- برای تصویر واقعی مرتبط، از رسانهٔ وردپرس، عنوان یا شرح همراه و Alt توصیفی استفاده می‌کنیم. برای هر نمونه‌کار، مسئله، امکانات انجام‌شده، فناوری تأییدشده و لینک جزئیات را ثبت می‌کنیم. [راهنمای تصاویر گوگل](https://developers.google.com/search/docs/appearance/google-images)، [شناسنامهٔ نمونه‌کارها](../portfolio.md).
- در FAQ معمولاً چهار تا شش پرسش متمایز و مؤثر در تصمیم مشتری کافی است. گوگل نمایش FAQ rich result را از ۷ مه ۲۰۲۶ متوقف کرده و FAQ برای پاسخ به مشتری نگه داشته می‌شود. [به‌روزرسانی مستندات Google Search Central](https://developers.google.com/search/updates#may-2026).
- برای هر صفحه عنوان و توضیح متای متناسب، مقصد لینک‌های داخلی و مسیر تماس ثبت می‌شوند. برای canonical و مالک متادیتا به [سئوی فنی مشترک](../../../../WEB-DEVELOPMENT-STANDARDS/shared/20-TECHNICAL-SEO-SCHEMA-v1.0.md) رجوع می‌کنیم. لینک داخلی متن روشن و `href` واقعی دارد. [راهنمای لینک‌های گوگل](https://developers.google.com/search/docs/crawling-indexing/links-crawlable).
- عبارت‌های هر شناسنامه برای تحقیق و نگارش‌اند، بدون ادعای حجم جست‌وجو. پس از انتشار می‌توان پرس‌وجوهای واقعی را در Search Console بررسی کرد.
