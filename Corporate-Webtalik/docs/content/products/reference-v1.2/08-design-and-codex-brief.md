# 08 | نقشه طراحی سکشن‌ها و Brief اجرا برای Codex

> **این فایل نقشه محتوایی/طراحی است، نه اجازه ساخت.** پس از تأیید نهایی، Codex باید به سورس واقعی سایت وبتالیک مراجعه کند و سکشن‌ها را روی کامپوننت‌های موجود بنشاند؛ از صفر یک UI مستقل یا طرح تصادفی نسازد.

## اصول ثابت طراحی

- فارسی RTL، رنگ‌های مشکی، سفید و **طلایی صرفاً Accent**؛ خوانایی بر تزئین اولویت دارد.
- تایپوگرافی فارسی از فونت‌های محلی پروژه؛ فونت جدید CDN اضافه نشود.
- Hero کوتاه و تمیز؛ عنوان سئو و CTA دیده شوند. عنوان روی تصویر شلوغ یا با افکت زیاد محو نشود.
- تصاویر **واقعی** از داشبورد/وب/موبایل؛ نمایش بدون داده شخصی. تصویر تخیلی رقیب وارد سایت نشود.
- کارت‌ها ظریف و حرفه‌ای، متناسب با طراحی فعلی سایت. Scroll و Sticky فقط وقتی معنا دارند؛ محتوا حتی با JavaScript یا انیمیشن غیرفعال قابل‌خواندن باشد.
- هندسه موبایل: Grid تبدیل به Stack، عکس محصول اندازه مناسب، Tabs قابل پیمایش با کیبورد؛ `prefers-reduced-motion` رعایت شود.
- HTML Semantic، H1 تک، عنوان‌ها منظم، لینک HTML، alt دقیق، تصاویر سبک، توجه به CWV.

## لندینگ فروشگاه — ترتیب اجرایی

1. Hero با عنوان و زیرعنوان و CTA ثابت «ثبت سفارش اختصاصی»؛ عکس واقعی وب/پنل/موبایل.
2. «فروشگاه و پنل چگونه کار می‌کنند؟» توضیح جریان خرید/عملیات، نه GIF صرفاً تزئینی.
3. ویترین اجزای واقعی با Tab: وب‌سایت، پنل، موبایل؛ فقط بخش‌های تأییدشده.
4. امکانات: کاتالوگ و جست‌وجو، سفارش، مشتری، پرداخت/ارسال، محتوای سایت؛ نه ۲۰ کارت تکراری.
5. سفارشی‌سازی طراحی/قابلیت/API؛ تفکیک استاندارد/سفارشی.
6. فناوری‌ها به‌صورت مختصر و با کاربرد.
7. مراحل سفارش، عوامل هزینه، FAQ.
8. CTA پایانی.

## لندینگ املاک — ترتیب اجرایی

1. Hero: سامانه جامع املاک اختصاصی + CTA + تصویر واقعی صفحه ملک.
2. نمایش نمونه روند «مخاطب ملک را می‌بیند / تیم اطلاعات را مدیریت می‌کند».
3. رابط‌ها: وب‌سایت، پنل، اپ (فقط در وضعیت تأیید).
4. امکانات پایه قابل اثبات: ملک، پروژه ساختمانی، رسانه، نقش/دسترسی؛ هر ادعا بر اساس آخرین سورس.
5. سفارشی‌سازی: برند، فرم‌ها، فرایند انتشار/نقش‌ها.
6. امکانات تکمیلی مانند CRM فقط تحت عنوان **قابل بررسی** و نه ویژگی فعال.
7. فناوری، سفارش، هزینه، FAQ.
8. CTA پایانی.

## لندینگ شرکتی — ترتیب اجرایی

1. Hero: سایت شرکتی و مدیریت محتوا + CTA + تصویر واقعی محصول.
2. نمایش صفحه سایت/پنل محتوا.
3. امکانات: خدمات، درباره، نمونه‌کار، مقاله، رسانه؛ تأیید از سورس.
4. کاتالوگ بدون پرداخت، در صورت نوع پروژه.
5. سفارشی‌سازی برند و توسعه فرایندهای اختصاصی؛ اپ موبایل فقط به‌عنوان درخواست جدا.
6. فناوری، مراحل، هزینه، FAQ.
7. CTA پایانی.

## پیوند تصمیم محتوا و طراحی

- اگر بخشی از متن هنوز سند ندارد، اول وضعیت در `09` روشن شود؛ **برای پرکردن فضای طراحی** متن تخیلی یا کارت غیرواقعی نسازید. هر توصیف وضعیت کد/مخزن/تست صرفاً داخلی است؛ به صفحه عمومی منتقل نشود.
- سکشن‌ها را می‌توان با حفظ ترتیب منطقی فشرده کرد؛ تعداد سکشن برای سئو هدف مستقلی نیست.
- فهرست محصولات باید قبل از CTA پایانی باشد؛ بعد از CTA سکشن معرفی جدید نگذارید.
- CTA در Hero و پایان تکرار می‌شود اما نام/رفتار یکسان است؛ «مشاوره رایگان»، «خرید»، «رزرو دمو» بدون مسیر واقعی نیاید.
