# 07 | مسیر ثبت سفارش اختصاصی (بدون خرید و پرداخت)

## اصل تجاری

در هاب، لینک «مشاهده جزئیات» کاربر را به لندینگ محصول می‌برد. در هر لندینگ تنها CTA تجاری: **ثبت سفارش اختصاصی**. عمل CTA بازکردن یک فرم واقعی درخواست پروژه است، نه checkout، پرداخت، رزرو خودکار وقت یا ایجاد حساب اجباری.

## رفتار CTA

1. کاربر روی «ثبت سفارش اختصاصی» کلیک کند.
2. فرم مشترک یا صفحه تماس/درخواست پروژه باز شود.
3. **نام و شناسه محصول** از همان لندینگ به فرم منتقل شود (فقط از allowlist سه محصول؛ به رشته ورودی غیرمعتبر اعتماد نشود).
4. کاربر شرح حداقلی نیاز را وارد کند و درخواست ارسال شود.
5. پیام تأیید ارسال فقط پس از پاسخ موفق Backend؛ شناسه/مسیر پیگیری اگر واقعاً پیاده‌سازی شده باشد نشان داده شود. قول «تا ۲۴ ساعت» بدون سیاست عملیاتی واقعی ممنوع.
6. هیچ مبلغ ثابت، درگاه یا مرحله خرید نشان داده نشود.

## فیلدهای پیشنهادی فرم

| فیلد | اجباری؟ | توضیح |
|---|---|---|
| نام و نام خانوادگی یا نام نماینده | بله | شیوه خطاب در پاسخ |
| راه تماس معتبر | بله | موبایل یا ایمیل با اعتبارسنجی؛ حداقل یک کانال |
| نام کسب‌وکار | خیر | اطلاعات تجاری مفید |
| محصول انتخابی | بله، از لینک پر شود | Store / RealEstate / Corporate؛ کاربر بتواند اصلاح کند |
| هدف پروژه | بله | شرح مسئله در یک textarea کوتاه |
| طراحی/برندسازی اختصاصی | انتخابی | UI/UX و هویت بصری |
| وب‌سایت، پنل، اپلیکیشن | انتخابی | تعیین اجزای موردنیاز، نه وعده وجود همه در بسته پایه |
| قابلیت یا اتصال ویژه | اختیاری | شرح درخواست خارج از پایه |
| سایت فعلی / لینک مرجع | اختیاری | URL معتبر و بدون اجازه دریافت رمز |
| بازه زمانی یا محدودیت اجرایی | اختیاری | فقط اطلاعات کمکی؛ وعده زمان ندهید |
| رضایت با شرایط حریم خصوصی | بر اساس سیاست/الزام واقعی | متن قابل دسترس و لینک معتبر |

## UX پیشنهادی

- فرم در موبایل و دسکتاپ کوتاه و RTL؛ فیلدهای اختیاری در بخش «جزئیات بیشتر» باز شوند.
- نام محصول به‌طور واضح بالای فرم باشد: «درخواست نسخه اختصاصی [نام محصول]».
- نمونه‌ای از پیام پایان: «درخواست شما ثبت شد. اطلاعات ارسال‌شده برای بررسی اولیه استفاده می‌شود.» فقط در صورت موفقیت واقعی.
- خطاهای اعتبارسنجی نزدیک هر فیلد و قابل خواندن برای Screen Reader.
- Spam protection، Rate Limit و ثبت امن/حداقلی داده در backend مطابق معماری سایت مقصد.
- هیچ اطلاعات حساس حساب/رمز/کلید API را از مشتری در فرم اولیه نخواهید.
- می‌توان بعد از ارسال، لینک مشاهده خدمات مرتبط داد، اما CTA دوم تجاری در خود لندینگ نسازید.

## مسیر فنی هنوز انتخاب نشده

تا زمان بررسی سایت شرکتی مقصد، نه URL جدید، نه Endpoint و نه Schema ذخیره‌سازی فرض شود. اگر سایت فرم درخواست پروژه موجود دارد، اول امکان استفاده مجدد از آن بررسی شود. لینک از همه لندینگ‌ها باید کار کند و `product_source` در داده درخواست ثبت شود.

## معیار پذیرش

- [ ] CTA هر سه لندینگ به فرم واقعی می‌رسد.
- [ ] محصول انتخابی اشتباه/خالی نمی‌شود.
- [ ] فرم بدون لاگین عمومی قابل ارسال است (مگر سیاست مشخص خلافش باشد).
- [ ] ارسال تکراری و خطاها مدیریت می‌شوند؛ پیام موفقیت ساختگی نیست.
- [ ] هیچ پرداخت یا cart در مسیر وجود ندارد.
- [ ] داده فرم فقط در سامانه مجاز نگهداری می‌شود.
