# تصمیم‌های انتشار قالب علی اسدی

این سند معیار مرور یافته‌های ممیزی ۱٫۱٫۱ است. اجرای موارد به نسخهٔ قالب و دادهٔ واقعی وابسته است. برای انتقال این الگو به پروژهٔ دیگر، ابتدا مالک فعلی رفتار و طراحی را مشخص کنید.

| یافته | تصمیم اجرایی |
|---|---|
| ۱. عنوان و دادهٔ خالی | H1 اصلی خانه در main و مستقل از اسلایدر است. قالب‌های اختیاری خدمات وقتی Page Title سراسری خاموش است H1 قابل‌دسترس دارند. اندازه و ظاهر عنوان‌های موجود سر جای خود می‌ماند. |
| ۲. پرده و ورود متن | پرده فقط روی سند مقصد یا رفرش اجرا می‌شود و وضعیت خروج تزئینی ندارد. تنظیم ورودِ بالای صفحه در این پروژه عمداً هم‌زمان با باز شدن پرده شروع می‌شود تا صفحه خالی نماند. حرکتِ پایین صفحه با viewport شروع می‌شود و مالک هر transform واحد است. |
| ۳. سئوی ویدئو | Schema فقط در صفحهٔ پخش عمومیِ دارای منبع واقعی، کاور و تاریخ معتبر اضافه می‌شود. گراف Yoast صاحب خروجی است و fallback فقط در نبود افزونه اجرا می‌شود. Video Sitemap و اعتبارسنجی ایندکس به محیط انتشار وابسته‌اند. |
| ۴. اعتبارسنجی و دسترسی | nonce رشته‌ای، قابلیت کاربر و وضعیت ذخیره بررسی شوند. پیش از رندر تصویر یا پیش‌نمایش ویدئو، attachment و والد بررسی شوند. رسانهٔ واقعاً خصوصی به مسیر ذخیره و سرو دارای کنترل دسترسی نیاز دارد. |
| ۵. تصاویر | لینک خالی کاور با جایگاه تزئینی حفظ‌کنندهٔ ابعاد جایگزین شده است. alt کتابخانهٔ رسانه، اندازه‌های ذاتی و srcset/sizes حفظ شوند. در آرشیو و آلبوم انتخاب eager/lazy با WordPress و در هیروی منتخب اولویت با تصویر اصلی است. |
| ۶. وبلاگ | بلوک‌های منتخب و Journal بخشی از طراحی وبلاگ‌اند. قبل از تغییر شمار کارت‌ها، محتوا و نیاز طراحی مشخص و هزینهٔ DOM اندازه‌گیری شود. |
| ۷. پخش ویدئو | پخش تک‌کلیکی با پوستر خود آپارات قراردادی تأییدشده است. تغییر به facade نیازمند بررسی رفتار واقعی پخش است. پیام وضعیت افزوده برای ویدئوی بومی مستلزم نمونهٔ محلی واقعی و پذیرش UI است. |
| ۸. دارایی‌های اسکرول | preload شرطی دسکتاپ وابسته به تصمیم پیش از اولین حرکت کاربر است. تغییر اولویت دریافت یا حذف فایل فقط با waterfall همان مسیر و بررسی حرکت اولیه انجام شود. |
| ۹. کوئری ویرایشگر و فوتر | فوتر شبکه‌های اجتماعی را مستقیم از دادهٔ مشتری می‌گیرد. انتخابگر موجود آهنگ برای تعداد فعلی مناسب است. اگر تعداد زیاد شد، جست‌وجوی صفحه‌بندی‌شده با مجوز مناسب در نظر گرفته شود. |
| ۱۰. سورس قدیمی | خانهٔ شرکتی قدیمی، افکت متنی وابسته به پردهٔ قدیمی و entryهای بدون مصرف آن از سورس و build حذف شده‌اند. قالب‌های اختیاری خدمات، مسیرهای قابل تولید و تنظیماتشان جدا از این زنجیره‌اند. |
| ۱۱. AJAX | HTML مستقیم هر URL معتبر باقی می‌ماند. در تعویض سریع، URL نهایی هم‌مبدأ، عنوان و تگ‌های SEO با نتایج به‌روزرسانی می‌شوند. تغییر به endpoint جزءصفحه نیازمند شواهد شبکه و قرارداد کش است. |
| ۱۲. گالری | عکس‌های صفحه‌بندی‌شده زیربخش آلبوم و مکمل هم‌اند. canonical آلبوم پایه است و ورودی خارج محدوده به URL معتبر برمی‌گردد. |
| ۱۳. سازگاری PHP | حداقل نسخهٔ قالب و نسخهٔ هدف هاست جدا ثبت شوند. بالا بردن حداقل PHP به قرارداد واقعی مشتری و تست همان نسخه نیاز دارد. |
| ۱۴. نوع محتوا | شناسه‌ها، slug و metaهای track، clip و album قرارداد داده‌اند. انتقال به افزونهٔ جدا پروژهٔ مهاجرت مستقل و نیازمند نگاشت، بکاپ و آزمون URLهاست. |
| ۱۵. تحویل | سورس و lockfile در پروژهٔ توسعه نگه‌داری شوند. بستهٔ اجرا باید همهٔ فایل‌های manifest مصرف‌شده را داشته باشد. برای بازبینی، بکاپ بازیابی و بستهٔ انتقال تأییدشده اولویت دارند. پوشهٔ staging و نسخهٔ تکراری فقط پس از تطبیق و تأیید مسیر حذف شوند. |
