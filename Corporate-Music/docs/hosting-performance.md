# عملکرد سایت علی اسدی روی هاست

| مورد GTmetrix | بررسی و اقدام |
|---|---|
| حجم و تعداد درخواست‌ها | گزارش ۸۸ درخواست و ۸٫۴۵ مگابایت، چند iframe و چند کپی از JS/CSS و فونت آپارات را نشان می‌دهد. صفحهٔ اول و آرشیو اکنون ابتدا کاور بومی و نسبت ثابت دارند. درخواست آپارات از این فهرست‌ها به انتخاب کاربر وابسته است. |
| فونت | قالب فقط یک WOFF2 محلی Peyda دارد. ایران‌سنسِ iframe متعلق به آپارات است. مسیر preload و CSS برای Peyda باید یکسان بماند. |
| اندازهٔ تصویر | کاورهای فهرست از attachment و srcset/sizes بومی استفاده کنند. کاور هیرو دارای اولویت است. بدون دیدن عنصر LCP و ابعاد واقعی آن، quality یا اندازهٔ همهٔ تصاویر را تغییر ندهید. |
| زنجیرهٔ درخواست‌های حیاتی | CSS مسیر و فونت محلی حفظ می‌شوند. modulepreloadهای اختیاری دسکتاپ اولویت پایین دارند. تغییر مالک اسکرول پس از حرکت اول کاربر مجاز نیست. |
| Cache-Control | در بررسی دامنهٔ اصلی، Peyda حدود ۱۴ روز cache داشت و بنر WebP هدر Cache-Control نداشت. برای فایل‌های hashدار CSS/JS کش بلند و immutable مناسب است. برای تصاویر با URL ثابت و uploads عمومی، TTL کوتاه‌تر با امکان پاک‌سازی کش تعریف شود. هدر واقعی پاسخ Nginx یا لایهٔ کش را بررسی کنید. |
| TTFB | عکس گزارش حدود ۱٫۶ ثانیه تا اولین بایت، شامل ۷۶۶ms اتصال و ۸۶۶ms بخش backend، نشان می‌دهد. جداگانه با GET مهمان روی هاست اندازه‌گیری شود. کش پاسخ عمومی برای مسیرهای مجاز باید درخواست‌های ورود، پیشخوان، پیش‌نمایش، محتوای رمزدار و بازدیدکنندهٔ واردشده را دور بزند. |
| CDN و موقعیت تست | زمان اتصال از ایران و نقطهٔ اروپایی یکسان نیست. ابتدا هر دو موقعیت را با URL و شرایط کش یکسان مقایسه کنید. CDN برای بررسی موفق گزارش الزامی نیست. اگر اضافه شد، دسترسی مخاطب ایران، cache purge و رفتار upstream بررسی شوند. |

تست کوتاه انتشار شامل بررسی Network خانه و آرشیو قبل و بعد از انتخاب ویدئو، هدر CSS و تصویر، و یک رفرش و انتقال داخلی برای پرده است. آمار واقعی پس از انتقال از دامنهٔ اصلی گرفته شود.
