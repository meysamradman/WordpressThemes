# راهنمای عملکرد و کش علی اسدی روی هاست

روش سنجش و سیاست کش در [استاندارد مشترک](../../WEB-DEVELOPMENT-STANDARDS/shared/09-PERFORMANCE-AND-CACHE.md) است. این سند شیوهٔ تأیید روی `aliasadioriginal.ir` را ثبت می‌کند.

| موضوع | قرارداد و روش بررسی روی هاست |
|---|---|
| حجم و درخواست‌ها | صفحهٔ اول و آرشیو ویدئو ابتدا کاور محلی دارند. درخواست‌های آپارات در این فهرست‌ها پس از انتخاب کاربر آغاز شوند. در جزئیات، پلیر رسمی قرارداد مستقل دارد. |
| فونت | قالب فقط یک WOFF2 محلی Peyda دارد. ایران‌سنسِ iframe متعلق به آپارات است. مسیر preload و CSS برای Peyda باید یکسان بماند. |
| اندازهٔ تصویر | کاورهای فهرست از attachment و srcset/sizes بومی استفاده کنند. کاور هیرو دارای اولویت است. بدون دیدن عنصر LCP و ابعاد واقعی آن، quality یا اندازهٔ همهٔ تصاویر را تغییر ندهید. |
| زنجیرهٔ درخواست‌های حیاتی | CSS مسیر و فونت محلی حفظ می‌شوند. modulepreloadهای اختیاری دسکتاپ اولویت پایین دارند. تغییر مالک اسکرول پس از حرکت اول کاربر مجاز نیست. |
| Cache-Control | نمونهٔ دامنه در 2026-11-18: CSS اصلی ۱۴ روز max-age داشت، کاور WebP بررسی‌شده ETag/Last-Modified داشت و TTL صریح نداشت. کش تمام‌صفحه از هدر عمومی تأیید نشد. بعد از تغییر، HTML، CSS هش‌دار و یک WebP از uploads را جدا با GET مهمان بررسی کنید. |
| TTFB | GET مهمان و زمان بخش اتصال/انتظار را جدا ثبت کنید. نبود هدر HIT به‌تنهایی وضعیت کش داخلی Nginx را مشخص نمی‌کند. تنظیم واقعی سرور و استثناها طبق استاندارد مشترک و با مجوز اعمال شوند. |
| CDN و موقعیت تست | زمان اتصال از ایران و نقطهٔ اروپایی یکسان نیست. ابتدا هر دو موقعیت را با URL و شرایط کش یکسان مقایسه کنید. CDN برای بررسی موفق گزارش الزامی نیست. اگر اضافه شد، دسترسی مخاطب ایران، cache purge و رفتار upstream بررسی شوند. |

تست کوتاه انتشار شامل Network خانه و آرشیو قبل و بعد از انتخاب ویدئو، هدر CSS و تصویر، رفرش و انتقال داخلی برای پرده است. برای به‌روزرسانی قالب از [قواعد بستهٔ همین پروژه](wordpress.md#قواعد-بستهٔ-هاست) استفاده کنید.
