# استاندارد اجرایی HTML، SEO، ریسپانسیو و حرکت

## دامنه و نحوهٔ استفاده

مبنای توسعه و بازبینی تدریجی سایت‌های مشتری است. فعلاً در Corporate-Webtalik و Corporate-Music (علی اسدی) اعمال می‌شود؛ Radman-Design-Library مشمول این ثبت نیست. برای پروژهٔ مشتری بعدی، سند و مرجع را به داکیومنت مستقل آن منتقل و جدول مالک‌ها را با سورس همان پروژه تطبیق بدهید؛ هیچ وابستگی runtime یا همگام‌سازی خودکار میان پروژه‌ها نسازید.

مرجع کامل: [GENERAL-HTML-SEO-RESPONSIVE-GSAP-GUIDE-v1.2.md](reference/GENERAL-HTML-SEO-RESPONSIVE-GSAP-GUIDE-v1.2.md)، نسخهٔ بدون تغییر فایل تحویلی مالک در ریشهٔ آرشیو. این سند لایهٔ اجرایی آن برای قالب مشتری است؛ متن اصلی یا منابعش را جای قرارداد فعلی پروژه نگذارید. هنگام ارتقای مرجع، اختلاف نسخه را بررسی کنید؛ ادغام یا تغییر کد خودکار نیست.

**وضعیت:** قواعد ثبت شده‌اند؛ انطباق کامل صفحات هنوز تأیید نشده است. این ثبت، مجوز حذف افکت، تغییر طراحی، بازنویسی صفحات، فعال‌کردن ردیابی یا تغییر سیاست ایندکس نیست. تغییرات جدید و بازبینی مالکِ درگیر از این قرارداد پیروی کنند؛ اصلاح صفحات قبلی مطابق فهرست تدریجی پایین انجام شود.

## ارزیابی مرجع و تطبیق ضروری

مبنای راهنما مناسب است: یک URL و DOM اصلی، HTML قابل‌خزش، حرکت به‌عنوان enhancement، بارگذاری انتخابی و تفکیک دادهٔ واقعی از تست آزمایشگاهی. یک H1، عرض‌های تست، اندازهٔ لمسی و زمان حرکت قرارداد تیم هستند؛ سهمیه یا تضمین رتبه‌بندی گوگل نیستند.

- در این دو قالب، **یک H1 توصیفی برای هر صفحه** قرارداد اجرایی است؛ ثابت یعنی در HTML اولیه وجود داشته باشد و هویت صفحه با اسلاید/کلمات چرخشی جایگزین نشود، نه اینکه انیمیشن کوتاه روی همان عنوان ممنوع باشد.
- `span`/`div` را به سهمیه تبدیل نکنید. برچسب، شمارنده و متن تبلیغیِ بدون نقش عنوان p/span هستند؛ عنوان واقعی سکشن/کارت heading می‌ماند. span داخل عنوان فقط برای محتوای ترکیبی، شکست خط واقعی یا حرکت لازم است؛ حروف فارسی جدا نشوند.
- مثال GSAP مرجع الگوی مفهومی است، نه کد آمادهٔ الصاق: scope به ریشهٔ ماژول، cleanup مطابق lifecycle موجود، لغو timer/RAF و حذف listener/observer لازم است. `clearProps:'all'` را کورکورانه کپی نکنید؛ style مربوط به layout یا افکت دیگر را پاک نکنید. نمونهٔ مرجع cleanup نهایی `mm.revert()` را نشان نمی‌دهد؛ آن را در disposer موجود ثبت کنید، نه یک موتور lifecycle دوم. در cleanup داخلی matchMedia، context.revert را دوباره صدا نزنید.
- تغییر transform/opacity ترجیح عملکردی است؛ حرکت بومی scrollLeft/Scroll Snap موجود مجاز است. انیمیشن کوتاه اندازهٔ پنل فقط با مسئولیت هندسهٔ همان ماژول و بررسی layout/CLS قابل استفاده است؛ همهٔ مالک‌های فعلی را به transform بازنویسی نکنید.
- «محتوای اصلی در HTML» با تعویق فایل صوت/ویدئو تعارض ندارد: عنوان، توضیح، کاور و لینک جزئیات/دانلود از ابتدا حاضرند؛ بایت‌های فایل پخش طبق [media.md](media.md) با درخواست کاربر می‌آیند. محتوای صفحات بعد از طریق URL و صفحه‌بندی بومی قابل دسترس است، نه اینکه همهٔ آرشیو در DOM اول بارگیری شود.
- افکت‌های تأییدشده، زمان‌بندی، Hero، preloader و ویدئوی تزئینی موجود خودکار حذف یا ساده نشوند. پیش‌فرض **طراحی جدید** بدون preloader مسدودکننده است؛ نمونه‌های موجود باید جداگانه از نظر نمایش فوری محتوا، خطا، storage، reduced-motion و راه خروج بررسی شوند. این استثنا به معنی تأیید انطباق فعلی آن‌ها نیست.

## ۱. HTML، محتوا و SEO

- محتوای اصلی از PHP با API بومی WordPress رندر شود؛ عنوان/متن/لینک مهم وابسته به اجرای JS، hover یا اولین swipe نباشد. لینک مقصد `<a href>` واقعی و کنترل عملیات `<button type="button">` باشد. فرم label و خطای قابل‌فهم داشته باشد؛ placeholder جای label نیست.
- یک main اصلی، landmarks مناسب، H1 صفحه، H2 سکشن و H3 کارت/زیرموضوع؛ H4–H6 فقط بر اساس محتوا. section محتوایی عنوان مناسب داشته باشد؛ wrapper صرفاً چیدمانی را section بی‌معنا نکنید. برای ظاهر، سطح heading تغییر نکند و فونت‌های Hafez/Peyda طبق tokens/base حفظ شوند.
- title و description مختص موضوع URL، طبیعی و بدون keyword stuffing باشند؛ طول قطعی snippet یا تعداد کلمه/heading وعده داده نشود. فوتر لینک‌های مهم و تماس معتبر داشته باشد؛ برای SEO لینک یا متن تکراری نسازید.
- **Yoast فعال مالک title/description/canonical، OG/social metadata، schema و sitemap است.** فیلد خالی افزونه را قالب دور نزند؛ helper fallback `inc/seo.php` فقط بدون افزونهٔ شناخته‌شده یا طبق قرارداد فعلی خودش کار کند. `wp_head`، `wp_body_open` و `wp_footer` حفظ شوند. تحلیل متن افزونه ممکن است محتوای template را نشناسد؛ برای سبزکردن امتیاز افزونه، HTML تکراری یا متن مخفی اضافه نکنید.
- Canonical، redirect، status HTTP، robots و sitemap باید با URL نهایی سازگار باشند؛ هر صفحهٔ آرشیوِ صفحه‌بندی‌شده قابل دسترسی و canonical متناسب خودش داشته باشد. صفحه‌بندی AJAX همان href واقعی و fallback بومی را حفظ کند. robots.txt جای noindex نیست؛ noindex باید برای crawler قابل دریافت باشد.
- noindex محیط local/staging حفظ شود؛ تغییر indexability و دامنه/redirectها فقط در آماده‌سازی انتشار و با بررسی تنظیمات واقعی انجام شود. URL تست، جستجو، preview، خصوصی و رمزدار طبق سیاست فعلی عمومی/ایندکس نشوند.
- JSON-LD فقط مطابق محتوای قابل مشاهده و اطلاعات واقعی؛ بدون schema موازی قالب و افزونه، امتیاز/قیمت/موجودی/هویت ساختگی یا تضمین rich result. `meta keywords` اضافه نشود. صحت دادهٔ نهایی مشتری پیش از انتشار لازم است.
- تصویر محتوایی alt مرتبط، تزئینی alt خالی؛ لوگوی لینک‌دار نام دسترس‌پذیر داشته باشد. ابعاد ذاتی و نسبت صحیح حفظ شوند. کاورهای محتوایی از شناسهٔ رسانه و srcset/sizes بومی وردپرس می‌آیند. تصویر ثابت طراحی برگهٔ سفارشی از WebP محلی در قالب و در صورت نیاز srcset/sizes همان قالب می‌آید. تصویر شاخص برگه منبع این تصاویر نیست. محتوای رمزدار/خصوصی، excerpt، تصویر و metadata آن نباید از guardهای موجود عبور کند.
- تأیید Search Console یک‌بار از integration منتخب؛ Analytics فقط با provider/ID واقعی مالک و یک محل تزریق. افزودن سرویس، CDN، فونت، آیکون، placeholder tracking ID یا درخواست خارجی خودکار ممنوع؛ جزئیات مالکیت در [wordpress.md](wordpress.md).

## ۲. یک DOM و ریسپانسیو

- همان URL و محتوای اصلی در دسکتاپ/موبایل؛ viewport برابر width=device-width, initial-scale=1 و zoom باز. سکشن یا نسخهٔ PHP کامل موبایل را با `wp_is_mobile()` تکثیر نکنید. استثنای واقعی نیازمند قرارداد cache/SEO جداست، نه تشخیص دلخواه دستگاه.
- Grid/Flex/gap و logical properties/RTL؛ breakpoint بر اساس شکستن محتوا. ترتیب DOM و مسیر Tab منطقی بماند؛ جابه‌جایی بصری نباید خواندن با کیبورد/فناوری کمکی را به‌هم بزند. عرض، فونت و line-height از مالک موجود مصرف شوند.
- H1، معرفی، لینک‌های مهم، metadata و structured data در موبایل حذف نشوند. آکاردئون می‌تواند محتوای حاضر را جمع کند؛ متن اصلی با اولین کلیک از سرور ساخته نشود.
- عرض‌های 320/360/390/768/1024 و دسکتاپ نقاط نمونهٔ پوشش‌اند، نه الزام اجرای کل ماتریس برای هر ویرایش کوچک. برای تغییر محدود، breakpointهای تحت‌تأثیر؛ برای پذیرش انتشار، پوشش کامل و دستگاه واقعی. اسکرول افقی ناخواسته را اصلاح کنید؛ overflow:hidden عمومی برای پنهان‌کردن عیب نگذارید.
- اندازهٔ بدنه معمولاً نزدیک 16px و سطح لمس نزدیک 44px توصیهٔ کاربردی است؛ glyph می‌تواند کوچک‌تر و hit area مستقل باشد. کنتراست و focus-visible، کیبورد، لمس، نام کنترل‌ها، Escape/بازگشت فوکوس برای منو/دیالوگ و عملکرد بدون hover بررسی شوند؛ کوچک‌کردن glyph مجوز هدف لمسی غیرقابل استفاده نیست.
- در صورت نیاز picture/art direction و srcset/sizes؛ تصویر LCP را بی‌دلیل lazy نکنید. eager و fetchpriority=high فقط برای منبع واقعاً مهم بالای صفحه، نه همهٔ کارت‌ها. پایین صفحه lazy با ابعاد رزرو‌شده و کشف‌پذیری HTML؛ preload بی‌دلیل و دانلود دو نسخهٔ تصویر نداشته باشید.

## ۳. GSAP، اسکرول و بارگذاری

- فقط GSAP محلی و مالک‌های فعلی. CSS/JS مصرف‌کننده از entry و enqueue همان route؛ ابزار/پنل یا کل registry کتابخانه به مشتری منتقل نشود. tokens/base/button/icon و اجزای واقعی مشترک تکرار نشوند. محتوای مشتری از helper/editor خودش بیاید، نه نسخهٔ جدا برای هر viewport.
- خاموش‌کردن اجرا با media query مانع دانلود static import نیست. برای اثر واقعاً سنگین، مرز import شرطی/page entry و Network واقعی بررسی شود؛ برای حذف چند بایت، chunkهای بی‌دلیل یا loader موازی نسازید.
- متن/لینک/تصویر مهم در CSS پایه دیده شود. state اولیهٔ پنهان فقط پس از enhancement مطمئن، با fallback برای نبود JS، شکست import، تغییر breakpoint و reduced-motion. H1 اصلی پشت reveal طولانی یا منبع سنگین معطل نماند.
- transform/opacity، read/write جدا، حداقل DOM و بدون اندازه‌گیری پیوستهٔ layout. will-change سراسری و دائمی نسازید. matchMedia/context و lifecycle موجود برای cleanup؛ cleanup فقط اموال همان مالک را آزاد کند.
- reveal کوتاه و خوانا؛ تغییر کلمه با ارتفاع پایدار و H1 مستقل از شعار متغیر. hover/mouse-follow در لمس حذف یا به حالت قابل استفاده تبدیل شود. pin طولانی، اسکرول افقی اجباری و parallax عمیق در موبایل پیش‌فرض ندارند؛ افکت موجود با شواهد و تصمیم مالک اصلاح شود.
- pin wrapper و transform فرزند مسئولیت جدا داشته باشند؛ smoother، zoom و افکت دیگر هم‌زمان transform یک عنصر را ننویسند. اسکرول/فوکوس بی‌دلیل قفل نشود. offscreen/hidden-tab/reduced-motion و پاک‌سازی tween، ScrollTrigger، listener، observer، RAF و timer طبق نوع اثر رعایت شود.
- WebGL/مدل سنگین فقط با نیاز و سنجش؛ پوستر/تصویر سبک و fallback موبایل. این قرارداد مجوز افزودن Three.js یا افکت جدید نیست.

## ۴. کاروسل و رسانه

- محتوای مهم پیش‌فرض دستی؛ فلش نام‌دار، لمس/درگ، کیبورد، focus-visible و وضعیت/نشانگر موقعیت. از مالک کاروسل و پلیر فعلی استفاده کنید؛ انتخاب هر نوع محتوا مسئول renderer آن است. اندازهٔ قاب ثابت و بدون CLS.
- autoplay فقط با نیاز مشخص؛ کنترل توقف/شروع، توقف روی hover و ورود فوکوس، و شروع‌نشدن در reduced-motion. پس از توقف به‌علت فوکوس، بدون درخواست صریح کاربر دوباره شروع نشود. اسلاید مخفی کنترل focusable فعال نداشته باشد؛ aria-hidden روی جدِ دارای فوکوس قرار نگیرد.
- تیتر، متن و لینک اسلایدها قابل کشف از HTML؛ fetch همهٔ آرشیو یا همهٔ فایل‌های رسانه ممنوع. صفحات بعد لینک مستقل و enhancement AJAX موجود داشته باشند. Lazy تصویر، deferred صوت/ویدئو و preload=none طبق [media.md](media.md)، بدون پخش خودکار صوت.
- پوستر/کاور سبک از فایل پخش مستقل است؛ ویدئوی تزئینیِ از قبل تأییدشده استثنای guarded همان سند است. فایل سنگین Hero نباید نمایش متن و CTA را مسدود کند.

## ۵. Loading و ورودی صفحه

- برای طرح جدید بدون preloader تمام‌صفحه، تایمر اجباری یا انتظار لوگو پیش از محتوا. تغییر موارد تصویب‌شدهٔ قدیمی یک کار جداست؛ صرف ثبت استاندارد آن‌ها را حذف نکند.
- loading/skeleton فقط هنگام درخواست واقعی؛ فضا رزرو، وضعیت aria-live/aria-busy متناسب، خطا و retry/خروج مدیریت شود. عنصر مزاحم نباید صفحه را تا ابد مسدود کند.
- scriptهای frontend از enqueue موجود با module/defer متناسب؛ منبع JS، parse/execute و کار main thread هم بررسی شوند. loader ظاهری معیار LCP نیست.

## ۶. پذیرش، شواهد و اصلاح تدریجی

برای تغییر معمول، مالک/routeهای مصرف‌کننده را مشخص و checks کوتاه مرتبط انجام دهید. تغییر مستندات build یا مرورگر نیاز ندارد. نتیجه باید دقیق بگوید فقط سورس، build، مرورگر محلی یا محیط انتشار بررسی شده؛ «بهینه/SEO کامل» بدون شاهد گفته نشود.

معیار انتشار: HTML اولیه و بدون JS، reduced-motion، heading/link/metadata بدون تکرار، کد HTTP/redirect/canonical، موبایل و کیبورد، loading/LCP media، Network و Long Task مرتبط؛ سپس بررسی sitemap/ایندکس با دامنه و ابزار واقعی. noindex محلی را برای تست انتشار خاموش نکنید.

هدف CWV در صدک ۷۵ دادهٔ واقعی کاربران، جدا برای موبایل/دسکتاپ: **LCP ≤ 2.5s، INP ≤ 200ms، CLS ≤ 0.1**. Lighthouse/DevTools تشخیص آزمایشگاهی‌اند؛ امتیاز محلی تضمین دادهٔ میدانی یا رتبه نیست. نبود دادهٔ کافی باید اعلام شود؛ صرفاً برای جمع‌کردن معیار، tracker اضافه نشود.

### صف بازبینی (انجام‌نشده، نه فهرست عیب اثبات‌شده)

- [ ] P1 — مسیرهای نمایندهٔ خانه، خدمات/محتوای ثابت، آرشیو و جزئیات: H1/H2/H3، یک main، HTML اولیه، لینک واقعی، alt و privacy؛ اصلاح در مالک مشترک فقط پس از بررسی همهٔ مصرف‌کننده‌ها.
- [ ] P1 — مالکیت واقعی Yoast/قالب و خروجی metadata، canonical صفحه‌بندی، HTTP، robots/sitemap و تفاوت local/production؛ تنظیم نهایی و داده‌های مشتری جداگانه.
- [ ] P1 — نمایش متن/CTA بدون JS و هنگام شکست import؛ بازبینی preloader موجود و gate ورود Hero بدون حذف خودکار طراحی.
- [ ] P2 — موبایل/RTL، ترتیب فوکوس، لمس، کنتراست، zoom و اسکرول افقی؛ چیدمان و hit area کنترل‌ها به‌خصوص پلیر/منو/کاروسل.
- [ ] P2 — ورودی‌ها و waterfall: lazy/LCP، ابعاد/srcset، audio/video/poster، import/enqueue واقعی موبایل و routeها؛ اثبات با Network، نه حدس از کد.
- [ ] P2 — pin/parallax، cleanup، reduced-motion، خروج از دید/تب و هزینهٔ layout/Long Task؛ حفظ افکت تأییدشده تا تصمیم مستند.
- [ ] P3 — پذیرش مهمان روی هاست، موبایل واقعی، دامنه نهایی، Search Console و CWV میدانی پس از فراهم‌شدن محیط/دسترسی لازم.

هر مورد فقط پس از بررسی scope مشخص و شواهد همان مسیر بسته شود؛ از تیک‌زدن گروهی صفحات بررسی‌نشده و گزارش‌های روزانهٔ تکراری در docs خودداری کنید.

## منابع و نگهداری

مرجع تحویلی همهٔ منابع پایه را دارد. در ثبت این لایه، بخش‌های منتخب با [Google mobile-first](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)، [WAI carousel](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/)، [Core Web Vitals](https://web.dev/articles/vitals) و [GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/) تطبیق داده شد. سایر ادعاها و الگوی کد مرجع، گواه اجرای واقعی در این قالب‌ها نیستند. در تغییر API یا سیاست انتشار، مستند رسمی همان موضوع دوباره بررسی شود.

| معماری/دادهٔ مشتری | `docs/architecture.md`، `radmanct/inc/client.php`، `inc/pages/music-home.php` و editor بومی |
| SEO | `radmanct/inc/seo.php`، `docs/wordpress.md`؛ Yoast و fallback مستقل از صفحات |
| آهنگ | `inc/content/music.php`، `inc/music.php`، `template-parts/music/`؛ credits/date/lyrics در editor |
| ویدئو/گالری | `inc/content/collections.php`، `inc/videos.php`، `inc/albums.php`؛ archive/detail بومی و API رسانه |
| پلیر/کاروسل/AJAX | `src/js/ui/audio-controls.js`، `music-player.js`، `carousel.js`، `pages/archive.js` و `docs/media.md` |
| دارایی/حرکت/ظاهر | `inc/assets.php`، `src/js/runtime/lifecycle.js`، tokens/base و page entryهای واقعی |

مسیرهای نماینده: خانه، بیوگرافی/تماس، آرشیو/جزئیات track، clip و album، taxonomy و صفحه‌بندی آن‌ها. نام/کاور/اطلاعات اثر، متن شعرِ موجود در جزئیات و لینک دانلود عمومی در HTML بمانند؛ این به معنی دریافت خودکار فایل پخش نیست. پلیر ثابت فقط خانه و پلیر inline فقط جزئیات آهنگ، با یک مالک مشترک و preload=none؛ کنترل شعر به dock اضافه نشود. پالت اختصاصی مشتری حفظ و CSS از Webtalik بی‌اجازه کپی نشود. این ثبت اثبات انطباق همهٔ مسیرها نیست.
