# Architecture

Standalone Radman CT Music, copied from Corporate-Webtalik as a source baseline. Blog and native track module were selected from the independent Radman Design Library and remapped to local data. No runtime access or synchronization to either source project.

| Owner | Responsibility |
|---|---|
| `radmanct/inc/content/music.php` | Native `track`, `music_category`, `_rdc_track`, artist/poet/arranger/composer/release fields and nonce/capability-checked saves |
| `radmanct/inc/music.php` | Normalized metadata, local audio/privacy guards, one track card renderer |
| `radmanct/template-parts/music/` | Music archive/category and single content; same main query |
| `radmanct/inc/pages/music-home.php` | Home editorial filter and bounded native queries |
| `radmanct/template-parts/sections/home/{music-intro,latest-tracks,latest-videos}.php` | Named home composition; shared track/blog card renderers |
| `radmanct/inc/client.php` | Current customer copy, footer links and selected fixed dark sections; no settings framework |
| `radmanct/inc/assets.php` | Conditional entry loading and shared static/dynamic module graph |
| `radmanct/src/css/tokens.css`, `base.css` | Single palette/font/radius definitions and tag typography; Peyda for all headings and body |
| `radmanct/src/css/ui/music.css` | Shared archive/single/home music UI |
| `radmanct/src/css/ui/text-entrance.css` | Shared entrance for the selected titles and full introductions on home, biography and contact. `src/js/ui/text-entrance.js` starts offscreen targets once as they reach the viewport. Titles preserve Persian word boundaries and the selected introductions animate as complete blocks. |
| `radmanct/src/css/pages/music{,-home}.css` | Small page entries selecting needed UI; home reuses shared track cards, video cards and the button renderer |
| `radmanct/src/js/admin/music-editor.js` | Native media picker, only on track editor; frontend audio uses the native audio engine with a progressive custom control bar on detail pages |
| `radmanct/inc/seo.php` | Fallback yields to Yoast SEO; never duplicate canonical/metadata/schema |
| `tools/local-wordpress/` | Isolated Docker runtime and guarded first-install provisioning |

WordPress owns editorial content, attachment IDs, menus, users and configuration. No customer source database or user accounts were copied. The optional audio download defaults to the playback attachment. Audio/image guards preserve private/password-protected parents. Demo content is explicitly replaceable, including an original eight-second synthetic playback test file.

Local runtime: `http://127.0.0.1:8098`, project `corporate-music`, volumes `corporate-music-database` and `corporate-music-wordpress`. Start/Stop never reset credentials or content. Yoast files are installed in this runtime, with no source-project settings copied.

For a future server move, transfer this theme including consumed `dist/`, local fonts/languages, WordPress uploads/database and the selected plugins through a normal WordPress migration. Replace local URL references using a serialization-aware migration, supply production database configuration/HTTPS and remove local-only MU restrictions/environment/debug settings from the hosting setup. No deployment is performed by this project setup.

The client homepage follows the supplied artist mockup: charcoal/plum surfaces, mint #16cc9f actions/brand and a green hero. All palette values remain in tokens.css. The shared header/navigation/footer are client layouts, not Webtalik clones. Header search targets native track search. Primary destinations are /, /music/, /videos/, /gallery/, /about-us/ and /contact-us/. Biography and contact copy live in WordPress. Contact uses page-contact-us.php and the existing route-only artist.css. Client::booking() owns the booking contact, phone action and messaging handle. The contact footer uses the same social renderer as the rest of the site, with a contact-specific size and handle.


Corporate Music uses native WordPress document navigation. The decorative curtain uses 27 horizontal strips that collapse vertically in the artist palette. The Hub-inspired desktop dissolve keeps the 12 millisecond stagger and uses an 860 millisecond strip duration with a gentler opening. Direct visits show the page immediately. The mobile sequence uses a shorter duration. The arrival marker also sets the offset for the first-paint text motion. `ui/page-loading.js` records a short-lived destination marker during navigation and leaves the originating page visible. The header initializer uses that marker for internal navigation and the browser navigation entry for reloads. CSS starts the reveal immediately and the last strip ends it via `animationend`, with a bounded fallback. ScrollSmoother can attach during the curtain before the first scroll. A visit that has already begun scrolling or restored an offset keeps native scrolling for that document. The curtain respects reduced motion and resets on cancellation, history restoration or timeout. `pages/archive.js` owns AJAX status and shows a thin accent at the result boundary for delayed requests. Rapid requests cancel earlier ones and failed requests offer the ordinary link. The audio play button shows wait state from native playback events. Video buffering feedback belongs to the native video player or the Aparat iframe.

The native posts page, category/search archives and post detail use the Corporate Music palette and typography tokens. The header and page layouts use `rdc-ctr` from `src/css/site.css`, with the 1300px cap and logical gutter from `tokens.css`. Post details and their related sections use `rdc-ctr--read` with the same gutter. The blog base stylesheet owns the shared grid and card styles. Archive and detail styles load on their respective routes. The shared archive entry handles category and pagination navigation, while the search and sidebar enhancement load dynamically only for the blog.

Music archives use eight entries per native main query and the shared pages/archive.js AJAX owner used by blog and media archives; ordinary pagination links work without JavaScript. The list variant of Music\card reuses its metadata/credit renderer; home retains the compact variant. Single tracks compose a cover/credit/download row, template-parts/music/player.php and optional editorial/lyrics sections. src/js/ui/audio-controls.js owns only the native audio control UI, selected by pages/music.js on track singles; native browser controls remain the no-JavaScript fallback. No autoplay or second audio engine. The archive entry selects ui/music-archive.css; the separate detail entry selects ui/music-detail.css and audio-player.css. Both reuse ui/music-credits.css; neither loads the other page layout or homepage styles. Metadata is never fabricated for empty credits.

Biography uses page-about-us.php with route-only pages/biography.css. The native page editor owns the biography paragraphs. The biography-only works panel edits _rdc_bio_works, rendered by sections/biography/works.php. The row controls load only in the biography editor. Keep the page password guard before either content or image. The biography template renders the supplied portrait and original emblem from images/pages/biography.webp. The adjacent handle and social links remain native text and individually rendered icons. The homepage promotional artwork is a template asset under images/pages/home-social*.webp, rendered by social-promo.php below the video rail with responsive sources and lazy loading. AliAsadiOriginal is native text; the adjacent social SVGs use the same template-parts/ui/socials.php renderer and ui/socials.css owner as the footer. Client\socials() owns the single customer social list; missing URLs remain noninteractive. Keep fixed artwork in the template and theme assets for bespoke pages, with declared dimensions and responsive sources where useful. Editorial covers for posts, tracks, projects, videos and albums remain WordPress attachments.

Native gallery/video ownership: inc/content/collections.php registers album (/gallery/) and clip (/videos/), independent category/tag taxonomies and guarded metadata saves. inc/admin/collections.php extends the native list tables without replacing author, taxonomy, date, quick/bulk editing or Yoast columns. The old placeholder WordPress pages are retained as drafts; their public routes now belong to native archives.

inc/albums.php owns validated ordered attachment IDs and sixteen-photo paging inside albums. inc/videos.php owns local video validation, real quality-download IDs and the homepage video query. A missing 1080/720/480 file produces a disabled button; never label a different source as another resolution. Customer fields belong in the native editor: album image order/featured cover, clip primary video/quality files/featured cover/title/body/excerpt, and track credits/date/lyrics/audio/download. Metadata and media protections must survive quick edits and draft saves.

archive-album.php and archive-clip.php use the native main query, shared category-tree renderer and pages/archive.js. Album archives and single album galleries render sixteen items per request. The shared archive helper appends the next gallery batch near the end of the list and keeps real pagination links as a fallback. Single albums use gallery_page. Video archives retain their four-item pagination. Lightbox markup/style/motion has one owner for the gallery; native dialog, keyboard/RTL arrows, touch and focus return are required. Without JavaScript, image links and ordinary pagination still work.

Gallery/video styles follow the supplied references: four square photo columns with a fine accent border, two video columns, full-width detail player and separate quality download actions. Gallery omits category controls from the archive and album layout, preserving the taxonomy and editor. A one-image album opens its selected image directly from the archive through the shared lightbox, including when the featured cover and selected image use the same attachment. ui/media-card.css owns shared music and video card surfaces. ui/media-frame.css owns cropping and hover/focus behavior for music, video and gallery images, while the video-only outline remains in ui/video-grid.css. Page entries retain their own Grid layouts and select their existing radius tokens. Hover animation is limited to fine pointers and users who allow motion. Video details have a separate entry that shares ui/aparat.css with the home and video archive entries. Video archives currently omit the category control at the request of the client; preserve taxonomy registration, editor fields, routes and the existing category renderer for later use. Video archives show four full-width rows, player at inline start (right in RTL), copy and shared download action beside it; mobile stacks the same DOM. Aparat actions link to the video page, where provider download availability applies; local actions select a real quality file or the native playback attachment. Home uses the shared compact download action beside the one-line description. Its Aparat frames prepare when their cards enter the viewport. Attachments remain intrinsic/responsive/lazy; native video uses preload=none and no autoplay. ui/video-player.js delegates native playback controls and keeps archive cover behavior working after AJAX swaps. No second playback engine, remote service, new runtime dependency or invented real artist media is introduced. Temporary demo albums/videos use existing local media. The approved Radman screenshot.png remains the theme thumbnail.

Local database runtime uses pinned MySQL 8.4.13 LTS and a separate MySQL volume. WordPress APIs remain portable to MariaDB; no engine-specific theme dependency is permitted. Keep utf8mb4_unicode_520_ci as the shared default collation and preserve existing table collations. Start/Stop preserves data and credentials. Retained MariaDB volumes are recovery data, not MySQL data directories; engine changes require explicit backup/restore into a different volume. Private logical/physical/filesystem backups and restore manifests live under ignored backups/.

Artist identity uses the native WordPress custom_logo theme mod and site_icon option with media attachments. Preserve the original supplied wordmark PNG unchanged when vector tracing alters its lettering. The six supplied social marks live as separate 24-unit SVG files in images/icons/social/ and are selected by the existing icon renderer through an explicit filename allowlist and per-request cache. They render inline with currentColor; do not add a font/icon CDN, sprite bitmap or additional JavaScript. Keep missing social URLs noninteractive until the owner provides actual addresses. Native WordPress owns 32/180/192/270 site-icon variants and header output; do not duplicate favicon tags. Theme screenshot remains the approved Radman thumbnail.

The homepage track rail uses src/js/ui/carousel.js, adapted from the selected design-library carousel without its workshop UI/dots. It owns one-card movement, rapid-click targets, RTL/LTR keyboard/Home/End, mouse dragging from the card or cover links with click suppression, native touch/snap, boundary buttons, overflow visibility, reduced motion and cleanup. music-home.js mounts this owner once through the existing lifecycle; the previous inline scrollBy handler is removed. No library runtime dependency or second GSAP/vendor is introduced. Both homepage music and video sections compose this rail owner. Fractional visible columns retain a preview of the next card on desktop and mobile. Header and side navigation share one position and boundary state. Side arrows appear when the cards overflow. The homepage rails select up to eight tracks and six videos. Native video uses preload=none.

UI icon contract: inc/icons.php renders only selected entries from inc/icons/catalog.php as local inline SVG with a 24-unit viewBox, rounded caps/joins and currentColor. src/css/ui/icon.css owns base geometry, stroke and directional mirroring once; tokens.css defines --rdc-ico-sz:1.25rem and --rdc-ico-stroke:1.5 consistently in Corporate-Webtalik and Corporate-Music. Component-specific sizes remain explicit at their consuming control (for example hero CTA or social marks). Filled playback glyphs use the catalog path fill instead of a different stroke width. Each customer runtime remains self-contained; no sibling-project imports, icon font, CDN or per-page SVG copies.

Homepage online playback owns one native audio element in template-parts/music/home-player.php. The front-page template renders it once after home sections; music-player.js moves the dock outside transformed wrappers and restores it during cleanup. Only homepage music buttons select tracks; archives/details keep their own layouts and videos continue inline. The dock reuses music/player.php (compact+dock) and audio-controls.js for native play/pause/seek/mute/volume; its own owner handles same-origin deduplicated previous/next selection, cover/title/artist and close/Escape focus return. Sources are absent initially, selected only on an explicit play action and released on close/page cleanup. Starting a home video pauses music; starting music pauses home videos. No lyrics display or lyrics control is included. UI geometry is in ui/home-player.css, imported only by the music-home entry, without a second engine or vendor dependency. The decorative waveform uses audio-wave.js and music/wave.php: responsive seeded bars in synchronized muted/accent layers, clipped by native playback progress. CSS transform animations run for 1.7 seconds with staggered negative delays while audio plays; pause, buffering, hidden document, offscreen and reduced-motion stop visual motion. The shared size observer only regenerates bars when width density or source changes (24–224 bars per layer); listeners and observers are disposed with audio-controls.js. No audio analysis, full-file decoding, waveform fetch or RAF loop. The native range remains the keyboard/touch control above the bars with visible wrapper focus. One progress custom property follows native timeupdate with short CSS interpolation, disabled for reduced-motion and direct seeking; transport is centered on the dock itself. Reference media and queries stay bounded; no playlist-wide audio prefetch. Single tracks use the same player.php renderer and audio-controls.js with an inline wave variant under cover/credits and above the existing lyrics. ui/audio-wave.css owns waveform/progress/transport geometry once; music-home and music-detail entries import it after audio-player.css. Only home-player.css owns fixed positioning and only the home JS owns queue/dock behavior. Video modules are preserved.

Media loading contract for audio/video, gallery, archives and detail pages: [docs/media.md](media.md). Read it before changing a media consumer.

Clips may select a validated Aparat URL in _rdc_clip.aparat, taking precedence over local playback. Videos::aparat_id owns validation; ui/aparat.php renders the official iframe. Home and archives render a local cover and keep the iframe in an inert template. video-player.js mounts the iframe according to the current media contract (home: viewport preparation; archive: explicit selection). Runtime verification and the pending policy decision are recorded in review-decisions.md. The detail page retains the provider poster, native lazy loading and provider Play. No embed script, API, copied/proxied video or CDN extraction. Local video still uses its attachment/featured cover with preload=none. Aparat controls cross-origin playback and quality; omit fake local downloads. See media.md.

The home dock has one icon-only, accessibly labeled collapse/expand button in home-player.php, owned by music-player.js and home-player.css. Folding retains the same audio and transport, hides timeline/volume, and keeps the cover/title, play and expand action. It never reloads or pauses audio; closing still stops/releases it and resets the expanded layout. No detail-page folding or parallel mini-player.

Dock fold/open glyphs use the shared local icon catalog and 1.5 stroke. Keep the expanded toggle 20px glyph inside a 40px hit area; the compact capsule uses the existing upward chevron, with no permanent text or large border. Pointer hints reuse the existing cursor label; keyboard focus shows an anchored label. Preserve aria-expanded and the native button.

Folded home dock follows the compact capsule: maximum 17rem width, round cover at right, title and artist, play/pause, upward expand chevron and close. Previous/next, waveform and volume are expanded-only on every viewport. Keep one audio instance and do not pause/reload it when folding.

Frontend implementation and staged review: [frontend-standard.md](frontend-standard.md). The full general v1.2 guide is preserved there; existing project owners and approved designs remain independent.

Shared media download buttons use the existing button() renderer with variant=download. ui/download-button.css owns the dark compact box, mint download tile, small secondary media icon and shared hover markup once; music detail, video archive and local video quality actions consume it through their existing CSS entries. Consumers select geometry with --rdc-download-* properties and keep only layout margins/widths locally. Do not copy icon backgrounds, button markup or motion into page styles. Aparat links still open the provider video page; the visual variant does not turn them into direct file downloads.

The homepage editor owns up to four ordered featured track IDs in _rdc_home_feature_tracks via inc/admin/music-home.php. The hero queries public, unprotected tracks in selection order and falls back to up to three latest published tracks ordered by publication date when no eligible selection remains. The selector uses native admin controls; the hero reuses the existing player, prioritizes only the first cover and defers audio until interaction.

The header switches at 1024px. Below that width it uses one dialog for the navigation, with the trigger and close button at the inline start (right in RTL). menu-panel.js owns dialog state, focus return and the shared scroll lock. menu-panel.css owns the short entrance animation and honors reduced motion. Desktop hover effects only load at desktop widths. Typography and palette stay in tokens.css and base.css. Blog, music and collection archives use template-parts/ui/archive-pagination.php and ui/archive-pagination.css. The shared owner centers controls and chooses direction-aware arrows for RTL and LTR.
