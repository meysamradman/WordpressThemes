# ورودی نسخه‌های جدید Hub

نسخه جدید را داخل `incoming/` بگذار؛ ZIP اصلی یا پوشه استخراج‌شده هر دو قابل بررسی‌اند.
قرار دادن فایل مستقیم داخل پوشه `update` هم قابل قبول است.

برای هر نسخه ترجیحاً یک پوشه مستقل بساز، مثلاً:

```text
update/incoming/6.0.4/
  hub.zip
  hub-core.zip
  hub-elementor-addons.zip
```

هر سه بسته را، اگر داری، با هم قرار بده تا هماهنگی نسخه‌ها بررسی شود. فایل خریداری‌شده
یا ZIP اصلی را با نسخه اصلاح‌شده جایگزین نکن. اطلاعات ورود و کلیدها را اینجا نگذار.

در نوبت بعد کافی است بگویی «نسخه جدید را داخل update گذاشتم؛ مقایسه و اصلاحات قبلی را اعمال کن».
آپدیت خودکار و اجرای خودکار فایل‌های این پوشه وجود ندارد.
اعلان آپدیت قالب و افزونه‌ها در وردپرس باید فعال بماند. کاربر می‌تواند از همان‌جا
آپدیت کند و سپس نسخه اصلی جدید را اینجا قرار دهد؛ بازگشت لایسنس با نصب نسخه اصلی
برای این گردش کار پذیرفته شده است. هنگام حذف لایسنس، updater را دوباره غیرفعال نکن.

روند نگهداری برای عامل بعدی:

1. ابتدا `../docs/license-local-build.md`، `../docs/change-manifest.json` و
   `../docs/license-changes.patch` را بخوان.
2. فایل‌های نسخه ورودی را فقط بخوان؛ ساختار و نسخه هر بسته را بررسی و از ورودی اصلی محافظت کن.
3. کد جدید را با نسخه اصلی قبلی و نسخه اصلاح‌شده مقایسه کن؛ خصوصاً manager لایسنس،
   بررسی دامنه/لغو، خطای بازدیدکننده، Merlin، صفحه دمو/افزونه و شرط دریافت طرح کتابخانه.
4. وصله را معنایی تطبیق بده؛ patch قدیمی را بدون بررسی روی نسخه تازه اجرا نکن.
   اگر فروشنده این بخش‌ها را تغییر داده، ابتدا مسیر واقعی را دوباره پیدا کن.
5. کتابخانه Hub Collections، URL و API version آن، ویجت‌ها، کنترل‌ها و فایل‌های JS/CSS
   اصلی را حفظ کن. فقط شرط لایسنس را از کتابخانه بردار. بهینه‌سازی شبکه مجوز جدا می‌خواهد.
   اعلان آپدیت قالب و افزونه‌ها حفظ شود؛ بررسی نسخه قالب باید کش‌شده و دوره‌ای باشد،
   نه یک اتصال HTTP در هر صفحه. Skill پروژه در `../.agents/skills/hub-maintenance/SKILL.md` است.
6. شماره نسخه محلی را از نسخه جدید مشتق کن؛ ثابت نسخه افزونه Elementor را صرفاً برای
   نام‌گذاری بسته تغییر نده چون در API کتابخانه هم مصرف می‌شود.
7. lint فایل‌های تغییرکرده و smoke کوتاه مناسب نسخه را اجرا کن. پاسخ شبیه‌سازی‌شده
   کتابخانه را به‌عنوان تأیید زنده سرور فروشنده گزارش نکن.
8. گزارش مقایسه را در `reports/`، بکاپ را در `../backups/` و خروجی نهایی را در
   `../releases/` بگذار؛ مستند و manifest را مطابق نتیجه نهایی به‌روز کن.
