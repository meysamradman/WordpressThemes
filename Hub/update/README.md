# به‌روزرسانی Hub

| پوشه | کاربرد |
| --- | --- |
| `update/new/` | سه ورودی آپدیت بعدی به‌صورت ZIP یا استخراج‌شده. بعد از تأیید خالی بماند. |
| `update/old/` | محل موقت پوشه‌های قبلی هنگام تعویض. بعد از تأیید خالی بماند. |
| `releases/` | فقط یک ZIP تحویل برای نسخهٔ جاری. سه ZIP قابل نصب و manifest داخل آن‌اند. |

۱. نسخهٔ هر ورودی را از هدر بخوان و افزونه‌ها را با نسخه‌های همراه تعریف‌شده در قالب تطبیق بده. پچ را روی کپی کاری با [مستند تغییرات](../docs/license-local-build.md) و [diff](../docs/license-changes.patch) بازبینی کن. ورودی را حین بررسی دست‌نخورده نگه دار و نسخهٔ API کتابخانه را حفظ کن.

۲. PHP، updater، مجموعهٔ فایل‌های هر ZIP و Hub Collections را بررسی کن. `python tools/build-release.py` یک ZIP تحویل می‌سازد. پوشه‌ها را کامل جابه‌جا کن تا فایل‌های نسخهٔ قبلی باقی نمانند. اگر تعویض شکست خورد، پوشه‌ها را از `old/` برگردان. پس از تأیید، محتوای `new/`، محتوای `old/`، بستهٔ قبلی و بکاپ موقت آن را پاک کن. پوشه‌های جاری فقط در ریشهٔ Hub بمانند.

۳. داکر کپی مستقلی دارد. پیش از تعویض داکر، تفاوت فایل‌ها با نسخهٔ قبلی و بکاپ بازیابی را بررسی کن. پس از تعویض، نسخهٔ قالب و هر دو افزونه، صفحهٔ اول و در صورت درخواست Elementor و Hub Collections را چک کن. هنگام تعویض سه بسته به Elementor، دیتابیس و uploads دست نزن.

از ZIP تحویل، سه ZIP داخلی را استخراج کن و هرکدام را در بخش مربوط قالب یا افزونه در وردپرس نصب کن. هش فایل‌های مبنا و گزارش بررسی بیرون از بسته می‌مانند. برای تطبیق بعدی، فقط مبنای فایل‌های تغییرکردهٔ همین نسخه را نگه دار. نصب آپدیت اصلی فروشنده می‌تواند پچ محلی را جایگزین کند. اعلان آپدیت مستقل از فعال‌سازی باقی می‌ماند.
