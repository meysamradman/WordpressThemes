# WordpressThemes

مرجع نگهداری سورس قالب‌ها و مستندات Radman، با همان چیدمان پوشه‌های محلی:

| پوشه | کاربرد |
|---|---|
| Corporate-Elementor-Catalog | قالب و بسته‌های مستقل نسخهٔ المنتوری/کاتالوگ |
| Corporate-Music | فضای پروژهٔ موسیقی؛ فعلاً بدون سورس اجرایی |
| Corporate-Webtalik | قالب PHP سفارشی سایت Webtalik |
| Hub | سورس و مستندات نگهداری محلی Hub و وابستگی‌های مصرف‌شده |
| Radman-Design-Library | مرجع مستقل طراحی‌ها و ماژول‌های قابل انتقال |

این پوشه یک Git مشترک دارد، ولی قالب‌ها و محیط‌های WordPress/Docker مستقل‌اند. مخزن برای نگهداری کد است؛ Release، استقرار یا push خودکار ندارد. کد، مستندات، تست‌ها، فایل‌های build/lock و دارایی‌های محلی لازم برای اجرا حفظ می‌شوند. node_modules، لاگ/تصویر موقت مرورگر، دیتابیس، تنظیمات خصوصی، آرشیوها، بکاپ‌ها و قالب‌های صرفاً مرجع وارد Git نمی‌شوند. فایل‌های ضروری vendor و dist حذف نشده‌اند؛ فایل‌های ignoreشده روی کامپیوتر باقی می‌مانند.

## ذخیرهٔ فقط یک پروژه

از ریشهٔ همین مخزن، برای دیدن تغییرات یک پروژه بدون تغییر Git:

```powershell
.\tools\Save-Project.ps1 -Project Corporate-Webtalik -CheckOnly
```

برای ثبت تغییرات همان پوشه و، در صورت درخواست، ارسال به GitHub:

```powershell
.\tools\Save-Project.ps1 -Project Corporate-Webtalik -Message "Update custom theme" -Push
```

بدون `-Push` فقط commit محلی ساخته می‌شود. تغییرات پوشه‌های دیگر وارد commit نمی‌شوند؛ staged بودن تغییرات پروژهٔ دیگر یا وجود commit منتشرنشدهٔ مربوط به پروژه‌های دیگر، مسیر خودکار را متوقف می‌کند. Git خودِ commitها را push می‌کند؛ فایل‌های بدون تغییر دوباره بارگذاری کامل نمی‌شوند.

برای پروژهٔ تازه، یک پوشهٔ معمولی اینجا اضافه کنید و همین فرمان را با نام آن اجرا کنید؛ داخل آن `git init` نزنید. ساخت محیط اجرا و قواعد هر قالب در README/AGENTS همان پروژه است. اطلاعات محرمانهٔ محلی را طبق راهنمای پروژه تنظیم کنید؛ این مخزن دیتابیس یا محتوای داخل volumeهای Docker را نگهداری نمی‌کند.
