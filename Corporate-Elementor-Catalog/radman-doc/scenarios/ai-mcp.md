# اتصال ابزارهای هوش مصنوعی با MCP

## CONFIRMED — نیاز محصول

مالک محصول اتصال سایت نصب‌شده روی سرور به Claude، Codex و کلاینت‌های سازگار MCP را خواسته است تا عامل بتواند در حد دسترسی مجاز روی محتوا و طراحی کار کند. دامنه شامل صفحات PHP/Gutenberg رادمان، تنظیمات ظاهری و هدر/فوتر/بلوک‌های مشترک، و صفحات منتخب Elementor است. پشتیبانی قالب از این اتصال نباید آن را به سایت Headless، React SPA یا هاست Node تبدیل کند.

این قابلیت **اختیاری و جدا از runtime عمومی** باشد؛ سایت بدون کلاینت AI، کلید، MCP Adapter یا Elementor کامل کار کند. در حالت خاموش endpoint/ابزار اختصاصی رادمان فعال نباشد، دارایی یا query اضافهٔ frontend نداشته باشیم و اتصال خودکار خارجی انجام نشود. اتصال مدیریتی آگاهانه، استثنای اختیاری به منع اتصال بی‌نیاز است؛ نه CDN یا سرویس اجباری نمایش سایت.

## CONFIRMED — شروع پیاده‌سازی، ۲۰۲۶-۱۰-۲۱

مالک اکنون اجرای اتصال MCP برای مسیر اختصاصی و Elementor و ایجاد/ویرایش وبلاگ، محصول و نمونه‌کار را خواسته است؛ تعویق قبلیِ شروع MCP برداشته شد. اتصال رسمی خود Elementor برای سندهای آن ترجیح دارد. با تأیید بعدی مالک، ابزارهای رادمان در یک افزونهٔ اختیاری مستقل `radmanct-mcp` با ماژول‌های داخلی قرار گرفتند؛ Content مالک دادهٔ محصول/نمونه‌کار است و MCP برای برگه/وبلاگ به آن وابسته نیست. برای بستهٔ آزمایشی قبلی مهاجرت یا alias اضافه نمی‌شود؛ نام‌های نهایی از همین نسخه مبنای آپدیت‌های بعدی‌اند. اتصال واقعی کلاینت و ماتریس کامل طراحی هنوز تأیید نشده‌اند. [قرارداد، ابزارهای موجود و محدودیت‌ها](../engineering/mcp.md).

## PROPOSED — ترتیب اجرا

1. شناسایی فقط‌خواندنی: فهرست صفحات/زبان، تشخیص مالک محتوا PHP/Gutenberg/Elementor، ساختار هدر/فوتر و قابلیت‌های قابل دسترس. اطلاعات محرمانه، token و تنظیمات غیرمرتبط در پاسخ نباشند.
2. ویرایش محدود با revision و مسیر preview: محتوا، بلوک/چیدمان معتبر و tokens ظاهری؛ تغییر از همان validator و مالک ذخیره‌سازی پنل عبور کند. انتشار/حذف تابع اختیار داده‌شدهٔ کاربر و مجوز native وردپرس باشد.
3. Elementor: فقط برای سند متعلق به آن و از API/adapter پشتیبانی‌شده؛ metadata، CSS تولیدی و چرخه ذخیرهٔ Elementor حفظ شوند. سازندهٔ رادمان و Elementor بی‌اجازه محتوای یکدیگر را بازنویسی نکنند. امکانات Pro به نصب و مجوز همان افزونه وابسته‌اند.

ویرایش محتوای یک صفحه با تغییر سورس PHP/طراحی اختصاصی مشتری یکسان نیست. تغییر فایل‌های Child Theme از مسیر مخزن و انتشار پروژه انجام شود؛ MCP پایه به معنی اجرای PHP/JS دلخواه، shell عمومی یا ویرایش آزاد همهٔ فایل‌های سرور نیست. دامنهٔ طراحی مستقیم هر ابزار پیش از اجرا به‌صورت مشخص اعلام شود.

## PROPOSED — محدودهٔ کار عامل در هر بخش

این جدول دامنهٔ پیشنهادی مرحلهٔ آینده است، نه فهرست ابزارهای ساخته‌شده یا تضمین توانایی هر کلاینت.

| بخش | کار قابل ارائه به عامل | مرز تغییر |
|---|---|---|
| صفحهٔ اختصاصی PHP | خواندن محتوای وردپرس و Template انتخاب‌شده؛ ویرایش فیلدها و تنظیماتی که صفحه واقعاً مصرف می‌کند | تغییر markup یا CSS اختصاصی از Child Theme و مسیر انتشار پروژه؛ ساختار ثابت PHP با ویرایش محتوای برگه عوض نمی‌شود |
| صفحهٔ Gutenberg | خواندن درخت بلوک و ویرایش بلوک‌های پشتیبانی‌شده | شناسه، ساختار معتبر و محتوای صفحه حفظ شوند؛ تبدیل خودکار به Elementor انجام نشود |
| صفحهٔ Elementor | خواندن ساختار و تنظیمات قابل دسترس؛ ویرایش محتوای همان سند و طراحی در حد API معتبر | قابلیت‌های افزونه/نسخه شناسایی شوند؛ JSON یا CSS تولیدی با مسیر موازی دست‌کاری نشود |
| هدر و فوتر رادمان | خواندن و تغییر ردیف/عنصر و گزینه‌های مجاز سازنده | همان schema، validator و revision پنل؛ اثر سراسری پیش از اعمال مشخص باشد |
| بلوک مشترک | خواندن منبع و محل‌های مصرف؛ ویرایش محتوای پشتیبانی‌شده | تغییر یک منبع روی چند محل اثر دارد؛ وضعیت انتشار و زبان هر منبع رعایت شود |
| تنظیمات ظاهری | فونت محلی، رنگ/عرض و جلوه‌های دارای کنترل واقعی | مقدارهای مجاز پنل؛ بدون افزودن فونت/CDN خارجی یا CSS/JS دلخواه |
| کاتالوگ و نمونه‌کار | ایجاد و ویرایش محتوای native و دادهٔ مجاز Core در ماژول فعال | در سایت بدون آن ماژول، نوع محتوا ارائه نشود؛ صرف اتصال MCP ماژول را فعال نکند |

## PROPOSED — سناریوهای استفاده

### ۱. اتصال به سایت مشتری روی سرور

مدیر اتصال را آگاهانه فعال و از Claude یا Codex احراز هویت می‌کند. عامل نام/نشانی سایت، محیط، زبان و توانایی‌های مجاز را می‌خواند تا سایت آزمایشی با سایت اصلی اشتباه نشود. فهرست صفحات و قابلیت‌ها محدود و صفحه‌بندی‌شده باشد؛ خواندن همهٔ نوشته‌ها، فایل‌ها یا محصولات برای یک درخواست کوچک لازم نباشد. اتصال یک کلاینت، دسترسی همهٔ کاربران یا کلاینت‌های دیگر را باز نکند.

### ۲. سایت عمدتاً PHP و صفحهٔ تماس Elementor

خانه و خدمات با PHP اختصاصی ساخته شده‌اند و تماس با ما Elementor است. درخواست «متن تماس و فاصلهٔ فرم را اصلاح کن» فقط سند تماس و کنترل‌های در دسترس آن را هدف بگیرد؛ صفحهٔ خانه، هدر رادمان و renderer صفحات دیگر تغییر نکنند. اگر تغییر موردنظر به widget یا نسخهٔ Pro در دسترس نیاز دارد، عامل محدودیت را مشخص کند و سند را به ساختار دیگری تبدیل نکند.

در درخواست «چیدمان خانه را عوض کن»، عامل ابتدا تفاوت تغییر فیلدهای موجود با تغییر سورس طرح مشتری را مشخص کند. اگر کنترل ساختار از طریق MCP آن پروژه وجود ندارد، کار طراحی به تغییر قابل بازبینی Child Theme تبدیل شود؛ صرف موفق‌شدن ذخیرهٔ عنوان برگه به معنی انجام طراحی نباشد.

### ۳. تغییر هدر یا محتوای مشترک

درخواست «دکمهٔ استعلام را به هدر اضافه کن» با نسخهٔ فعلی چیدمان و عناصر مجاز انجام شود. برای تغییر متن یک بلوک مشترک، عامل پیش از ذخیره بداند آن بلوک در هدر، فوتر یا صفحات دیگری مصرف می‌شود؛ پیش‌نمایش باید اثر مشترک را روشن کند. تکثیر ناخواستهٔ منبع به‌جای ویرایش مشترک یا تغییر همهٔ صفحات به‌جای یک محل انجام نشود. تخصیص مستقل صفحه/زبان فقط پس از ساخته‌شدن آن قابلیت قابل ارائه است.

### ۴. ویرایش فارسی و انگلیسی

عامل زبان سند هدف و ترجمهٔ متناظر را می‌خواند. درخواست تغییر محتوای انگلیسی، متن فارسی یا جهت سراسری سایت را عوض نکند. برای متن مشترک سازنده و بلوک‌ها، مالک ترجمه همان قرارداد WPML آن بخش باشد. نبود ترجمه یا افزونه، به ساخت رابطهٔ ترجمهٔ جعلی یا بازنویسی زبان دیگر منجر نشود؛ قابلیت موجود و کار باقی‌مانده در نتیجه مشخص باشند.

### ۵. بازبینی، ذخیره و تعارض

تغییر نسبت به نسخه‌ای مشخص آماده شود و خلاصهٔ اثر آن قابل مشاهده باشد. ذخیرهٔ draft، پیش‌نمایش و انتشار عملیات متمایز هستند؛ پیش‌نمایش تأییدِ انتشار نیست. انتشار یا حذف فقط در محدودهٔ اختیار داده‌شدهٔ همان جلسه و مجوز وردپرس انجام شود؛ برای اقدامی که قبلاً مجاز شده سؤال تکراری ایجاد نشود.

اگر مدیر هم‌زمان صفحه یا چیدمان را تغییر داده باشد، عامل نسخهٔ جدید را بخواند و اختلاف را حل کند؛ دادهٔ جدید با snapshot قدیمی بازنویسی نشود. شکست ذخیره یا تولید دارایی، نتیجهٔ موفق نمایش ندهد. پس از ذخیرهٔ موفق، هماهنگی CSS و کش از مسیر همان مالک و ادغام پشتیبانی‌شده انجام شود؛ موتور کش جدیدی در قالب ساخته نشود.

### ۶. قطع اتصال و سایت بدون قابلیت اضافه

خاموش‌کردن اتصال، مجوزهای بعدی آن را متوقف کند و محتوا/طرح ذخیره‌شده باقی بماند. سایت بدون MCP، بدون Elementor و بدون کاتالوگ نیز به کار معمول خود ادامه دهد. عامل برای انجام تغییر یک صفحه، نصب اجباری این قابلیت‌ها یا اتصال خارجی frontend ایجاد نکند.

## PROPOSED — پذیرش مرحلهٔ آینده

- گزارش پایان کار، سند/زبان هدف، تغییر واقعی، وضعیت draft یا published و محدودیت بررسی را مشخص کند؛ پاسخ موفق ابزار با تأیید طراحی بصری یا سرعت سایت یکی نباشد.
- مسیر فقط‌خواندنی واقعاً داده را تغییر ندهد؛ اتصال خاموش، ماژول غایب، کاربر بدون مجوز و revision قدیمی رفتار روشن داشته باشند.
- تغییر کوچک، خواندن/بازسازی کل سایت را لازم نکند؛ assetهای مدیریت و MCP وارد صفحات عمومی نشوند.
- هر قابلیت فقط پس از پیاده‌سازی و بررسی همان مسیر به عامل معرفی شود؛ نام ابزار یا وجود فایل در بسته نشانهٔ آماده‌بودن قابلیت نیست.

## مسیر فنی بررسی‌شده و OPEN

مسیر ترجیحی بررسی آینده، Adapter رسمی WordPress و Abilities API است؛ endpoint اختصاصی موازی بدون نیاز ساخته نشود. [مستند رسمی MCP Adapter](https://github.com/WordPress/mcp-adapter/tree/trunk/docs/getting-started) در بررسی ۲۰۲۶-۱۰-۱۸، WordPress 6.9+ را برای Abilities داخلی ذکر می‌کند. این شرط قابلیت اختیاری آینده است؛ حداقل اعلام‌شدهٔ قالب پایه را اکنون تغییر نمی‌دهد. نسخه و وجود API در مرحله اجرا دوباره بررسی شوند.

بستهٔ مستقل اختیاری و مسیر Abilities API بومی انتخاب شده‌اند؛ transport و احراز هویت به Adapter رسمی وردپرس و رمز برنامهٔ همان کاربر واگذار می‌شوند. نسخهٔ نصب‌شدهٔ Adapter و اتصال عملی Codex/Claude هنوز پذیرش می‌خواهند. permission callback، مجوز کاربر واقعی، schema محدود و کنترل نسخه لازم‌اند؛ برچسب «read-only» ابزار جای کنترل سمت سرور را نمی‌گیرد.

بررسی جدید سورس ارسالی، وجود MCP داخلی Elementor 4.3.5 در `modules/mcp/` و Abilities رسمی Atomic را تأیید کرد؛ اتصال و دامنهٔ نسخه‌های دیگر باید جدا بررسی شوند. موجودی دوبارهٔ ۲۰۲۶-۱۰-۲۱ شامل خود `woodmart-mcp` نسخهٔ 1.0.2، AI نسخهٔ 1.4.0 و MCP Adapter نسخهٔ 0.7.1 است و سورس اتصال/مجوز/عملیات آن‌ها بررسی شد. گزارش قبلی نبود سورس دیگر مبنا نیست. رابط نصب/تشخیص وابستگی، تولید تنظیمات کلاینت، رمز برنامه و skill مرجع مطالعه‌اند؛ ساخته‌شدن آن رابط در رادمان ادعا نشود.
