# فایل‌های CSS و سازگاری افزونه‌ها

## WP Rocket محلی — اجرای محدود، ۲۰۲۶-۱۰-۳۰

پیام موفقیت اولیهٔ «is good to go» متعلق به NoticeSubscriber خود WP Rocket است؛ is_new_user نسخهٔ نصب‌شده با خالی‌بودن previous_version آن را دوباره نمایش می‌دهد. با درخواست مالک، integration رادمان از filter رسمی rocket_display_default_notice فقط روی screenهای _page_rdct- خروجی false می‌دهد. صفحهٔ افزونه‌ها/خود Rocket و هشدارهای دیگر هدف نیستند؛ source افزونه یا گزینهٔ نسخه/کش برای پنهان‌سازی پیام تغییر نکرد. نبود همین notice در مدیریت رادمان در مرورگر دیده شد و قرارداد جداشدن screenها پاس شد.

با درخواست مالک WP Rocket نصب‌شدهٔ 3.23.5.1 در سایت مشترک فعال شد. تنظیم اولیه: minify CSS/JS و defer روشن؛ combine JS، delay JS، CSS delivery/RUCSS، lazyload دوم، کش کاربران واردشده، preload پس‌زمینه، CDN و میزبانی فونت بیرونی خاموش. تصاویر فعلاً loading بومی WordPress و کامپوننت را حفظ می‌کنند. فایل‌های minified رادمان از manifest می‌آیند؛ موتور تازهٔ build یا کش اختصاصی نداریم. CSS delivery/RUCSS به سرویس بیرونی وابسته است و برای محیط local قابل پذیرش نیست؛ [مستند رسمی](https://docs.wp-rocket.me/article/1514-private-intranet-offline).

`inc/integrations/rocket.php` فقط هنگام فعال‌بودن Rocket بارگذاری می‌شود: مسیر دقیق dist/js قالب، Child فعال و Components از delay استثناست تا آغاز موشن/پریلودر/ناوبری به اولین کلیک وابسته نشود؛ این استثنا سایر افزونه‌ها را پوشش نمی‌دهد و مقدارهای قبلی را حفظ می‌کند. ذخیره/افزودن/حذف تنظیمات رادمان، چیدمان سازنده و theme mods چایلد، حداکثر یک purge رسمی در shutdown همان درخواست صف می‌کند. ذخیرهٔ مستقیم builder که updated_option ندارد نیز از هوک رسمی خود رادمان پوشش دارد. reference محدود WoodMart inc/integrations/rocket.php بررسی شد؛ سورس یا framework آن منتقل نشد.

WP_CACHE در wp-config محلی با API خود افزونه فعال و config/advanced-cache ساخته شد؛ مالکیت پوشه‌های cache/wp-rocket، cache/min و wp-rocket-config برای کاربر وب اصلاح شد. دو GET بدون ورود فایل HTML و gzip کش خانه را ساختند؛ HTML پاسخ شامل نشان Rocket، ماژول‌های صفحه و illustration باقی ماند. قرارداد محدود استثنا/پاکسازی و lint پاس شدند. یک تلاش ابزار CLI برای تکرار activation داخل bootstrap فعال، خطای redeclare در همان فرایند موقت داد؛ مسیر اصلاح‌شده فقط API ساخت فایل/تنظیم ثابت را مصرف کرد و GETهای بعدی fatal نداشتند. هشدارهای PHP 8.4 مربوط به Elementor و update-checker بستهٔ نصب‌شده همچنان وجود دارند. بستهٔ Rocket موجود تغییرات شخص ثالث در کنترل لایسنس دارد؛ فایل افزونه در این کار اصلاح نشد و این بررسی تأیید اصالت بسته نیست.

این شاهد کارکرد کش صفحه است، نه تأیید بصری منو/GSAP/Elementor یا benchmark. بررسی مرورگر، تمام صفحات، تنظیمات تهاجمی و سرور مقصد هنوز بازند. در توسعه با تغییر مستقیم سورس/build، کش Rocket از مدیریت پاک شود؛ ذخیرهٔ تنظیمات/سازنده خودکار purge می‌شود. ثابت WP_CACHE و config در volume همین سایت‌اند، نه در Theme؛ محیط local/offline، داده و نسخه‌های رادمان تغییر نکردند.

## تأییدشده

- محیط پیشنهادی نصب طبق [تصمیم نهایی هاست و دیتابیس](../engineering/architecture.md): PHP 8.3+، MySQL 8.0+ یا MariaDB 10.11+، Apache/Nginx و بدون Node runtime. سازگاری PHP 8.4 هدف صریح باقی است؛ نسخهٔ پیشنهادی حداقل اجباری نیست. پشتیبانی نسخه‌های آینده بدون تست از پیش تضمین نشود.
- هر دو موتور MySQL و MariaDB هدف سازگاری‌اند؛ نسخهٔ پایین‌تر دیتابیس که نسخهٔ هدف WordPress پشتیبانی می‌کند، بدون دلیل فنی مستند مسدود نشود. مصرف API استاندارد وردپرس و SQL قابل‌حمل شرط طراحی است؛ آزمون مستقل هر دو موتور برای ادعای پذیرش لازم است.
- سازگاری با نسخه پایدار جدید Elementor و Elementor Pro هدف انتشار باشد؛ نسخه دقیق هر دو در گزارش تست ثبت و با ارتقا دوباره بررسی شود. «جدید» به معنی نسخه beta/RC نیست مگر جدا درخواست شود.
- CSS قالب هم نسخه معمولی و هم نسخه minified داشته باشد؛ قالب همیشه نسخه minified را بارگذاری کند، از جمله در RTL/LTR. حالت debug هم خودکار به فایل معمولی تغییر نکند.
- فایل‌های CSS مدیریت از عمومی جدا باشند؛ هر صفحه مدیریت فقط فایل‌های لازم خودش را دریافت کند. قرارداد معمولی/minified برای CSS مدیریت نیز برقرار است.
- تأکید ۲۰۲۶-۱۰-۲۱: همین قرارداد برای JS و افزونه‌های Content/Components/MCP و Child نیز برقرار است؛ manifest تولیدشده تنها خروجی runtime minified را معرفی کند. فایل خوانا و source برای توسعه‌اند؛ debug وردپرس این انتخاب محصول را عوض نکند. باندل‌کردن به معنی تحمیل تمام کامپوننت‌ها/سبک‌ها به همهٔ صفحات نیست؛ پایهٔ کوچک مشترک و chunkهای شرطی حفظ شوند.
- رادمان با WP Rocket، WPML، Elementor و Elementor Pro و افزونه‌های امنیتی تداخل نداشته باشد؛ رعایت استانداردهای وردپرس و کیفیت حرفه‌ای هدف محصول است.
- پشتیبانی **Slider Revolution** نیز الزامی و اختیاری در نصب است؛ قالب بدون آن کامل کار کند. نمایش از مسیر رسمی shortcode/block/ادغام صفحه انجام شود؛ فایل یا لایسنس آن از قالب‌های مرجع کپی/همراه‌سازی نشود.
- این موارد نیاز و معیار پذیرش‌اند؛ بررسی محدود PHP/DB با Elementor/Pro ارسالی انجام شده است، ولی ماتریس کامل افزونه‌ها، مرورگر، کش و WPML واقعی هنوز تأیید نشده‌اند. وضعیت فعلی فقط در سند پیاده‌سازی گزارش می‌شود.

## پذیرش پیشنهادی

- سورس ES2022+ و خروجی ES2020 طبق [منابع محلی](local-assets.md) هستند. هدف Vite تضمین پشتیبانی API/CSS یا polyfill نیست؛ مرورگرهای هدف Chrome/Edge، Firefox و Safari و موبایل واقعی باید جدا بررسی شوند. شبیه‌سازی عرض موبایل روی Chrome دسکتاپ شاهد عملکرد دستگاه واقعی یا Safari نیست؛ نتیجه و نسخهٔ مرورگر در سند پیاده‌سازی ثبت شود.

- PHP قالب در نسخه‌های هدف، خصوصاً 8.4، بدون خطای syntax، fatal، warning یا deprecation ناشی از کد رادمان اجرا شود؛ صرف lint یا مشاهده سورس WoodMart اثبات سازگاری runtime نیست.
- نسخه معمولی و minified از نظر رفتار یکسان باشند؛ مرورگر فقط فایل minified موردنیاز را درخواست کند، نه هر دو نسخه.
- با کش سرد/گرم، پاک‌کردن کش و تغییر تنظیمات/فونت/layout، خروجی جدید درست نمایش داده شود.
- قابلیت‌های بهینه‌سازی WP Rocket جدا بررسی شوند؛ cache، پردازش CSS و تأخیر JS باعث خرابی صفحات PHP، تعاملات Vanilla JS، انیمیشن GSAP/ScrollTrigger، ویجت‌های Elementor یا منوی هدر نشوند. در صورت نیاز استثنای محدود و مستند تعریف شود؛ سازگاری به معنی غیرفعال‌کردن همه بهینه‌سازی‌ها نیست.
- زبان، URL، داده و کش WPML طبق سناریوی زبان صحیح باشند.
- Elementor و Elementor Pro شامل ویرایش/preview، نمایش عمومی و قابلیت‌های توافق‌شده نسخه هدف بررسی شوند. پشتیبانی Pro به معنی تأیید خودکار همه قابلیت‌های آن یا جایگزینی هدر/فوترساز رادمان نیست.
- Slider Revolution در صفحه دارای اسلایدر با/بدون موشن، RTL/LTR، Elementor و کش/تأخیر JS بررسی شود؛ زمان راه‌اندازی اسلایدر و وابستگی‌هایش دستکاری یا تکرار نشوند. نبود اسلایدر نباید از طرف رادمان باعث enqueue فایل اسلایدر شود. افزونه خودش تنظیم بارگذاری global/page-specific دارد؛ تنظیم واقعی آن جدا بررسی شود و قالب فرض نکند همه درخواست‌های آن محلی‌اند. [راهنمای رسمی تنظیمات عمومی](https://www.sliderrevolution.com/help/global-settings-panel/).
- افزونه امنیتی منتخب نباید با ذخیره مجاز تنظیمات، REST/Ajax معتبر، preview و فایل‌های محلی تعارض داشته باشد. قالب برای دورزدن محدودیت امنیتی، مجوز و nonce را حذف نکند.

## باز

محیط پیشنهادی و پشتیبانی هر دو موتور قطعی‌اند و دیگر OPEN نیستند. metadata فعلی حداقل PHP 8.0 را اعلام می‌کند؛ تغییر این حداقل در تصمیم پیشنهادی 8.3 درخواست نشده است. ماتریس واقعاً آزموده‌شدهٔ PHP/WordPress/MySQL/MariaDB و نسخه‌های هدف Elementor/Pro، نام افزونه‌های امنیتی، تنظیمات WP Rocket و قابلیت‌های دقیق Elementor Pro همچنان باید تکمیل شوند. تضمین سازگاری با تمام افزونه‌ها و هر پیکربندی بدون تست داده نمی‌شود.
