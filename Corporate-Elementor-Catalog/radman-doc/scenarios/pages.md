# صفحات و روش نمایش

## SEO و طراحی سفارشی — CONFIRMED، ۲۰۲۶-۱۰-۳۰

طراحی اختصاصی، رفتار SEO صفحهٔ WordPress را دور نمی‌زند. Title سند، Robots و Canonical از hookهای هسته/افزونهٔ SEO می‌آیند؛ templateها متای موازی، عنوان ثابت و noindex/index اجباری چاپ نکنند. H1 واقعی، Loop، عنوان و وضعیت/رمز صفحه و صفحه‌بندی حفظ شوند. همین قرارداد برای آرشیو و جزئیات وبلاگ، نمونه‌کار و کاتالوگ است؛ سفارشی‌بودن ظاهر مجوز حذف wp_head/wp_footer نیست. متادیتای پیشرفته و Canonical آرشیو در نبود افزونهٔ SEO، تکمیل‌شده فرض نمی‌شوند. [قرارداد صفحه، دارایی و override مشتری](../engineering/client-customization.md).

## استفادهٔ کامل بدون Elementor

برگه‌ها همچنان موجودیت استاندارد WordPress با عنوان، نشانی و وضعیت انتشارند. محتوای عمومی با Gutenberg و قالب پیش‌فرض نمایش داده می‌شود؛ طراحی اختصاصی کدنویسی‌شده از template/partial در Child Theme استفاده می‌کند و برای همان برگه انتخاب می‌شود. محتوای قابل ویرایش فقط در محل‌هایی نمایش داده می‌شود که template برای آن در نظر گرفته است؛ خاموش‌کردن Elementor طراحی ذخیره‌شدهٔ آن را خودکار به PHP تبدیل نمی‌کند. فهرست‌ها مستقل از ویرایشگر صفحه‌اند: برگه‌ها، دسته‌ها و پیوندها در «نمایش ← فهرست‌ها» مرتب و در عنصر منوی سازندهٔ هدر/فوتر انتخاب می‌شوند. صفحهٔ خانه و برگهٔ نوشته‌ها از تنظیمات خواندن WordPress تعیین می‌شوند. جزئیات و آرشیو محتوا نیز renderer مستقل خود را دارند؛ هیچ‌کدام نیازمند نصب Elementor نیستند.

## تأییدشده

**اصلاح مالک، ۲۰۲۶-۱۰-۲۸:** تصاویر محتوایی صفحات سفارشی، مانند Hero و گالری، از رسانهٔ WordPress انتخاب و با شناسهٔ attachment ذخیره شوند؛ قابل تغییر با کنترل بومی برگه باشند. طراحی PHP به فایل محتوایی ثابت در Child یا URL تاریخ‌دار وابسته نشود. آیکون و تزئین ثابتِ خود طراحی طبق قرارداد دارایی‌ها مستقل‌اند. [مصرف و انتقال رسانه](../engineering/media.md).

عرض، gutter و فضای ابتدا/انتهای محتوای PHP/سفارشی از [سناریوی مشترک چیدمان](layout-spacing.md) پیروی کنند. این سند همچنین مالک مرز containerهای Elementor/Pro و همسانی عرض Gutenberg است؛ قواعد متعارض برای هر template جدا نوشته نشوند.

- صفحات اصلی با PHP/HTML5 و داده داینامیک WordPress ساخته شوند و HTML آماده از سرور بگیرند.
- طراحی بصری با CSS اختصاصی؛ تعامل عمومی با Vanilla JavaScript و انیمیشن اختیاری با GSAP/ScrollTrigger محلی.
- صفحه عمومی به React، Next.js یا Elementor وابسته نباشد. کل سایت React SPA یا Headless نیست.
- React تنها برای تعامل پیچیده‌ای که واقعاً نیاز دارد مجاز است؛ این استثنا روش پیش‌فرض ساخت صفحه نیست.
- Gutenberg ابزار مدیریت محتوای استاندارد WordPress باشد. برای طراحی کاملاً اختصاصی مشتری، ساختار، CSS و تعاملات قابل کدنویسی مستقیم باشند.
- هر صفحه منتخب، مثلاً تماس، می‌تواند در صورت نصب Elementor با آن ساخته شود؛ سایر صفحات PHP اختصاصی باقی بمانند. قالب بدون Elementor کامل کار کند.
- انتخاب روش برگه در مدیریت واضح باشد: «رادمان ـ PHP اختصاصی/محتوای استاندارد» یا «Elementor». عبارت «React رادمان» در انتخاب‌گر قبلی کنار گذاشته شد.
- هدر/فوتر اختصاصی با خروجی PHP/HTML در هر دو حالت برقرار باشد.
- وبلاگ، محصول و نمونه‌کار طراحی پایه سبک داشته باشند؛ چندین استایل آماده و انتخاب‌گر آن‌ها ساخته نشود. هیچ طرح یا چیدمان آماده‌ای نباید طراحی اختصاصی مشتری را محدود کند.
- ظاهر متفاوت برای همان پروژه سفارشی‌سازی شود، بدون افزودن خودکار همه طرح‌های مشتری به هسته.

فهرست/آرشیو و جزئیات نقش متفاوت دارند؛ حذف چندطرحی به معنی حذف صفحات لازم یا تنظیمات رنگ/فونت نیست. تبدیل خودکار محتوا میان روش‌های ویرایش تعهد فعلی نیست.

## CONFIRMED — انتخاب روش طراحی محتوا

**تکمیل مالک — ۲۰۲۶-۱۰-۲۰:** مسیر Elementor باید با ویرایشگر بومی Atomic/V4 هماهنگ باشد. مسیر PHP اختصاصی و Elementor دو ماژول مستقل‌اند و بتوان در یک سایت از هر دو برای برگه‌های متفاوت استفاده کرد؛ فعال‌شدن Atomic نباید سایت را به Elementor وابسته یا برگه‌های اختصاصی را تبدیل کند. انتخاب طراحی در تنظیمات قابل استفاده باشد و نبود پیش‌نیاز با وضعیت روشن توضیح داده شود؛ ذخیرهٔ ترجیح طراحی با فعال‌شدن افزونه/ماژول اشتباه نشود. [قرارداد اتصال Atomic و حدود واقعی](../engineering/elementor.md).

طبق درخواست ۲۰۲۶-۱۰-۱۹، وبلاگ، محصول و نمونه‌کار هر کدام در تنظیمات قالب انتخاب مستقل داشته باشند: «طراحی اختصاصی رادمان» با PHP/HTML و سفارشی‌سازی مشتری، یا «Elementor Pro Theme Builder». آرشیو و صفحهٔ جزئیات مستقل‌اند؛ مثلاً آرشیو محصول اختصاصی و جزئیات آن المنتوری باشد. این انتخاب روش نمایش است و کتابخانهٔ چندین طرح آماده ایجاد نمی‌کند.

انتخاب روش نمایش، داده یا محتوای ذخیره‌شده را تبدیل/حذف نمی‌کند و ماژول محصول یا نمونه‌کار را خودکار فعال نمی‌کند. نبود Elementor Pro یا نبود طرح منتشرشدهٔ منطبق با شرایط نمایش، به خروجی اختصاصی برگردد. هدر و فوتر همچنان متعلق به سازندهٔ رادمان باشند. اجرای پایه و طراحی اختصاصی به نصب Elementor وابسته نیستند. رفتار فعلی، انتخاب‌های دقیق و مرز آزمون در [قرارداد روش نمایش](../engineering/renderers.md) ثبت است.

## پیشنهاد تجربه انتخاب و پذیرش

یک کنترل مشخص در برگه، در صورت تناسب با Template استاندارد WordPress، بدون دو انتخاب‌گر متعارض. حالت Elementor فقط با افزونه فعال قابل استفاده و نبود آن دارای وضعیت/fallback روشن باشد. Canvas بدون هدر/فوتر تصمیم جدا می‌خواهد. تغییر روش محتوای قبلی را خودکار حذف نکند.

پروژه بدون Elementor نصب و صفحات با HTML اولیه نمایش داده شوند؛ یک تماس Elementor اضافه شود و نمایش دیگر صفحات تغییر نکند. هدر/فوتر، فونت و زبان هر دو حالت صحیح باشند. بدون JS، محتوای اصلی قابل خواندن بماند.

## باز

برگه‌ها اکنون Template صریح «طراحی اختصاصی رادمان» و Template «رادمان — المنتور با هدر و فوتر» دارند. اولی با سابقهٔ ویرایش Elementor هم خروجی استاندارد/PHP را انتخاب می‌کند؛ دومی در نبود افزونه از انتخاب جدید حذف می‌شود و قالب PHP مستقل باقی می‌ماند. انتخاب نمایش آرشیو/جزئیات سه بخش بالا نیز جداست و پیش از نصب پیش‌نیاز قابل ذخیره است؛ اجرای Pro همچنان به افزونه و طرح منطبق نیاز دارد. [وضعیت اتصال](../engineering/elementor.md). تبدیل محتوای روش‌ها و جایگزینی هدر/فوتر با Theme Builder در دامنه نیست.

قرارداد دقیق ویرایش بخش‌های اختصاصی با Gutenberg/metadata و تجربه تغییر روش صفحه دارای محتوا هنوز باز است. طبق [تصحیح سناریوی زبان‌ها](languages.md)، هر زبان برگهٔ واقعی و مستقل متصل به ترجمهٔ متناظر دارد؛ افزودن زبان از همان روال WPML انجام شود و نسخه‌ها تصویر/محتوا/طراحی مستقل داشته باشند. داشتن برگهٔ ترجمهٔ خانه/درباره/خدمات، برگهٔ اضافی برای محصول نیست. انتخاب اجباری پایه/override شرط این روال نباشد؛ فایل template مشترک در Child همچنان مجاز است. برگه‌های استاندارد از UI بومی WPML استفاده می‌کنند؛ روال استقلال و sync قالب در [سفارشی‌سازی مشتری](../engineering/client-customization.md) ثبت است. نگاشت فیلدهای اختصاصی به ATE و پذیرش واقعی همچنان بازند؛ اصل رندر PHP و نصب روی هاست PHP دیگر باز نیست.

## عنوان صفحه — CONFIRMED

عنوان صفحه پیش‌فرض مستقل در تنظیمات قالب دارد: نمایش، رنگ/گرادینت/تصویر/ویدئوی زمینه، پوشش، ارتفاع، مسیر راهنما و تایپوگرافی ارثی. هر برگه می‌تواند نمایش را از قالب ارث ببرد یا روشن/خاموش کند و ظاهر اختصاصی داشته باشد. آرشیو و جزئیات وبلاگ، محصول و نمونه‌کار نیز هرکدام مستقل‌اند؛ دادهٔ موجود خودکار بازطراحی نشود و عنوان بومی قالب تکرار نشود. [مالک فنی و مرز المنتور](../engineering/page-title.md).
