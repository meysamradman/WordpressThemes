# قرارداد اجرایی عرض و فاصله

## رنگ مستقل نماهای محتوا — ادامهٔ سورس، ۲۰۲۶-۱۰-۲۴

نیاز و اصلاح مالک در [محتوا](../scenarios/content.md) است. در ۲۰۲۶-۱۰-۲۵ دامنه به پس‌زمینه محدود شد: `inc/content-colors-settings.php` شش scope وبلاگ/محصول/نمونه‌کار × آرشیو/جزئیات و فقط کلید background دارد. شش مقدار اختیاری در همان `radman_settings` ذخیره می‌شوند؛ validator فقط رشتهٔ خالی یا HEX شش‌رقمی را می‌پذیرد و ورودی نامعتبر تنظیمات قبلی را حفظ می‌کند. reset قسمت «طراحی محتوا» این کلیدها را نیز برمی‌گرداند. کنترل تنظیمات از ColorSetting و FieldGroup مشترک است.

متاباکس، ذخیرهٔ override، ثبت metadata و قاعدهٔ WPML مربوط به `_rdct_content_colors` حذف شدند؛ فایل‌های PHP/JS/CSS اختصاصی متاباکس و ورودی‌های build نیز حذف شدند. metadata قبلی از دیتابیس پاک نمی‌شود ولی دیگر خوانده و اعمال نمی‌شود. رنگ‌های قدیمی متن، عنوان، لینک، کارت و حاشیه نیز از schema و خروجی حذف شدند؛ وجود کلیدهای تاریخی در تنظیمات باعث اعمال آن‌ها نیست.

`inc/content-colors.php` فقط زمینهٔ اصلی همان درخواست را resolve و یک background-color معتبر روی `#main-content` به handle موجود `rdct-theme` اضافه می‌کند؛ فایل frontend، JavaScript، AJAX یا خواندن metadata ندارد. هدر/فوتر، کارت، عنوان و پیوند هدف نیستند؛ پس‌زمینهٔ صریح سکشن/ویجت داخل محتوا بازنویسی نمی‌شود. Canvas مستقل بدون main قالب هدف این CSS نیست. قرارداد محدود، استقلال نماها، حذف نقش‌های اضافی، ورودی نامعتبر و نبود خواندن metadata را بررسی می‌کند.

مرجع محدود Bridge `framework/admin/options/general/map.php` برای background/box قبلاً بررسی شد؛ framework آن منتقل نشد. override متاباکس این مرجع پس از اصلاح مالک دیگر نیاز رادمان نیست. بررسی‌های واقعی در [foundation](../implementation/foundation.md) است؛ پذیرش ظاهری نصب جدید هنوز باقی است.

اصلاح Theme 0.1.5 — ۲۰۲۶-۱۰-۲۱: template بومی Full width در resolver مشترک شرکت می‌کند؛ فقط mode همان درخواست full می‌شود و تنظیم ذخیره‌شده تغییر نمی‌کند. فاصلهٔ بالا/پایین و gutter از قرارداد سراسری می‌آیند و article استاندارد container/body می‌گیرد. اگر همان برگه با Elementor ساخته شده باشد، مسیر external و خروجی بی‌محدودیت قبلی حفظ می‌شود. صفحه‌بندی محتوای چندبخشی در برگهٔ عادی، Full width و جزئیات از helper مشترک native استفاده می‌کند.

عرض wide با `--rdct-content-wide` از همان layout حل‌شده می‌آید؛ در حالت custom دیگر به container_width عمومی محدود نیست. `theme_json` نیز برای بوم custom همان wideSize را می‌دهد و contentSize را به کوچک‌ترِ عرض خواندن و بوم محدود می‌کند. بلوک alignfull فقط در canvas مدیریت‌شدهٔ full از gutter خودش بیرون می‌زند؛ فرمول بر مبنای عرض والد و margin منطقی است، نه 100vw، و gutter موبایل مستقل مصرف می‌شود. حالت boxed/custom، قالب‌های ناشناختهٔ مشتری و Elementor این breakout را نمی‌گیرند. overflow کل سایت پنهان نشده است؛ بررسی بصری چند اندازه همچنان پذیرش جداست.

بدنهٔ محتوای عمومی، رسانه و پیمایش محلی جدول از [کامپوننت بدنهٔ مشترک](components.md) پیروی می‌کنند؛ این قرارداد جای width/gutter resolver را نمی‌گیرد و overflow کل سایت را پنهان نمی‌کند. برگه، مقاله و محصول همان استایل بدنه را مصرف می‌کنند؛ کنترل‌های Elementor مستقل‌اند.

پیاده‌سازی پایهٔ ۲۰۲۶-۱۰-۱۹؛ مالک رفتار [سناریوی چیدمان](../scenarios/layout-spacing.md) است. تأیید بصری روی سایت مشتری هنوز انجام نشده است.

## داده و resolver

`inc/layout-settings.php` schema، validation و resolver مشترک تنظیمات را دارد. scopeها `content` و single/archive برای blog/catalog/portfolio هستند. پیش‌فرض content حالت contained و سایر scopeها inherit است. برای override باید حالت همان scope از inherit تغییر کند؛ فیلد خالی/null از سراسری ارث می‌برد و صفر فاصله معتبر است. ورودی نامعتبر مقدار قبلی را حفظ می‌کند. schema محتوای محصول/نمونه‌کار هیچ query یا فعال‌سازی ماژولی انجام نمی‌دهد.

| کنترل | محدودهٔ فعلی، px صحیح |
|---|---|
| container_width موجود سایت | ۹۶۰–۱۶۰۰؛ پیش‌فرض ۱۲۰۰ |
| reading_width | ۳۲۰–۱۲۸۰؛ پیش‌فرض ۷۶۰ |
| سقف عرض custom محتوا/سازنده | ۳۲۰–۲۵۶۰ |
| gutter دسکتاپ/تبلت/موبایل | ۰–۱۶۰ یا خالی برای ارث‌بری |
| فاصلهٔ بالا/پایین محتوا، دسکتاپ/تبلت/موبایل | ۰–۳۲۰ یا خالی برای ارث‌بری |

`inc/layout.php` صفات wrapper و filter استاندارد `wp_theme_json_data_theme` را فراهم می‌کند. فقط دادهٔ layout تم به‌روزرسانی می‌شود؛ دادهٔ ذخیره‌شدهٔ Elementor یا Global Styles کاربر دست‌کاری نمی‌شود. `src/css/layout.css` با CSS Variables و logical properties، سقف عرض، مرکزشدن و فاصلهٔ محتوا را اعمال می‌کند. تا 48rem موبایل، بالاتر از آن تا 64rem تبلت و بالاتر از 64rem پایه مصرف می‌شود. `tablet_gutter/top/bottom` همان schema و کنترل مشترک مدیریت را دارند؛ null هر دستگاه از پایه ارث می‌برد، نه دستگاه مجاور. دادهٔ قدیمی و مقدار صفر حفظ می‌شوند. محاسبهٔ عرض به JavaScript وابسته نیست.

در main مدیریت‌شده، padding داخلی container مستقیم و margin اضافی فوتر صفر می‌شوند؛ padding ابتدا/انتها یک مالک دارد. بنابراین فاصلهٔ قبلیِ حاصل از جمع margin فوتر و padding محتوا کاهش می‌یابد؛ دادهٔ ذخیره‌شده پاک نمی‌شود. چیدمان‌های قبلی سازنده با schema نسخهٔ ۱ و width=full معتبر می‌مانند.

## مالکیت خروجی و استفادهٔ سفارشی

`Layout\elementor_content()` برای template المنتوری/Canvas/Header Footer، برگهٔ ساخته‌شده با Elementor فعال یا renderer فعال Pro، مالکیت محتوا را خارجی تشخیص می‌دهد. main کلاس `rdct-lyt-external` می‌گیرد و محدودیت عرض/padding رادمان نمی‌گیرد. `page.php` برای برگهٔ المنتوری از part سادهٔ `content/elementor.php` استفاده می‌کند؛ selector روی `.elementor`/`.e-con` یا تحمیل `!important` نداریم.

`Layout\custom_template()` فهرست مسیرهای صریح PHP در `radmanct/layout/custom_templates` را با نام template همان برگه تطبیق می‌دهد. پیش‌فرض `templates/custom.php` است؛ Child نمونه `templates/custom-page.php` را اضافه می‌کند. این templateها مستقل از meta قبلی Elementor، main مدیریت‌شده و تنظیمات مشترک محتوا می‌گیرند. adapter محتوای Elementor نیز از همین تشخیص استفاده می‌کند؛ منطق نام template در دو جا کپی نمی‌شود. این فهرست مسیر فایل را include نمی‌کند و template تازه یا انتخاب جدیدی در مدیریت ایجاد نمی‌کند.

Template سفارشی ثبت‌نشده به‌صورت پیش‌فرض از مدیریت خودکار main خارج است. توسعه‌دهنده می‌تواند wrapper خود را با `rdct_content_layout_attributes('content')` یا scope معتبر دیگر و فرزند مستقیم `.rdct-ctr` بسازد. برای استفاده از main والد بدون انتخاب صریح PHP، filter قبلی `radmanct/layout/manage_custom_template` باقی است. این روش‌ها نباید روی یک ناحیه با هم اعمال شوند. نمونهٔ Child padding تکراری article ندارد؛ [سفارشی‌سازی مشتری](client-customization.md).

## پنل و سازنده

`inc/layout-page.php` متای خصوصی `_rdct_page_layout` را با همان `normalize_field()` و حدود schema عمومی حل می‌کند؛ فقط scope محتوای یک برگه اعمال می‌شود. پیش‌فرض ارث‌بری کامل است، numeric خالی از عمومی و صفر صریح است. mode=inherit همهٔ overrideهای ذخیره‌شده را غیرفعال می‌کند؛ مقادیر برای انتخاب دوباره باقی می‌مانند و حالت inherit کاملاً خالی metadata را حذف می‌کند. override فعال پس از پیش‌فرض template تمام‌عرض اعمال می‌شود؛ override صریح برگه می‌تواند آن پیش‌فرض را تغییر دهد. مرز زودهنگام Elementor/Pro و opt-out قالب‌های ناشناخته حفظ شده‌اند. header/footer و آرشیو/جزئیات سایر نوع‌ها این meta را مصرف نمی‌کنند.

`inc/admin/page-layout.php` فقط در مدیریت بارگذاری می‌شود: متاباکس native سازگار با block editor، Select/Input و گروه جمع‌شوندهٔ هر دستگاه؛ بدون CSS/JS جدید یا React دوم. عنوان‌ها از labels مشترک تنظیمات می‌آیند. ذخیره با nonce مخصوص ID برگه، مجوز هم‌زمان edit_theme_options/edit_post، بررسی نوع page و رد autosave/revision انجام می‌شود. کلیدهای ناشناخته حذف، ورودی نامعتبر با مقدار معتبر قبلی جایگزین و فیلد غایب حفظ می‌شود. این metadata داخل Elementor یا REST عمومی منتشر نمی‌شود؛ تاریخچهٔ revision این تنظیمات و تطبیق عرض بوم ویرایشگر Gutenberg با استثنای تک‌برگه در این مرحله پیاده نشده‌اند. `theme.json` همچنان پیش‌فرض سراسری را مالک است؛ خروجی و پیش‌نمایش سایت override برگه را دارند.

کنترل‌های سراسری در «چیدمان و فاصله‌ها» هستند. اصلاح نهایی مالک: شش نمای وبلاگ/کاتالوگ/نمونه‌کار از زیرمنوی آرشیو/جزئیاتِ والد همان نوع محتوا باز می‌شوند؛ تب افقی و صفحهٔ طراحی محتوا حذف شدند. هر صفحه روش نمایش، چیدمان، رنگ پس‌زمینه و سایدبار همان scope را با اجزای مشترک نشان می‌دهد. `layout-fields.js` از همان Input/Select و schema PHP استفاده می‌کند؛ پیش‌فرض inherit، حالت‌های contained/full/custom، عرض اختصاصی و gutter/فاصلهٔ بالا/پایین دستگاه‌ها حفظ شدند. خروجی واقعی Elementor زودهنگام از wrapper/variables چیدمان رادمان خارج می‌شود و تنظیم fallback همچنان ذخیره‌شدنی است. تنظیم ماژول خاموش آن را فعال نمی‌کند. بازنشانی عمومی فقط عمومی و بازنشانی هر صفحه فقط scope همان نما را برمی‌گرداند. هیچ کلید ذخیره یا تنظیم کاربر مهاجرت/بازنویسی نشد.

`builder-layout-fields.js` همان اجزای مدیریت را برای full/contained/custom، customWidth و gutter مصرف می‌کند. gutter هدر/فوتر چهار ورودی مستقل پایه، `laptopGutter`، `tabletGutter` و `mobileGutter` دارد: صحیح ۰–۱۶۰ px؛ خالی/null از پایه و پایه از سایت ارث می‌برد. صفر حفظ می‌شود؛ ارث‌بری به دستگاه مجاور زنجیر نمی‌شود. کلیدهای قبلی و schema نسخهٔ ۱ حفظ شده‌اند. `inc/builder/layout.php` validation و CSS Variables خروجی PHP را دارد؛ عرض هدر/فوتر مستقل از محتواست. background محدود نمی‌شود، محتوای ردیف سقف و gutter می‌گیرد. CSS در بازهٔ لپ‌تاپ/تبلت متغیر `--builder-device-gutter` را انتخاب می‌کند؛ محاسبه فقط یک مالک دارد و قواعد پایه مقدار دستگاه را بازنویسی نمی‌کنند. تنظیم ردیف/عنصر مستقل باقی است. این گسترش، کنترل چهار دستگاهِ فاصلهٔ عمومی محتوای صفحه نیست.

`builder-settings-panel.js` همراه Library/Assignment با اولین ورود به تنظیمات چیدمان lazy وارد می‌شود؛ React مدیریت وارد frontend نمی‌شود. CSS سازنده همچنان شرطی است.

در سازنده، دستگاه کنترل gutter از همان عرض مشترک پیش‌نمایش می‌آید؛ پنل مقدار همان دستگاه را نشان می‌دهد و انتخاب دستگاه آن پنل نیز بوم را هماهنگ می‌کند. تغییر تب یا عنصر مقدار دستگاه را reset نمی‌کند. نوع full/contained/custom و customWidth همچنان برای کل چیدمان هستند؛ تغییر اندازهٔ preview آنها را بازنویسی نمی‌کند. [جزئیات کنترل و ظاهر چهار دستگاه](builder.md).

## شواهد محدود

بررسی پایه شامل Build، ۴۵ بررسی کوتاه Node و قراردادهای PHP settings، builder، builder-appearance، admin-typography و `tests/layout-contract.php` روی PHP 8.4.26 بود. در ۲۰۲۶-۱۰-۲۳ قرارداد layout با ارث‌بری/صفر/رد ورودی تبلت، استقلال موبایل و override تک‌برگه گسترش یافت و همراه settings روی PHP 8.4 پاس شد. مرز Elementor/نوع محتوا، ترتیب template تمام‌عرض، بازنشانی و guardهای nonce/capability/autosave/revision بررسی شدند. قراردادها stub هستند؛ بررسی بصری، ذخیره در editor واقعی، اجرای Pro/Gutenberg، cache، WPML و سرعت روی سرور انجام نشده‌اند.
