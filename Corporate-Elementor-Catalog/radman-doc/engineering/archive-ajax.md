# AJAX آرشیو اختصاصی محصول و وبلاگ

## Intro مستقل و CSS منتخب — ۲۰۲۶-۱۱-۰۱

پاسخ fragment، `intro` و `header` رشته‌ای و `filters` با مقادیر رشته‌ای را کنار `html/title/scope` دارد؛ transport نوع داده را پیش از commit بررسی می‌کند. header در هدف `[data-rdct-archive-header]` به‌روز و filters در رویداد `rdct:archive-updated` منتقل می‌شود تا سایدبار و ComboBox پس از Back/Forward با زمینهٔ واقعی taxonomy/search هماهنگ بمانند. `Archives::intro()` hook قبلی بخش اول وبلاگ را اجرا می‌کند؛ `view(scope,false)` فقط ادامه را می‌سازد. Child دو هدف intro و view دارد تا بخش تمام‌عرض بالا مستقل از سایدبار ثابت زیر آن عوض شود. مصرف‌کنندهٔ قدیمی بدون intro target، دو رشته را در همان view ترکیب می‌کند؛ محصول/نمونه‌کار intro خالی دارند. query، اندازهٔ صفحه و History موازی نشده‌اند.

بخش Child فقط در fragment نیازمندش، linkهای stylesheet محلی از manifest می‌دهد. helper مشترک `archive-styles.js` آن‌ها را جدا، بر اساس URL deduplicate و پیش از commit بارگذاری می‌کند؛ خطای CSS مسیر خطا/تلاش دوبارهٔ قبلی را حفظ می‌کند. transport پس از preparation دوباره stale بودن درخواست را بررسی می‌کند؛ cancel و timeout موجود هنگام آماده‌سازی هم برقرارند. سایدبار در fragment نیست و دوباره query/render نمی‌شود. مرورگر/کندی واقعی شبکه این نوبت بررسی نشدند.

**حالت خالی وبلاگ — ۲۰۲۶-۱۰-۲۰:** partial مشترک نتایج، وضعیت blog را به empty state می‌دهد؛ پیام تغییر/پاک‌کردن فیلتر می‌آید و فرم جستجوی عمومی دوم ساخته نمی‌شود. فیلتر GET همان وبلاگ برای تلاش بعدی باقی است. کاتالوگ/نمونه‌کار پیام خودشان و جستجوی عمومی سایت fallback قبلی را حفظ می‌کنند. این رفتار در HTML اولیه و fragment از همان partial می‌آید و منطق JavaScript جدا ندارد.

وضعیت ۲۰۲۶-۱۰-۲۰: کد پایه پیاده شد؛ پذیرش مرورگر/نصب واقعی باقی است. نیاز محصول در [سناریوی محتوا](../scenarios/content.md) و مرز Elementor در [renderer](renderers.md) است.

جست‌وجوی بومی `?post_type=radman_product&s=...` به طراحی کاتالوگ و fragment همان catalog می‌رود؛ `rm_search` صریح اولویت دارد و فیلتر بعدی می‌تواند URL را به آرشیو محصول منتقل کند. جست‌وجوی بومی وبلاگ scope/design وبلاگ دارد؛ ابزارک جست‌وجوی سایدبار وبلاگ با adapter والد و `post_type=post` نتایجش را به نوشته‌ها محدود می‌کند. جست‌وجوی عمومی هدر محدود نشده است. انتخاب native Select یا ComboBox فقط یک change روی select اصلی می‌دهد؛ تایپ/IME در ورودی داخلی ComboBox درخواست آرشیو نمی‌فرستد. debounce، لغو درخواست قبلی، حفظ نتایج هنگام خطا و retry همان موتور مشترک‌اند.

## رندر و query

**اصلاح صفحه‌بندی — ادامهٔ سورس، ۲۰۲۶-۱۰-۲۴:** ترتیب پیش‌فرض وبلاگ و کاتالوگ بدون جستجو، در نبود `orderby` سفارشی، تاریخ و سپس شناسهٔ یکتا است؛ جهت قبلی `order` حفظ می‌شود. جستجوی بدون انتخاب ترتیب، کاملاً ترتیب relevance بومی WordPress را حفظ می‌کند؛ چون relevance در آرایهٔ `orderby` مانند تاریخ/شناسه پشتیبانی نمی‌شود، tie-breaker جدید به این مسیر تحمیل نشده است. انتخاب صریح عنوان/قدیمی‌ترین/جدیدترین شناسهٔ هم‌جهت دارد. این ترتیب از جابه‌جایی ناشی از تاریخ/عنوان برابر جلوگیری می‌کند، ولی snapshot ثابت هنگام انتشار/حذف هم‌زمان محتوا نیست. در وبلاگ، فقط هنگام وجود فیلتر یا ترتیب معتبر رادمان، `ignore_sticky_posts` فعال می‌شود تا سنجاق‌شدن، قیود و ترتیب را دور نزند؛ نوشتهٔ سنجاق‌شده از نتایج منطبق حذف نمی‌شود و وبلاگ بدون فیلتر سیاست بومی خود را نگه می‌دارد. HTML اولیه و fragment همان query اصلی را مصرف می‌کنند؛ query یا asset جدید ندارند. قرارداد و بررسی‌های واقعی در [foundation](../implementation/foundation.md) ثبت‌اند.

`inc/archives.php` فقط آرشیو blog/catalog/portfolio بدون renderer منطبق Pro را مجاز می‌داند؛ feed، preview، REST، مدیریت، جزئیات و جستجوی مختلط سایت وارد این مسیر نمی‌شوند. HTML اولیه و پاسخ AJAX هر دو از partialهای `content/blog-results.php`، `content/catalog-results.php` و `content/portfolio-results.php` می‌آیند؛ Child Theme همان partial و کارت را override می‌کند. header عنوان آرشیو، هدر/فوتر سایت و کنترل وضعیت بیرون fragment هستند.

## تکمیل صفحه‌بندی نمونه‌کار — ۲۰۲۶-۱۰-۲۹

با درخواست بررسی مالک، صفحه‌بندی نمونه‌کار نیز به انتقال مشترک با مقدار `_rdct_fragment=portfolio` متصل شد؛ توضیح عمومی marker در ادامه برای blog/catalog همان قرارداد را دارد. قالب والد و Child هر دو partial نتایج نمونه‌کار را مصرف می‌کنند؛ نمایش کارت‌ها و طراحی فعلی تغییر نکرده است. پیوند واقعی صفحه‌بندی، مسیر taxonomy، حالت بدون JS، لغو پاسخ قدیمی، خطا/retry و History همان کنترلر مشترک‌اند. فرم فیلتر/جستجوی تازه‌ای برای نمونه‌کار اضافه نشده و AJAX روی جزئیات یا طرح Pro اجرا نمی‌شود. بررسی کوتاه scope و partial اختصاصی، rendererها، انتقال JS و lint پاس شد؛ پذیرش Back/Forward در مرورگر و DB واقعی انجام نشد.

درخواست GET به همان URL عمومی با `_rdct_fragment=blog|catalog` می‌رود. بعد از query اصلی WordPress، در `template_redirect` فقط template نتایج رندر و JSON شامل scope/html/title برگردانده می‌شود؛ `get_header`، `get_footer` و preloader اجرا نمی‌شوند. endpoint موازی با query محصول دوم، مسیر نوشتن یا nonce عمومیِ قابل انقضا نداریم. method غیر GET با ۴۰۵ و scope نامعتبر/renderer غیرمجاز با ۴۰۹ رد می‌شود. پاسخ از همان زبان و زمینهٔ URL استفاده می‌کند و cache خصوصی مرورگر/واسط برای fragment غیرفعال است. پارامتر داخلی از پیوندهای صفحه‌بندی پاک می‌شود؛ قالب صفحهٔ کامل با پاسخ JSON مخلوط نشود.

query کاتالوگ همان مالک Core و پارامترهای `rm_*` است. وبلاگ در `inc/blog-archive.php` مستقل از Core، query اصلی نوشته‌ها در home/category/tag/author/date را مصرف می‌کند؛ پارامترهای `rdct_search`، `rdct_category`، `rdct_tag` و `rdct_sort` محدود و whitelist می‌شوند. قیود قبلی taxonomy با AND حفظ و query ثانویه/مدیریت/feed/REST دست‌نخورده‌اند. تعداد نوشته‌ها از تنظیم native با سقف ۴۸ می‌آید؛ termها حداکثر ۱۰۰ به‌علاوهٔ انتخاب فعالند. کل مجموعهٔ محتوا برای فیلتر در مرورگر دانلود نمی‌شود. بدون AJAX نیز همین فرم GET و query کار می‌کنند.

## چرخهٔ مرورگر

### فیلترهای فعال و دادهٔ مشترک — Theme 0.1.6

وبلاگ نیز مانند کاتالوگ فیلترهای فعال جستجو، دسته، برچسب و ترتیب را با پیوند حذف تکی نمایش می‌دهد. حذف یکی، انتخاب‌های دیگر و زمینهٔ آرشیو/زبان را نگه می‌دارد و به صفحهٔ اول برمی‌گردد؛ پاک‌کردن همه، زمینهٔ بومی دسته/برچسب/نویسنده/تاریخ را عوض نمی‌کند. پیوندهای واقعی GET با همان کنترلر AJAX موجود مصرف می‌شوند و بدون JavaScript نیز قابل استفاده‌اند. action وبلاگ فقط کلیدهای scalar مجاز برای routing را نگه می‌دارد؛ پارامترهای نامرتبط، صفحه‌بندی قبلی و marker داخلی وارد پیوند حذف نمی‌شوند.

`inc/archive-filters.php` مالک مشترک دریافت محدود termها، memoization در همان درخواست بر اساس زبان/taxonomy، ترتیب‌ها و markup امن حذف است. انتخاب فعال بیرون از صد نتیجه با یک lookup محدود اضافه می‌شود؛ رندر دوباره query تکراری نمی‌سازد. وبلاگ همچنان بدون Content کار می‌کند و query محصول در افزونهٔ Content باقی است. CSS فیلتر موجود بین listing/catalog مشترک است؛ asset یا وابستگی عمومی تازه اضافه نشد. قرارداد PHP هر دو آرشیو، escaping، حذف تکی و حفظ routing را پاس کرد؛ lint سه فایل و سه بررسی انتقال AJAX نیز پاس شدند. پذیرش تعاملی مرورگر/هاست و سنجش سرعت از این بررسی‌ها نتیجه نمی‌شوند.

`frontend.js` فقط با marker اختصاصی، `archives.js` را به‌صورت lazy وارد می‌کند؛ `archive-request.js` مالک انتقال و ترتیب درخواست است. فقط submit فرم مشخص، تغییر select، جستجوی debounce با فاصلهٔ ۳۵۰ms و کلیک معمولی روی صفحه‌بندی/حذف یا پاک‌کردن فیلتر دریافت می‌شوند. پیوند کارت، کلیک دارای modifier، دانلود و مقصد خارجی دست‌نخورده‌اند. تایپ composition جدا رعایت می‌شود.

URL فرم از action صفحهٔ اول و فیلدهای خودش ساخته می‌شود؛ صفحه‌بندی قبلی و پارامتر داخلی حذف، routing پیوند ساده و زبان حفظ می‌شوند. ارسال به origin دیگر مجاز نیست و fetch از redirect پیروی نمی‌کند. درخواست قبلی Abort و با شمارهٔ نسل نامعتبر می‌شود؛ پاسخ قدیمی حتی با بی‌اثر بودن لغو روی سرور، DOM را بازنویسی نمی‌کند. timeout پانزده‌ثانیه‌ای به همان درخواست تعلق دارد. خطا نتایج قبلی را حفظ و retry نشان می‌دهد؛ reload/redirect خودکار برای خطا نداریم.

پس از موفقیت فقط view نتایج جایگزین، document.title تازه و URL بدون پارامتر داخلی با History API ثبت می‌شود. popstate انتخاب و صفحهٔ مقصد را دوباره دریافت می‌کند؛ رویداد بازگشت، timer جستجوی قبلی را هم لغو می‌کند. focus و محدودهٔ انتخاب فیلد جستجو بازگردانده می‌شوند؛ بعد از صفحه‌بندی view فوکوس/اسکرول می‌گیرد. aria-busy، شمار نتیجهٔ زنده و پیام خطا وجود دارند. pagehide درخواست/timer را لغو می‌کند تا نشست بازگشته با پاسخ قدیمی تغییر نکند.

رویداد محلی `rdct:archive-updated` پس از جایگزینی به مشتری اجازهٔ اتصال رفتار لازم روی partial خودش را می‌دهد؛ اسکریپت دلخواه داخل fragment اجرا نمی‌شود. کارت‌های پایه نیازی به engine دوم ندارند. stylesheet وضعیت مشترک در ورودی catalog/listing است؛ فرم وبلاگ استایل سبک مشترک فیلتر را مصرف می‌کند. React، jQuery، PJAX و اتصال خارجی تازه نداریم.

## مرجع، شواهد و حدود

بخش محدود `themes/woodmart/js/scripts/wc/ajaxFilters.js` برای جدایی ناحیهٔ محتوا، فرم و popstate و `global/ajaxSearch.js` برای درخواست جستجو خوانده شد؛ فقط الگوی چرخه تطبیق داده شد. engine فروشگاهی، WooCommerce، event bus و کتابخانهٔ PJAX منتقل نشدند. Elementor/Pro مالک تعاملات widgetهای خودش باقی است؛ shortcode فیلتر GET رادمان خودکار Loop Grid را AJAX نمی‌کند.

Build، هفت بررسی دارایی/ترجمه و سه بررسی کوتاه انتقال AJAX پاس شدند. lint هشت PHP و دو قرارداد PHP آرشیو/فیلتر با شبکهٔ خاموش پاس شدند. بررسی‌ها رقابت پاسخ‌ها، لغو، scope اشتباه، فرم GET/زبان، query اصلی و fragment بدون chrome را پوشش می‌دهند. مرورگر، لمس، DB واقعی، ماتریس پیوندها/WPML/کش و benchmark اجرا نشدند؛ کیفیت بصری و Back/Forward واقعی هنوز پذیرش می‌خواهند. سرعت بالا هدف معماری است، نه نتیجهٔ اندازه‌گیری‌شده.

## نمونه‌کار و نمایش بیشتر

طراحی مشتری در `radmanct-child/inc/portfolio/archive.php`، `template-parts/portfolio/` و override نتایج `template-parts/content/portfolio-results.php` است؛ CSS مستقل `src/css/pages/portfolio/archive.css` فقط در آرشیو اختصاصی نمونه‌کار/دستهٔ آن enqueue می‌شود. عنوان اصلی آرشیو H1 و عنوان کارت نمونه‌کار طبق انتخاب مالک H3 است؛ دسته/توضیح/CTA heading نیستند و ظاهر عنوان از تنظیمات H3 ارث می‌برد. query اصلی ۸ مورد با ترتیب date/ID نزولی دارد؛ مدیریت، feed، REST، query ثانویه و renderer واقعی Elementor تغییر نمی‌کنند. قالب و Content پایه به Child وابسته نیستند.

`data-rdct-load-more` در کنترلر مشترک `archives.js` همان transport، timeout، لغو، خطا/retry و آماده‌سازی رسانه را مصرف می‌کند. `archive-results.js` فقط فرزندان `data-rdct-archive-items` را بدون شناسهٔ تکراری اضافه و `data-rdct-archive-pagination` را با صفحهٔ بعد جایگزین می‌کند؛ پاسخ نامعتبر پیش از mutation رد می‌شود. درخواست تکراری هنگام بارگذاری مهار و focus کیبورد به عنوان اولین کارت تازه منتقل می‌شود. در حالت append نشانی/عنوان صفحهٔ مبدأ ثابت می‌ماند؛ Refresh مجموعهٔ انباشته را بازسازی نمی‌کند. ورود مستقیم به هر صفحه و fallback بدون JS همان دسته/زبان و صفحه‌بندی بومی را نگه می‌دارند؛ تغییر معمولی آرشیو همچنان replace و History موجود را دارد. CSS و افکت مرجع کپی نشده‌اند. حرکت رسانهٔ مشتری در `src/js/portfolio/media.js` با موتور مشترک [پارالاکس](components.md#پارالاکس-تصویر-در-قاب-ثابت--ادامهٔ-سورس-۲۰۲۶-۱۰-۲۶) و vendor همان Parent اجرا می‌شود: دامنهٔ ۶٪، scrub=0.5، حداقل عرض ۷۶۸ و بدون حرکت/دریافت vendor در reduced-motion. دو لایهٔ مستقل برای پارالاکس و زوم ۱٫۰۴۵ هاور/focus مانع تداخل transform می‌شوند؛ تصویر و ویدئو با هم در قاب حرکت می‌کنند. رویداد archive-updated کارت تازه را یک بار متصل و lifecycle مشترک، کارت حذف‌شده و خروج صفحه را پاک می‌کند. این طرح برای حرکت داخل قاب از مرجع Orisa Split معرفی‌شدهٔ مالک الهام می‌گیرد؛ تطابق بصری زنده با آن تأیید نشده است.
