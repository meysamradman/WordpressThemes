# هویت و نام‌گذاری Radman CT

## قرارداد مقصد نسخهٔ Elementor و وضعیت اجرا

نسخهٔ Elementor اجرا شده است: مسیر طرح PHP مشتری و Child حذف شده‌اند؛ هدر/فوترساز، کتابخانه و کد PHP داخلی آن‌ها حفظ می‌شوند. تغییر پیشوند اجرایی از `rdct-` به مقصد `rde-` هنوز انجام نشده و درخواست جداگانه می‌خواهد. شناسه‌های ذخیره‌شدهٔ المنتور، meta و هویت بسته‌ها تغییر نمی‌کنند.

| کاربرد | قرارداد مقصد |
|---|---|
| نسخهٔ Elementor در همین مخزن | `rde-`؛ `rd` برای Radman و `e` برای Elementor |
| نسخهٔ سفارشی در مخزن مستقل | `rdc-`؛ `c` برای Custom؛ آن مخزن اینجا تغییر نمی‌کند |
| کلاس و ID اختصاصی | `rde-{module}__{part}`؛ modifier با `--{variant}` |
| marker و custom property اختصاصی | `data-rde-*` و `--rde-*` |
| رویداد اختصاصی جدید | `rde:*` |

نام‌های اجرایی فعلی `rdct-*`، helperهای `rdct_*`، namespaceها، text domainها و شناسه‌های بسته/ویجت/کنترل فعلاً قرارداد سازگاری‌اند؛ جدول‌های بعدی وضعیت موجود را نشان می‌دهند. نام مقصد نباید اکنون کنار نام قدیمی در کد اضافه شود. تغییر prefix فرانت‌اند در کار آینده، مجوز تغییر خودکار نام بسته، API، دادهٔ Elementor، متا، option، slug یا محیط Docker نیست. مهاجرت احتمالی هر قرارداد ذخیره‌شده باید جدا طراحی و تأیید شود.

## واژه‌نامهٔ کوتاه مقصد

در تغییر نام آینده، بخش‌های پرتکرار هم کوتاه شوند؛ دستور قبلیِ کامل‌نگه‌داشتن `title`، `item`، `text` و مانند آن مربوط به سورس قدیمی است و برای مقصد جایگزین می‌شود. نام‌ها ثابت و قابل جستجو باشند، نه حروف تصادفی یا مخفف موردی.

| مفهوم | مخفف | مفهوم | مخفف |
|---|---|---|---|
| Text / Title | `tx` / `ttl` | Description / Subtitle | `desc` / `sttl` |
| Label / Item / Link | `lbl` / `itm` / `lnk` | Wrapper / Inner | `wrp` / `inr` |
| Container / Content | `ctr` / `cnt` | Header / Footer | `hdr` / `ftr` |
| Button / Icon / Image | `btn` / `ico` / `im` | Gallery / Preview | `gal` / `pv` |
| Entrance / Enter / Word | `ent` / `en` / `wd` | Scroll / Motion | `scr` / `mot` |
| Panel / Navigation | `pnl` / `nav` | Background / Color | `bg` / `clr` |
| Media / Visual | `md` / `vis` | Section / Sidebar | `sec` / `sb` |
| Service / Project | `svc` / `prj` | Archive / Article | `arc` / `artc` |

نمونهٔ مقصد: `rde-btn__lbl`، `rde-card__ttl`، `rde-hero__desc` و `rde-tx-en__wd`. نام روشن و کوتاه مثل `hero`، `menu`، `card`، `work`، `logo`، `grid` و `row` می‌ماند. عنوان‌های قابل مشاهده، توابع/متغیرهای داخلی خوانا، APIهای مرورگر و نام‌های بومی WordPress/Elementor/کتابخانه‌ها مخفف نشوند. modifier پویای renderer و پسوند بومی asset تنها با بررسی تولیدکننده/مصرف‌کننده تغییر کند؛ برای چند حرف، لایهٔ تبدیل زمان اجرا نسازید.

در اجرای آینده PHP، CSS، JS، previewهای Classic/Atomic، dataset، ARIA و تست‌ها هماهنگ تغییر کنند؛ نگاشت توسعه ایستا باشد و به فرانت‌اند ارسال نشود. نام کنترل یا نوع ویجت ذخیره‌شده، schema، Global/Dynamic، responsive و ترجمه با کوتاه‌سازی کلاس‌ها تغییر نمی‌کند. حجم خام/Gzip و تعداد فایل و رفتار حفظ شوند؛ کوتاه‌شدن نام به‌تنهایی شاهد افزایش FPS نیست.

## قراردادهای پیاده‌سازی فعلی تا مهاجرت

متادیتای افزونه‌ها: نام نمایشی کوتاه و قابل ترجمه، توضیح یک‌جمله‌ای کوتاه دربارهٔ کاربرد و `Author: Radman` مشترک باشد. نام و توضیح انگلیسی header در ترجمهٔ همان افزونه معادل فارسی داشته باشند؛ جزئیات معماری و عبارت تبلیغاتی وارد توضیح فهرست افزونه‌ها نشوند. رابط استاندارد WordPress حفظ شود.

بستهٔ تأییدشدهٔ کامپوننت‌ها **Radman CT Components**، slug/domain `radmanct-components` و namespace `RadmanCTComponents` دارد. basename `radmanct-components/radmanct-components.php` در آپدیت ثابت می‌ماند. پیشوند `rdct-`، helperهای `rdct_*` و IDهای قبلی ویجت‌ها حفظ می‌شوند؛ کلاس‌ها از قرارداد کوتاه ماژول در ادامه پیروی می‌کنند.

قرارداد اجرایی قبلی: **CONFIRMED — ۲۰۲۶-۱۰-۲۰**، با نام «Radman CT / radmanct / rdct-». نام بسته و سازگاری سورس فعلی تا اجرای جداگانهٔ قرارداد مقصد حفظ می‌شوند؛ برند مشترک و پیشوند هدف تابع بخش بالای همین سند است.

| کاربرد | قرارداد |
|---|---|
| نام قالب | Radman CT — Corporate & Catalog |
| پوشه و text domain قالب | `radmanct` |
| Child Theme | `radmanct-child` / Radman CT Child |
| افزونهٔ محتوا | `radmanct-content/radmanct-content.php` / Radman Content |
| افزونهٔ اتصال AI | `radmanct-mcp/radmanct-mcp.php` / Radman MCP |
| namespace PHP | `RadmanCT`، `RadmanCTChild`، `RadmanCTContent` و `RadmanCT\Mcp` |
| توابع عمومی PHP | `rdct_` |
| کلاس، شناسهٔ DOM، data attribute، CSS variable | `rdct-`، `data-rdct-`، `--rdct-` |
| تنظیمات JS عمومی | `window.rdctBuilder`، `window.rdctSettings` و خانوادهٔ `rdct…` |
| hook توسعهٔ جدید | `radmanct/…` |
| نام نویسنده | Radman |

اصلاح مالک در ۲۰۲۶-۱۱-۰۱: نام نمایشی افزونه‌ها کوتاه و تابع زبان مدیریت باشد: `Radman Content` ← «محتوای رادمان»، `Radman Components` ← «کامپوننت‌های رادمان» و `Radman MCP` ← «رادمان MCP». metadata بومی افزونه، کارت‌های قالب و منو/عنوان تنظیمات همین نام‌ها را از text domain مربوط ترجمه می‌کنند. هویت فنی خانواده همچنان Radman CT است؛ basename، پوشه، text domain، namespace، گزینه‌ها و شناسه‌های ذخیره‌شده تغییر نمی‌کنند. نام قالب و Child در این درخواست تغییر نکرده است. نام افزونهٔ ثالث مثل Elementor متعلق به خودش است.

نام‌های فعلی مانند `rdct-card__title` و `rdct-menu--mobile` فعلاً در سورس معتبرند؛ نام مقصد از واژه‌نامهٔ کوتاه بالا پیروی می‌کند. nesting عمیق، selector زنجیره‌ای غیرضروری و تغییر نام پویا هنگام build مبنا نیست. پسوند مؤلف به هر جزء اضافه نشود. طول کم پیشوند به‌تنهایی ادعای افزایش محسوس سرعت نیست؛ CSS شرطی و کم‌حجم، minification و نداشتن وابستگی تکراری اولویت‌اند.

## کلاس‌های کوتاه و قابل نگهداری — ۲۰۲۶-۱۰-۲۳

مالک کوتاه‌بودن نام‌ها و قرارداد یکسان برای CSS/JS/PHP اختصاصی، تنظیمات، هدر/فوترساز و adapterهای Elementor را خواسته است. کوتاه‌سازی نام، حجم خام HTML/CSS و رشته‌های selector در JS را کم می‌کند؛ میزان کاهش حجم انتقال بعد از gzip/Brotli باید اندازه‌گیری شود و از طول اسم، بهبود محسوس سرعت نتیجه‌گیری نشود.

قاعدهٔ سورس موجود پیش از تغییر آینده: `rdct-{module}__{part}` و در صورت نیاز `--{state-or-variant}`؛ نمونهٔ موجود `rdct-ib__title` است. در مقصد، نام ماژول و بخش هر دو طبق واژه‌نامهٔ کوتاه بالا تغییر می‌کنند. نامی مثل `rde-x__t` بدون معنی ثبت‌شده مناسب نیست. از توصیف کل مسیر فایل/کامپوننت در هر کلاس خودداری شود.

| شناسهٔ ماژول | معنی و وضعیت |
|---|---|
| `ib` | Icon Box؛ در سورس موجود است |
| `im` | Image؛ در سورس موجود است |
| `fb` | Flip Box؛ در سورس موجود است |
| `bld` | Builder مشترک هدر/فوتر و محیط ویرایش آن |
| `nav` | Navigation |
| `stg` | Settings |
| `crs` / `tbl` | Carousel / Table |
| `cnt` / `prd` / `prj` | Content / Product / Project |
| `gal` / `lib` / `pre` | Gallery / Library / Preloader |
| `ctr` / `lyt` / `cat` / `clt` | Container / Layout / Catalog / Client |
| `cmp` / `pg` / `spec` | Component / Pagination / Specifications |
| `mob` / `mot` / `bdr` | Mobile / Motion / Border |
| `clr` / `pnl` / `hdr` / `ftr` | Color / Panel / Header / Footer |
| `adm` / `cor` / `ico` / `tr` / `fld` | Admin / Core / Icon / Text Reveal / Field Group |

قبل از اختراع مخفف، همین فهرست و نام‌های ماژول فعلی بررسی شوند؛ یک مفهوم با چند مخفف نام‌گذاری نشود. مخفف تازه فقط هنگام نیاز واقعی به این فهرست افزوده شود. نام خوانای کوتاهی مثل `card` یا `menu` الزاماً به مخفف نیاز ندارد. عنوان‌های قابل مشاهدهٔ فارسی/انگلیسی مخفف نشوند.

**CONFIRMED — ۲۰۲۶-۱۰-۲۳:** مالک تغییر هماهنگ کلاس‌های اختصاصی در کل قالب و افزونه‌های رادمان را تأیید کرد. اتصال PHP، CSS، JS، preview و Child همراه کلاس تغییر می‌کند. نگاشت ثابت و قابل جستجو در [`tools/css-class-map.json`](../../tools/css-class-map.json) مرجع تبدیل نام‌های قبلی است؛ پیشوندها مخفف ماژول هستند و بخش خوانا حفظ می‌شود. کلاس/شناسهٔ WordPress، Elementor و افزونه‌های دیگر، ID ویجت/کنترل، schema، کلید تنظیمات، metadata، API عمومی، asset handle، شناسهٔ DOM، `data-rdct-*` و متغیرهای CSS با این تغییر دست‌کاری نمی‌شوند. نام‌گذاری خودکار و متفاوت کلاس‌ها در هر build نداریم.

CSS سفارشی خارج از سورس پروژه، از جمله Custom CSS ذخیره‌شدهٔ Elementor یا Child مشتری، باید با نگاشت به‌روزرسانی شود؛ دیتابیس بازنویسی و alias سراسری تولید نمی‌شود. پس از نصب بسته‌های هماهنگ، کش صفحات و دارایی‌ها پاک شود تا HTML و CSS قدیم/جدید مخلوط نشوند.

**تکمیل ۲۰۲۶-۱۰-۲۴:** کلاس انتخابگر مستقل آیکون `rdct-ico-picker` مطابق نگاشت مشترک است. `rdct-library` و prefix بومی `rdct-icon-` در adapter Icons Manager شناسهٔ value ذخیره‌شدهٔ Elementor هستند، نه کلاس تزئینی قابل تغییر؛ همراه نوع control قبلی حفظ شدند. آزمون نام‌گذاری فقط همین دو شناسه را در فایل canonical/generated ادغام آیکون مستثنا می‌کند، نه همهٔ کلاس‌های یک پوشه.

برای رفتار جدید JS، marker مشخص `data-rdct-*` در جایی که اتصال رفتاری لازم است ترجیح دارد؛ برای هر عنصر تزئینی marker اضافی ساخته نشود. متغیر محلی JS در سورس خوانا بماند؛ minifier خروجی را کوتاه می‌کند. نام property یا رشتهٔ کلاسِ مشترک با PHP را نباید بدون قرارداد mangle کرد. حذف کد/سبک بلااستفاده، اشتراک منطق و بارگذاری شرطی طبق [دارایی‌ها](assets.md) همچنان اولویت بهینه‌سازی است. تغییر نام، ادعای افزایش سرعت یا نتیجهٔ اندازه‌گیری gzip/Brotli نیست؛ شواهد ساخت و بررسی در [وضعیت پیاده‌سازی](../implementation/foundation.md) ثبت می‌شود.

**تفکیک افزونه‌ها — ۲۰۲۶-۱۰-۲۱:** مالک یک افزونهٔ اختیاری MCP با ماژول‌های داخلی خواست؛ اتصال Content/Theme/Elementor افزونه‌های اختصاصی جدا نمی‌سازد. افزونهٔ محصول/نمونه‌کار از همین نسخه پوشه، فایل ورودی و text domain برابر `radmanct-content` و namespace برابر `RadmanCTContent` دارد. با دستور صریح مالک، alias، bootstrap سازگاری یا مهاجرت از بستهٔ آزمایشی Core نداریم؛ کدهای مربوط حذف شدند. از این نام نهایی به بعد، basename هر افزونه در آپدیت‌های بعد ثابت می‌ماند و Version افزایش می‌یابد. نسخهٔ Content فعلی 0.1.2 و MCP 0.1.1 است. بستهٔ Core خالی یا همه‌کاره ساخته نمی‌شود. نام گزینه‌ها/CPTها/schema داده به این دلیل بازطراحی نشدند و لایهٔ تبدیل اضافه نشده است.

پشتیبان سازنده با فرمت جدید `rdct-builder` صادر می‌شود؛ فرمت قبلی `radman-builder` نیز طبق [قرارداد بازیابی سازنده](builder.md) برای همان سایت و همان نوع سازنده پذیرفته می‌شود.

## سازگاری اطلاعات قبلی

**عنوان رابط — ۲۰۲۶-۱۰-۲۲:** عنوان کامپوننت معنای مشخص داشته باشد؛ مانند Expandable Panels، Content Box، Flip Box و Icon Box. عنوان انگلیسی با حروف استاندارد و ترجمهٔ فارسی همراه نام انگلیسی قابل جستجو ارائه شود. پسوند Atomic نوع ویرایشگر را مشخص می‌کند. تغییر عنوان، شناسهٔ widget/prop، نام فایل، کلید تنظیمات یا نگاشت WPML ذخیره‌شده را تغییر نمی‌دهد.

**نام نهایی چایلد — ۲۰۲۶-۱۰-۲۱:** پوشه/text domain برابر `radmanct-child` و عنوان `Radman CT Child` است؛ نام آزمایشی `radmanct-client` کنار گذاشته شد. چایلد افزونه یا پیش‌نیاز Elementor نیست و فقط در «نمایش ← پوسته‌ها» مدیریت می‌شود. نام نهایی در build، ZIP و namespace یکسان است؛ مهاجرت برای نام آزمایشی اضافه نمی‌شود. آپدیت والد فایل‌های اختصاصی مشتری در چایلد را جایگزین نمی‌کند.

تغییر نام محصول مجوز حذف یا بازنویسی دیتابیس نیست. optionهای `radman_settings`، `radman_builder_*`، `radman_core_*`، metaهای `_radman_*`، CPT/Taxonomyهای `radman_product*` و `radman_portfolio*`، شناسه‌های کنترل ذخیره‌شده و actionهای underscore قدیمی باقی می‌مانند. نام templateهای وابسته به CPT نیز عمداً قدیمی است. این موارد قرارداد داده‌اند، الگوی نام‌گذاری جدید نیستند.

نوع ویجت‌های ذخیره‌شدهٔ Elementor یعنی `radman-text-reveal` و `radman-icon` و context ترجمهٔ WPML یعنی `Radman Builder` و `Radman Cursor` حفظ می‌شوند؛ ظاهر، دستهٔ ویجت، کلاس خروجی و namespace کد جدیدند. `wpml-config.xml` باید با همان نام ذخیره‌شدهٔ ویجت منطبق بماند.

`inc/legacy-settings.php` در اولین بار راه‌اندازی قالب جدید، theme mods قالب قبلی هم‌نوع را به نام جدید کپی می‌کند؛ مقدار موجودِ مقصد برنده است، اصل حذف نمی‌شود و یک marker مانع بازگرداندن دوبارهٔ تنظیمات حذف‌شده می‌شود. چایلد فقط از چایلد قبلی ارث می‌برد. optionها و metaهای مشترک نیازی به تبدیل ندارند.

نصب موجود باید قالب/چایلد جدید را صریحاً فعال کند؛ تغییر پوشه خودکار روی سرور انجام نشده است. Core با slug جدید نیز افزونه‌ای جدا از نظر WordPress است: Core قدیمی را غیرفعال و سپس Core جدید را فعال کنید؛ داده حفظ می‌شود. Core جدید هنگام فعال بودن slug قدیمی از ثبت تکراری ماژول‌ها جلوگیری و اخطار مدیریت نمایش می‌دهد. updater محلی فقط بستهٔ جدید را مدیریت می‌کند؛ تبدیل خودکار افزونهٔ نصب‌شده انجام نمی‌دهد.

CSS سفارشی مشتری با selectorهای قدیمی و کد سفارشی دارای namespace/hook قدیمی باید به قرارداد جدید منتقل شوند؛ alias فراگیر برای CSS/PHP ایجاد نشده است. فایل‌های مرجع `themes/`، نام حساب GitHub، لوگوی مؤلف، آرشیو تاریخی، مسیر مستندات `radman-doc/` و شناسهٔ skillهای موجود تغییر هویت محصول نیستند و حفظ می‌شوند.

## CSS، SCSS و Tailwind

مبنای فعلی **Modern CSS ماژولار** با Vite است؛ sourceهای `.css` و خروجی readable/minified داریم. SCSS یا Tailwind نصب و وارد مبنا نشده‌اند. SCSS پیش‌پردازنده است و پیش از نصب به CSS تبدیل می‌شود؛ با خروجی یکسان، سرعت مرورگر یکسان است. nesting بی‌رویه می‌تواند خروجی را بزرگ کند. [مستند Sass](https://sass-lang.com/documentation/style-rules/).

Tailwind در WordPress قابل استفاده است و CSS استاتیک بدون runtime تولید می‌کند؛ خودبه‌خود سریع‌تر از CSS کم‌حجم فعلی نیست. ساخت کلاس با concatenation در PHP/JS برای scanner کافی نیست و کلاس‌های پویا/Elementor به قرارداد source روشن نیاز دارند. تغییر ابزار طراحی فعلی تصمیم جداگانه می‌خواهد. [مستند تشخیص کلاس‌ها](https://tailwindcss.com/docs/detecting-classes-in-source-files).

در ادامهٔ کار پیش از افزودن شناسهٔ جدید، این قرارداد و مالک داده را بررسی کنید؛ هیچ جایگزینی سراسری روی کلیدهای ماندگار، نام حساب‌ها، منابع ثالث یا فایل‌های باینری انجام نشود. شواهد واقعی در [وضعیت پیاده‌سازی](../implementation/foundation.md) ثبت می‌شود.
