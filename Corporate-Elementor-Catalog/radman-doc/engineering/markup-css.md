# استاندارد Modern CSS و DOM کمینه

## CONFIRMED — سند ارسالی مالک، ۲۰۲۶-۱۰-۲۷

این قرارداد برای HTML، PHP، React و CSS اختصاصی Theme، Child و افزونه‌های رادمان است؛ امکانات، خوانایی و دسترس‌پذیری برای کاهش شمار خطوط حذف نشوند. مالکیت فایل و بارگذاری شرطی در [دارایی‌ها](assets.md) است؛ این سند مالک قواعد markup و CSS است.

## ساختار و چیدمان

- هر node و wrapper باید دلیل معنایی، چیدمان، تعامل یا طراحی داشته باشد. برای فاصله یا یک کلاس تازه، wrapper نسازید؛ ابتدا parent موجود را بررسی کنید. عمق DOM و کلاس هم‌معنی را کاهش دهید؛ کلاس scope یا hook لازم حذف نشود.
- تأکید مالک در ۲۰۲۶-۱۰-۲۹: این بازبینی وظیفهٔ پیش‌فرض پیاده‌سازی هر بخش است و نباید به تذکر مجدد مالک وابسته باشد. وقتی renderer مشترک و چیدمان سفارشی روی هم قرار می‌گیرند، لایه‌های هم‌وظیفه ادغام شوند؛ استفاده از کامپوننت مجوز افزودن wrapper تکراری نیست. موتور مشترک حفظ شود و برای کم‌کردن DOM موتور موازی ساخته نشود.
- اصلاح صریح مالک در ۲۰۲۶-۱۰-۲۹: عنوان‌ها باید heading واقعی با سطح مناسب باشند؛ span جای عنوان نیست و دور عنوان یا تک‌تک حروف صرفاً برای استایل اضافه نشود. متن مستقیم و کلاس روی heading اولویت دارد؛ جداسازی درونی فقط برای نیاز واقعیِ افکت/محتوای ترکیبی و با حفظ heading معنایی مجاز است. در پنل خدمات، h2 مستقیم و br برای شکست خط، p برای توضیح/شماره، ul/li برای ویژگی‌ها و figure برای قاب تصویر استفاده می‌شود.
- در جای مناسب header، nav، main، section، article و footer استفاده شوند؛ جایگزینی کور div با عنصر معنایی نیز مجاز نیست. nodeهای لازم WordPress، Elementor، accessibility، preview و JavaScript حفظ شوند. DOM بومی Elementor متعلق به خود آن است؛ رادمان wrapper موازی بی‌دلیل نسازد.
- Flex برای رابطهٔ یک‌بعدی و Grid برای رابطهٔ دوبعدی انتخاب شوند. فاصله با gap و padding مالک همان چیدمان باشد. minmax، auto-fit و clamp/min/max فقط برای نیاز واقعی استفاده شوند. برای layout عادی، float، transform، absolute positioning یا JS جای Flex/Grid ننشیند؛ استثنا باید علت فنی داشته باشد.
- ارتفاع طبیعی محتوا و اندازهٔ ذاتی رسانه مبناست. width/max-width/height حدسی و تکراری اضافه نشود. ابعاد خود لوگو/تصویر با سهم فضا یا عرض عنصر در کانتینر یکی نیست؛ انتخاب auto نباید مخفیانه درصد سفارشی را فعال کند.
- RTL/LTR با logical properties و ترتیب واقعی DOM حل شوند؛ ظاهر به متن فارسی یا یک عرض خاص وابسته نباشد. موبایل، تبلت، لپ‌تاپ و دسکتاپ و ارث‌بری تنظیمات حفظ شوند.

## تصویر و رسانه

- نسبت طبیعی تصویر حفظ شود؛ crop فقط با انتخاب طراحی و aspect-ratio/object-fit مناسب باشد. ابعاد ذاتی HTML برای جلوگیری از جابه‌جایی چیدمان نگه داشته شوند. لوگوی خطی نباید فضای baseline متن را به ارتفاع چیدمان اضافه کند.
- تصاویر رسانهٔ WordPress از API بومی، srcset و sizes مناسب استفاده کنند؛ picture فقط وقتی source متفاوتی واقعاً وجود دارد ساخته شود. تصویر مهم بالای صفحه بدون دلیل lazy نشود. SVG و fallback محلی در [رسانه](media.md) تعریف می‌شوند.

## CSS و مرز کامپوننت

- لینک‌های رابط سایت در حالت عادی، hover و active زیرخط خودکار نگیرند؛ بازخورد با رنگ/کادر و focus مشخص باشد. استایل underline منتخبِ صریح کامپوننت یا تایپوگرافی ذخیره‌شده تصاحب نشود. این قاعده به UI مدیریت/ویرایشگر تعمیم داده نشود.

- قانون هم‌معنی، declaration پوشانده‌شده، media query بلااستفاده و override تکراری حذف شود. specificity پایین بماند؛ :where در جای مناسب و !important فقط با دلیل ضروری. شمار کلاس کمتر، جای استقلال و نگهداری را نگیرد.
- tokenهای رنگ، فونت و فاصله با custom properties مشترک باشند. inline style برای مقادیر واقعاً پویا مثل انتخاب ذخیره‌شدهٔ کاربر مجاز است؛ مقدار ثابت در CSS باشد. property بی‌مصرف در خروجی چاپ نشود، ولی دادهٔ ذخیره‌شدهٔ کاربر حذف نشود.
- Base، Layout، Component و Admin مالک جدا دارند. CSS/JS feature و preset فقط هنگام مصرف معتبر وارد شود؛ پنل مدیریت، Elementor و فرانت به stylesheet عمومی یکدیگر وابسته نشوند. selector رادمان استایل ویجت خارجی یا WordPress Admin را تغییر ندهد.
- کنترل‌های عمومی فرانت شامل Input، Select، Textarea، Checkbox/Radio، Button، Tab و نمایش درختی دسته‌ها، برای رفتار هم‌معنی پایهٔ مشترک قابل استفاده در کل قالب داشته باشند؛ taxonomy، گزینه‌ها، URL و وضعیت انتخاب ورودی‌اند و منطق محصول در موتور عمومی hardcode نشود. تراز متن/فلش، RTL/LTR، label، تعامل کیبورد و حالت‌های focus/disabled/error در همان پایه حل شوند؛ داده و رفتار اختصاصی آرشیو در مالک خود باقی بماند. ظاهر حرفه‌ای با هندسه، فاصله‌ها، رنگ و تایپوگرافی منسجم ساخته شود؛ native بودن به معنی ظاهر خام مرورگر نیست. هر کنترل فقط CSS و رفتار موردنیاز خود را بارگذاری کند؛ برای فیلد ساده JS اجباری ساخته نشود.
- PHP/Child و adapterهای Classic/Atomic از renderer/metadata مشترک موجود استفاده کنند؛ سیستم موازی editor، uploader یا layout ساخته نشود. [قرارداد کامپوننت‌ها](components.md).

کنترل‌های عمومی سایت، درخت دسته و ویجت‌های داده مالک مستقل در Components دارند؛ Theme/Child فقط adapter یا مصرف‌کننده‌اند. API، مسیرها و مرز Elementor در [کنترل‌ها و دادهٔ مشترک](components.md#کنترلها-و-داده-مشترک) است. قواعد مدیریت در [Admin UI](admin-ui.md) جدا می‌مانند؛ stylesheet سایت به کنترل‌های editor تحمیل نشود.

## بازبینی محدود و شواهد

پیش از تغییر، مصرف‌کنندگان selector، hook، responsive، تصویر و JS بررسی شوند. پیش از افزودن کلاس/عنصر/CSS روشن شود آیا ساختار موجود یا Flex/Grid کافی است، آیا قانون مشابهی هست، آیا اندازه لازم است و scope/Elementor آسیب نمی‌بیند.

پس از تغییر، کاهش node/class و CSS در نمونهٔ قابل‌شمارش گزارش شود؛ اندازه‌گیری محدود به همان نمونه است. Build، lint و قرارداد مرتبط کوتاه اجرا شوند. تأیید بصری دستگاه‌ها، RTL/LTR، نصب Elementor و رفتار واقعی از بررسی source جدا گزارش شوند؛ موفقیت build اثبات ظاهر یا سرعت نیست. بسته‌بندی، تست طولانی و مرورگر تابع دستور مالک و قواعد پروژه‌اند.
