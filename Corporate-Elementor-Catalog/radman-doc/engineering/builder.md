# قرارداد هدر و فوترساز

بازبینی دارایی ۲۰۲۶-۱۱-۰۱: منابع فقط از انتخاب جاری برگه/سایت/زبان آماده می‌شوند و پایهٔ CSS بین هدر و فوتر مشترک است؛ gate برگهٔ Elementor Canvas مانع enqueue بی‌مصرف طرح ذخیره‌شده می‌شود. انتخاب‌ها و renderer تغییر نکردند. [مسیر، شواهد و حدود ماژولار بودن](assets.md#بارگذاری-و-مرز-ماژولها).

## مرز نمای موبایل و منابع

**OPEN:** `Rendering::row()` اکنون آیتم‌ها را قبل از visibility رندر می‌کند؛ `Responsive::attributes()` کلاس hidden دستگاه را می‌سازد و `Builder::enqueue()` کل درخت layout منتخب را پیمایش می‌کند. `mobileMenuId` منوی مستقل دارد، ولی markup هر دو منو تولید می‌شود؛ این حالت معادل حذف منابع دسکتاپ در موبایل نیست. جداسازی رندر و requirements دستگاه باید همراه سیاست روشن کش، تغییر viewport و fallback بدون JS تکمیل شود؛ صرف افزودن hide یا media به CSS اثبات عدم دریافت منابع نیست. در مرجع محلی WoodMart، حذف server-side شاخهٔ desktop_only شرط `mobile_optimization` و `woodmart_is_mobile()` دارد؛ این سیاست خودکار به رادمان منتقل نشده است.

## حذف درجا و بازبینی تخصیص — ۲۰۲۶-۱۱-۰۱

عملیات حذف ردیف `WP_List_Table` دکمهٔ بومی است و با تأیید مرورگر در همان صفحه، از transport موجود و عملیات `delete` استفاده می‌کند؛ POST، nonce و capability همان API حفظ شده‌اند. صفحهٔ تأیید `admin-post` حذف شد؛ GET قدیمی فقط به فهرست برمی‌گردد. ماژول مستقل `builder-list.js` فقط در دو فهرست بارگذاری می‌شود و جز transport مشترک وابستگی ندارد؛ React، media و CSS سازنده وارد فهرست نمی‌شوند. موفقیت، HTML همان فهرست با همان URL را تازه می‌کند تا شمارنده‌ها، صفحه‌بندی، جست‌وجو و ستون‌ها از یک renderer بیایند. شکست تازه‌سازی پس از حذف موفق، فقط همان فهرست را reload می‌کند و حذف دوباره نمی‌فرستد؛ خطای حذف در notice بومی نشان داده می‌شود. فوکوس و اعلان وضعیت حفظ می‌شوند.

ستون محل استفاده علاوه بر تخصیص سایت/زبان، تعداد انتخاب‌های مستقیم برگه را از یک query تجمیعی آماده‌شده روی metadata بومی می‌خواند؛ زباله‌دان و auto-draft محاسبه نمی‌شوند. query فقط در فهرست مدیریت اجرا می‌شود و بار جدیدی به فرانت نمی‌دهد. تعداد، میزان نمایش واقعی طرح یا تعداد صفحات ارث‌برنده نیست.

بازبینی محدود Hub `theme/metaboxes/liquid-header.php` و `theme/theme-options/liquid-header-layout.php`، و WoodMart `class-headers-list.php` و `class-frontend.php::get_current_id`، الگوی پیش‌فرض + انتخاب برگه را تأیید کرد. انتخاب فعلی رادمان برای Home/برگهٔ نوشته‌ها، پیش‌فرض سایت/زبان، footer مستقل و حالت none حفظ شد؛ مهاجرت به CPT عمومی یا موتور Elementor لازم نیست. bridge فعلی WPML نسخه‌های مستقل متصل را حل می‌کند؛ نبود ترجمهٔ فعال طبق رفتار فعلی به طرح مبدأ برمی‌گردد. حذف فقط ارجاع‌های همان شناسه را پاک می‌کند و طرح‌های زبان دیگر حذف نمی‌شوند.

شواهد این نوبت: build و lint چهار فایل PHP، ۱۰ آزمون کوتاه JS، قراردادهای stub حذف/انتخاب برگه/WPML با و بدون افزونه و بررسی فقط‌خواندنی فهرست در WordPress محلی پاس شدند. بررسی محلی هیچ طرح، محتوا یا تنظیمی را تغییر نداد. آزمون کلیک در مرورگر و پذیرش واقعی WPML/RTL/LTR در این نوبت انجام نشد؛ نتیجهٔ stub جای آن‌ها نیست.

۹ بررسی متمرکز manifest/گراف دارایی و یکتایی کلیدها/دامنهٔ ترجمه‌های تازه نیز پاس شدند. اجرای کامل فایل `assets.test.mjs` دو شکست در بخش‌های خارج از این تغییر داشت: بودجهٔ حجم `settings.js` و نبود ترجمهٔ `Font family` در labels تنظیمات. این موارد در این نوبت اصلاح نشده‌اند و نتیجهٔ کامل آن فایل سبز گزارش نمی‌شود.

## کاهش کار تکراری در پیش‌نمایش و sticky — ۲۰۲۶-۱۰-۲۹

پیش‌نمایش مشترک هدر/فوتر رویدادهای ResizeObserver، resize و آماده‌شدن فونت را در یک requestAnimationFrame تجمیع می‌کند؛ نگاشت آیتم به کانتینر برای هر چیدمان یک‌بار ساخته می‌شود. هنگام تعویض سند یا unmount، فریم معلق و observer/listener پاک می‌شوند. iframe همچنان بدون اجرای script است و موتور یا wrapper دیگری اضافه نشده است.

هدر sticky در حالت انتقال به body، ابتدا مختصات placeholder را یک‌بار می‌خواند و سپس فقط مقدارهای واقعاً تغییرکرده را می‌نویسد. reduced motion پس از توقف tween، در هر رویداد اسکرول دوباره gsap.set ایجاد نمی‌کند. قراردادهای کوتاه ورود/خروج، بازگشت سریع، breakpoint، پاک‌سازی و تجمیع اندازه‌گیری پاس شدند؛ سرعت واقعی و ظاهر مرورگر در این نوبت اندازه‌گیری نشدند.

## فهرست مستقل و انتخاب زبان — ۲۰۲۶-۱۰-۲۹

تکثیر مستقل — اصلاح ۲۰۲۶-۱۱-۰۱: عملیات «تکثیر» در فهرست، `new=1&copy=ID` را باز می‌کند؛ هنگام افزودن نیز انتخاب مبدأ از طرح‌های ذخیره‌شده در نوار سازنده ممکن است. داده از همان read/schema می‌آید؛ نام جدید الزامی است و فقط ذخیره، شناسهٔ تازه می‌سازد. مبدأ، تخصیص سایت و ارتباط ترجمه‌های WPML تغییر نمی‌کنند؛ تکثیر جای عملیات افزودن ترجمهٔ متصل نیست. تغییر مبدأ روی draft ویرایش‌شده تأیید دورریختن می‌خواهد و خطای read دادهٔ جاری را حفظ می‌کند.

حذف و تغییر نام در فهرست — اصلاح نهایی مالک ۲۰۲۶-۱۱-۰۱: عملیات بومی زیر عنوان شامل ویرایش، تکثیر، تغییر نام و حذف دائمی برای همهٔ طرح‌ها، حتی default، است. تغییر نام فرم یا صفحهٔ جدا ندارد: لینک فهرست خود سازنده را با فوکوس روی نام باز می‌کند؛ نام در نوار ابزار همیشه قابل ویرایش است و با ذخیرهٔ همان سازنده همراه چیدمان ثبت می‌شود. نام خالی/نامعتبر پیش از ذخیره رد می‌شود و conflict چیدمان، نام را تغییر نمی‌دهد. شکست نادر CAS نام پس از ذخیرهٔ چیدمان، با warning و revision تازه برمی‌گردد؛ نام ویرایش‌شده برای تلاش مجدد حفظ می‌شود و ادعای تراکنش مشترک دو option نداریم. مسیر قدیمی admin-post تغییر نام فقط redirect به سازنده است. حذف همچنان با تأیید، capability، nonce و POST انجام می‌شود. حذف در API و فهرست یک مسیر مشترک دارد؛ تخصیص‌های سایت/زبان که به طرح حذف‌شده اشاره دارند روی none قرار می‌گیرند و overrideهای برگهٔ آن طرح حذف می‌شوند تا ارث‌بری سراسری برقرار شود. حذف default بدون تخصیص صریح، all را نیز none می‌کند. علامت حذف در index موجود مانع بازگشت خودکار default و ذخیرهٔ مجدد آن از تب قدیمی می‌شود؛ شناسه‌های دیگر و طرح‌های قبلی مهاجرت نمی‌شوند. نام default نیز در index موجود نگه‌داری می‌شود. storage گزینه‌ای سطل زباله ندارد؛ عنوان عملیات صریحاً «حذف دائمی» است. CSS اختصاصی فهرست اضافه نشده است؛ JS کوچک مستقل برای حذف درجا طبق بخش جدید همین سند بارگذاری می‌شود.

طبق [اصلاح مالک](../scenarios/header-footer.md)، URLهای `admin.php?page=rdct-header` و `rdct-footer` فهرست‌اند؛ `&layout=ID` همان ویرایشگر موجود را باز می‌کند. با اصلاح ۲۰۲۶-۱۱-۰۱، فهرست از `WP_List_Table` و استایل بومی وردپرس استفاده می‌کند؛ entry و CSS اختصاصی فهرست حذف شدند و React، media، فونت مدیریت رادمان، بوم و Inspector برای فهرست enqueue نمی‌شوند. جدول عنوان قابل مرتب‌سازی، جست‌وجوی GET، نماهای همه/فعال/غیرفعال، تخصیص‌ها، صفحه‌بندی بومی و عملیات ویرایش دارد؛ ستون ترجمه فقط با WPML نمایش داده می‌شود. «افزودن هدر/فوتر» با `&new=1` مستقیم سازنده را با draft خالی و غیرفعال باز می‌کند؛ نام در نوار همان سازنده وارد می‌شود. بازکردن این URL هیچ رکوردی نمی‌سازد؛ اولین ذخیرهٔ نام‌دار، عملیات `create` همان API احرازشده را با validator و Storage موجود و سقف ۱۲ طرح اجرا می‌کند و URL به شناسهٔ ساخته‌شده تغییر می‌کند. فرم واسط و handler ساخت admin-post حذف شده‌اند؛ ذخیره‌های بعدی همان revision معمول را دارند. ساخت طرح، تخصیص سایت را عوض نمی‌کند. storage، شناسه‌های ذخیره‌شده و renderer موازی نشده‌اند. مدیریت نام/حذف و پشتیبان موجود داخل ویرایشگر حفظ شده است.

نوار ابزار پیوند فهرست دارد و کنترل دستی RTL/LTR حذف شد. جهت مستقیماً از translation_state و سپس جهت سایت می‌آید؛ state/effect اضافی تغییر جهت هم حذف شد. فهرست با لینک زبان‌های متصل و علامت افزودن زبان غایب، همان تب ترجمه‌های ویرایشگر را باز می‌کند؛ جدول/ارتباط زبان تازه ایجاد نشده است.

تنظیمات هدر/فوتر فقط تخصیص طرح‌های ذخیره‌شده به کل سایت یا زبان معتبر WPML را مدیریت می‌کند. عملیات سبک `assignments` عنوان، شناسه، وضعیت و تخصیص‌ها را بدون ردیف‌ها و دادهٔ ویرایشگر برمی‌گرداند. انتخاب‌ها تا «ذخیرهٔ تغییرات» اصلی در draft مستقل هر زبان می‌مانند؛ ارث‌بری زبان، تخصیص مستقل را حذف می‌کند. ذخیره فقط کلیدهای تغییرکرده را اعمال می‌کند و خطای میانی، تغییرات ذخیره‌نشده را نگه می‌دارد. زبان ناشناخته رد می‌شود؛ زبان global وردپرس عوض نمی‌شود. کنترل انتخاب تمام عرض ستون خود است و پیوند ویرایش و فهرست کنار آن قرار دارد. انتخاب Dropdown به‌تنهایی محتوای سایت را تغییر نمی‌دهد.

مرجع محدود: Hub `theme/theme-options/liquid-header-layout.php` و `liquid-footer.php` برای انتخاب Template و `liquid/structure/header.php` برای مصرف انتخاب. چارچوب Redux، post typeهای Hub یا source آن منتقل نشدند. بررسی UI UX Pro Max محدود به label متصل و عرض خوانا بود؛ Design System دیگری اضافه نشد.

Build، lint هشت PHP و ۱۶ تست کوتاه JS مرتبط پاس شدند. قرارداد PHP API و WPML با doubleهای موجود، از جمله انتخاب زبان بدون تغییر زبان global، پاس شد. بررسی فقط‌خواندنی روی نصب مشترک، دو مسیر فهرست، لینک ویرایش قبلی، عدم enqueue ویرایشگر/media و منع کاربر ناشناس را تأیید کرد؛ دادهٔ کاربر تغییر نکرد. مرورگر و WPML واقعی بررسی نشدند. در اجرای جانبی settings-ui یک تست قدیمی کنترل رنگ در line 73 خطا داشت؛ این کنترل در این تغییرات ویرایش نشده و پذیرش آن از نتایج فوق نتیجه نمی‌شود.

## تفکیک تنظیمات کلی و فشردگی پنل — ۲۰۲۶-۱۰-۲۸

طبق [اصلاح رابط مالک](../scenarios/header-footer.md)، layout دیگر به‌عنوان حالت مبهم تب تنظیمات عنصر نمایش داده نمی‌شود. چرخ‌دنده عنوان مستقل Header/Footer builder settings و دکمهٔ بازگشت دارد؛ region با عنوان واقعی label می‌شود. سه تب اصلی عناصر/ساختار/ویرایش عنصر هستند و نبود انتخاب، پیام کوتاه انتخاب عنصر می‌دهد. اصلاح بعدی مالک، details و فشرده‌سازی قبلی را رد کرد: تنظیمات کلی اکنون با TabList مشترک چهار بخش عمومی/چیدمان‌ها/پشتیبان/ترجمه‌ها دارد. Library فقط برای بخش فعال و با mode مشخص mount می‌شود؛ رفتار header فقط برای header است. عرض/تخصیص/فعال‌سازی در تنظیمات سراسری باقی ماندند؛ storage/schema و داده‌ها تغییر نکردند.

انتخاب دستگاه تکراری Inspector حذف و badge دستگاه فعلی کنار نام عنصر قرار گرفت؛ همان چهار دستگاه/ارث‌بری و toolbar مشترک مصرف می‌شوند. انتخاب گروه استایل Button از select به تب‌های قابل‌دید تبدیل شد؛ تایپوگرافی تب مستقل و رنگ آیکون/سایه عنوان ثابت دارند. callbackها و renderer مشترک عوض نشدند. دکمه‌های کتابخانه Grid دو ستون با gap و متن قابل‌شکستن دارند. تناسب کارت از `themes/elementor/assets/css/editor.css` بررسی شد: آیکون ۲۸px با فاصلهٔ بالای ۱۵px و ناحیهٔ عنوان ۴۰px؛ کارت حداقل ۸۵px و gap برابر ۱۰px دارد. انتخاب مقصد افزودن عنصر از دراپ‌دان به دکمهٔ نام کانتینر متصل به ساختار تبدیل شد. details/summary در فایل‌های سازنده باقی نماند؛ موتور یا وابستگی تازه ساخته نشد.

در عرض موبایل، قانون ۳۶px منوی auto-fold وردپرس با inset narrow تداخل داشت. build CSS منطقی را با selectorهای زبان پایین می‌آورد و specificity آن‌ها بالاتر بود؛ محدودهٔ ۳۶px اکنون فقط عرض ۷۸۳px به بالا است. مرورگر width واقعی ۳۹۰ و x=0 را در viewport=390 تأیید کرد؛ toolbar حدود ۱۰۸px شد، در برابر حدود ۱۸۶px قبل از اصلاح. انتخاب عرض پیش‌نمایش همچنان مستقل از عرض UI است؛ resize، تنظیم ذخیره‌شدهٔ دستگاه را خودکار تغییر نمی‌دهد.

مشاهدات نسخهٔ قبلی شامل هدر/فوتر و عرض ۳۹۰px بود، اما ظاهر آن نسخه توسط مالک رد شد و تصویر قدیمی `builder-ui-header.png` شاهد پذیرش طراحی نیست. برای اصلاح فعلی، build، lint فایل labels، diff check و ۱۲ بررسی کوتاه panel/Inspector/library/loading موفق بودند. در تب مستقل مرورگر روی وردپرس مشترک، کارت‌ها، تنظیمات عمومی/چیدمان‌ها و گروه‌های استایل/تایپوگرافی دکمه دیده شدند؛ فوتر چهار تب مشترک و حالت اولیهٔ چیدمان‌ها داشت. در viewport=390 عرض editor برابر ۳۹۰ و x=0 و عرض/scrollWidth تب‌های استایل هر دو ۳۴۸px بود؛ viewport بازگردانده شد. تصاویر جدید `artifacts/qa/builder-elements-modern.png` و `builder-settings-modern.png` ثبت شدند. هیچ مقدار یا چیدمانی ذخیره نشد. یک تست قدیمی ColorField در builder-workspace هنوز markup قبل از Pickr را انتظار دارد و fixture آن فاقد useRef است؛ ادعای پاس کامل آن فایل نمی‌شود. پذیرش نهایی طراحی با مالک است؛ drag لمسی واقعی، تمام حالت‌های ذخیره و پوشش همهٔ دستگاه‌ها در این اصلاح انجام نشدند. نسخه 1.1.1 ثابت است.

پس از پرسش مالک، کنترل موجود در مرورگر بررسی شد: انتخاب دکمه ← استایل ← رنگ‌ها در حالت عادی، شامل رنگ متن/پس‌زمینه/حاشیه است؛ رنگ‌های هاور گروه جدا دارند. هدر و فوتر همان ButtonFields و renderer مشترک را مصرف می‌کنند؛ تنظیم رنگ موازی اضافه نشد. تغییر موقت پس‌زمینه به #e53935 در preview واقعی به rgb(229,57,53) رسید و سپس با Undo به snapshot اولیه و وضعیت بدون تغییر ذخیره‌نشده برگشت. چیدمان ذخیره نشد؛ این شاهد پذیرش تمام رنگ‌ها/هاورها یا کنترل بومی Elementor نیست.

## انتظار پیش‌نمایش و درخواست اول — ۲۰۲۶-۱۰-۲۸

اصلاح پس از گزارش چند لودینگ پیاپی: spinner ریشهٔ PHP و مرحلهٔ dynamic import پیش‌نمایش حذف شدند؛ Preview همیشه در ورود لازم است و اکنون import ثابت دارد. فقط خود Preview تا پاسخ واقعی و load iframe نشانگر دارد. build، پنج بررسی کوتاه preview و lint PHP موفق بودند؛ در تب مستقل وردپرس مشترک، iframe آماده، aria-busy=false، صفر نشانگر باقی‌مانده و بدون خطای console دیده شد. این شاهد اندازه‌گیری سرعت یا ثبت همهٔ فریم‌های ورود نیست؛ چیدمان ذخیره نشد.

اولین preview دیگر تأخیر عمدی ۴۰۰ms ندارد؛ پس از داشتن HTML، debounce چهارصد میلی‌ثانیه برای ویرایش‌های پیاپی حفظ است تا به‌ازای هر حرف درخواست PHP مستقل نفرستد. لودینگ مشترک تا آماده‌شدن iframe باقی می‌ماند؛ فاصلهٔ میان دریافت HTML و load فایل‌های آن دیگر وضعیت خالی ندارد. خطای iframe پیام و retry موجود را فعال می‌کند. انتخاب/drag روی خروجی قدیمی همچنان بسته و لغو درخواست قدیمی محفوظ است. [مالک نشانگر مشترک مدیریت](admin-ui.md).

در یک اجرای read-only CLI روی وردپرس مشترک، boot وردپرس ۱۵۴۲ms و رندر هدر/فوتر به‌ترتیب ۸۷۱/۲۶ms بود. این یک نمونهٔ محلی است؛ زمان HTTP/مرورگر، بنچمارک یا اثبات منشأ تمام کندی‌ها نیست. انتظار راه‌اندازی وردپرس با تغییر ظاهر spinner حذف نشده است؛ معماری PHP و sandbox پیش‌نمایش بازنویسی نشد. در مرورگر، هدر و فوتر در تب مستقل به حالت آماده رسیدند؛ دادهٔ ذخیره‌شده یا تب‌های در حال ویرایش مالک دست‌کاری نشدند.

## بازبینی CSS/JS و اشتراک — ۲۰۲۶-۱۰-۲۸

هدر و فوتر همان entry مدیریت builder.js، CSS مدیریت builder.css، schema و renderer مشترک را با kind مستقل مصرف می‌کنند؛ موتور React جدا برای هرکدام یا React bundled دوم وجود ندارد. enqueue مدیریت به screens ثبت‌شده و edit_theme_options محدود است. CSS عمومی builder با یک handle مشترک برای چیدمان فعال آماده می‌شود؛ sticky/transparent فقط هدر منتخب و منو/پنل/دکمه بر اساس مصرف همان چیدمان بارگذاری می‌شوند. مرور محدود شرط‌های enqueue در class-backend.php وودمارت ادامه یافت؛ framework آن منتقل نشد.

Inspector پیش‌تر کنترل‌های منو، پنل و آیکون را با هر انتخاب—even متن ساده—وارد graph ثابت خود می‌کرد. اکنون خانوادهٔ انتخابی dynamic import می‌شود؛ دکمه هم همین مسیر مشترک را دارد. component بارگذاری‌شده در state همان Inspector استفادهٔ مجدد دارد؛ خروج/تغییر انتخاب نتیجهٔ دیررس را اعمال نمی‌کند. خطا پیام و تلاش دوباره دارد. نگاشت تکراری icons از config حذف شد؛ iconChoices تنها کاتالوگ مصرف‌شده است. کنترل‌ها، رنگ، media picker و CSS موجود مشترک ماندند؛ stylesheet یا loader framework تازه اضافه نشد.

چاپ دستی لینک‌های CSS پایهٔ preview حذف و همهٔ استایل‌های لازم از dependency queue وردپرس یک‌بار چاپ می‌شوند. done موقتاً برای سند مستقل خالی و در finally بازگردانده می‌شود؛ previewهای پی‌درپی CSS پایه را گم نمی‌کنند. در نمونهٔ جاری قبل از اصلاح duplicate URL وجود نداشت؛ ادعای حذف درخواست تکراری مشاهده‌شده نمی‌شود. یکپارچه‌کردن مسیر چاپ، وابستگی مشترک و ترتیب آن را حفظ می‌کند.

graph ثابت minified Inspector در snapshot بررسی‌شده از ۴۶۸۸۱ به ۳۸۶۸۷ بایت رسید؛ این کاهش حدود ۸KB کد دریافتی در آن مرحله است، نه اندازه‌گیری سرعت مرورگر یا کاهش کل کد قابلیت‌ها. build، قرارداد graph/React مشترک و بررسی‌های کوتاه Inspector/preview پاس شدند. رندر read-only وردپرس مشترک برای هدر/فوتر، یک نسخه از هر stylesheet، دو CSS پایه، نبود script در iframe و حفظ done را تأیید کرد. مرورگر، Network و ذخیره/Undo در این تغییر اجرا نشدند. نسخه 1.1.1 ثابت است.

## DOM کمینه و اندازهٔ لوگو — ۲۰۲۶-۱۰-۲۷

طبق [استاندارد ارسالی مالک](markup-css.md)، تصویر/لوگو دیگر div داخلی مخصوص presentation ندارد؛ class و custom propertyهای visual با همان item واکنش‌گرا ادغام می‌شوند. marker انتخاب/drag، رنگ، فونت، شناسه‌ها و اندازه‌های چهار دستگاه محفوظ‌اند. در fixture دو‌عنصری، divهای ردیف/چیدمان/دو item از ۶ به ۴ کاهش یافتند. دو لایهٔ ردیف و columns برای زمینه/فاصلهٔ تمام‌عرض و محتوای محدود به عرض سایت باقی‌اند؛ wrapperهای لازم GSAP و خود Elementor به‌صورت کور حذف نشدند. این renderer در هدر/فوتر رادمان برای صفحات PHP و Elementor مشترک است؛ بازنویسی DOM داخلی همهٔ ویجت‌های Elementor ادعا نمی‌شود.

تصویر لوگو display:block دارد تا baseline متن ارتفاع اضافی نسازد. سقف ارتفاع دلخواه حفظ است ولی مقدار صفر به معنی نسبت طبیعی تصویر است، نه سقف پنهان ۴rem. picture فقط در صورت source اختصاصی دستگاه ساخته می‌شود؛ ابعاد ذاتی، sizes/srcset و بارگذاری مناسب هدر/فوتر در [رسانه](media.md) محفوظ‌اند.

اندازهٔ لوگو با سهم عنصر در Flex یکی نیست. width=auto مقدار customWidth ذخیره‌شده را فعال نمی‌کند و درصد غیرفعال دیگر در style چاپ نمی‌شود؛ دادهٔ تنظیمات حفظ است. قاعدهٔ دسکتاپ custom که زیر قاعدهٔ عمومی item پوشانده می‌شد اصلاح شد. دو declaration تکراری ستون و دکمه ادغام و چهار selector مربوط به wrapper داخلی حذف‌شده پاک شدند. selector جدید !important ندارد و منابع frontend/admin همچنان جدا هستند.

ساخت، ۴۱ قرارداد کوتاه JS/asset، قراردادهای PHP visual/appearance/responsive/grid/nested و lint چهار فایل PHP پاس شدند. تأیید بصری میزبان، حالت‌های RTL/LTR و نصب واقعی Elementor در این تغییر اجرا نشد؛ عدد کاهش DOM فقط برای fixture گفته‌شده است. نسخه و ZIP تغییر نکردند.

## شروع هدر چسبان پس از بخش اول — ۲۰۲۶-۱۰-۲۷

انتخاب stickyStart=immediate|after-first-section به تنظیم هدر افزوده شد؛ پیش‌فرض و دادهٔ قدیمی immediate است و کنترل فقط با sticky فعال دیده می‌شود. انتخاب پس از بخش اول مطابق `liquid-template-tags.php::stickyTrigger=first-section` هاب است: هدر ابتدا طبیعی اسکرول می‌شود، پس از پایان اولین section محتوای اصلی ثابت و با برگشت بالا آزاد می‌شود. اولین section در PHP/Gutenberg یا کانتینر مستقیم صفحهٔ Elementor/Atomic شناخته می‌شود؛ در نبود بخش معتبر به رفتار قبلی برمی‌گردد. شناسایی DOM خاص Template مشتری نیاز به قرارداد section واقعی دارد، نه حدس ارتفاع viewport.

ماژول کوچک sticky-header تنها با data attribute همان انتخاب import می‌شود؛ RAF/ResizeObserver و placeholder همان هدر را نگه می‌دارند، clone یا موتور دوم GSAP/ScrollTrigger ندارد. دسکتاپ/همهٔ دستگاه‌ها، admin-bar و هدر شفاف حفظ‌اند؛ تشخیص وضعیت بدون انیمیشن GSAP دریافت نمی‌کند. در مرورگر محلی پیش از مرز position=relative و پس از مرز position=fixed/top=32px تأیید شد؛ این پذیرش محدود صفحهٔ دو section است و تمام Templateهای ثالث را پوشش نمی‌دهد. [فاصلهٔ منو](navigation.md)، [تصویر/لوگو](media.md) و [رنگ و چیدمان پنل](admin-ui.md) مالک مستقل دارند.

## بازبینی یکپارچهٔ فیلدها و کد مدیریت — ۲۰۲۶-۱۰-۲۷

مالک درخواست کرد پنل‌ها یک‌جا از نظر فیلد تکراری، ماژولار بودن و استفادهٔ آسان بررسی شوند. منبع هر تنظیم حفظ شد و انتخاب دستگاه بالای inspector مبناست: منوی اصلی فقط در نمای غیرموبایل، فهرست/حالت موبایل فقط در موبایل و کلید پنل فقط برای دستگاه جاری دیده می‌شوند. ویرایش drawerDevices اعضای سایر دستگاه‌ها را نگه می‌دارد؛ تنظیمات پنل فقط وقتی همان دستگاه پنل دارد نمایش دارند. مقادیر مخفی‌شده پاک یا reset نمی‌شوند. ظاهر منو یک Select بومی فشرده است؛ گروه دکمه‌های بلند چندردیفه حذف شد.

CSSهای بدون مصرفِ عرض/فعال‌سازی toolbar و قاب‌های properties/library قبلی پس از جست‌وجوی مصرف در JS/PHP حذف شدند. فایل‌ها همچنان فقط مدیریت‌اند و frontend به این helperها وابسته نیست. قراردادهای کوتاه حفظ تنظیمات بین دستگاه‌ها، شرط عرض پنل، حذف فیلد بی‌اثر، انتخابگر مشترک و schema واقعی Classic/Atomic پاس شدند؛ ظاهر و لمس نصب تازه هنوز پذیرش نشده است.

## عناصر خالی و ساده‌سازی inspector — اصلاح تصویر مالک، ۲۰۲۶-۱۰-۲۷

دکمهٔ تازه قبلاً text خالی داشت و renderer عمومی عمداً دکمهٔ بدون نام را حذف می‌کرد؛ wrapper متناسب با محتوا در preview هم عرض صفر می‌گرفت. اکنون دکمهٔ تازه با عنوان ترجمه‌شدهٔ «دکمه» و URL خالی شروع می‌شود؛ URL خالی همچنان لینک جعلی یا کلیک ناخواسته نمی‌سازد. برای هر عنصر با خروجی خالی، renderer فقط در preview جای‌نگهدار «برای افزودن محتوا انتخاب کنید» می‌دهد تا انتخاب/کشیدن/اندازه‌گیری ممکن باشد. محتوای ذخیره‌شدهٔ قدیمی تغییر نمی‌کند و placeholder به سایت عمومی نمی‌رود. مخفی‌سازی صریح دستگاه همچنان رعایت می‌شود.

متن دکمه ورودی تک‌خطی و همراه لینک بالای تب محتواست؛ newTab فقط همان‌جا قرار دارد. طبق اصلاح بعدی تصویر مالک، اندازه/جایگاه عنصر مستقیم و بدون details/summary است: `builder-item-layout.js` دو ردیف فشردهٔ تراز و عرض را با ChoiceControl آیکونی مشترک می‌سازد؛ label/tooltip گزینه‌ها حفظ‌اند و آیکون ابتدا/انتها با RTL/LTR هماهنگ است. چهار حالت عرض در یک ردیف می‌مانند و ورودی درصدی فقط هنگام custom یا ارث‌بری custom دیده می‌شود. CSS فقط inspector مدیریت را هدف می‌گیرد؛ در پنل باریک اندازهٔ دکمه‌ها کمتر می‌شود. انتخاب دستگاه/ذخیره‌سازی/رفتار عرض عوض نشده است. الگوی کنترل از Group_Control_Flex_Item نسخهٔ ارسالی Elementor بررسی شد؛ CSS یا runtime آن وارد نشده است. کنترل چیدمان کانتینر اصلی و فرزندان گروه همچنان مستقیم‌اند. عنوان تکراری دستگاه و توضیح تکراری لوگو در VisualFields حذف شدند. گزینه‌های جداگانهٔ جهت و legacy stack/inline یکی شدند؛ دادهٔ قدیمی stack در کنترل جهت به‌صورت ستونی دیده می‌شود و ویرایش جهت دستگاه، override قدیمی متضاد را inline می‌کند. PHP/CSS قدیمی برای سازگاری خواندن باقی‌اند؛ موتور جدیدی ساخته نشده است. Build و قراردادهای کوتاه موفق‌اند؛ ظاهر نصب جدید هنوز پذیرش نشده است.

## اصلاح کشیدن با ماوس پس از گزارش نصب 0.1.61

مسیر قدیمی Pointer فقط برای لمس فعال بود و ماوس به HTML5 drag روی دکمهٔ کوچک وابسته بود؛ بررسی‌های منطق قبلی، کارکرد واقعی آن مسیر را اثبات نمی‌کردند. اکنون `builder-pointer-drag.js` با Pointer Capture مسیر مشترک mouse/touch/pen است؛ دکمهٔ عنصر روی بوم، کارت کتابخانه، نام عنصر در Navigator و دستگیره همگی همان bind را دارند. Drag بومی هم‌زمان غیرفعال است. آستانهٔ ۵px کلیک را از کشیدن جدا می‌کند؛ Escape، pointercancel، از دست‌رفتن capture، blur و unmount لغو می‌کنند. رهاکردن فقط یک mutation/history commit می‌سازد و کلیکِ پس از کشیدن مهار می‌شود. این ماژول پس از شروع سازنده به‌صورت async می‌آید و وارد صفحهٔ عمومی نمی‌شود.

هنگام کشیدن، نام عنصر کنار نشانگر، خط درج سمت درست RTL/LTR و قاب دریافتِ گروه خالی دیده می‌شوند؛ در ساختار نیز خط پیش از عنصر مقصد مشخص است. ناحیهٔ افزودن کانتینر مقصد drop است؛ انتقال عنصر موجود به آن، کانتینر جدید را با همان ID عنصر در یک تغییر تاریخچه می‌سازد. «انتقال به ابتدای گروه» نیز در ابزار عنصر منتخب، مسیر کلیکی کمکی دارد. الگوی تعامل از راهنمای رسمی [Elementor](https://elementor.com/help/how-to-move-sections-in-elementor/) و [ناحیه‌های دریافت هدر](https://xtemos.com/docs-topic/header-rows-and-columns/) بررسی شد؛ چارچوب آن‌ها وارد نشده است.

workspace مدیریت به محدودهٔ viewport زیر admin bar و کنار منوی باز/جمع‌شدهٔ وردپرس مقید است؛ اسکرول در بوم/inspector باقی می‌ماند و toolbar با اسکرول صفحه زیر نوار وردپرس نمی‌رود. این تغییر روی هدر سایت یا sticky عمومی اثر ندارد. قرارداد رویدادها انتقال پنل از جای سوم به ابتدای همان گروه در RTL برای mouse/touch/pen را بدون dragstart شبیه‌سازی می‌کند؛ این شاهد جای کشیدن واقعی مرورگر نیست. پذیرش UI/ماوس/لمس روی نصب اصلاح‌شده باز است؛ ZIP 0.1.61 شامل این اصلاح بعدی نیست.

**اصلاح نوار پیش‌نمایش طبق تصویر مالک:** عدد ۱۴۴۰ و slider عرض صرفاً اندازهٔ viewport موقت بودند و در layout ذخیره نمی‌شدند؛ برای رفع ابهام هر دو از toolbar حذف شدند. چهار دکمهٔ دستگاه همچنان viewport را عوض می‌کنند و RTL/LTR باقی است. عرض واقعی و کناره‌ها از تنظیمات سایت/چیدمان موجود خوانده می‌شوند؛ schema و دادهٔ ذخیره‌شده تغییر نکردند.

طبق اصلاح [مالک رفتار](../scenarios/header-footer.md)، «ردیف» در رابط کانتینر نام دارد؛ schema نسخهٔ ۱ و IDهای قبلی حفظ شدند. اکنون عنصر `container` با `items` و `layout`، گروه داخلی واقعی است؛ `appearance` عرض/جایگاه خود گروه در والد و `layout` چیدمان فرزندان را مالک‌اند. ۸ کانتینر اصلی، ۶ فرزند در هر کانتینر، حداکثر دو سطح گروه داخلی و ۹۶ شناسهٔ کل حفظ می‌شوند. PHP و JS حدود عمق/تعداد و منع انتقال گروه داخل خودش یا زیرگروهش را بررسی می‌کنند. افزودن روی بوم انتخاب Flex/Grid دارد؛ گروه جدید افقی بدون شکستن خط و عناصر تصویری/دکمهٔ جدید متناسب با محتوا شروع می‌شوند. جهت چهار دستگاه، تراز/پخش، فاصله و ستون‌ها در تب محتوا قرار دارند. دادهٔ قدیمی به گروه تبدیل یا بازنویسی خودکار نمی‌شود.

`builder-tree.js` مالک پیمایش/ویرایش immutable و `builder/tree.php` مالک پیمایش PHP برای asset و رشته‌های ترجمه‌اند. drag/drop بوم و Navigator، انتخاب، انتقال، تکثیر با IDهای تازه، حذف و Undo/Redo همین درخت را مصرف می‌کنند. CSS و renderer گروه از همان موتور Flex/Grid استفاده می‌کنند؛ موتور frontend یا وابستگی تازه ندارند. کانتینر خالی فقط در preview فضای دریافت drop دارد و در سایت خروجی خالی تولید نمی‌کند. nesting نامحدود و برابری کامل Elementor ادعا نمی‌شود.

عرض `custom` با `customWidth` درصدی ۵–۱۰۰ و overrideهای laptop/tablet/mobile اضافه شد؛ دستگیرهٔ انتخاب‌شده در بوم راهنمای اندازه را حین کشیدن نشان می‌دهد و فقط در رهاکردن یک تغییر تاریخچه ثبت می‌کند. مقدار عددی در «اندازه و جایگاه» هم قابل ویرایش است. scale قاب، جهت RTL/LTR، لغو حرکت و تنظیم با کلیدهای جهت/Home/End پوشش دارند. Grid ستون‌های responsive قبلی را نگه می‌دارد؛ دستگیرهٔ عرض در Grid نمایش ندارد. عرض کلی سایت همچنان خارج سازنده است.

فعال‌سازی هر طرح، عرض و فاصلهٔ کنارهٔ چهار دستگاه در بخش عمومی تنظیمات خود سازنده قرار دارند؛ شفافیت و رفتار چسبان نیز متعلق به همان طرح‌اند. بخش lazy «هدر و فوتر» در تنظیمات قالب فقط طرح ذخیره‌شدهٔ سایت/زبان را انتخاب می‌کند و layout/revision را ویرایش نمی‌کند. ویرایشگر برگه فقط انتخاب طرح، ارث‌بری یا مخفی‌سازی دارد. ذخیرهٔ خود طرح از API و revision موجود استفاده می‌کند؛ overwrite بدون revision نداریم. داده و renderer تغییر نکرده‌اند و `createBuilderRequest(config)` transport مشترک مدیریت باقی می‌ماند.

ترجمه‌های WPML در گروه جمع‌شوندهٔ مشخص در کتابخانه باقی‌اند؛ کنترل مبهم تخصیص زبان از سازنده حذف و به تنظیمات سایت رفت. toast پایین، قابل‌بستن و پیام موفقیت زمان‌دار است؛ خطا خودکار محو نمی‌شود. toolbar و تب‌ها جمع‌وجورتر و توضیحات دائمی غیرضروری حذف شدند. پنل renderer تنظیمات نیز lazy شد تا ورودی مدیریت زیر بودجهٔ قبلی بماند. بررسی‌های کوتاه PHP/JS و WPML شبیه‌سازی‌شده موفق‌اند؛ ظاهر تصویر جدید، drag واقعی، ذخیره/Undo و WPML واقعی هنوز پذیرش نشده‌اند. نسخه/ZIP تغییر نکردند.

ادامهٔ سورس ۲۰۲۶-۱۰-۲۶: نوع مستقل `panel` به whitelist و schema نسخهٔ ۱ اضافه شد؛ دادهٔ قبلی مهاجرت نمی‌شود. defaults آن بدنهٔ خالی است و inspector همان کنترل‌های مشترک منبع محتوا، Template/بلوک، layout و motion را مصرف می‌کند. محتوای داخلی از سازنده تحمیل نمی‌شود؛ renderer و دارایی مشترک در [مالک پنل](navigation.md) هستند. انتخاب Template در پیش‌نمایش inert سازنده به معنی پذیرش چرخهٔ واقعی ذخیره/بازکردن Elementor نیست.

## اتصال بومی WPML — Theme 0.1.49

ماژول اختیاری `inc/integrations/wpml.php` فقط با WPML بارگذاری می‌شود؛ resolver عمومی در `wpml/builder.php` و عملیات/فهرست زبان‌های مدیریت در `wpml/admin-builder.php` جدا هستند. storage گزینه‌ای و شناسه‌های قدیمی چیدمان عوض نشده‌اند. فقط هنگام افزودن/اتصال ترجمه، reference بومی مخفی `rdct_layout` ساخته می‌شود؛ ارتباط زبان‌ها با گروه native WPML است، نه جدول ترجمهٔ دوم یا برگهٔ عمومی خالی. index غیرautoload `radman_builder_wpml` شناسهٔ چیدمان را به reference نگاشت می‌کند. نوع مخفی در داشبورد کارهای ترجمه نمایش داده نمی‌شود؛ عنوان reference نباید به‌جای JSON سازنده وارد ATE شود.

رابط `builder-translations.js` از کنار همان چیدمان، ایجاد نسخهٔ مستقل، اتصال چیدمان ذخیره‌شدهٔ موجود و بازکردن نسخهٔ متصل را فراهم می‌کند. ذخیرهٔ تغییرات قبل از اتصال لازم است. نسخهٔ تازه از محتوای ذخیره‌شده کپی و غیرفعال ساخته می‌شود؛ مدیر پس از ویرایش و ذخیره آن را فعال می‌کند. اتصال نسخهٔ موجود payload آن را بازنویسی نمی‌کند. مجوز `edit_theme_options`، POST/nonce، revision و قفل CAS موقت برای عملیات هم‌زمان برقرارند؛ اتصال نسخهٔ متعلق به گروه دیگر رد می‌شود. انتخاب زبان مبدأ بعد از اتصال قفل است؛ رابط قطع اتصال/تغییر گروه فعلاً ساخته نشده است.

انتخاب سراسری/برگه پس از تعیین چیدمان از `wpml_object_id` برای همان reference به زبان جاری نگاشت می‌شود؛ ترجمهٔ ناموجود یا غیرفعال همان fallback انتخاب‌شده را نگه می‌دارد. همهٔ چیدمان‌ها/زبان‌ها در فرانت رندر نمی‌شوند. متن نسخهٔ مستقل دوباره از String Translation عبور نمی‌کند؛ رشته‌های ثبت‌شده، زبان مبدأ همان نسخه را می‌گیرند. preview با زبان reference اجرا و در finally زبان قبلی را بازیابی می‌کند؛ طبق اصلاح ۲۰۲۶-۱۰-۲۹ جهت preview از همان زبان می‌آید و کلید تغییر دستی نوار بالا حذف شده است. فهرست زبان‌های مدیریت محلی و cache همان درخواست است؛ درخواست جداگانه برای دریافت فهرست زبان‌ها/جستجو اضافه نشده است.

حذف چیدمان index خودش را پاک می‌کند، نه ترجمه‌های دیگر را. reference مخفی باقی می‌ماند و هنگام ایجاد دوبارهٔ همان زبان، فقط اگر payload قبلی واقعاً حذف شده باشد قابل استفادهٔ مجدد است؛ حذف آبشاری گروه WPML انجام نمی‌شود. نبود WPML عملیات ترجمه و خواندن index عمومی را فعال نمی‌کند. sync دو meta انتخاب هدر/فوتر در `wpml-config.xml` از نوع copy-once است؛ نسخه‌های مستقل بعداً قابل تغییرند. این bridge ترجمهٔ خودکار JSON گزینه‌ها در ATE نیست.

Hookها با سورس WPML ارسالی 5.0.2 و مستند رسمی [نوشتن زبان](https://wpml.org/wpml-hook/wpml_set_element_language_details/)، [خواندن زبان](https://wpml.org/wpml-hook/wpml_element_language_details/) و [گروه ترجمه](https://wpml.org/wpml-hook/wpml_get_element_translations/) تطبیق داده شدند: نوع در hook نوشتن/گروه `post_rdct_layout` و در خواندن جزئیات `rdct_layout` است. الگوی نگاشت شناسه از هدر/فوتر Hub بررسی شد؛ کد/فریم‌ورک آن منتقل نشد. قرارداد mock اتصال، استقلال، فعال‌سازی، اتصال موجود، بازگشت زبان preview، مجوز/revision و حالت بدون WPML پاس شد؛ نصب واقعی WPML، رابط مرورگر، کش چندزبانه و پذیرش عملی هنوز بازند.

## تناسب پیش‌نمایش و تراز محتوا — ۲۰۲۶-۱۰-۲۰

عنصر سازنده ظرف Flex عمودی با align-items و text-align هماهنگ دارد؛ لوگو/دکمه و متن از تراز واقعی محتوا پیروی می‌کنند و لینک‌های اجتماعی justify-content هماهنگ دارند. override لپ‌تاپ/تبلت/موبایل با `--builder-content-align` به فرزند می‌رسد. توزیع ردیف با تراز محتوای هر ستون متفاوت است: ستون equal سهم برابر می‌گیرد؛ برای گروه فشرده از auto استفاده می‌شود. عرض ذخیره‌شدهٔ ستون‌ها خودکار تغییر نمی‌کند. پذیرش بصری مرورگر هنوز انجام نشده است.

وضعیت در ۲۰۲۶-۱۰-۱۸: ویرایشگر، کتابخانهٔ چیدمان، تخصیص، ذخیره و پیش‌نمایش PHP ساخته شده‌اند. بررسی کوتاه WordPress/PHP/DB پاس شده؛ تجربهٔ بصری مرورگر، دستگاه لمسی و WPML واقعی هنوز تأیید نشده‌اند. نیاز محصول در [سناریو](../scenarios/header-footer.md) و محتوای مشترک در [بلوک‌ها](../scenarios/reusable-blocks.md) است.

## داده و ذخیره

هر سازنده یک چیدمان اصلی و حداکثر ۱۲ چیدمان نام‌دار اضافه دارد. دادهٔ اصلی در `radman_builder_header` و `radman_builder_footer` حفظ شده؛ چیدمان نام‌دار با پسوند شناسهٔ تولیدشدهٔ سرور ذخیره می‌شود. index کوچک `radman_builder_library` فقط در مدیریت مصرف می‌شود. optionهای چیدمان و index با autoload خاموش ساخته می‌شوند؛ flag سبک در theme mods مانع خواندن دادهٔ سازندهٔ غیرفعال است. سایت عمومی فهرست همهٔ چیدمان‌ها یا بلوک‌ها را query نمی‌کند.

schema نسخهٔ ۱ شامل enabled، rows و items است؛ حداکثر ۸ کانتینر اصلی و ۶ فرزند در هر کانتینر؛ nesting محدود طبق بخش بالا است. عناصر فعلی container/logo/image/menu/panel/text/button/block/search/copyright/icon/contact/social هستند. انتخاب تصویر و لوگوی واکنش‌گرا از [موتور رسانه](media.md) می‌آید. منو از جایگاه primary/footer یا یک فهرست منتخب استفاده می‌کند؛ شناسهٔ منوی ناموجود به منوی تصادفی دیگری fallback نمی‌کند. جستجو از فرم استاندارد وردپرس با ID یکتا و کپی‌رایت از سال/نام سایت استفاده می‌کند. block فقط ارجاع به منبع مجاز native است؛ [قرارداد بلوک مشترک](content-blocks.md).

### عناصر تماس، آیکون و شبکهٔ اجتماعی — ۲۰۲۶-۱۰-۱۹

**پیاده‌سازی‌شده:** عنصر `icon` از فهرست SVG محلی، عنوان دسترس‌پذیر و لینک اختیاری استفاده می‌کند. `contact` متن همراه آیکون اختیاری دارد؛ برای متن تلفن/ایمیل می‌توان جهت auto/RTL/LTR انتخاب کرد. تلفن و ایمیل با `tel:` و `mailto:` نمایش داده می‌شوند؛ هیچ درخواست شبکه‌ای برای نمایش ایجاد نمی‌شود. هر دو عنصر نشانی داخلی، fragment و HTTP/HTTPS نیز می‌پذیرند. لینک بدون عنوان رد می‌شود.

عنصر `social` حداکثر ۸ لینک پروفایل با عنوان، نشانی HTTP/HTTPS، مسیر داخلی یا fragment و آیکون اختیاری دارد؛ `#` نیز برای لینک موقت طراحی مجاز است. این قابلیت اشتراک‌گذاری خودکار یا اتصال به API شبکه‌ها نیست. طول عنوان هر پروفایل حداکثر ۵۰۰ بایت، عنوان تماس/آیکون ۲۰۰۰ بایت، URL حداکثر ۲۰۴۸ بایت و اندازهٔ آیکون ۸ تا ۶۴ پیکسل است. URL اجرایی، protocol-relative و تکرار شناسه رد می‌شوند. حذف فایل آیکون، متن تماس/پروفایل را حذف نمی‌کند؛ عنصر صرفاً آیکونی ناموجود، لینک خالی نمی‌سازد.

اعتبارسنجی و renderer در `radmanct/inc/builder/elements.php` فقط برای این انواع بارگذاری می‌شوند. CSS مستقل `src/css/components/builder-links.css` فقط با مصرف این عناصر enqueue می‌شود؛ CSS آیکون نیز فقط با نام موجود در کاتالوگ اضافه می‌شود. خروجی عمومی PHP و inline SVG است و JS جدیدی ندارد. کنترل‌های تکرارشونده در `builder-linked-fields.js` همراه inspector تنبل مدیریت هستند؛ ساخت/تکثیر داده در `builder-elements.js` از رابط جداست.

عنوان و URL هر پروفایل با کلید `link-{link-id}-text/url` زیر شناسهٔ عنصر در WPML ثبت می‌شوند. جابه‌جایی لینک، کلید را تغییر نمی‌دهد؛ تکثیر عنصر یا ردیف، شناسه‌های داخلی تازه می‌سازد. hook ترجمه با خروجی escape‌شده مصرف می‌شود؛ بررسی واقعی افزونهٔ WPML و تجربهٔ بصری هنوز باقی است. الگوی محدود تفکیک عنصر/تنظیمات از `themes/woodmart/inc/modules/header-builder/elements/class-social.php` و `class-infobox.php` بررسی شد؛ چارچوب share/follow و وابستگی‌های آن منتقل نشدند.

متن plain text است؛ اجرای HTML/PHP/JS دلخواه نداریم. URL فقط http/https/mailto/tel، مسیر داخلی یا fragment می‌پذیرد. شناسه‌ها یکتا و پایدارند؛ فیلد ناشناخته حذف و schema/نوع نامعتبر رد می‌شود. دادهٔ قدیمی appearance پیش‌فرض می‌گیرد. CSS/JS آزاد ذخیره نمی‌شود.

ذخیرهٔ اصلی از AJAX احرازشدهٔ WordPress با POST، مجوز `edit_theme_options`، nonce، سقف ۲۵۶ KiB، عمق JSON محدود و validator مشترک انجام می‌شود. تغییر چیدمان با compare-and-swap روی مقدار serialized option در SQL ذخیره می‌شود؛ دو ذخیره با revision یکسان نمی‌توانند هر دو موفق شوند. گزینهٔ جدید با add_option و کلید یکتا ایجاد می‌شود. مسیر قدیمی admin-post نیز همین مالک ذخیره‌سازی را مصرف می‌کند. این تضمین مربوط به دادهٔ هر چیدمان است؛ تخصیص‌ها و theme mods تراکنش مشترک چندجدولی ندارند.

خطا، انقضای نشست یا conflict، state و تغییرات ذخیره‌نشدهٔ ویرایشگر را پاک نمی‌کند. هنگام درخواست ذخیره/تعویض چیدمان، کنترل‌های ویرایش قفل موقت دارند. پس از موفقیت، دادهٔ canonical سرور و revision تازه مبنا می‌شوند. آدرس پنل شناسهٔ چیدمان باز را حفظ می‌کند تا Reload به چیدمان اصلی برنگردد. حذف چیدمان اصلی یا چیدمان دارای تخصیص سایت/زبان/برگه رد می‌شود.

## مدیریت و تجربهٔ ویرایش

### حذف فضای خالی خروجی — ۲۰۲۶-۱۰-۲۰

رندر جزئیات عنصر/ردیف در `inc/builder/rendering.php` از schema و مدیریت سازنده جدا شد. متن/دکمهٔ خالی، بلوک بدون خروجی و منوی حذف‌شده یا بدون خروجی، در سایت ستون خالی نمی‌سازند؛ ردیف بدون خروجی نیز padding ندارد. wrapper کاملاً خالی هدر/فوتر نمایش داده نمی‌شود. محتوای عنصر یک بار رندر می‌شود و fragment بلوک مشترک همان cache قبلی را مصرف می‌کند.

`Responsive::collapse` مخفی‌سازی ردیف را از اجزای باقی‌مانده برای هر چهار دستگاه محاسبه می‌کند؛ وقتی همهٔ اجزا در یک دستگاه مخفی باشند، خود ردیف نیز مخفی می‌شود. visibility قدیمی و hiddenDevices جدید با هم رعایت می‌شوند و انتخاب صریح ردیف حفظ است؛ این محاسبه فقط خروجی است و دادهٔ ذخیره‌شده را بازنویسی نمی‌کند. در preview، عنصر بی‌محتوا و ردیف تازهٔ خالی، marker انتخاب/Drop خود را حفظ می‌کنند. پس از افزودن محتوای قابل‌نمایش، ردیف دوباره مطابق تنظیمات خودش دیده می‌شود.

الگوی محدود بررسی خالی‌بودن ردیف در `themes/woodmart/inc/modules/header-builder/class-frontend.php` خوانده شد؛ موتور مرجع وارد نشد. قراردادهای کوتاه منو و responsive، خروجی منوهای مستقل، حفظ تراز/عرض، مخفی‌سازی مشتق‌شده و Drop ردیف خالی را پوشش می‌دهند؛ مرورگر و لمس واقعی هنوز شواهد جدا می‌خواهند.

### بازیابی پشتیبان و سازگاری نام قبلی — ۲۰۲۶-۱۰-۲۰

**وضعیت نسخهٔ پایه: پیاده‌سازی این بخش تکمیل شد؛ پذیرش مرورگر باقی است.** دامنه شامل دریافت فایل JSON و بازیابی همان سایت/همان سازنده، تغییرات ذخیره‌نشده، تأیید جایگزینی، Undo/Redo، پیام/لغو، خطا و حفظ مدل فعلی است. انتقال بین سایت‌ها و remap محتوا همچنان خارج از این نسخه‌اند.

رابط کتابخانه مراحل خواندن و بررسی را با live status فارسی/انگلیسی نشان می‌دهد؛ کاربر می‌تواند بازیابی را لغو یا فایل دیگری انتخاب کند. لغو صریح، focus را به دکمهٔ بازیابی برمی‌گرداند. خطا در خود بخش با role=alert نمایش داده می‌شود و پس از عملیات جدید/موفق باقی نمی‌ماند. context دارای revision قدیمی یا عملیات مدیریت، وضعیت قبلی را نمایش نمی‌دهد؛ unmount بی‌صدا لغو می‌کند. hint محدودیت حجم/سایت و نیاز به ذخیره همیشه حاضر است.

خروجی draft جاری با JSON فشرده ساخته می‌شود تا فاصله‌گذاری فایل را بی‌دلیل از سقف ۲۵۶ KiB عبور ندهد؛ اندازهٔ واقعی Blob نیز قبل از دانلود کنترل می‌شود. خروجی بزرگ یا دانلود ناموفق پیام روشن دارد. anchor موقت در موفقیت/شکست حذف و Blob URL آزاد می‌شود؛ هیچ آپلود، تغییر مسیر یا ذخیرهٔ خودکار رخ نمی‌دهد. فرمت خروجی با reader همان بخش round-trip بررسی می‌شود. برای نسخهٔ موجود روی سرور باید فایل‌های PHP و dist همین نسخه با هم نصب شوند.

خواندن فایل و چرخهٔ درخواست بازیابی در `src/js/admin/builder-backup.js` از رابط کتابخانه جدا شدند. خروجی جدید فرمت `rdct-builder` دارد؛ ورودی قدیمی `radman-builder` نیز پذیرفته می‌شود، با همان محدودیت نسخهٔ ۱، نوع header/footer، origin دقیق همان سایت و سقف ۲۵۶ KiB. این سازگاری مجوز انتقال بین سایت‌ها یا مصرف دادهٔ قالب‌های مرجع نیست. validator نهایی PHP همچنان از درخواست احرازشدهٔ `validate` مصرف می‌شود؛ import endpoint تازه یا مسیر نوشتن خودکار ندارد.

انتخاب فایل جدید، تغییر چیدمان/داده، شروع عملیات مدیریت، بستن پنل و unmount درخواست قبلی را لغو می‌کنند. پیش و پس از خواندن فایل/پاسخ سرور و تأیید جایگزینی، token درخواست و شناسه/revision/مدل جاری کنترل می‌شوند؛ پاسخ قدیمی و خطای درخواست منقضی‌شده state یا پیام چیدمان جدید را تغییر نمی‌دهد. خطای خواندن/اعتبارسنجی مدل فعلی را نگه می‌دارد و انتخاب مجدد همان فایل ممکن است. بازیابی موفق فقط دادهٔ canonical سرور را وارد تاریخچهٔ محلی می‌کند؛ تا ذخیره منتشر نمی‌شود.

مرجع محدود، بخش import/export و پیام‌ها در `themes/woodmart/inc/modules/header-builder/class-backend.php` و مسیر ذخیرهٔ احرازشده در `class-manager.php::save_header` است؛ فقط الگوی جدایی مدیریت و اعتبارسنجی بررسی شد. چهار بررسی کوتاه `tests/builder-backup.test.mjs` فرمت قدیم/جدید، فایل بزرگ/ناقص، سایت/نوع نادرست، تأیید/انصراف، پاسخ دیررس، لغو و تلاش مجدد را می‌پوشاند. این شواهد جای پذیرش مرورگر یا انتقال بین سایت‌ها نیستند.

### تکمیل عملیات ردیف و تفکیک منطق — ۲۰۲۶-۱۰-۲۰

عملیات حرکت/تکثیر ردیف و انتقال عنصر در `src/js/admin/builder-mutations.js` از رابط React جدا شد؛ هر دو سازنده و مسیرهای drag، لمس و دکمه از همین توابع immutable استفاده می‌کنند. سقف هشت ردیف/شش عنصر و شناسه‌های پایدار انتقال حفظ‌اند؛ تکثیر، شناسهٔ ردیف/عنصر/لینک ترجمه را تازه می‌سازد. بازگشت Undo/Redo همان state قبلی را مصرف می‌کند. الگویی که پیش‌تر از backend سازندهٔ WoodMart برای جدایی مدیریت خوانده شد، دوباره فقط در همین محدوده بررسی شد؛ framework تازه‌ای وارد نشد.

ردیف انتخاب‌شده اکنون در تب پیشرفتهٔ Inspector دکمه‌های جابه‌جایی، تکثیر و حذف دارد؛ تکثیر/حذف روی ابزار ردیف فعال پیش‌نمایش هم در دسترس‌اند. حذف همان تأیید قبلی را حفظ می‌کند و دیگر به رفتن به فهرست ساختار وابسته نیست. کنترل‌های قدیمی ساختار و خروجی PHP/schema بدون تغییر باقی‌اند. `tests/builder-workspace.test.mjs` انتقال بین ردیف‌ها، سقف ظرفیت، عدم تغییر دادهٔ قبلی، هویت لینک‌های ترجمه و برگشت تاریخچه را بررسی می‌کند. مرورگر/لمس/Focus واقعی هنوز تأیید نشده‌اند.

### کنترل‌های لوگو و دکمه

لوگو همچنان از Site Identity استاندارد می‌آید؛ آپلودکننده یا منبع خارجی موازی اضافه نشده است. هر عنصر لوگو عرض ۰–۵۱۲ و حداکثر ارتفاع ۰–۲۵۶ پیکسل، مستقل برای دسکتاپ، لپ‌تاپ، تبلت و موبایل دارد. صفر دسکتاپ یعنی پیش‌فرض قبلی؛ صفر هر دستگاه دیگر یعنی ارث‌بری دسکتاپ، نه دستگاه مجاور. گسترش چهار دستگاه در ۲۰۲۶-۱۰-۲۰ با حفظ کلیدهای قبلی انجام شد؛ نبود کلید تازه نیز صفر است. تصویر با `object-fit:contain` و فضای موجود ردیف نمایش داده می‌شود؛ ابعاد native تصویر وردپرس حذف نمی‌شوند. اندازهٔ عنوان متنیِ جایگزین همچنان از appearance متن می‌آید.

دکمه سه ظاهر solid/outline/plain، رنگ accent اختیاری شش‌رقمی، گردی ۰–۶۴ پیکسل یا ارث‌بری از قالب، padding افقی ۰–۶۴ و عمودی ۰–۴۸ پیکسل دارد. صفر حفظ می‌شود؛ رشتهٔ CSS آزاد پذیرفته نیست. `newTab` فقط boolean است و لینک دارای آن `target=_blank` همراه `rel=noopener noreferrer` می‌گیرد؛ پیش‌فرض false است. رنگ صریح متن عنصر بر انتخاب ظاهر اولویت دارد. متن/URL همان مسیر escape و ترجمهٔ قبلی را مصرف می‌کنند.

validation/متغیرهای CSS در `inc/builder/visuals.php` و کنترل‌های مدیریت در `builder-visual-fields.js` هستند؛ کنترل‌ها فقط همراه Inspector بارگذاری می‌شوند. CSS همان فایل شرطی سازنده است؛ JS فرانت یا وابستگی جدیدی وجود ندارد. کنترل عرض لوگو و سه ظاهر ساده از بررسی محدود `class-logo.php` و `class-button.php` WoodMart تطبیق داده شدند؛ موتور CSS، انتخابگر تصویر موازی، حالت سه‌بعدی و چارچوب آن کپی نشده‌اند. `tests/builder-visuals-contract.php` bounds، پیش‌فرض قدیمی، صفر، رنگ امن، لینک تب تازه و خروجی عمومی/preview را پوشش می‌دهد.

### ظاهر و چیدمان موبایل — ۲۰۲۶-۱۰-۱۹

ردیف Flex مقدار `mobileLayout=stack/inline` دارد؛ دادهٔ قبلی stack را حفظ می‌کند. در حالت inline، عناصر با عرض equal کنار هم تقسیم فضا می‌کنند، auto عرض طبیعی خود را دارد و full همچنان تمام ردیف را می‌گیرد. مرز موبایل ۴۸rem و قواعد CSS منطقی‌اند. این قرارداد قبلی حفظ شده؛ کنترل چهار دستگاه و Grid طبق بخش بعد گسترش یافته است. انتخاب فهرست موبایل و sidebar در [قرارداد ناوبری](navigation.md) است.

رنگ متن مستقل `color` برای ردیف و عنصر از hex شش‌رقمی یا مقدار خالیِ ارث‌بری استفاده می‌کند. عنصر می‌تواند رنگ ردیف را override کند؛ متن دکمه فقط با رنگ صریح همان عنصر تغییر می‌کند، تا انتخاب رنگ ردیف، خوانایی دکمهٔ accent را بی‌دلیل عوض نکند. زیرمنو روی زمینهٔ سراسری خود رنگ خوانای ink دارد. انتخاب scheme روشن/تیرهٔ ردیف در `themes/woodmart/inc/modules/header-builder/elements/class-row.php` بررسی و به کنترل مستقل سبک رادمان تطبیق داده شد؛ موتور style آن کپی نشد.

عنصر `fontSize` و `mobileFontSize` با عدد صحیح ۰ تا ۹۶ پیکسل دارد؛ صفر یعنی ارث‌بری. اندازهٔ دسکتاپ در موبایل نیز ارث می‌رسد مگر override موبایل انتخاب شود. عنوان متنی سایت نیز از اندازهٔ انتخاب‌شده پیروی می‌کند؛ این گزینه اندازهٔ تصویر لوگو را تغییر نمی‌دهد. خانوادهٔ فونت، منابع محلی و ownership Elementor همچنان از تنظیمات مرکزی‌اند؛ فونت یا درخواست شبکه‌ای تازه ایجاد نشده است. مقدار CSS آزاد یا اندازهٔ رشته‌ای/منفی/بیش از سقف رد می‌شود.

کنترل‌ها در Inspector تنبل و قواعد نمایش در CSS موجود سازنده‌اند؛ JS عمومی تازه‌ای برای ظاهر اضافه نشد. `tests/builder-appearance-contract.php` پیش‌فرض ارث‌بری، رنگ امن، سقف اندازه، marker موبایل و خروجی PHP پیش‌نمایش را پوشش می‌دهد؛ اندازه/تضاد رنگ انتخابی مدیر تضمین خودکار دسترس‌پذیری نیست و ظاهر واقعی هنوز بازبینی می‌خواهد.

### عرض، تخصیص و ورودی درخواست — ۲۰۲۶-۱۰-۱۹

با درخواست مالک، پنل سازنده تمام عرض فضای موجود مدیریت شده و سقف ۱۴۰۰ پیکسل برداشته شد. انتخاب مستقل `width=full/contained/custom` برای هر چیدمان هدر/فوتر وجود دارد؛ پیش‌فرض، از جمله برای دادهٔ قدیمی، `full` است. full سقف عرض را برمی‌دارد، contained عرض سایت را مصرف می‌کند و custom سقف معتبر مستقل دارد. gutter دسکتاپ/موبایل مستقل و قابل ارث‌بری است؛ عرض عمومی و preview از یک CSS استفاده می‌کنند. عرض مقاله‌ها با این گزینه تغییر نمی‌کند؛ [قرارداد فنی چیدمان](layout.md).

کنترل تخصیص سایت/زبان مستقل از کتابخانهٔ بسته است و اکنون در پنل «تنظیمات چیدمان» قرار دارد. وضعیت از دادهٔ ذخیره‌شده محاسبه می‌شود: غیرفعال، پیش‌فرضِ انتخاب فعلی، یا فعال ولی انتخاب‌نشده؛ ارث‌بری زبان از سایت لحاظ می‌شود. تغییر ذخیره‌نشده، تخصیص را قفل می‌کند. این وضعیت ادعای نمایش در همهٔ برگه‌ها نیست؛ override برگه و Elementor Canvas در توضیح روشن شده‌اند. ذخیره یا افزودن عنصر، بی‌اجازه تخصیص را تغییر نمی‌دهد.

در درخواست AJAX، بعد از کنترل capability و پیش از بررسی native nonce، ورودی nonce غیررشته‌ای، خالی یا بیش از ۱۲۸ بایت رد می‌شود؛ operation هم allowlist صریح دارد و نوع/عملیات نامعتبر پیش از خواندن layout رد می‌شود. nonce جای capability را نگرفته است. الگوی محدود nonce در `themes/woodmart/inc/modules/header-builder/class-manager.php` و کنترل دسترسی مدیریت در `class-backend.php` بررسی شد؛ این بررسی ممیزی امنیت کل WoodMart یا Radman CT نیست. `tests/builder-api-contract.php` مرز مجوز، nonce بدشکل، GET، عملیات/شناسه نامعتبر، payload محدود و حفظ داده در revision قدیمی را پوشش می‌دهد.

### هدر چسبان پایه — ۲۰۲۶-۱۰-۱۹

تنظیم چیدمان `sticky` با سه مقدار `off`، `desktop` و `all` ساخته شد؛ پیش‌فرض و داده‌های قدیمی `off` هستند. کنترل فقط در هدرساز نمایش داده می‌شود. کل هدر منتخب سایت/زبان/برگه در جای طبیعی سند باقی می‌ماند و با CSS `position: sticky` می‌چسبد؛ تکثیر DOM، listener اسکرول، GSAP یا React عمومی برای آن نداریم. تنظیم روی فوتر و پیش‌نمایش inert اعمال نمی‌شود. نمایش رفتارش باید در سایت عمومی بررسی شود، نه iframe کوتاه سازنده.

فایل مستقل `src/css/components/sticky-header.css` فقط برای هدر فعال و منتخب با حالت چسبان enqueue می‌شود. دسکتاپ از breakpoint مشترک ۴۸rem استفاده می‌کند؛ حالت all روی موبایل هم اعمال می‌شود. زمینه از token قالب می‌آید، ردیف‌ها تنظیم رنگ خود را حفظ می‌کنند و offset نوار استاندارد مدیریت وردپرس برای بازه‌های ۳۲/۴۶ پیکسل لحاظ شده است. در چاپ رفتار چسبان خاموش است؛ جهت‌ها با CSS logical مشترک‌اند. تغییر نوار مدیریت توسط افزونه و هدر خیلی بلند در موبایل هنوز بررسی بصری نشده‌اند.

اصلاح مالک در ۲۰۲۶-۱۰-۲۷: هدر چسبان اسکرول نرم را خاموش نمی‌کند. حالت شروع فوری در smooth-header با pinReparent می‌ماند؛ «پس از بخش اول» دیگر به پین فوری fallback نمی‌کند و همان کنترل مشترک sticky-header را مصرف می‌کند. پایان اولین section/container قابل‌دید داخل main معیار است؛ در اسکرول نرم خود header فقط هنگام فعال‌شدن به body منتقل می‌شود و placeholder جای محتوا را نگه می‌دارد. cleanup همان node و inline styleهای تحت مالکیت را برمی‌گرداند. CSS خودکار sticky و زمینهٔ هدر شفاف پیش از مرز فعال نمی‌شوند. offset نوار مدیریت حفظ است.

انیمیشن مشترک GSAP ورود ۳۲۰ms با power3.out و خروج ۲۲۰ms با power2.in است؛ برگشت اسکرول هنگام گذار، tween قبلی را متوقف و از موقعیت فعلی ادامه می‌دهد. reduced motion بدون حرکت است. رویداد update خود ScrollSmoother همان کنترل را به‌روز می‌کند؛ ticker مستقل، clone و کتابخانهٔ مرجع اضافه نشدند. Hub `LiquidStickyHeader`، sentinel انتهای first-section و انتخاب firstRow قابل‌دید برای این اصلاح خوانده شدند. ساخت و ۲۹ قرارداد کوتاه JS/دارایی پاس شدند؛ بررسی مرورگری میزبان و تطابق پیکسل‌به‌پیکسل اجرا نشدند. [مالک ادغام](effects.md).

مرجع محدود تنظیمات مستقل و default در `themes/woodmart/inc/configs/header-builder-settings.php` بررسی شد؛ clone، slide، hide-on-scroll و موتور JS آن منتقل نشدند. مستندات رسمی [ScrollSmoother](https://gsap.com/docs/v3/Plugins/ScrollSmoother/) از Context7 توضیح transform روی content و محدودیت عناصر fixed را تأیید کرد؛ ادغام جاری با پین fixed و pinReparent در مالک جلوه‌ها ثبت است. شفافیت گزینهٔ مستقل زیر است؛ مخفی‌شدن هوشمند هنگام اسکرول ساخته نشده است.

### هدر شفاف، Grid و چهار دستگاه — ۲۰۲۶-۱۰-۲۰

گزینهٔ boolean مستقل `transparent` با پیش‌فرض false فقط برای هدر منتخب عمومی اعمال می‌شود؛ فوتر و preview ایزوله overlay نمی‌شوند. CSS مستقل و ماژول JS کوچک فقط با marker همان هدر بارگذاری می‌شوند. پس از اندازه‌گیری ارتفاع، margin منفی انتهای هدر محتوا را زیر آن قرار می‌دهد؛ ResizeObserver تغییر ارتفاع، از جمله صفرشدن بر اثر مخفی‌شدن ردیف‌ها، را به‌روز می‌کند. Sticky همان CSS بومی قبلی است؛ هدر چسبان پس از شروع اسکرول زمینهٔ خوانا می‌گیرد. خواندن ارتفاع در هر scroll تکرار نمی‌شود؛ RAF، cleanup و fallback resize وجود دارند و حالت Sticky خاموش listener اسکرول ندارد. clone، رفرش صفحه و دارایی خارجی اضافه نشده‌اند. رفتار واقعی روی hero، نوار مدیریت و ScrollSmoother هنوز بازبینی بصری می‌خواهد.

ردیف `rowLayout=flex/grid` دارد؛ دادهٔ قدیمی Flex می‌ماند. Grid پایه ۱–۶ ستون `minmax(0,1fr)` و موبایل ۱–۳ ستون دارد؛ gap و padding مستقل، صفر معتبر، حداقل عرض صفر و شکست متن مانع تحمیل عرض محتوای طولانی می‌شوند. عنصر full همهٔ ستون‌ها را می‌گیرد؛ auto/equal آن span را در دستگاه منتخب قابل بازنشانی می‌کنند. فهرست تازهٔ فوتر پیش‌فرض عمودی و expanded دارد؛ فهرست ذخیره‌شده تغییر اجباری نمی‌کند. ستون تودرتوی دلخواه همچنان جزو schema نیست.

چهار بازهٔ ظاهر با مبنای rem هستند: موبایل زیر ۴۸، تبلت ۴۸ تا زیر ۶۴، لپ‌تاپ ۶۴ تا زیر ۹۰ و دسکتاپ از ۹۰. لپ‌تاپ/تبلت برای تعداد ستون، gap و padding از پایه ارث می‌برند (`null`) یا override محدود دارند؛ متن ۰–۹۶ px با صفرِ ارث‌بری و عرض عنصر inherit/equal/auto/full مستقل‌اند. موبایل نیز عرض مستقل دارد و کنترل‌های فاصله/متن قبلی را حفظ می‌کند. اندازهٔ تصویر لوگو طبق بخش بالا و gutter کل چیدمان طبق [قرارداد چیدمان](layout.md) در چهار دستگاه مستقل‌اند. رنگ و نوع کلی ردیف Flex/Grid مشترک‌اند؛ این نسخه مدعی override تمام خصوصیات در چهار دستگاه نیست.

تراز ردیف/عنصر و توزیع عناصر نیز در لپ‌تاپ/تبلت/موبایل override مستقل با مقدار inherit دارند. ورودی‌ها فقط start/center/end و برای ردیف stretch یا justify=space-between می‌پذیرند؛ جهت‌های فیزیکی یا CSS آزاد پذیرفته نیستند. selectorهای scoped فقط ناحیهٔ override همان عنصر/ردیف را تغییر می‌دهند؛ تراز منوهای همان عنصر، از جمله متن منوی عمودی فوتر، هماهنگ است. در ردیف Flex، لپ‌تاپ/تبلت حالت inherit/stack/inline مستقل دارند؛ stack با Grid تک‌ستونی و inline با تقسیم عرض عناصر equal نمایش داده می‌شود. Grid ردیف از همین گزینهٔ Flex تأثیر نمی‌گیرد و عرض full/auto انتخابی عنصر حفظ می‌شود. حالت موبایل قبلی حفظ شده است.

`hiddenDevices` برای ردیف و عنصر فهرست یکتای desktop/laptop/tablet/mobile است؛ `display:none` فضای چیدمان و قابلیت فوکوس فرزندان را حذف می‌کند. visibility قدیمی حفظ می‌شود؛ اولین تغییر checkbox آن را با حفظ قصد قبلی به فهرست چهار دستگاه تبدیل می‌کند. validation و تولید attribute در `inc/builder/responsive.php`، کنترل‌ها در `builder-controls.js` و مرزها/پیش‌فرض preview در `builder-devices.js` متمرکزند. schema نسخهٔ ۱ و دادهٔ موجود سازگار می‌مانند.

Preview چهار preset با عرض ۱۴۴۰/۱۲۰۰/۹۰۰/۳۹۰ و اسلایدر عرض ۳۲۰–۲۵۶۰ px دارد؛ بوم در عرض بزرگ اسکرول می‌خورد و toolbar wrap می‌شود. عرض و دستگاه انتخابی در App مشترک‌اند: toolbar، Inspector و gutter تنظیمات چیدمان هم‌زمان همان اندازه را نشان می‌دهند؛ با تغییر تب/عنصر مقدار به دسکتاپ برنمی‌گردد. انتخاب دستگاه فقط UI است، در layout ذخیره یا وارد Undo نمی‌شود و تغییر عرض درخواست AJAX جدید ندارد. در Inspector فقط یک انتخاب‌گر دستگاه و کنترل لوگوی همان دستگاه دیده می‌شود؛ کنترل‌های مستقل ماژول برای مصرف ایزوله fallback محلی دارند. عرض دلخواه فقط اندازهٔ مشاهده است و breakpoint سفارشی ذخیره نمی‌کند. Drop از Grid، stack و full همان دستگاه و جهت RTL/LTR استفاده می‌کند؛ ترتیب داده و DOM همچنان مشترک است و تغییر مستقل ترتیب با ردیف‌های مجزا/hiddenDevices انجام می‌شود. مرز رفتار منوی موبایل و Sticky desktop همچنان ۴۸rem است؛ دستگاه ظاهر لپ‌تاپ/تبلت آن را تغییر نمی‌دهد. شواهد و محدودیت اجرای تازه در [وضعیت پیاده‌سازی](../implementation/foundation.md) ثبت می‌شوند.

ورودی‌های مستقل هدرساز، فوترساز و بلوک‌های مشترک زیر رادمان هستند. React موجود WordPress با dependency `wp-element` مصرف می‌شود؛ React دوم bundle نمی‌شود. CSS/JS مدیریت فقط در صفحهٔ سازنده و با مجوز لازم وارد می‌شوند. سرویس درخواست، کتابخانه، پیش‌نمایش، appearance و تاریخچه ماژول‌های جدا دارند؛ هیچ‌کدام وارد frontend نیستند.

Drag & Drop بومی ماوس، مسیر Pointer برای لمس/قلم با آستانهٔ حرکت و handle جدا، انتقال بین ردیف‌ها و دکمه‌های جابه‌جایی کیبورد وجود دارند. Escape/لغو اشاره‌گر وضعیت drag را پاک می‌کند؛ پس از انتقال، focus به handle عنصر منتقل‌شده برمی‌گردد. اجرای واقعی لمس/قلم و کیفیت بصری باید روی دستگاه بررسی شوند.

تکثیر ردیف/عنصر شناسهٔ تازه می‌سازد؛ Undo/Redo تا ۲۰ تغییر محلی است و پس از تغییر تازه، Redo قبلی حذف می‌شود. تغییر چیدمان یا ذخیرهٔ موفق مبنای نشست را تازه می‌کند. خروج یا تعویض با تغییر ذخیره‌نشده هشدار دارد. حذف ردیف و چیدمان تأیید می‌خواهد.

ردیف gap برابر ۰–۶۴ px، padding عمودی ۰–۱۲۰ px، رنگ hex/شفاف، تراز و توزیع عناصر دارد. عنصر تراز و عرض برابر/متناسب محتوا/تمام ردیف دارد. نمایش قدیمی همه‌جا/دسکتاپ/موبایل با کنترل مخفی‌سازی چهار دستگاه بالا سازگار است و اجرا CSS است. ستون تودرتوی دلخواه در schema این نسخه وجود ندارد. تایپوگرافی از مالک سراسری قالب می‌آید.

نسخهٔ پشتیبان JSON، kind، نسخه، نشانی سایت و layout را دارد. import فقط برای همان سایت و همان سازنده پذیرفته و دوباره سمت سرور validate می‌شود؛ ID منو و بلوک سایت دیگر بی‌صدا مصرف نمی‌شود. import فقط state ویرایشگر را عوض می‌کند، Undo دارد و تا ذخیره منتشر نمی‌شود. انتقال میان سایت‌ها و remap منو/رسانه/بلوک در این نسخه ساخته نشده است.

### فاصله‌های مستقل موبایل — ۲۰۲۶-۱۰-۱۹

ردیف‌ها دو override اختیاری `mobileGap` (۰–۶۴ px) و `mobilePadding` (۰–۱۲۰ px، فضای عمودی) دارند. مقدار `null` به معنی استفاده از مقدار دسکتاپ است؛ دادهٔ قدیمی بدون این کلیدها همان ظاهر قبلی را حفظ می‌کند. مقدار صفر یک انتخاب صریح و معتبر است. در Inspector، گزینهٔ «استفاده از فاصلهٔ دسکتاپ» کنار هر کنترل، ارث‌بری را روشن/خاموش می‌کند. خاموش‌کردن آن از مقدار فعلی دسکتاپ شروع می‌شود؛ روشن‌کردن دوباره override را حذف می‌کند.

رندر مشترک PHP فقط برای override صریح، متغیرهای CSS عددی محدود چاپ می‌کند. CSS سازنده در عرض کمتر از ۴۸rem آن‌ها را با fallback دسکتاپ مصرف می‌کند؛ دسکتاپ تغییر نمی‌کند. JS عمومی، تشخیص دستگاه سمت سرور یا stylesheet تازه‌ای اضافه نشده است. این تنظیمات برای هدر و فوتر یکسان‌اند و در preview هم از همان مسیر validate/render عبور می‌کنند. الگوی کنترل مستقل موبایل از بخش `mobile_height` ردیف WoodMart بررسی شد؛ ارتفاع ثابت و موتور style آن وارد رادمان نشدند تا ردیف با محتوای فارسی و شکستن متن رشد کند.

قرارداد `tests/builder-appearance-contract.php` ارث‌بری دادهٔ قدیمی، صفر، سقف مجاز، نوع/عدد نامعتبر، حفظ مقدار مستقل دسکتاپ و خروجی preview را بررسی می‌کند. کیفیت بصری فاصله‌ها و لمس هنوز روی مرورگر/سرور تأیید نشده‌اند.

## پیش‌نمایش

### بازیابی خطا و جلوگیری از ویرایش نمای قدیمی — ۲۰۲۶-۱۰-۲۰

چرخهٔ debounce/لغو درخواست در `builder-preview-loader.js` مستقل از رابط است؛ فقط عملیات احرازشدهٔ `preview` به AJAX محلی می‌فرستد و enabled=false تنها روی کپی payload اعمال می‌شود. لغو قبل از ارسال، تغییر چیدمان/جهت و unmount، timer و AbortController را آزاد می‌کنند؛ پاسخ دیررس حتی اگر transport لغو را نادیده بگیرد، state را عوض نمی‌کند. پاسخ خالی/نامعتبر به‌عنوان موفقیت مصرف نمی‌شود.

شناسهٔ چیدمان، جهت و JSON مدل، کلید تازگی پیش‌نمایش‌اند. تا وقتی پاسخ همان کلید آماده نشده، یا هنگام ذخیره/خطا، کادرهای انتخاب و ابزارهای جابه‌جایی/تکثیر/حذف روی خروجی قبلی نمایش داده نمی‌شوند. تصویر قبلی می‌تواند هنگام انتظار باقی بماند اما مقصد ویرایش نیست. خطا با alert و دکمهٔ «تلاش دوباره برای پیش‌نمایش» نمایش داده می‌شود؛ تلاش دوباره مدل و تاریخچه را تغییر نمی‌دهد و چیزی منتشر نمی‌کند. aria-busy وضعیت انتظار را اعلام می‌کند.

در `builder-api.js` شکل ضروری پاسخ قبل از تحویل به رابط کنترل می‌شود: preview دارای HTML غیرخالی، validate دارای layout، و عملیات مدیریت دارای id، layout/revision، فهرست نام‌ها و defaults هستند. پاسخ موفق ناقص دیگر به `setStored` نمی‌رسد؛ پیام خطای native سرور و دادهٔ فعلی ویرایشگر حفظ می‌شوند. این کنترل دفاع از state رابط است؛ validator اصلی schema و مجوز همچنان PHP است و قواعد محتوای عناصر در JS دوباره پیاده نشده‌اند.

میان‌برهای Ctrl/Command+Z، Ctrl/Command+Shift+Z و Ctrl/Command+Y از همان تاریخچهٔ بیست‌مرحله‌ای استفاده می‌کنند. تشخیص در `builder-shortcuts.js` است؛ input، textarea، select، متن قابل‌ویرایش و textbox، ترکیب Alt، IME و رویداد قبلاً مصرف‌شده مستثنا هستند تا Undo تایپ باقی بماند. در زمان عملیات مدیریت، میان‌بر تاریخچه state را عوض نمی‌کند.

`tests/builder-preview.test.mjs` لغو پیش/پس از ارسال، پاسخ دیررس، شکست/تلاش دوباره، عدم تغییر مدل، قفل نمای قدیمی و حفظ Undo متن را با mock بررسی می‌کند؛ `tests/builder-transport.test.mjs` پاسخ ناقص، خطای غیر JSON، پیام conflict و POST احرازشدهٔ محلی را می‌سنجد. این شواهد جای مرورگر، لمس یا اجرای واقعی سرور نیستند. مرجع محدود رابط/پیام وضعیت همان `themes/woodmart/inc/modules/header-builder/class-backend.php` است؛ چرخهٔ درخواست رادمان مستقل است و سورس یا وابستگی آن کپی نشده است.

ماژول React پیش‌نمایش از ورودی اصلی مدیریت جدا و به‌صورت dynamic import بارگذاری می‌شود؛ استفاده از React همان `wp-element` باقی می‌ماند. هنگام تغییر عرض موبایل/دسکتاپ، بارگیری تصویر/فونت یا تغییر محتوا، ResizeObserver اندازهٔ wrapper واقعی محتوا را دوباره می‌سنجد؛ محدودیت حداقل ۲۴۰ پیکسل حفظ است. observer، callback زمان‌بندی‌شده و listener تغییر اندازه هنگام تعویض سند/بستن preview یا unmount پاک می‌شوند. در نبود ResizeObserver، اندازه‌گیری اولیه و تغییر عرض iframe fallback هستند. نگاشت انتخاب همچنان از کادر فعلی iframe خوانده می‌شود. این تغییر script داخل iframe اجرا نمی‌کند و sandbox/inert/CSP قبلی را حفظ می‌کند. چرخهٔ setup/cleanup طبق مستند رسمی React از Context7 است؛ اجرای واقعی مرورگر هنوز بررسی نشده است.

پیش‌نمایش پس از بازکردن، تغییرات را با debounce برابر ۴۰۰ ms به مسیر احرازشده می‌فرستد. درخواست قدیمی لغو و پاسخ دیررس کنار گذاشته می‌شود. همان renderer PHP با دادهٔ validateشده استفاده می‌شود؛ option، revision و خروجی عمومی تغییر نمی‌کنند و URL عمومی draft وجود ندارد.

iframe از srcDoc، sandbox بدون اجازهٔ script و فرم، محتوای inert و CSP استفاده می‌کند؛ لینک‌ها، فرم‌ها و منوهای درون آن تعاملی نیستند. انتخاب ویرایشی از بیرون iframe طبق بخش بعد انجام می‌شود. CSS عمومی/سازندهٔ minified، فونت منتخب محلی، tokens و styles بلوک‌های native چاپ می‌شوند؛ CSS مدیریت، React، GSAP یا جلوه‌های صفحه وارد آن نمی‌شوند. کنترل چهار دستگاه، عرض دلخواه و جهت RTL/LTR از نوار اصلی و مستقل از دادهٔ چیدمان است. جهت پیش‌نمایش، ترجمهٔ خودکار متن نیست؛ متن در حال ویرایش نمایش داده می‌شود. در این مرحله رفتار منوی بازشونده یا Elementor داخل iframe آزمایش نمی‌شود.

گزارش ۲۰۲۶-۱۰-۱۹ از `prepare.js` در شاخهٔ Vue.js devtools مرورگر، تزریق hook افزونه به iframe را نشان داد. سورس رسمی [Vue Devtools v7.7.10](https://github.com/vuejs/devtools/blob/v7.7.10/packages/devtools-kit/src/core/iframe/index.ts) قاب‌های دارای `data-vue-devtools-ignore` را از تزریق کنار می‌گذارد؛ این نشانگر اکنون هنگام ساخت iframe درج می‌شود. `sandbox=allow-same-origin` و منع script/CSP حفظ شده‌اند؛ `allow-scripts` اضافه نشده است. قرارداد کوتاه وجود نشانگر و محدودیت sandbox را بررسی می‌کند؛ رفع پیام در مرورگر سرور هنوز تأیید نشده و رفتار تمام نسخه‌های افزونه تضمین نمی‌شود. پس از جایگزینی build باید صفحهٔ سازنده کامل بارگیری مجدد شود؛ iframe قدیمی ممکن است listener تزریق قبلی را نگه دارد.

### بوم و پنل کناری — ۲۰۲۶-۱۰-۱۹

با تصویر ارسالی مالک و بررسی بخش navigation/tab سورس محلی Elementor، رابط به workspace با toolbar بالا، پنل کناری منطقی و بوم بزرگ بازطراحی شد. پنل چهار ورودی عناصر، تنظیم عنصر، ساختار و تنظیمات چیدمان دارد. Inspector سه تب محتوا، استایل و پیشرفته دارد؛ بخش ساختار دیگر زیر بوم تکرار نمی‌شود. فهرست عناصر کارت‌های آیکون‌دار، جستجو و انتخاب ردیف مقصد دارد. انتخاب اولین عنصر در چیدمان خالی ردیف هم می‌سازد؛ حدود هشت ردیف/شش عنصر حفظ و ظرفیت کامل گزارش می‌شود. کنترل عرض/Sticky، تخصیص و کتابخانه در تنظیمات چیدمان قرار دارند. حالت تمام‌صفحه با حفظ overflow قبلی و خروج Escape، و میانبر Ctrl/Cmd+S برای ذخیرهٔ تغییر معتبر اضافه شدند. پس از ذخیره انتخاب حفظ می‌شود؛ تعویض چیدمان پنل عناصر را باز می‌کند.

PHP فقط در درخواست preview شناسه‌های `data-builder-preview-row/item` چاپ می‌کند؛ سایت عمومی marker ویرایشی ندارد. لایهٔ مدیریت کادرهای واقعی ردیف/عنصر را با ResizeObserver، resize قاب و آماده‌شدن فونت اندازه می‌گیرد؛ دکمهٔ انتخاب و دستگیرهٔ جابه‌جایی بیرون از iframe روی همین کادرها قرار می‌گیرند. عنصر منتخب ابزار تکثیر/حذف نیز دارد. انتخاب با کلیک و کیبورد در دسترس است. هیچ script یا handler به سند preview تزریق نمی‌شود؛ inert و منع script/form حفظ‌اند. تایپ مستقیم روی متن preview ساخته نشده است.

Drag & Drop از کارت عناصر به بوم، جابه‌جایی با دستگیرهٔ ردیف/عنصر و مسیر ساختار مشترک است. تعیین قبل/بعد عنصر در `builder-drag.js`، برای LTR/RTL و چیدمان stack موبایل جهت صحیح را مصرف می‌کند؛ index پس از حذف از همان ردیف اصلاح می‌شود تا انتقال یک خانه جابه‌جا نشود. drag بیرونی بدون state خود سازنده پذیرفته نمی‌شود؛ لمس/قلم همان resolver بوم را با آستانهٔ حرکت مصرف می‌کنند. دکمه‌های حرکت ردیف/عنصر در Navigator، و انتقال بین ردیف‌ها در بخش پیشرفتهٔ عنصر، مسیر کیبورد هستند. این منطق هنوز در مرورگر/دستگاه واقعی بررسی نشده است.

Inspector در `builder-inspector.js`، Navigator در `builder-navigator.js` و منطق انتخاب در `builder-selection.js` جدا هستند. Inspector/Navigator با اولین ورود به پنل مربوط import می‌شوند؛ React همان `wp-element` وردپرس است. تب‌ها، انتخاب رنگ/HEX/ارث‌بری و استایل آن‌ها از [اجزای مشترک مدیریت](admin-ui.md) می‌آیند؛ framework/CSS/font کامل Elementor کپی نشده است. CSS فقط صفحهٔ سازنده را پوشش می‌دهد؛ Grid با جهت مدیریت، scroll مستقل پنل/بوم و چیدمان تک‌ستونه در عرض کمتر دارد. این تغییر schema یا مهاجرت داده ندارد و به Elementor وابسته نیست. بوم همچنان پیش‌نمایش PHP با debounce/لغو درخواست قدیمی است، نه موتور frontend موازی.

بررسی انتخاب پس از جابه‌جایی/حذف/چیدمان خالی و اولویت hit-test و ندیدن عنصر مخفی با آزمون محدود پاس شد. قرارداد PHP حضور marker فقط در preview را بررسی کرد؛ بررسی واقعی کوتاه `tools/qa-builder.ps1` برای ذخیره/SQL CAS/تخصیص/پیش‌نمایش و مجوز نیز پاس شد. این‌ها اجرای واقعی رابط React، اندازه‌گیری کادرها در مرورگر، لمس، کیفیت بصری یا WPML واقعی را تأیید نمی‌کنند.

## تخصیص و خروجی عمومی

### منوی چندسطحی — ۲۰۲۶-۱۰-۱۹

منوی هدر ساده و عنصر منوی هر دو سازنده، کنترل مستقل زیرمنو با Vanilla JS دارند. لینک والد تغییر نمی‌کند؛ دکمهٔ جدا با عنوان ترجمه‌پذیر، `aria-controls` یکتا و `aria-expanded` کنار آن ساخته می‌شود. زیرمنو در موبایل و دسکتاپ با همان دکمه کار می‌کند؛ زیرمنوی هم‌سطح قبلی بسته می‌شود. Escape ابتدا زیرمنوی جاری را می‌بندد و focus را به دکمهٔ آن برمی‌گرداند؛ Escape بعدی منوی موبایل را می‌بندد. خروج focus، کلیک بیرون و تغییر breakpoint وضعیت باز را پاک می‌کنند. انتخاب عادی لینک در موبایل منو را می‌بندد؛ کلیک دارای modifier، download و `_blank` بی‌دلیل وضعیت را تغییر نمی‌دهند.

بدون JS هیچ لینک یا زیرمنویی از HTML حذف نمی‌شود؛ در موبایل زیرمنوها قابل مشاهده‌اند و در دسکتاپ fallback قبلی hover/focus حفظ است. با JS تعامل بازکردن زیرمنو صریحاً با دکمه انجام می‌شود. متن دکمه از PHP و ترجمهٔ محلی می‌آید؛ جهت/فاصله‌ها با CSS logical است. React، GSAP، jQuery یا کتابخانهٔ منوی دیگری وارد این قابلیت نشده‌اند.

`navigation.js` اکنون chunk مستقل و فقط در وجود `[data-rdct-menu]` وارد می‌شود؛ listener کلیک document و تغییر breakpoint میان منوهای همان اجرا مشترک‌اند و initialize تکراری یک منو آن را دوباره آماده نمی‌کند. الگوی جدا بودن opener از لینک و بستن زیرمنو با بررسی محدود `themes/woodmart/js/scripts/menu/mobileNavigation.js` تطبیق داده شد؛ انیمیشن، مگامنو و ساختار وابستهٔ آن وارد رادمان نشدند.

سه بررسی محدود `tests/navigation.test.mjs` برای لینک والد/آیکون و focus، لینک موبایل و modifier و پاک‌شدن وضعیت با خروج/تغییر breakpoint پاس شدند. محیط DOM سادهٔ آزمون است؛ CSS واقعی، hover، لمس و مرورگر هنوز بررسی نشده‌اند. Build، قرارداد PHP سازنده و lint دو فایل PHP تغییرکرده با PHP 8.4.26 نیز پاس شدند. این قابلیت معادل تأیید کل سازنده یا WPML واقعی نیست.

اولویت انتخاب: تخصیص صریح برگه، پیش‌فرض زبان جاری WPML، پیش‌فرض سایت، چیدمان اصلی. انتخاب برگه در باکس «هدر و فوتر رادمان» ویرایشگر برگه است؛ هر کدام می‌تواند ارث‌بری، چیدمان مشخص یا عدم نمایش باشد. ذخیرهٔ meta به nonce، مجوز ویرایش برگه و `edit_theme_options` نیاز دارد و autosave/revision آن را تغییر نمی‌دهد. برگه‌های ترجمه‌شده meta مستقل دارند. زبان می‌تواند دوباره از پیش‌فرض سایت ارث‌بری کند.

بدون چیدمان فعال/معتبر، هدر/فوتر سادهٔ قالب نمایش داده می‌شود؛ انتخاب صریح «عدم نمایش» آن fallback را نیز حذف می‌کند. فیلتر `radmanct/builder/allowed` با kind همچنان opt-out پروژه را فراهم می‌کند. صفحات PHP و Template اختیاری Elementor همین خروجی PHP/HTML را می‌گیرند؛ Canvas متعلق به Elementor رفتار خود آن را دارد.

CSS کوچک سازنده فقط برای چیدمان مصرف‌شدهٔ فعال بارگذاری و بلوک‌های همان چیدمان برای assets آماده می‌شوند. navigation از ماژول Vanilla JS موجود استفاده می‌کند. لوگو از Site Identity استاندارد است. ID منو به kind و عنصر وابسته است؛ CSS از ویژگی‌های منطقی RTL/LTR استفاده می‌کند. خروجی عمومی به پنل React، CDN، Node یا MCP وابسته نیست.

## WPML، مرجع و شواهد

متن/URL هنگام ساخت و ذخیره از `wpml_register_single_string` ثبت می‌شوند. کلید چیدمان اصلی همان `kind/item-id/property` و چیدمان نام‌دار `kind/layout-id/item-id/property` است؛ تغییر نام عنوان layout ترجمه‌ها را بی‌اعتبار نمی‌کند. خروجی از `wpml_translate_single_string` عبور و escape می‌شود؛ نبود WPML مقدار اصلی را نگه می‌دارد. منوی منتخب از نگاشت nav_menu و بلوک مشترک از قرارداد ترجمهٔ خودش استفاده می‌کند. فهرست زبان‌های پنل از hook زبان‌های فعال WPML است؛ اجرای این hookها با افزونهٔ واقعی هنوز تأیید نشده است.

الگوی جدایی renderer، تنظیم و CSS شرطی از بررسی محدود `themes/woodmart/inc/modules/header-builder/class-frontend.php` استفاده شده؛ framework، storage اختصاصی CSS و عناصر نامرتبط آن کپی نشده‌اند. قرارداد AJAX با مرجع رسمی [check_ajax_referer](https://developer.wordpress.org/reference/functions/check_ajax_referer/) بررسی شد؛ nonce جای capability را نمی‌گیرد.

`tests/runtime/builder.php` از مسیر دستی `tools/qa-builder.ps1` روی WordPress 7.1.3/PHP 8.4.26/MariaDB در محیط موقت بدون دسترسی بیرونی پاس شد: ذخیره/JSON نامعتبر، revision قدیمی و شکست SQL CAS پس از تغییر رقیب، نام‌گذاری، ثبت کلید ترجمه، تخصیص سایت/زبان/برگه، ارث‌بری، منع حذف مورد مصرف، preview بدون تغییر ذخیره و مرز دسترسی. این بررسی کوتاه حدود ۹ ثانیه بود؛ شبکه/دیتابیس/فایل موقت پاک شدند. تست واقعی WPML، مرورگر، لمس، کش افزونه‌ای و Theme Builder المنتور از این شواهد نتیجه نمی‌شوند.

Sticky پایه، هدر شفاف و کنترل چهار دستگاه طبق قرارداد بالا ساخته شدند. مگامنوی ستونی و پنل کناری انتخابی چهار دستگاه اکنون پایهٔ اجرایی دارند؛ حدود و پذیرش باقی‌مانده در [سناریوی منوی چندحالته](../scenarios/header-footer.md) و [مالک ناوبری](navigation.md) است. clone/slide/hide-on-scroll، Ajax Search، انتقال بین سایت‌ها، تاریخچهٔ پایدار و تعامل افزونه‌ها در preview فعلاً ساخته نشده‌اند؛ اضافه‌شدن هر کدام باید مطابق سناریو و ماژول جدا باشد. کاتالوگ، MCP و لایسنس جزئی از تکمیل این سازنده نیستند.
