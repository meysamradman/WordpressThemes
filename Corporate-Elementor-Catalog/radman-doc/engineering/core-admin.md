# مدیریت Core و راه‌اندازی کاتالوگ

## چیدمان صفحه و فونت مدیریت — ۲۰۲۶-۱۱-۰۲

صفحهٔ موجود تنظیمات Content عرض محدود، کارت‌های Grid واکنش‌گرا، فاصله‌های gap و عملیات هم‌تراز دارد؛ جستجو و مقصد تماس کنترل‌های native و فرم‌های مستقل قبلی را حفظ می‌کنند. CSS فقط روی صفحهٔ خودش است و JS تازه‌ای ندارد. وقتی Theme رادمان فعال است، handle همین صفحه (`rdct-core-settings`) از فونت مشترک مدیریت Peyda استفاده می‌کند؛ فونت جدید یا کپی فایل در Content اضافه نشده و افزونه بدون Theme همچنان فونت بومی مدیریت را دارد. ویرایشگرها عضو این allowlist نیستند.

Build و PHP lint پاس شدند. بررسی native وردپرس برای صفحهٔ Content یک font-face و برای `post.php` صفر stylesheet تنظیمات/فونت رادمان نشان داد. ظاهر نهایی مرورگر و سرور مالک در این مرحله بررسی نشد؛ ZIP بازتولید نشده و انتقال تغییر به سرور به سورس Theme و dist مربوط به Content نیاز دارد.

## فهرست مشترک محصول و نمونه‌کار — Content 0.1.3

`inc/admin/content-list.php` ستون تصویر/کد مرجع و enqueue استایل فهرست را مشترک می‌کند. `catalog-list.php` فقط قیمت/تماس و فیلترهای مخصوص محصول را نگه می‌دارد؛ نمونه‌کار همان تصویر/کد و ستون دستهٔ native خودش را دارد و قیمت نمی‌گیرد. ستون افزونه‌های دیگر حفظ و کد escape می‌شود. stylesheet واحد `src/css/admin/content-list.css` فقط در `edit.php` نوع محتوای فعال enqueue می‌شود؛ حالت portfolio-only فایل query کاتالوگ را وارد نمی‌کند. basename و متادیتا ثابت‌اند و تغییر نسخه مسیر آپدیت native دارد. قرارداد کوتاه مدیریت کاتالوگ/ستون مشترک پاس شد؛ مرورگر و آپدیت واقعی میزبان از این نتیجه نمی‌شوند.

وضعیت: پیاده‌سازی ۲۰۲۶-۱۰-۱۹. مرز مدل داده و فعال‌سازی در [ماژول‌های محتوا](content-modules.md) و نیاز رابط در [تنظیمات](../scenarios/settings.md) است. این صفحه با PHP و Settings API استاندارد کار می‌کند؛ برای دو کلید و انتخاب مقصد، React، AJAX یا endpoint جدید لازم نشده است.

## ماژول‌ها و دسترسی

### فهرست کاربردی محصولات — ۲۰۲۶-۱۰-۲۰

`inc/admin/catalog-list.php` فقط با کاتالوگ فعال در مدیریت وارد می‌شود. فهرست native محصولات ستون تصویر، کد مرجع و انتخاب قیمت/تماس دارد؛ مقدار قیمت صفر حفظ و متن escape می‌شود. حالت قیمت بدون مقدار به‌صراحت «قیمت وارد نشده» نشان می‌دهد. ستون‌های taxonomy و افزونه‌های دیگر حذف نشده‌اند؛ تصویر بدون لینک/alt تکراری صرفاً برای شناسایی کنار عنوان است.

فیلترهای دسته/برند/ویژگی در بالای فهرست با GET و دکمهٔ native وردپرس اعمال می‌شوند. query فقط فهرست اصلی `edit.php` با نوع `radman_product` را تغییر می‌دهد؛ قیود موجود taxonomy با AND حفظ و ورودی آرایه‌ای نادیده گرفته می‌شود. فهرست هر taxonomy حداکثر ۱۰۰ term به‌علاوهٔ انتخاب ذخیره‌شده دارد؛ همهٔ محصولات برای ساخت رابط خوانده نمی‌شوند. جستجوی عنوان/متن، تاریخ، صفحه‌بندی و ویرایش گروهی همچنان native هستند؛ جستجوی کد یا مرتب‌سازی JSON متادیتا ساخته نشده است.

CSS مستقل `src/css/admin/catalog-list.css` فقط روی همین فهرست enqueue می‌شود؛ JS، وابستگی Theme یا دارایی عمومی اضافه نشده است. الگوی ستون native به‌صورت محدود در `themes/bridge/includes/qode-custom-taxonomy-field.php` خوانده و امضای hookهای CPT و `restrict_manage_posts` با مستند رسمی Context7 تطبیق داده شد. قرارداد کوتاه `tests/catalog-admin-contract.php` حفظ قیود افزونهٔ دیگر، جدایی نوشته/نمونه‌کار/query ثانویه/ویرایشگر و escape/قیمت صفر را بررسی می‌کند؛ پذیرش جدول در مرورگر باقی است.

منوی مستقل «هستهٔ رادمان» به `manage_options` نیاز دارد. هر کارت محصول/نمونه‌کار، کاربرد، وضعیت ذخیره‌شده و checkbox مستقل خودش را دارد؛ ورودی hidden مقدار خاموش را هم صریح ارسال می‌کند. فعال/غیرفعال‌کردن فقط با ذخیرهٔ فرم استاندارد و nonce/مجوز native وردپرس اعمال می‌شود. کارت‌ها دادهٔ محتوا را اسکن یا شمارش نمی‌کنند و خاموش‌کردن ماژول داده را حذف نمی‌کند. وضعیت و لینک‌ها بعد از ذخیره مطابق تنظیم جدید ساخته می‌شوند.

برای ماژول روشن و CPT ثبت‌شده، لینک مدیریت با capability `edit_posts` همان post type و لینک افزودن با `create_posts` خودش نشان داده می‌شود؛ capability ثابت نقش مدیر جایگزین آن‌ها نشده است. آرشیو از `get_post_type_archive_link` می‌آید و اگر وجود نداشته باشد لینک جعلی نداریم. این لینک‌ها انتخاب طراحی PHP/Pro را عوض نمی‌کنند و آرشیو نیاز به ایجاد برگهٔ دستی ندارد.

الگوی جدا بودن عنوان/وضعیت/عملیات کارت از `themes/woodmart/inc/admin/modules/setup-wizard/templates/plugins.php` بررسی شد؛ فقط تجربهٔ رابط تطبیق داده شده، نه wizard، نصب‌کننده، framework یا منابع آن. آیکون‌ها Dashicons محلی وردپرس هستند.

## برگهٔ تماس محصولات با جستجوی محدود

در ویرایش محصول، انتخاب تماس وقتی مقصد عمومی برای زبان جاری موجود نباشد راهنمای روشن نشان می‌دهد؛ مدیر دارای `manage_options` پیوند تنظیم مقصد را در تب جدا می‌بیند تا draft جاری از دست نرود. این پیام با تغییر حالت قیمت/تماس همان لحظه هماهنگ است؛ پس از تغییر مقصد در تب تنظیمات، دادهٔ راهنما با بازکردن مجدد ویرایشگر تازه می‌شود. انتخاب مقصد هنوز همان تنظیم واحد Core است و تنظیم موازی یا فرم تماس تازه ندارد.

بررسی مقصد در helper مستقل `Catalog::contact_url` انجام می‌شود تا محصول تازه/پیش‌نویس هم راهنمای درست داشته باشد. wrapper قدیمی `inquiry_url` همچنان انتشار و نوع محصول را پیش از مصرف عمومی بررسی می‌کند؛ مقصد نیز باید برگهٔ منتشرشدهٔ بدون رمز و ترجمهٔ موجود باشد. قیمت/تماس عمومی و پنل از یک اعتبارسنجی مقصد استفاده می‌کنند. دادهٔ راهنما فقط در ویرایش محصول دارای مجوز وارد config می‌شود؛ نمونه‌کار چنین query یا کنترل تازه‌ای ندارد.

`inc/admin/inquiry.php` فقط وقتی کاتالوگ روشن است فرم جستجو و انتخاب مقصد را رندر می‌کند. کاتالوگ خاموش یا حالت فقط نمونه‌کار، query برگه، اسکن مقصد یا ورودی قابل تغییرِ مقصد ندارد. مقدار قبلیِ مقصد هنگام نبود فیلد یا خاموش‌بودن ماژول حفظ می‌شود؛ روشن‌کردن تازهٔ کاتالوگ در همان ذخیره، به خطای کاذبِ فیلد غایب منتهی نمی‌شود. انتخاب صریح صفر در ماژول روشن لینک استعلام را خاموش می‌کند.

جستجو GET فقط خواندنی است؛ ورودی رشته‌ای حداکثر ۳۲۰ بایت sanitize و در HTML escape می‌شود. query از `get_posts` برای حداکثر ۲۰ برگهٔ منتشرشدهٔ بدون رمز، با `no_found_rows` و بدون cache متا/term بی‌مصرف استفاده می‌کند. `suppress_filters=false` مسیر فیلترهای زبان را باز می‌گذارد؛ اجرای واقعی WPML در این مرحله ادعا نمی‌شود. اگر انتخاب قبلی در این نتایج نباشد، فقط همان ID خوانده و در صورت عمومی/منتشرشده/بدون رمز بودن به فهرست افزوده می‌شود؛ سقف معمول خروجی ۲۱ گزینه است. در نتیجه برای پیدا کردن برگهٔ خارج از ۲۰ نتیجهٔ اول باید جستجو کرد، نه همهٔ برگه‌های سایت را یک‌جا بارگذاری کرد.

فرم جستجوی مدیریت بیرون فرم ذخیره است و nonce نوشتن/عملیات POST تازه‌ای ندارد. برای جلوگیری از تصور حفظ تغییرات ذخیره‌نشده در جستجوی GET، کنار آن راهنمای ذخیره قبل از جستجوی دوباره آمده است. validator مقصد همچنان فقط برگهٔ عمومی معتبر یا صفر را قبول و در ورودی نامعتبر مقدار قبلی را حفظ می‌کند. این انتخاب فقط مقصد حالت «تماس با ما» در محصول است؛ قیمت/تماس در ویرایش همان محصول انتخاب می‌شود و فرم عمومی، ارسال یا ثبت درخواست فعلاً DEFERRED است. [قرارداد قیمت/تماس](content-modules.md).

## فایل‌های مدیریت و بسته

`inc/admin/assets.php` مالک مشترک manifest و بارگذاری minified تنظیمات و ویرایشگر محتواست؛ manifest یک‌بار و فقط هنگام نیاز خوانده می‌شود. مسیر فقط CSS/JS minified موجود و بدون traversal است؛ helper نوع CSS را با JS اشتباه نمی‌گیرد. Core از Theme، فونت قالب یا پوشهٔ آن وابستگی runtime نمی‌گیرد. CSS مستقل `src/css/admin/settings.css` فقط در `toplevel_page_radmanct-content` و با مجوز بارگذاری می‌شود. صفحهٔ تنظیمات JS تازه ندارد؛ ویرایشگر اطلاعات محصول همان React موجود WordPress و Media Library قبلی را نگه می‌دارد.

پس از Build و بازتولید ترجمه‌های مستقل Core، بستهٔ `radmanct/bundled-plugins/radmanct-content.zip` و SHA-256 manifest با `tools/bundle-content.ps1` تازه می‌شوند. این بسته برای نصب‌های بعدی است؛ افزونهٔ نصب‌شده روی سرور را خودکار به‌روز نمی‌کند. برای دریافت این تغییرها باید پوشهٔ افزونهٔ `radmanct-content` و dist/languages آن هم به‌روز شود؛ جایگزینی Theme به‌تنهایی کافی نیست. schema محتوا، کلیدها و داده‌های موجود عوض نشده‌اند.

## بررسی انجام‌شده و حدود

`tests/core-settings-contract.php` با stub مجوز مدیریت، capability سفارشی CPT، خاموشی query مقصد، query محدود، حذف صفحات غیرعمومی، حفظ انتخاب قبلی، فیلد غایب، صفر، ورودی نامعتبر و assets شرطی را بررسی می‌کند. Build، ترجمه‌ها، ۳۰ آزمون کوتاه Node و lint پنج فایل PHP در PHP 8.4 پاس شدند. بستهٔ Core و hash آن نیز تازه و با قرارداد محلی نصب بررسی می‌شوند. این مرحله اجرای تازهٔ Settings API/ذخیره در دیتابیس واقعی، مرورگر، WPML، Multisite یا اندازه‌گیری عملکرد را اثبات نمی‌کند؛ محیط runtime طولانی/کامل تکرار نشده است.

APIهای native `get_posts` و capabilityهای post type با مستند رسمی WordPress از Context7 تطبیق داده شدند؛ `get_posts` به‌طور استاندارد شمارش کل را کنار می‌گذارد. سقف خروجی به query صریح اضافه شده، نه اینکه همهٔ برگه‌ها ابتدا خوانده و بعد در PHP بریده شوند.
