# قرارداد فونت و تایپوگرافی

نیاز رفتاری در [سناریوی تایپوگرافی](../scenarios/typography.md)، ظاهر کنترل‌ها در [رابط مدیریت](admin-ui.md) و کارهای باز در [نقشهٔ کار](../product/roadmap.md) است. اینجا فقط قرارداد جاری نگهداری می‌شود؛ گزارش اجرای کار و نسخه‌های قبلی به آن اضافه نشود.

## سه لایهٔ تنظیمات و طراحی

1. عمومی پایهٔ خانواده، وزن، اندازه، ارتفاع خط و رنگ همهٔ بخش‌هاست.
2. `blog_typography`، `catalog_typography` و `portfolio_typography` در همان `radman_settings` فقط انتخاب مستقل هر نوع محتوا را روی پایه حل می‌کنند؛ هر پروفایل مشترک آرشیو/جزئیات خودش است. مقدار خالی از عمومی ارث می‌برد، نه از وبلاگ؛ کپی/همگام‌سازی خودکار پروفایل‌ها انجام نشود.
3. CSS مشتری فقط برای استثنای عمدی همان عنصر/سکشن اولویت دارد؛ خانوادهٔ ثابت، تنظیمات موازی یا قطع بی‌دلیل ارث‌بری مجاز نیست. انتخاب ذخیره‌شدهٔ مالک حفظ شود.

مقایسه براساس مقدار مؤثر پس از resolve است. انتخاب صریح خانوادهٔ بدنه، خانواده‌های ارثی نقش‌ها را برای همان پروفایل بازحل می‌کند؛ انتخاب صریح H1/H2… همچنان استثنای مستقل است. بنابراین برابر بودن یک فیلد با عمومی به معنی برابر بودن کل پروفایل نیست.

پروفایل خالی یا کاملاً برابر stylesheet اختصاصی نمی‌سازد. فقط تفاوت خانواده/وزن/اندازه/ارتفاع خط/رنگ در scope `body.rdct-site #main-content` چاپ شود. رنگ تنها، مجوز تکرار فونت/اندازه نیست. @font-face فقط برای خانوادهٔ مصرفی تازه‌ای که در عمومی حاضر نیست اضافه شود؛ فونت عمومی ممکن است همچنان در هدر/فوتر مصرف شود.

## registry، نقش‌ها و اعتبارسنجی

- فایل فونت فقط در مسیر canonical همین registry نگهداری شود؛ پوشهٔ هم‌محتوا یا کپی در dist ساخته نشود. فونت تازهٔ مشترکِ پروفایل محتوا و Page Title با `enqueue_font_faces()` و یک handle به‌ازای خانواده اعلان شود؛ CSS هر مصرف‌کننده فقط تفاوت‌های خودش را نگه دارد.
- `inc/font-registry.php` مرجع واحد ID، family، گروه خط، فایل و وزن است؛ Theme و Elementor همان registry/فیلتر را مصرف می‌کنند. IDهای ذخیره‌شده و حروف بزرگ/کوچک مسیر فایل حفظ شوند.
- body والد headings/link/span است؛ H1–H6 از headings و در نهایت body ارث می‌برند. خانواده، وزن و ارتفاع خط هر نقش مستقل‌اند؛ مقدار خالی ارثی است. وزن انتخابی با خانوادهٔ مؤثر و وزن/بازهٔ Variable معتبر هماهنگ شود؛ وزن نامعتبر جعل نشود.
- اندازهٔ دسکتاپ/تبلت/موبایل با fallback دستگاه بزرگ‌تر و reset مستقل حل شود. ذخیرهٔ سازگار قبلی px عددی است؛ کنترل rem با adapter مقدار را رفت‌وبرگشت می‌دهد و CSS نهایی rem است. اعشار و مقدار خالی حفظ و ورودی نامعتبر رد شود.
- نقش link/span فقط با انتخاب صریح CSS مستقل می‌گیرد؛ span خالی از والد واقعی خودش ارث می‌برد. رنگ‌های body/headings/H1–H6/link/span و link_hover_color خالی یا HEX شش‌رقمی معتبرند.
- مقدار اندازه/رنگ یک‌بار در token تعریف و با `var()` مصرف شود؛ fallback تکراریِ همان مقدار ذخیره‌شده چاپ نشود. tokenهای نقش مانند `--rdct-size-h2`، `--rdct-line-height-h2` و `--rdct-text-link-color` مرز مصرف طراحی‌اند.

## استثنای اندازهٔ عنوان جمع‌وجور

عنوان H2 کارت محصول/نمونه‌کار عمداً `--rdct-card-title-size` با پیش‌فرض `1.25rem` و عنوان ابزارک محصول `--rdct-catalog-widget-title-size` با پیش‌فرض `1.0625rem` دارد. فقط `--rdct-size-h2` همان عنصر محدود می‌شود؛ H2 متن واقعی اندازهٔ تنظیمات را می‌گیرد. خانواده/وزن/رنگ/ارتفاع خط این عنوان‌ها همچنان از تنظیمات می‌آیند. برای تغییر طراحی، token محلی override شود؛ تنظیم عمومی، tag معنایی عنوان یا سیستم تنظیمات جدید دست‌کاری نشود.

## زبان و بارگذاری فونت

`Fonts::primary_group()` زبان معتبر جاری WPML، سپس `font_language` و locale را resolve می‌کند. `active_groups()` پیش‌فرض فقط گروه اصلی و با انتخاب صریح `mixed_language_fonts` هر دو گروه را برمی‌گرداند. انتخاب خانوادهٔ مکمل به‌تنهایی مجوز دانلودش در صفحه نیست؛ `Typography::used()`، CSS، registry Elementor و preload فقط گروه‌های واقعاً فعال را مصرف کنند.

فایل‌ها self-hosted و دارای metadata/مجوز معتبر باشند. فقط خانواده و وزن‌های مورد نیاز اعلان شوند؛ fallback سیستمی مثل Segoe UI اتصال خارجی نیست. @font-face تکراری برای نقش‌های دارای خانوادهٔ یکسان ساخته نشود و font-display:swap حفظ شود. ثبت خانوادهٔ جدید از registry/فیلتر مشترک انجام شود، نه loader مستقل یا دانلود runtime.

گزینهٔ block_google_fonts فقط مرز مصوب فونت شبکه‌ای را کنترل می‌کند؛ حذف کور فایل‌های افزونه‌ها یا ادعای جلوگیری از تمام اتصال‌های ثالث مجاز نیست. فونت فرانت باید مستقل از نصب Elementor و ابزار توسعه کار کند.

## کنترل‌ها و مرز ادیتورها

- تنظیمات فونت سه صفحهٔ اصلی/مکمل/بارگذاری دارد، نه تب زبان سایت. گروه خط، انتخاب زبان جدید نیست؛ نام کلیدهای persian/latin برای سازگاری داده حفظ می‌شود.
- `TypographyFields` و کنترل‌های مشترک family/weight/size/line-height مصرف شوند؛ نقشه/کلید موازی ساخته نشود. مقدار زبان/دستگاه غیرفعال و تغییر ذخیره‌نشده با hidden input کنترل‌شده حفظ شود؛ نام فرم تکراری نباشد. reset فقط همان نقش/گروه مربوط را بازنشانی کند و با ذخیرهٔ اصلی هماهنگ باشد.
- `typography-profiles.php` اعتبارسنجی/resolve و `content-typography-fields.js` فرم lazy همان پروفایل را انجام می‌دهند؛ صفحه، option، endpoint یا برنامهٔ مستقل Child ساخته نشود.
- فونت UI خود Gutenberg و Elementor بومی می‌ماند؛ stylesheet/hook عمومی برای تغییر UI آن‌ها اضافه نشود. تنظیم محتوای Elementor با مالکیت مصوب خودش و ثبت خانواده‌های محلی هماهنگ باشد.
- فونت پنل رادمان فقط روی صفحات خودش enqueue شود: `inc/admin/typography.php` و `src/css/admin/typography.css`، family مستقل `Radman CT Admin Peyda` از فایل محلی `persian/Peyda/PeydaWebVF.woff2` با وزن ۱۰۰–۱۰۰۰، unicode-range فارسی/عربی و font-display:swap. لاتین UI از stack سیستمی می‌آید؛ این محدودیت با فونت محتوای سایت یکی نیست.

## head و preload اختیاری

هیچ preload خودکاری صرفاً به دلیل انتخاب خانواده تولید نشود. فیلتر `radmanct/typography/preload` می‌تواند گروه مصرفی `persian` و/یا `latin` را اعلام کند. فقط یک فایل مناسبِ بدنه از هر گروه: Regular یا Variable شامل وزن ۴۰۰، و در نبود آن اولین فایل معتبر. URL دقیق CSS، type=`font/woff2` و crossorigin=`anonymous` باشد؛ منابع preload سایر افزونه‌ها حفظ و URLها deduplicate شوند. این فیلتر برای مصرف شناخته‌شده است، نه فعال‌سازی همگانی بدون سنجش.

## تغییر و پذیرش

مسیر و casing واقعی فایل، وزن‌های معتبر، دو گروه خط، reset و CSS تفاضلی با قراردادهای موجود بررسی شوند. `tests/content-typography-runtime.php` قرارداد خالی/برابر/تغییر رنگ/فونت تازه در شش نما را پوشش می‌دهد؛ وجود تست به معنی اجرای امروز یا پذیرش بصری نیست. CSS پایه/feature فقط طبق [مالک دارایی‌ها](assets.md) بارگذاری شود. موارد پذیرش باز در roadmap و تاریخچه در [آرشیو این سند](../archive/2026-11-02-documentation-cleanup/radman-doc--engineering--typography.md) است.
