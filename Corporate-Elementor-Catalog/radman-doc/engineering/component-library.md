# کتابخانهٔ محلی کامپوننت‌ها

## قرارداد جاری خانواده و طرح — ۲۰۲۶-۱۰-۲۸

تصمیم تأییدشدهٔ مالک در [سناریوی کامپوننت‌ها، بخش کتابخانه](../scenarios/components.md) ثبت شده است: صفحهٔ اصلی کارت خانواده دارد؛ انتخاب خانواده فهرست طرح‌های آن را باز می‌کند و انتخاب طرح مسیر پیش‌نمایش زنده و درج موجود را حفظ می‌کند. در کاتالوگ فعلی ۲۱ خانواده و ۹۴ نمونه وجود دارد؛ تعداد و گروه‌بندی از همان registry مشترک استخراج شوند، بدون ثبت موازی یا تغییر شناسه‌های نمونه‌ها. فهرست طرح‌ها عنوان، توضیح کوتاه و آیکون ساده دارد؛ بازگشت به خانواده‌ها باید ممکن باشد.

فعلاً عکس حتی برای کارت خانواده الزامی نیست و تولید/تهیهٔ ۹۴ screenshot از محدودهٔ جاری خارج است. رابط آیکونی باید بدون فایل تصویر کامل و قابل استفاده باشد؛ Thumbnail واقعی بعداً به‌صورت افزایشی و اختیاری به دادهٔ همان طرح افزوده می‌شود. SVG شماتیک تکراری نباید به‌عنوان خروجی واقعی معرفی شود. پیش‌نمایش تعاملی مستقل و تنها هنگام انتخاب طرح بارگذاری شود؛ بازکردن خانواده نباید iframe یا انیمیشن تمام طرح‌هایش را اجرا کند.

وضعیت سورس: renderer مشترک مدیریت و پنجرهٔ Elementor اکنون کارت‌های آیکونی خانواده و مرحلهٔ جداگانهٔ طرح‌ها را دارد. آیکون‌ها از کاتالوگ SVG و موتور موجود محلی می‌آیند؛ کتابخانهٔ آیکون، پوستهٔ popup یا registry موازی ساخته نشده است. دادهٔ طرح‌ها از کاتالوگ مشترک می‌آید و فقط طرح‌های خانوادهٔ انتخاب‌شده در DOM ساخته می‌شوند. صفحهٔ فعلی همهٔ ۲۱ خانواده را نشان می‌دهد؛ صفحه‌بندی برای بیش از ۲۴ خانواده حفظ شده است. تصویر واقعیِ معتبر در صورت افزودن بعدی قابل نمایش است؛ نبود آن فقط آیکون نشان می‌دهد، نه پیام درخواست screenshot.

بررسی محدود: Build، ۱۱ تست کوتاه Node و قرارداد PHP موفق شدند. در مرورگر محلی، ۲۱ کارت، بازشدن ۱۳ طرح دکمه و ۲۵ طرح نظر مشتری، انتخاب مستقیم طرح دورخط و آماده‌شدن پیش‌نمایش واقعی آن دیده شدند؛ بستن پیش‌نمایش src قاب را پاک و focus را به همان طرح برگرداند. این بررسی نصب میزبان یا درج/Undo/ذخیره در Elementor واقعی را تأیید نمی‌کند؛ مسیر مشترک markup و کنترل‌های بومی ادیتور با قرارداد PHP/Node بررسی شدند. فهرست ریشهٔ تصاویر فقط مرجع مرحلهٔ آینده است، نه کار لازم فعلی. شواهد قدیمی زیر مربوط به پیاده‌سازی زمان خود هستند و الزام تصویر آن‌ها با این قرارداد جایگزین شده است.

## اصلاح کلیک میانبر — ۲۰۲۶-۱۰-۲۵

فقط کلیک میانبر رادمان در capture گرفته می‌شود تا handler والد AddSectionArea هم‌زمان وارد حالت ویرایش نشود. launcher پنهان حفظ شده است. قرارداد توقف انتشار پاس شد؛ رفع تمام علت‌های React 130 روی میزبان هنوز اثبات نشده است.

مالک فعلی کتابخانه افزونهٔ `radmanct-components` است؛ ارتباط مستقل PHP/Classic/Atomic و فهرست امکانات در [قرارداد کامپوننت‌ها](components.md) آمده است. انتقال از Theme و تغییر domain، IDهای ذخیره‌شده و helperها را تغییر نمی‌دهد. کارت‌های نمونهٔ محلی از کاتالوگ مشترک می‌آیند؛ Image با placeholder SVG محلی و نمونهٔ Reveal به مدل‌های Classic/Atomic اضافه شد. shell و مدل‌ها همچنان بعد از آماده‌شدن Elementor/کلیک دریافت می‌شوند. نمونهٔ Image پس از درج با رسانهٔ مشتری جایگزین می‌شود؛ تصویر مرجع ثالث همراه آن نیست.

## مسیر جاری کم‌بار — Theme 0.1.4

**اصلاح سورس ظاهر داخل Elementor — ۲۰۲۶-۱۰-۲۸:** `ComponentsPage::assets(true)` اکنون فقط `elementor-library.css` را مصرف می‌کند و stylesheet/tokens و CSS تزریقی پنل مدیریت رادمان وارد این مسیر نمی‌شوند. shell اختصاصی `<dialog>`، header و دکمهٔ بستن PHP حذف شدند؛ `component-dialog.js` پنجرهٔ `lightbox` خود `elementorCommon.dialogsManager` را هنگام اولین کلیک می‌سازد. بستن صریح، Escape، کلیک بیرون و منع اسکرول به همان manager سپرده شده‌اند. الگوی native در `themes/elementor/assets/js/editor.js` و `assets/lib/dialog/dialog.js` نسخهٔ ارسالی 4.3.5 بررسی شد؛ پرس‌وجوی Context7 راهنمای مستقیمی برای این manager نداد و جزئیات از سورس همان نسخه تطبیق داده شدند. در نبود manager، میانبر درج فعال نمی‌شود و popup موازی ساخته نمی‌شود.

دکمه‌های داخل editor کلاس‌های بومی `e-btn` و حالت‌های `e-primary`/`e-btn-txt-border` دارند؛ input/select، رنگ، focus، disabled و فونت از stylesheet/متغیرهای خود ادیتور می‌آیند. `elementor-library.css` فقط اندازه/اسکرول پنجره و رنگ کارت/پیش‌نمایش با tokenهای بومی Elementor را تعیین می‌کند؛ فونت از `--e-a-font-family` می‌آید و قرارداد فونت فارسی مصوب محفوظ است. `library-layout.css` فقط چیدمان مشترک کارت/فیلتر/پیش‌نمایش است. پنل WordPress Admin همان palette و کنترل‌های مستقل خود را دارد؛ endpoint، مجوز، مدل درج و موتور کارت تکثیر نشدند. هنگام hide، درخواست معلق و preview متوقف و focus به میانبر بازمی‌گردد؛ ticket درخواست مانع اثر پاسخ قبلی پس از بستن/بازکردن سریع است. Build و قراردادهای کوتاه موفق‌اند؛ ظاهر واقعی روشن/تیره، RTL/LTR، کیبورد، ذخیره/Undo و نصب میزبان هنوز پذیرش نشده‌اند.

فوتر ادیتور فقط trigger داخلیِ همیشه‌مخفی دارد؛ shell بومی، کارت‌ها و مدل‌های fa/en و Classic/Atomic در HTML اولیه تولید نمی‌شوند. bootstrap سبک بعد از preview و `document:loaded` و رویداد بومی `elementor/init`، فقط دکمهٔ گرد نشان رادمان را در ردیف دکمه‌های افزودن section می‌گذارد؛ الگوی template و delegation از WoodMart و محل دکمه/نشان از `hub-templates-lib.js` مرجع‌اند. ظاهر نشان برندِ این میانبر استثنای محدودِ ورود کتابخانه است و مجوز skin مستقل برای کنترل‌ها نیست. launcher شناور روی بوم نمایش داده نمی‌شود. listener هر preview document فقط یک بار متصل می‌شود و polling/observer سراسری نداریم.

اولین کلیک POST هم‌مبدأ به `wp_ajax_radman_component_library` می‌زند؛ endpoint، capability، nonce و مجوز `edit_post` همان سند را پیش از ساخت markup مشترک کنترل می‌کند. مسیر عمومی/nopriv ندارد. پاسخ JSON حاوی HTML trusted/escapeشده و مدل‌های محلی است؛ سپس chunk اصلی Components import می‌شود. درخواست هم‌زمان تکرار نمی‌شود؛ شکست قابل تلاش مجدد است و تغییر سند پیش از پاسخ مانع درج payload قدیمی می‌شود. بار بعد همان dialog/مدل‌ها استفاده می‌شوند. پنل مستقل گالری از همان renderer بدون AJAX editor استفاده می‌کند.

نسخه‌های Classic و Atomic همچنان با شناسه‌های مستقل ثبت‌اند تا سند قدیمی و مدل انتخابی از بین نرود؛ منطق مشترک `Widgets\classic_in_panel()` با API بومی `show_in_panel/hide_on_search` فقط کارت و نتیجهٔ جستجوی Classic را هنگام موجودبودن نسخهٔ Atomic پنهان می‌کند. Atomic خاموش، Classic را دوباره نمایان می‌کند. غیرفعال‌سازی ثبت یا دستکاری دادهٔ سند نداریم. شواهد کوتاه و محدودیت بررسی هاست در [گزارش اجرا](../implementation/foundation.md) است؛ عدد سرعت هاست از تعداد درخواست یا زمان Docker استنباط نمی‌شود.

اصلاح Atomic پس از گزارش Loading بدون خطای JS — ۲۰۲۶-۱۰-۲۱: بعد از راه‌اندازی schema بومی Elementor 4.3.5، propهای قابل اتصال می‌توانند با `Union_Prop_Type` پوشانده شوند؛ این wrapper متد `generate()` ندارد. ساخت مدل نمونه اکنون نوع عضو را با `get_prop_type_from_value()` انتخاب، روی همان عضو مقدار typed تولید و با schema نهایی validate می‌کند. نوع ناشناخته مدل خالی می‌دهد؛ فراخوانی حدسی روی wrapper انجام نمی‌شود. فراخوانی قدیمی در فوتر کتابخانه PHP fatal ایجاد و چاپ اسکریپت‌های اصلی ادیتور را قطع می‌کرد. آزمون کامل startup و حدود پذیرش در [ادغام Elementor](elementor.md) ثبت شده است.

اصلاح lifecycle اولیه در ۲۰۲۶-۱۰-۲۰: dependency بومی `elementor-editor` و بررسی آماده‌بودن preview، سند و commandها اضافه شدند. مسیر جاری بالا، ورود chunk و ساخت مدل‌ها را تا کلیک عقب می‌اندازد؛ دیگر صرف آماده‌شدن preview موجب بارگذاری کتابخانه نمی‌شود. پنل مستقل Components entry عادی خودش را دارد. [علت، مرجع WoodMart و حدود تأیید](elementor.md).

وضعیت ۲۰۲۶-۱۰-۱۹: پایهٔ گالری، پیش‌نمایش و پنجرهٔ درج Elementor پیاده‌سازی شد. نیاز محصول در [سناریوی کامپوننت‌ها](../scenarios/components.md) و موتور مشترک در [قرارداد کامپوننت‌ها](components.md) است. این وضعیت به معنی پذیرش بصری یا تأیید درج در ویرایشگر واقعی نیست.

## مالکیت و فهرست مشترک

- `radmanct-components/inc/components/library.php` منبع مشترک نمونه‌ها و مدل درج است؛ `library-catalog.php` توسعهٔ همان فهرست، گروه‌بندی خانواده‌ها و metadata معرفی را نگه می‌دارد. شمارش فعلی ۲۱ خانواده و ۹۴ نمونهٔ قابل مشاهده است؛ شناسهٔ پنهان قدیمی برای سازگاری API حفظ شده است. دادهٔ مستقلی برای گالری مدیریت و Elementor نگهداری نمی‌شود.
- `radmanct-components/inc/admin/components-page.php` صفحهٔ «رادمان ← کامپوننت‌ها»، markup مشترک کارت‌ها، پنجرهٔ ویرایشگر و پیش‌نمایش محافظت‌شده را می‌سازد. این فایل فقط در مدیریت بارگذاری می‌شود؛ catalog نیز هنگام مصرف خوانده می‌شود.
- `radmanct-components/images/components/` محل دارایی‌های تصویری کتابخانه است؛ SVGهای شماتیک قدیمی screenshot خروجی نیستند و نباید جای پیش‌نمایش واقعی معرفی شوند. رابط فعلی به تصویر وابسته نیست؛ افزودن Thumbnail واقعی به مرحلهٔ آینده موکول شده است. محل فایل طبق [قرارداد دارایی‌ها](assets.md) است.
- `radmanct-components/languages/component-samples.json` متن فارسی/انگلیسی نمونه را مستقل از زبان پنل نگه می‌دارد. ترجمهٔ رابط در catalog معمول قالب است.
- افزودن نمونهٔ بعدی با ثبت همان کامپوننت موجود، تنظیمات، خانواده، عنوان، توضیح و آیکون در همین فهرست انجام شود؛ تصویر اختیاری است. کامپوننت جدید ابتدا renderer/asset مستقل خودش را لازم دارد. نام و شناسه با داکیومنت PHP یکی بمانند. نمونه‌های درون بسته trusted هستند؛ بارگذاری JSON دلخواه کاربر یا دریافت از اینترنت نداریم.

## گالری و پیش‌نمایش

گالری بدون Core و Elementor کار می‌کند و فقط معرفی، جستجوی نام/شناسه و پیش‌نمایش دارد؛ کد PHP یا مدیریت تکراری کامپوننت‌ها نمایش داده نمی‌شود. زبان نمونه از بالای کتابخانه انتخاب می‌شود و روی پیش‌نمایش و مدل درج‌شده اثر دارد. نمونهٔ متن و جهت fa/RTL و en/LTR مستقل از locale مدیریت هستند. ابزار موبایل، قاب را تا ۳۹۰ پیکسل محدود می‌کند؛ این شبیه‌سازی عرض است و جای تست دستگاه واقعی نیست.

در ابتدا هیچ iframe با src بارگیری نمی‌شود؛ انتخاب پیش‌نمایش فقط یک قاب فعال را باز می‌کند. بستن آن src را حذف و focus را به دکمهٔ آغازکننده برمی‌گرداند. قاب HTML مستقل دارد و از renderer واقعی کامپوننت، فونت و tokenهای قالب استفاده می‌کند؛ CSS مدیریت وارد آن نمی‌شود. preview استایل تشخیصی خودش را برای فضای اسکرول دارد و پیش‌نمایش تمام استایل‌های صفحهٔ مشتری نیست.

`admin_post_radman_component_preview` فقط برای کاربر دارای `edit_posts` یا `edit_theme_options` و nonce معتبر قابل استفاده است؛ handler ناشناس ندارد. شناسهٔ ناشناخته ۴۰۴، کاربر بدون مجوز ۴۰۳ می‌گیرد. شناسه فقط کلید فهرست ثابت است و به مسیر فایل تبدیل نمی‌شود. پاسخ no-cache/noindex و SAMEORIGIN است؛ CSP قاب منابع محلی را محدود می‌کند و connect خارجی ندارد. iframe فقط HTML ساخته‌شدهٔ رادمان را نمایش می‌دهد؛ ورودی HTML/URL آزاد مصرف نمی‌کند.

## درج در Elementor

### انتخاب کلاسیک و native Atomic — ۲۰۲۶-۱۰-۲۰

اگر Atomic در Elementor فعال و ویجت‌های native رادمان ثبت شده باشند، پنجرهٔ درج انتخاب‌گر «نوع عنصر» اتمیک/کلاسیک دارد؛ پیش‌فرض Atomic است. انتخاب فقط همان درج را تعیین می‌کند و سند موجود را تبدیل نمی‌کند. گالری مستقل از Elementor این انتخاب‌گر یا payload درج ندارد. غیرفعال‌بودن Atomic گزینه و مدل بومی را حذف می‌کند؛ نبود نمونهٔ Atomic به درج بی‌صدای کلاسیک منجر نمی‌شود.

اصلاح مالک، ۲۰۲۶-۱۰-۲۳ — CONFIRMED: پنجره در مرکز viewport و با فاصلهٔ برابر از لبه‌ها، ارتفاع محدود و اسکرول داخلی باشد. هر کامپوننت یک کارت داشته باشد؛ حالت‌های Text داخل تنظیمات انتخاب شوند. در حالت Atomic هم والد e-flexbox و هم فرزند تایپ‌دار بومی باشند؛ ظاهر والد به‌تنهایی معیار نوع درج نیست. اجرای واقعی درج/Undo/ذخیره هنوز پذیرش نشده است.

`Library\model(id, language, mode)` دو مدل مستقل از همان نمونه می‌سازد: کلاسیک با container و نام‌های ذخیره‌شدهٔ `radman-*`؛ بومی با والد `elType=e-flexbox` و ویجت `rdct-atomic-*`، نسخهٔ `0.0`، styles و props تایپ‌دار. envelope از `generate()` همان PropType واقعی ویجت تولید و با schema خودش validate می‌شود؛ مقدار mirror قدیمی yes به boolean واقعی تبدیل می‌شود. متن فارسی/انگلیسی و جهت هر نمونه حفظ می‌شوند. شناسهٔ تازه را فرمان native create/clone می‌سازد؛ دادهٔ نمونه یا سند قبلی بازنویسی نمی‌شود.

مدل‌های بومی با کلید fa-atomic/en-atomic در JSON محلی همان پنجره‌اند. انتخاب زبان/نوع هنگام کلیک ثبت می‌شود؛ import دیررس انتخاب جدید را جای آن مصرف نمی‌کند. `libraryModel` نوع/زبان ناشناخته و نمونهٔ غایب را رد می‌کند؛ adapter درج نیز جفت والد/ویجت بومی و کلاسیک را کنترل می‌کند. سایر مرزهای مجوز، سند جاری، حالت فقط‌خواندنی، clone مستقل و عدم انتشار خودکار حفظ شده‌اند.

Build و ۹۰ بررسی کوتاه Node پاس شدند؛ قراردادهای component-library و atomic-components با schema/PropTypes/Twig واقعی Elementor 4.3.5 و محیط WordPress/Widget_Base شبیه‌سازی‌شده، مدل هر چهار نمونه در دو زبان، UI فعال/غایب و جدایی payload گالری را بررسی کردند. lint دو فایل PHP اجرایی و دو قرارداد روی PHP 8.4 با شبکهٔ خاموش پاس شد. [ساختار native element/widget](https://github.com/elementor/elementor/blob/main/docs/atomic-builder/atomic-widgets/overview.md) و نمونه‌های JSON رسمی از Context7 با Flexbox و PropTypes نسخهٔ ارسالی تطبیق داده شدند. اجرای فرمان در editor واقعی و چرخهٔ ویرایش/Undo/ذخیره هنوز پذیرش نشده‌اند.

اتصال فقط روی hookهای `elementor/editor/after_enqueue_scripts` و `elementor/editor/footer` اجرا می‌شود. دکمهٔ «کتابخانهٔ کامپوننت‌های رادمان» در گوشهٔ پایین ویرایشگر، dialog بومی را باز می‌کند؛ کارت‌ها همان markup/فهرست گالری هستند. در مرورگر فاقد dialog، دکمه مخفی می‌شود؛ import سفارشی جایگزین ساخته نشده است.

پنجره در اولین کلیک فوراً با وضعیت بارگذاری باز می‌شود؛ فهرست کارت‌ها از AJAX همان سایت دریافت می‌شود. مدل‌های همهٔ ترکیب‌های زبان/نوع عنصر داخل فهرست ساخته یا embed نمی‌شوند. فقط هنگام درج، مدل نمونهٔ انتخاب‌شده با nonce و مجوز ویرایش سند از همان سایت دریافت می‌شود؛ `component-models.js` حداکثر ۳۲ مدل را به تفکیک سند، نمونه، زبان و نوع عنصر در حافظه نگه می‌دارد. بستن پنجره درخواست منتظر را لغو می‌کند؛ پاسخ نامعتبر یا لغوشده کش نمی‌شود. دو انتخاب «زبان نمونه» و «نوع عنصر» مستقل‌اند؛ نگه‌داشتن این metadata به معنی بارگذاری دو زبان، فونت انگلیسی یا همهٔ کامپوننت‌ها در سایت نیست. `src/js/admin/component-insert.js` فقط با کلیک درج import می‌شود و از `$e.run('document/elements/create')` با `getPreviewContainer()`، والد متناسب با نوع منتخب و `clone: true` استفاده می‌کند. نمونه به انتهای سند جاری اضافه می‌شود، تنظیمات قابل ویرایش‌اند و ذخیرهٔ صفحه همچنان با کاربر و چرخهٔ native Elementor است. جایگزینی محتوای سند یا انتشار خودکار نداریم. نبود فرمان/نوع ناشناخته خطا می‌دهد؛ خطای فرمان به‌عنوان موفقیت گزارش نمی‌شود و وضعیت کاربر را به بررسی صفحه دعوت می‌کند.

مدل هر درج کپی مستقل است و دوبار کلیک هم‌زمان در UI مسدود می‌شود. dialog با Escape، دکمهٔ بستن یا کلیک روی backdrop بسته می‌شود؛ کلیک داخل و کشیدن از داخل به بیرون آن را نمی‌بندد. بستن، preview را آزاد و focus را به دکمهٔ گرد آغازکننده در preview برمی‌گرداند. نام ویجت‌ها و کارت‌ها کوتاه و بدون پسوند Atomic است؛ انتخاب نوع درج همچنان مستقل است. فیلترها نوار responsive دارند و شناسهٔ فنی روی کارت چاپ نمی‌شود. نمونهٔ قدیمی icon-arrow برای سازگاری API باقی است ولی در گالری پنهان است؛ یک کارت Icon با picker مستقل داریم. منوی Classic فقط هنگام نبود adapter فعال Atomic در پنل دیده می‌شود.

تکمیل چرخه: خروجی خالی/فاقد شناسه از فرمان create موفق محسوب نمی‌شود. شناسهٔ سند پیش از import ابزار ثبت و پیش از اجرای فرمان کنترل می‌شود؛ تعویض سند یا container فقط‌خواندنی درج را رد می‌کند. بستن پنجره یا pagehide، درجِ هنوز در انتظار import/درخواست مدل را لغو می‌کند؛ فرمانی که قبلاً اجرا شده خودکار rollback نمی‌شود. دکمه‌های درج تا پایان عملیات موقتاً غیرفعال و سپس به وضعیت قبلی برگردانده می‌شوند؛ هر مدلِ دریافت‌شده برای هر درج clone مستقل می‌گیرد.

بررسی کوتاه تکمیل چرخه: Build، مجموع ۴۰ تست Node، lint فایل PHP مدیریت کتابخانه و قرارداد PHP آن روی 8.4.26 پاس شدند. دو تست جدید رد خروجی خالی/نامعتبر، پذیرش آرایهٔ معتبر و منع درج پس از تعویض سند/در container فقط‌خواندنی را با mock پوشش می‌دهند؛ بررسی مرورگر و ویرایشگر واقعی اجرا نشد.

فیلتر دسته و جستجوی نام/شناسه از اطلاعات ثابت همان فهرست مصرف می‌کنند؛ جستجو صورت‌های عربی/فارسی ی و ک و نیم‌فاصله را یکسان می‌گیرد و متن دکمه‌های کارت جزو index نیست. پیش‌نمایش وضعیت بارگذاری/آماده/خطا دارد؛ iframe بدون marker خروجی رادمان، مانند پاسخ nonce منقضی، آماده گزارش نمی‌شود. وضعیت این مراحل تأیید اجرای انیمیشن نیست. باز و بسته‌شدن پنجره overflow قبلی صفحه را حفظ می‌کند؛ pagehide پیش‌نمایش را آزاد می‌کند. انتخاب عرض و بازبودن پیش‌نمایش در aria اعلام می‌شوند.

## فایل‌ها و بارگذاری

`src/js/admin/components.js` فقط گالری/ویرایشگر را راه می‌اندازد؛ بدون React و GSAP در فهرست و بدون درخواست خارجی. `src/js/admin/component-preview.js` موتور مشترک انیمیشن را فقط در قاب نمونهٔ scroll مصرف می‌کند؛ hover و آیکون هیچ script انیمیشن ندارند. `src/css/admin/components.css` از tokenهای مشترک مدیریت و Peyda محلی استفاده می‌کند؛ ورودی‌ها، فاصلهٔ دکمه‌ها، حالت غیرفعال و رنگ‌ها داخل کتابخانه صریحاً scope دارند تا CSS وردپرس/Elementor ظاهر کارت‌ها را خراب نکند. `component-preview.css` فقط داخل قاب چاپ می‌شود. ورودی‌ها در `tools/build.mjs` ثبت و runtime از فایل‌های minified manifest استفاده می‌کند. هیچ‌کدام از مسیرهای کتابخانه در graph عمومی frontend وارد نشده‌اند.

## شواهد و موارد باقی‌مانده

اصلاح ۲۰۲۶-۱۰-۲۵: ساخت سورس/ترجمه و ۳۱ بررسی کوتاه Node پاس شدند؛ دریافت فقط مدل منتخب، کش محدود/لغو درخواست، استقلال زبان/نوع، حفظ tab آیکون و جدایی graph عمومی بررسی شدند. قرارداد PHP کتابخانه دریافت مدل منتخب و رد انتخاب/مجوز نامعتبر را نیز پوشش می‌دهد. lint چهار فایل PHP اجرایی با PHP 8.4.27 و قراردادهای کتابخانه، منابع محلی ادیتور و کنترل native Icons پاس شدند. استایل دکمه/فونت اصلاح سورس است؛ پذیرش بصری/Network روی میزبان انجام نشده و ZIP تازه ساخته نشده است. هشدار موجود Vite دربارهٔ import هم‌زمان static/dynamicِ `atomic-render-preview.js` باقی است؛ build شکست نخورد و این تغییر آن مسیر را اصلاح نکرد.

Build و ۳۸ تست کوتاه Node پاس شدند. lint چهار فایل PHP تغییرکرده و `tests/component-library-contract.php` روی PHP 8.4.26 پاس شدند: فهرست/تصاویر محلی، هر دو زبان، markup بدون preview زودهنگام، اعمال مخصوص editor و رد مجوز/nonce/شناسهٔ نامعتبر. `tests/component-library.test.mjs` فرمان درج mock، استقلال نمونه‌ها، شکست فرمان و جدایی graph عمومی را پوشش می‌دهد. این‌ها اجرای editor واقعی نیستند. ZIP داخلی Core پس از تغییر tokenهای مشترک مدیریت بازسازی شد؛ تغییر رفتار داده‌های Core نداشتیم.

باقی‌مانده: بازشدن dialog، جای دکمه در UI نسخهٔ نصب‌شده، درج/ویرایش/Undo/ذخیره در سند واقعی Elementor و کیفیت RTL/LTR/لمس/فونت در مرورگر بررسی شود. سورس محلی Elementor 4.3.5 و API فرمان با Context7 تطبیق داده شدند؛ سازگاری بصری با ویرایشگرهای متفاوت یا نسخه‌های آینده ادعا نمی‌شود. تست طولانی و محیط DB برای این تغییر اجرا نشود مگر مسئلهٔ مشخصی آن را لازم کند.

مرجع الگو: `themes/hub-elementor-addons/elementor/template-library/template-library.php` و بخش‌های مرتبط `assets/js/hub-templates-lib.js`؛ فقط تجربهٔ کارت/انتخاب/درج اقتباس شد. API خارجی، Backbone/Marionette اختصاصی کتابخانه، favorite و framework کامل Hub وارد رادمان نشدند. [فرمان create](https://github.com/elementor/elementor/blob/main/docs/assets/dev/js/editor/document/elements/readme.md) و [hook فایل ویرایشگر](https://developers.elementor.com/docs/scripts-styles/editor-scripts/) منابع API هستند.
