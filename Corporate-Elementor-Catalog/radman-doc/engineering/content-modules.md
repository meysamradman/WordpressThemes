# Radman CT Content و ماژول‌های مستقل محتوا

## برچسب محصول و بررسی فیلدها — CONFIRMED، ۲۰۲۶-۱۱-۰۲

مالک برچسب محصول مانند وبلاگ خواست. taxonomy مستقل و غیرسلسله‌مراتبی `radman_product_tag` در Content با مدیریت بومی، REST و مسیر `product-tag` ثبت شد؛ برچسب وبلاگ، ویژگی و برند ادغام یا مهاجرت نشدند. `rm_tag` در فیلتر استاندارد catalog، taxonomy template، انتخاب renderer/دارایی، metadata جزئیات، WPML config و allowlist محتوای MCP اضافه شد. ورود تگ در ویرایشگر از UI بومی می‌آید؛ مخزن/کنترل جدید ساخته نشد. جزئیات پنج ردیف کد/دسته/برند/ویژگی/برچسب دارد؛ کارت فشرده همچنان فقط کد و برند را می‌خواند. [ثبت بومی taxonomy](https://developer.wordpress.org/reference/functions/register_taxonomy/) از Context7 بررسی شد.

در نصب محلی برای همان شش محصول نمونه، پنج تگ مشترک و یک ابزارک تگ به آرشیو اضافه و rewrite یک‌بار تازه شد. حالت تماس سه محصول مقصدی نداشت؛ برگهٔ منتشرشدهٔ موجود «تماس با ما» با شناسهٔ ۱۳۳۹۱ در گزینهٔ موجود `radman_core_inquiry_page` انتخاب شد. فرم/ثبت درخواست/فروش ایجاد نشد. هر شش محصول دارای کد، دسته/برند/ویژگی، یک یا دو تگ، سه مشخصه و خروجی معتبر قیمت یا تماس بودند. گالری همچنان رسانه و موتور مشترک موجود را مصرف می‌کند. قراردادهای محدود escaping/دسترسی metadata، گالری، فیلتر و memoization زبان با تگ جدید پاس شدند؛ HTTP آرشیو تگ دو محصول و fragment ترکیبی برند/تگ دو محصول بدون سایدبار برگرداند. این شواهد جای پذیرش کامل WPML، ویرایشگر یا مرورگر نیستند.

## ترجمهٔ بومی مشخصات و قیمت با WPML — ۲۰۲۶-۱۰-۲۵

برای بستن شکاف ترجمهٔ دادهٔ تو‌در‌تو، `_radman_content_data` اکنون در XML بومی Translate است؛ whitelist فقط `specifications/*/label|value|unit` و `pricing/text` را به کار ترجمه معرفی می‌کند. version، code، شناسهٔ ردیف، gallery و pricing/mode متن ترجمه نیستند. storage، نسخهٔ schema و دادهٔ موجود مهاجرت نمی‌کنند؛ ACF، String Translation موازی و سیستم چندزبانهٔ اختصاصی اضافه نشده‌اند. عنوان فیلدهای job با همان hook بومی و منابع زبان Content فارسی/انگلیسی می‌شود.

WPML در پایان job متای سریال‌شده را بازسازی می‌کند؛ بنابراین برای مقصدی که از قبل دادهٔ معتبر مستقل دارد، `wpml_pre_save_pro_translation` یک snapshot در حافظهٔ همان درخواست می‌گیرد و `wpml_pro_translation_completed` فقط متن‌های ترجمه‌شده را روی آن ادغام می‌کند. code، gallery و حالت قیمت/تماس مقصد حفظ می‌شوند؛ مشخصات با id پایدار، نه موقعیت آرایه، تطبیق می‌یابند. ترتیب و ردیف‌های اختصاصی مقصد باقی می‌مانند؛ ردیف تازهٔ ترجمه‌شده تا سقف ۴۰ اضافه و ردیف مقصد خودکار حذف نمی‌شود. متن قیمت بدون تبدیل رقم/واحد پول منتقل می‌شود. برای ترجمهٔ نخست که هنوز meta ندارد، دادهٔ native بازسازی‌شدهٔ WPML مبناست؛ fallback ثبت‌شدهٔ خالی به اشتباه گالری مستقل محسوب نمی‌شود. payload نامعتبر مقصد موجود، دادهٔ معتبر قبلی را حفظ می‌کند. تکمیل بدون snapshot یا job نامرتبط دست به داده نمی‌زند؛ snapshot پس از مصرف آزاد است و option/جدول/صف همگام‌سازی دائمی نداریم.

مرجع محدود WoodMart `wpml-config.xml::custom-fields-texts`، [قرارداد رسمی WPML](https://wpml.org/documentation/support/language-configuration-files/custom-fields-translation-options/) از Context7 و parser/whitelist/اعمال job در WPML ارسالی 5.0.2 بررسی شدند؛ سورس مرجع تغییر نکرد. قرارداد کوتاه PHP از parser، matcher و numeric restoration واقعی WPML استفاده کرد؛ WordPress/DB و چرخهٔ دریافت/اعمال ATE واقعی mock هستند. پس از تازه‌شدن تنظیم XML، job تازه لازم است؛ jobهای قبلی خودکار بازنویسی نمی‌شوند. استقلال دو ماژول و نبود اجبار WPML در سایت تک‌زبانه حفظ است. این تغییر نگاشت هدر/فوتر/صفحات اختصاصی، sync انتخابی و پذیرش واقعی ترجمه/رسانه/کش را نمی‌بندد و اثبات ادغام بدون تعارضِ دو ذخیرهٔ هم‌زمان نیست.

نام و بستهٔ فعلی از ۲۰۲۶-۱۰-۲۱: **Radman CT Content 0.1.3** با `radmanct-content/radmanct-content.php`، text domain برابر `radmanct-content` و namespace برابر `RadmanCTContent`. نام Core در شواهد قدیمی تاریخی است. با درخواست مالک، سازگاری با بستهٔ آزمایشی قبلی یا مهاجرت اضافه نشده است. از این نام نهایی به بعد آپدیت native با basename ثابت انجام می‌شود؛ غیرفعال‌کردن یا آپدیت، محصول/نمونه‌کار و تنظیمات را حذف نمی‌کند. MCP از این بسته خارج و در [افزونهٔ مستقل](mcp.md) است.

وضعیت ۲۰۲۶-۱۰-۱۹: پایهٔ کاتالوگ و نمونه‌کار ساخته و در WordPress/DB موقت بررسی شده است؛ نیاز محصول در [سناریوی محتوا](../scenarios/content.md) باقی می‌ماند. مسیر افزونهٔ قابل نصب `radmanct-content/` و ZIP مستقل آن `radmanct-content-0.1.0.zip` است. Theme بدون این افزونه کار می‌کند؛ Core نیز برای ثبت/مدیریت داده به Theme وابسته نیست.

## فعال‌سازی و استقلال

رابط کارت‌های ماژول، لینک‌های مدیریت/افزودن/آرشیو، انتخاب مقصد با جستجوی محدود و بارگذاری مشترک فایل‌های مدیریت در [قرارداد مدیریت Core](core-admin.md) مالک مستقل دارند؛ وضعیت بررسی آن بخش نیز همان‌جاست.

منوی مستقل «هستهٔ رادمان» دو کلید جدا برای کاتالوگ و نمونه‌کار دارد؛ هر دو پیش‌فرض خاموش‌اند. فقط ماژول روشن، CPT/Taxonomy/متادیتا، hookهای مدیریت و پردازش مرتبط را ثبت می‌کند. حالت portfolio-only منطق query یا shortcodeهای کاتالوگ ندارد. حالت هر دو خاموش مدل محتوا و اتصال نمایشی قالب را هم وارد نمی‌کند. وبلاگ همان نوشتهٔ استاندارد WordPress است و این کلیدها روی دسترسی آن اثر ندارند.

فعال‌سازی، غیرفعال‌کردن ماژول، غیرفعال‌کردن افزونه و تعویض Theme داده را حذف نمی‌کنند؛ uninstall مخرب نداریم. rewrite فقط هنگام چرخهٔ فعال/غیرفعال و پس از تغییر کلیدها، یک بار در درخواست مدیریت بعدی تازه می‌شود؛ flush در هر درخواست عمومی نداریم. تنظیم فعال/غیرفعال پیکربندی کوچک است و فهرست محصولات را نمی‌خواند.

## داده و مدیریت

- کاتالوگ: CPT برابر `radman_product`، آرشیو پیش‌فرض `/products/`؛ taxonomyهای `radman_product_cat`، `radman_product_brand` و `radman_product_feature` برای دسته، برند و ویژگی.
- نمونه‌کار: CPT برابر `radman_portfolio`، آرشیو `/projects/` و taxonomy مستقل `radman_portfolio_cat`.
- عنوان، توضیح، خلاصه، تصویر شاخص و revision از WordPress/Gutenberg هستند. قابلیت‌های ویرایش از مجوز استاندارد نوشته و `map_meta_cap` استفاده می‌کنند؛ نقش/حساب عمومی تازه ساخته نشده است.
- متای ثبت‌شدهٔ `_radman_content_data` نسخهٔ ۱، کد مرجع، حداکثر ۲۰ شناسهٔ تصویر و تا ۴۰ ردیف مشخصات با id پایدار، label/value/unit دارد. مشخصات در UI محصول است؛ نمونه‌کار گالری دارد و فیلد/ستون/نمایش کد مرجع ندارد؛ کلید code در ساختار مشترک فقط برای سازگاری خالی می‌ماند. جدول اختصاصی، ویژگی عددی/بازه‌ای و فیلدساز عمومی وجود ندارند.

باکس اطلاعات تکمیلی، React خود WordPress و Media Library استاندارد را استفاده می‌کند. داده با دکمهٔ ذخیره/به‌روزرسانی همان نوشته ذخیره می‌شود. assets مدیریت فقط در ویرایش نوع محتوای فعال هستند؛ ویرایشگر مشخصات و CSS آن chunk اختیاری جدا دارند و در نمونه‌کار دریافت نمی‌شوند. مرورگر واقعی این UI بررسی نشده است.

**Content 0.1.7 — اصلاح متاباکس بر اساس تصویر مالک:** کد، گالری، نمایش قیمت/تماس و مشخصات گروه‌های جدا با جداکنندهٔ ساده و عرض محدود دارند؛ عنوان و اقدام افزودن گالری/مشخصات هم‌ردیف‌اند. عنوان تکراری قیمت از نمایش حذف و label دسترس‌پذیر آن حفظ شد؛ انتخاب قیمت/تماس، هشدار مقصد تماس و ذخیرهٔ داده تغییر نکردند. کارت تصویر به عرض کل متاباکس کش نمی‌آید؛ ورودی و انتخابگرها عرض منسجم و RTL/LTR منطقی دارند. این تغییر ظاهر مدیریت است؛ schema، nonce، محدودیت تعداد و مرز محصول/نمونه‌کار همان‌اند. پذیرش بصری Gutenberg/Classic روی هاست هنوز انجام نشده است.

نوشتن به nonce وابسته به نوشته، `edit_post` و نوع محتوای فعال نیاز دارد؛ autosave/revision یا نبود فیلد، اطلاعات قبلی را دست‌کاری نمی‌کند. JSON محدود به ۱۲۸ KiB و عمق ۸، اندازه‌ها/شناسه‌ها و رسانهٔ تصویر دارای مجوز بررسی می‌شوند؛ JSON/schema نامعتبر اطلاعات قبلی را حفظ می‌کند و notice مدیریت دارد. متا در REST عمومی نمایش داده نمی‌شود؛ endpoint عمومی نوشتن اختصاصی نداریم. هنگام update_post_meta، slash استاندارد WordPress رعایت می‌شود تا مقدار فنی دارای backslash خراب نشود.

## نمایش و query

**ادامهٔ سورس، ۲۰۲۶-۱۰-۲۴:** ترتیب پایدار پیش‌فرض و حفظ relevance طبق [قرارداد آرشیو](archive-ajax.md) اصلاح شد. cache درخواست گالری در `inc/integrations/content.php::gallery_ids` اکنون با شناسهٔ محتوا و زبان جاری WPML کلید می‌خورد؛ تغییر زبان در همان درخواست، تصاویر نگاشت‌شدهٔ زبان قبلی را مصرف نمی‌کند. بازگشت به زبان قبلی از cache همان زبان استفاده می‌کند. محافظ رمز پیش از cache و سقف ۲۰ تصویر و query با `suppress_filters=false` حفظ شدند. این بررسی قرارداد با hook شبیه‌سازی‌شده است، نه پذیرش نصب واقعی WPML.

### لمس گالری — Theme 0.1.13

از Theme 0.1.14، خود موتور dialog نیز در `shared/frontend/image-dialog.js` با Image افزونهٔ Components 0.1.6 مشترک شد؛ CSS نمایشی و adapter تشخیص گروه‌ها مستقل‌اند. قرارداد بارگذاری و استقلال بسته‌ها در [دارایی‌ها](assets.md) و جزئیات لایت‌باکس Image در [کامپوننت‌ها](components.md) است. CSS حالت hidden تصویر خراب صریح شد تا display:block آن را دوباره نشان ندهد.

گالری مشترک محصول/نمونه‌کار در dialog، swipe افقی touch/pen دارد؛ در RTL جهت پیمایش با جهت محتوا هماهنگ است. helper مشترک `shared/frontend/swipe.js` در Image افزونهٔ Components نیز مصرف می‌شود و به dist همان بسته تبدیل می‌شود؛ هاست به مسیر shared یا کتابخانهٔ تازه نیاز ندارد. listenerها فقط هنگام بازبودن dialog هستند و با بستن یا pagehide پاک می‌شوند. حرکت عمودی، ضربهٔ کوتاه، چند انگشت، pinch zoom، gesture لغوشده و نگه‌داشتن طولانی نباید تصویر را عوض کنند. `touch-action: pan-y pinch-zoom` فقط روی تصویر dialog اعمال است؛ اسکرول سند یا zoom مرورگر با preventDefault مسدود نمی‌شوند. تنها گروه دارای بیش از یک تصویر پیمایش می‌کند؛ تصویر بعدی پیش‌بارگذاری نمی‌شود. دکمه، کیبورد و fallback پیوندهای بدون JS حفظ شده‌اند. شش بررسی کوتاه گالری/swipe و Build پاس شدند؛ لمس دستگاه واقعی در این تغییر بررسی نشد.

### ابزارهای آرشیو و دسترسی مدیریت — ۲۰۲۶-۱۰-۱۹

در «طراحی محتوا» توضیح نقش Core و تفاوت نصب افزونه با روشن‌کردن ماژول‌ها اضافه شده است. لینک مدیریت ماژول‌ها فقط برای Core فعال و کاربر دارای `manage_options` می‌آید؛ در نبود آن، ورودی پیش‌نیازها نمایش داده می‌شود. لینک مدیریت موارد به مجوز ویرایش نیاز دارد و لینک آرشیو از API استاندارد WordPress فقط برای نوع فعال و ثبت‌شده گرفته می‌شود. لینک مصنوعی به آرشیو ماژول خاموش ساخته نمی‌شود. انتخاب renderer طبق [قرارداد روش نمایش](renderers.md) حتی برای ماژول خاموش قابل ذخیره است؛ این UI هیچ ماژولی را خودکار فعال نمی‌کند.

آرشیو برگهٔ دستی تازه نمی‌خواهد: بعد از روشن‌کردن هر ماژول و انتشار محتوا، CPT آرشیو مستقل خودش را دارد. مسیرهای پیش‌فرض `/products/` و `/projects/` هستند؛ برای زبان/ساختار پیوند سفارشی باید لینک تولیدشدهٔ «مشاهدهٔ آرشیو» مصرف شود. وجود template پایه به معنی تکمیل طراحی مشتری، فرم استعلام یا فیلتر پیشرفته نیست.

renderer فرم به ماژول `radmanct/inc/integrations/catalog-filters.php` تفکیک شده و فقط هنگام مصرف در آرشیو محصول/طبقه‌بندی خودش وارد می‌شود. فرم اصلی و shortcode همان خروجی را مصرف می‌کنند. شمار نتایج از `found_posts` کوئری اصلی خوانده می‌شود؛ کوئری شمارش موازی یا شمارش جدا برای هر term اضافه نشده است. فیلترهای فعال و ترتیب انتخاب‌شده با لینک مستقل حذف می‌شوند؛ باقی فیلترهای normalizeشده و زمینهٔ آرشیو/زبان حفظ و صفحه‌بندی از ابتدا شروع می‌شود. پارامترهای GET نامرتبط به URL حذف فیلتر کپی نمی‌شوند.

فهرست termها همچنان حداکثر ۱۰۰ قلم به‌علاوهٔ term منتخب بیرون از فهرست است. memoization فقط داخل همان درخواست و با کلید زبان/طبقه‌بندی است؛ نمایش دوبارهٔ فرم و shortcode query تکراری ندارد. cache پایدار، invalidation تازه یا ذخیرهٔ اطلاعات زبان در option اضافه نشده است. زبان query-string معتبر `lang` از action تولیدشدهٔ WordPress به hidden input تبدیل می‌شود تا فرم GET آن را حذف نکند؛ route پیوند ساده نیز حفظ است. این مسیر ادعای اجرای واقعی WPML یا تمام تنظیمات دامنه/پیوند آن نیست.

CSS نتایج و لینک‌های فیلتر فعال در همان stylesheet اختصاصی کاتالوگ/فیلتر قرار دارد؛ JS، React عمومی یا endpoint عمومی تازه نداریم. الگوی مستقل Active Filters در WoodMart فقط برای تجربهٔ حذف انتخاب بررسی شد؛ شمارش‌های فروشگاهی، WooCommerce، AJAX یا موتور facet آن منتقل نشده‌اند.

`tests/catalog-filters-contract.php` محدودیت query، استفادهٔ دوباره در همان زبان و تفکیک زبان‌ها، حفظ route/زبان، حذف مستقل انتخاب، escape، شمار اصلی در حضور کوئری ویجت و سکوت روی وبلاگ را بررسی می‌کند. `tests/content-navigation-contract.php` لینک‌های ماژول و مجوزها را پوشش می‌دهد؛ هر دو stub هستند و جای بررسی مرورگر/سرور را نمی‌گیرند.

Theme برای محصول و نمونه‌کار آرشیو، صفحهٔ جزئیات و CSS مستقل دارد؛ چند استایل آماده تحمیل نمی‌شود. اتصال نمایشی فقط با ماژول فعال وارد می‌شود. آرشیو محصول با query اصلی و صفحه‌بندی پیش‌فرض ۱۲ قلم کار می‌کند؛ جستجو، دسته، برند، ویژگی و ترتیب محدود جدیدترین/قدیمی‌ترین/عنوان دارد. ورودی‌های GET محدود و whitelist می‌شوند؛ tax_query استاندارد با قیود موجود ترکیب می‌شود و meta_query برای فیلتر مشخصات ساخته نشده است.

query کاتالوگ فقط آرشیو اصلی محصول و taxonomyهای خودش را هدف می‌گیرد؛ مدیریت، feed، REST، query ثانویه و وبلاگ دست‌نخورده‌اند. فهرست فیلترها حداکثر ۱۰۰ term و در صورت نیاز یک term منتخب اضافه دارد. گالری فقط شناسه‌های همان محتوا را به‌صورت محدود و گروهی می‌خواند؛ نوشتهٔ رمزدار تصویر/مشخصات خصوصی را در ابزارهای عمومی افشا نمی‌کند.

گالری CSS/JS جدا و dialog بومی با بستن/Escape، قبلی/بعدی و بازگشت focus دارد. JS فقط با marker گالری import می‌شود؛ بدون JS، تصاویر و پیوند فایل بزرگ باقی می‌مانند. عملکرد بصری، لمس و screen reader واقعی هنوز بررسی نشده‌اند. روش نمایش اختصاصی یا Pro طبق [قرارداد renderer](renderers.md) انتخاب می‌شود.

## استعلام، زبان و مرز

### جزئیات مشترک و وضعیت‌های خالی — ۲۰۲۶-۱۰-۱۹

`radmanct/inc/integrations/content-meta.php` نمایش کد مرجع محصول و termهای محصول/نمونه‌کار را مالک است. محصول دسته/برند/ویژگی و نمونه‌کار فقط دستهٔ خودش را می‌گیرد. خروجی `<dl>` معنایی، نام و نشانی escapeشده و `<bdi>` برای کد مختلط دارد؛ متادیتای خالی wrapper خالی نمی‌سازد. محافظ مشترک `content-access.php` محتوای عمومی منتشرشده را می‌پذیرد؛ نوع نامرتبط، ماژول خاموش و محتوای رمزدار پیش از خواندن داده/term کنار گذاشته می‌شوند. استثنای محدود پیش‌نمایش مجاز در بخش بعد مشخص است.

### پیش‌نمایش مجاز و رسانهٔ محصول — ۲۰۲۶-۱۰-۲۰

متادیتا، قیمت/تماس و منبع shortcode از `Content\Access::allowed` استفاده می‌کنند. پیش‌نویس/درانتظار/زمان‌بندی‌شده/خصوصی فقط وقتی قابل نمایش است که درخواست `is_preview`، single همان نوع، ID اصلی همان محتوا و `current_user_can('edit_post', id)` هم‌زمان برقرار باشند. `preview=true` یا مجوز ویرایش به‌تنهایی کافی نیست؛ مجوز برای یک محصول، اطلاعات draft محصول دیگری در Loop را باز نمی‌کند. رمز همچنان رعایت می‌شود. `is_preview` و capability با مستند رسمی Context7 بررسی شدند. این تغییر اطلاعات تکمیلی ذخیره‌شده را در پیش‌نمایش بومی قابل دیدن می‌کند؛ ذخیرهٔ زندهٔ فیلدهای فرم یا تغییر قرارداد autosave نیست.

رسانهٔ جزئیات اختصاصی در `inc/integrations/product-media.php` و partial قابل override `template-parts/content/product-media.php` است. تصویر شاخص و حداکثر ۲۰ تصویر گالری در یک گروه بزرگ‌نمایی قرار می‌گیرند؛ تصویر شاخص تکراری حذف و نبود/نامعتبر بودن تصویر اصلی با نخستین تصویر معتبر گالری جبران می‌شود. بدون تصویر، placeholder CSS می‌ماند و marker گالری تولید نمی‌شود. thumbnailهای اضافه در اندازهٔ `thumbnail` و lazy هستند؛ تصویر اصلی از `large` و اولویت native وردپرس استفاده می‌کند. مقصد پیوند بزرگ همان اندازهٔ large کنترل‌شده است، نه دانلود خودکار فایل اصلی پرحجم. بدون JS، پیوند تصویر کار می‌کند.

برچسب‌ها و پیوند امن تصویر بین این خروجی و گالری قبلی مشترک شدند؛ موتور dialog/RTL/کیبورد دوم ساخته نشد. گالری مشترک shortcode و نمونه‌کار تغییر رفتار نمایشی ندارد. stylesheet گالری در جزئیات محصول دارای تصویر شاخصِ تنها نیز بارگذاری می‌شود. الگوی محدود تصویر اصلی/تصاویر تکمیلی در `themes/woodmart/woocommerce/single-product/product-image.php` بررسی شد؛ WooCommerce، اسلایدر، زوم مرجع و چارچوب آن وارد نشدند. قراردادهای کوتاه متادیتا/رسانه و سه بررسی JS گالری پاس شدند؛ مرورگر/لمس و preview واقعی Elementor/WPML در این ادامه اجرا نشدند.

دریافت term از `get_the_terms` و cache استاندارد روابط همان نوشته است؛ query فهرست همهٔ دسته‌ها/محصولات ساخته نمی‌شود. نمایش هر taxonomy به ۲۰ مورد محدود است؛ این سقف خروجی است و ادعای محدودسازی SQL داخلی cache وردپرس نیست. شکست لینک term نام را به متن امن تبدیل می‌کند. لینک بازگشت از آرشیو native نوع محتوا می‌آید تا فیلترهای زبان و پیوند وردپرس حفظ شوند. APIها با Context7 و الگوی محدود label/link در `themes/woodmart/woocommerce/single-product/meta.php` تطبیق داده شدند؛ هیچ API، داده یا چارچوب WooCommerce وارد رادمان نشد.

قالب جزئیات از partial مستقل `template-parts/content/meta.php` استفاده می‌کند؛ Child Theme می‌تواند همین قسمت را بدون کپی کل صفحه تغییر دهد. CSS متادیتا در فایل مستقل `src/css/content-meta.css` است و در CSS جزئیات محصول/نمونه‌کار import می‌شود؛ در شورت‌کد المنتور فقط هنگام خروجی واقعی جدا مصرف می‌شود. renderer اختصاصی و المنتوری به خانوادهٔ فونت مرکزی وابسته‌اند و JS جدید ندارند. [ابزارهای PHP/Elementor](renderers.md).

حالت خالی آرشیو محصول، پیام مرتبط با تغییر/پاک‌کردن فیلتر دارد و فرم جستجوی عمومی سایت اضافه نمی‌کند؛ همان ابزار کاتالوگ مسیر جستجو/بازیابی است. نمونه‌کار پیام مستقل خودش و وبلاگ fallback جستجوی قبلی را حفظ می‌کنند.

گالری علاوه بر قبلی/بعدی و جهت کیبورد RTL/LTR، وضعیت بارگذاری، شمارهٔ تصویر و خطای تصویر ترجمه‌پذیر دارد. فقط تصویر بزرگ انتخاب‌شده در dialog بارگیری می‌شود؛ تصویر بزرگ بعدی پیش‌بارگذاری نمی‌شود. خطا، مسیر بستن یا رفتن به تصویر بعد را نمی‌بندد. overflow قبلی body و focus لینک بازکننده هنگام بستن برمی‌گردند؛ pagehide پس از بازگشت از bfcache نیز مسیر بستن را حفظ می‌کند. در شکست `showModal`، کلیک پیش از موفقیت prevent نمی‌شود و لینک فایل بزرگ قابل استفاده است. modifier، دکمهٔ غیرعادی ماوس، download و `_blank` رفتار native را حفظ می‌کنند.

`tests/content-meta-contract.php` مرز نوع محتوا/انتشار/رمز/ماژول، escape، سقف term، شکست لینک، route آرشیو و شورت‌کد/CSS مستقل را پوشش می‌دهد. سه آزمون `tests/gallery.test.mjs` بارگذاری تصویر انتخابی، خطا و بازگشت به تصویر دیگر، جهت RTL، اسکرول/focus، pagehide تکراری، modified click و شکست dialog را در DOM ساده بررسی می‌کنند. این بررسی‌ها تأیید native focus trap، کیفیت تصویر/لمس یا سرعت مرورگر نیستند.

### انتخاب قیمت یا تماس — اصلاح مالک در ۲۰۲۶-۱۰-۲۰

در ویرایش هر محصول، مدیر حالت `pricing.mode=contact/price` را انتخاب می‌کند. قیمت `pricing.text` متن نمایشی با واحد پول دلخواه، حداکثر ۳۲۰ بایت و ورودی UI حداکثر ۸۰ کاراکتر است؛ محاسبه، واحد پول سراسری، تخفیف، مالیات، موجودی، سبد و پرداخت ندارد. متن خالی چیزی نشان نمی‌دهد و رشتهٔ «۰» معتبر است. تغییر حالت متن قبلی قیمت را حذف نمی‌کند. داده در همان متای Core و schema نسخهٔ ۱ می‌ماند؛ نبود کلید قدیمی به contact و متن خالی تبدیل می‌شود و دادهٔ قبلی حذف نمی‌شود. ترجمه‌ها طبق copy-once متای موجود، مقدار مستقل خود را دارند.

در حالت تماس، پیوند مستقیم به برگهٔ عمومی و منتشرشدهٔ منتخب و نگاشت زبان آن داده می‌شود؛ query شناسهٔ محصول دیگر به نشانی افزوده نمی‌شود. مقصد draft/رمزدار/ترجمهٔ ناموجود و انتخاب صفر خروجی ندارند. کلید `radman_core_inquiry_page` و تابع `inquiry_url` برای سازگاری نام قبلی را حفظ کرده‌اند؛ رابط کاربری «تماس» نام دارد. فرم، ارسال، ذخیرهٔ درخواست و اعلان با دستور مالک **DEFERRED** هستند و جزو کمبود جاری نیستند؛ [تصمیم محصول](../scenarios/content.md).

کنترل قیمت/تماس و مشخصات در chunk اختیاری `src/js/admin/product-fields.js` فقط برای محصول وارد می‌شوند؛ نمونه‌کار این کنترل را ندارد. renderer عمومی مشترک Theme در `inc/integrations/product-display.php`، partial قابل override در `template-parts/content/product-display.php` و shortcode جدید `[rdct_product_display]` است. ابزار قدیمی `[radman_product_inquiry]` alias همان خروجی است تا صفحات قبلی با انتخاب قیمت هماهنگ شوند. خروجی عمومی قیمت/تماس به محصول فعال/منتشرشده/بدون رمز محدود است؛ پیش‌نمایش مجاز همان محصول از محافظ مشترک بالاتر پیروی می‌کند. متن escape می‌شود. CSS مستقل در جزئیات PHP import و در Elementor فقط هنگام مصرف enqueue می‌شود. هیچ JS عمومی جدید یا درخواست شبکه‌ای ندارد.

`wpml-config.xml` نوع محتوا و taxonomyها را ترجمه‌پذیر معرفی می‌کند. متای ساختاریافته طبق قرارداد بالای سند با Translate و whitelist متن معرفی می‌شود؛ ادغام job، دادهٔ مستقل مقصد را حفظ می‌کند. پذیرش واقعی ترجمهٔ خودکار هنوز باز است. شناسهٔ تصویر و مقصد تماس هنگام نمایش نگاشت WPML می‌گیرند. رشته‌های فارسی Core با فایل استاندارد افزونه `radmanct-content-fa_IR.mo` محلی ارائه می‌شوند؛ فونت/CDN، لایسنس یا اتصال خارجی اختصاصی اضافه نشده است. WPML واقعی هنوز آزمایش نشده است.

## بررسی انجام‌شده

### رسانهٔ مشترک محصول و نمونه‌کار — Theme 0.1.7

`inc/integrations/content-media.php` مالک مشترک تصویر شاخص و گالری است. adapter محصول همان نام/مرز product-only را نگه می‌دارد؛ partial مستقل `template-parts/content/project-media.php` نمایش نمونه‌کار را قابل override می‌کند. نمونه‌کار تصویر اصلی large و thumbnailهای سبک را در یک گروه dialog دارد؛ تصویر شاخص تکراری حذف می‌شود و نخستین تصویر معتبر گالری جای تصویر اصلی ناموجود/خراب را می‌گیرد. نمایش اختصاصی نمونه‌کار گالری دوم در انتهای صفحه نمی‌سازد. بدون تصویر placeholder CSS و بدون JavaScript پیوند واقعی تصویر باقی است. محافظ انتشار/رمز/پیش‌نمایش/ماژول پیش از دریافت رسانه اجرا می‌شود؛ حتی تصویر شاخصِ تنها stylesheet گالری را مصرف می‌کند. shortcode گالری و renderer مستقل Pro تغییر قرارداد ندارند.

کارت نمونه‌کار فقط دسته‌های پیونددار را از renderer متادیتای مشترک مصرف می‌کند؛ query فهرست محتوا یا engine تازه ساخته نشد. مبنای محدود نمایش تصویر/محتوا در `themes/hub/templates/portfolio/single/gallery-slider.php` و ورودی `single-liquid-portfolio.php` بررسی شد؛ اسلایدر، share و framework مرجع وارد نشدند. قرارداد رسانهٔ محصول/نمونه‌کار، متادیتا و سه بررسی JS گالری پاس شدند؛ پذیرش بصری/لمسی هاست باقی است. فهرست مدیریتی مشترک Content 0.1.3 در [مالک مدیریت](core-admin.md) ثبت است.

`tools/qa-core.ps1` روی WordPress 7.1.3/PHP 8.4.26 و دیتابیس موقت با شبکهٔ داخلی اجرا شد: خاموشی پیش‌فرض، ذخیرهٔ معتبر/نامعتبر/بدون nonce و مجوز، query واقعی دسته/برند/جستجو، حذف draft از نتایج، عدم اثر بر وبلاگ، نمایش مشخصات/گالری و CSS مرتبط، مقصد استعلام، حفاظت نوشتهٔ رمزدار و REST؛ سپس درخواست‌های تازه با Theme دیگر، فقط نمونه‌کار و هر دو خاموش. اطلاعات حفظ شدند و ماژول خاموش منطق query/نمایش خود را نداشت. این بررسی به build/check روزمره اضافه نشده است.

بررسی manifest، chunk مستقل مدیریت، نبود React عمومی، نسخهٔ minified و پوشش ترجمه در `npm run check` قرار دارد. افزونهٔ Core با مجوزهای قانونی استاندارد header ارائه می‌شود؛ هیچ سیستم فعال‌سازی لایسنس رادمان ندارد. PDF، مشخصات گروهی/عددپذیر، فیلتر پیشرفته و پذیرش واقعی WPML/کش/مرورگر باقی‌اند؛ فرم و ثبت درخواست با تصمیم جدید مالک DEFERRED هستند.

عنوان نمایشی صفحه و استثنای رسانه/پس‌زمینهٔ هر مورد، دادهٔ عمومی کاتالوگ نیست؛ در [ماژول عنوان صفحهٔ Theme](page-title.md) مالک دارد و به فعال‌بودن هر دو ماژول وابسته نیست.
