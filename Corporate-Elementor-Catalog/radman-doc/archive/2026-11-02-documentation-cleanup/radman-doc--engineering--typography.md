> آرشیو تاریخی پیش از جمع‌وجورکردن اسناد؛ مرجع قواعد جاری نیست. لینک‌ها به محل اصلی مقصدها اشاره می‌کنند.

# قرارداد فایل و انتخاب فونت

## عمومی، تفاوت محتوا و استثنای طراحی — اصلاح قطعی مالک، ۲۰۲۶-۱۱-۰۲

سه لایهٔ مشخص داریم: تنظیمات عمومی پایهٔ همهٔ صفحات است؛ `blog_typography`، `catalog_typography` و `portfolio_typography` فقط انتخاب‌های مستقل همان بخش را روی پایه حل می‌کنند؛ CSS طراحی مشتری فقط در scope عنصر/سکشن مربوط و برای استثنای عمدی اولویت دارد. پروفایل خالی از عمومی ارث می‌برد، نه از وبلاگ. تنظیمات وبلاگ نباید خودکار در محصول/نمونه‌کار کپی یا همگام شوند. سابقهٔ مقداردهی محلی بند بعد، قاعدهٔ ارث‌بری نیست. انتخاب ذخیره‌شدهٔ مالک هنگام این اصلاح تغییر نکرد.

مقایسه براساس مقدار مؤثر پس از resolve است؛ انتخاب خانوادهٔ بدنه می‌تواند خانوادهٔ تیترهای آن پروفایل را هم تغییر دهد، بنابراین برابر بودن نام یک فیلد با عمومی لزوماً به معنی برابر بودن کل پروفایل نیست. پروفایل خالی یا کاملاً برابر هیچ stylesheet اختصاصی نمی‌سازد. فقط تفاوت خانواده/وزن/اندازه/ارتفاع خط/رنگ چاپ می‌شود؛ @font-face فقط برای خانوادهٔ مصرفیِ تازه‌ای که در عمومی حاضر نیست لازم است. فونت‌های عمومی همچنان برای هدر/فوتر یا بخش‌های مصرف‌کننده باقی می‌مانند. تغییر صرفاً رنگ نباید فونت/اندازه را دوباره چاپ کند.

اصلاح تصویر مالک: H2 عمومی ۵۰px بود و اتصال مستقیم عنوان کارت/ابزارک به آن، عنوان‌های جمع‌وجور محصول را بزرگ کرده بود. H2 معنایی حفظ شد؛ اندازهٔ عنوان کارت مشترک محصول/نمونه‌کار عمداً از `--rdct-card-title-size` با پیش‌فرض `1.25rem` و عنوان ابزارک محصول از `--rdct-catalog-widget-title-size` با پیش‌فرض `1.0625rem` می‌آید. این‌ها فقط `--rdct-size-h2` همان عنصر را محدود می‌کنند؛ اندازهٔ H2 متن واقعی و خانواده/وزن/رنگ/ارتفاع خط از تنظیمات خودشان می‌آیند. برای طرح بعدی همان token محلی override شود؛ تنظیم H2 عمومی، tag عنوان یا سیستم تنظیمات جدید برای حل ظاهر کارت تغییر نکند.

خروجی اندازه، عدد را یک‌بار در token می‌نویسد و declaration مصرف‌کننده `font-size:var(--rdct-size-role)` دارد؛ رنگ نیز fallback تکراریِ همان HEX را دوباره چاپ نمی‌کند. متن و لینک سایدبار محصول tokenهای رنگ body/link را با fallback پالت می‌خوانند؛ رنگ تأکیدِ انتخاب فعال استثنای طراحی است. هیچ !important، خانوادهٔ ثابت، موتور یا فایل فونت تازه‌ای برای این اصلاح اضافه نشد.

CSS پایهٔ واقعاً مشترک کوچک می‌ماند؛ catalog و portfolio ورودی سبک مستقل و مشترکات کارت را از content-listing مصرف می‌کنند. CSS/JS سایدبار محصول فقط در نمای فعال و پُر، و منابع وبلاگ فقط در زمینهٔ وبلاگ بارگذاری می‌شوند. ساخت CSS/JS خالی برای هر نما یا کپی موتور فونت/حرکت لازم نیست؛ یک صفحهٔ ثابت ممکن است JS اختصاصی نخواهد. قرارداد پوشه/بارگذاری در [دارایی‌ها](../../engineering/assets.md) و مسیرهای مشتری در [سفارشی‌سازی](../../engineering/client-customization.md) است.

شواهد محدود: `tests/content-typography-runtime.php` چهار حالت خالی/برابر/رنگ/فونت تازه را روی هر شش نمای واقعی WordPress بررسی کرد؛ stylesheet اضافی برای خالی/برابر، font/size اضافه برای رنگ، و تکرار font-face تازه نداشت. قرارداد نقش‌ها، reset، responsive و هفت بررسی کوتاه Node پاس شدند. build و lint پاس شدند؛ خروجی HTTP آرشیو هر سه بخش فقط دو font-face موجود و صفر font-face تازه در پروفایل داشت و CSS سایدبار محصول/وبلاگ در صفحهٔ دیگری چاپ نشد. گراف JS سایدبار محصول، موتورهای نامرتبط را نداشت. مشاهدهٔ بصری/Network مرورگر و بنچمارک انجام نشدند.

## ارث‌بری محصول و نمونه‌کار مانند وبلاگ — تأکید مالک، ۲۰۲۶-۱۱-۰۲

خانواده، وزن، اندازه و ارتفاع خط محصول و نمونه‌کار از همان پروفایل‌های موجود و تنظیمات عمومی خوانده شوند؛ فونت ثابت یا پنل موازی در Child مجاز نیست. برای هماهنگی اولیهٔ ظاهر با وبلاگ، انتخاب‌های خالی پروفایل‌های محلی از انتخاب فعلی وبلاگ تکمیل شدند؛ این یک مقداردهی محلی بود، نه ارث‌بری دائمی از blog_typography. انتخاب صریح هر بخش اولویت دارد و تغییر بعدی مالک در طول کار حفظ شد؛ نمونه‌کار اکنون می‌تواند H1 را هم از فونت بدنهٔ پروفایل خودش بگیرد. دادهٔ هر سه پروفایل همچنان مستقل، در همان radman_settings و با reset/ارث‌بری موجود است.

اندازه/ارتفاع خط محتوای اصلی و عنوان/توضیح جزئیات از tokenهای مشترک مصرف می‌شوند. استثنای بعدیِ عنوان جمع‌وجور کارت/ابزارک در قرارداد سه‌لایهٔ بالا ثبت شده و جای اتصال مستقیم قبلی آن‌ها به اندازهٔ H2 عمومی را می‌گیرد. خانواده یا فایل فونت تازه‌ای اضافه نشد؛ شواهد و حدود پذیرش همین بخش در قرارداد بالا آمده‌اند.

خروجی اختصاصی هر سه پروفایل با تایپوگرافی عمومی مقایسه می‌شود؛ خانواده و وزنِ حل‌شده، ارتفاع خط، رنگ و اندازه‌های واکنش‌گرای یکسان دوباره چاپ نمی‌شوند. تنظیمات کاملاً یکسان حتی inline handle اختصاصی نمی‌سازند. alias نقش فقط همراه تغییر خانوادهٔ همان نقش لازم است؛ متغیرهای یکسان بدنه دوباره تعریف نمی‌شوند. بازگشت اندازهٔ موبایل به مقدار عمومی پس از override دسکتاپ باید حفظ شود. fallbackهای CSS و قواعد مرورگر که در DevTools خط می‌خورند، معادل بارگذاری تکراری فایل فونت نیستند و حذف عمومی آن‌ها مجاز نیست؛ هدر/فوتر همچنان مصرف‌کنندهٔ تایپوگرافی اصلی‌اند.

تایپوگرافی محتوا در همان `radman_settings` و تنها سه پروفایل `blog_typography`، `portfolio_typography` و `catalog_typography` ذخیره می‌شود؛ هرکدام مشترک فهرست/جزئیات همان محتواست. کلیدهای تکراری قبلی سایت محلی با حفظ انتخاب‌ها منتقل شدند. مقادیر خالی ارثی‌اند. `typography-profiles.php` اعتبارسنجی و resolve را با registry و موتور موجود انجام می‌دهد؛ `content-typography-fields.js` فقط در صفحهٔ تایپوگرافی انتخابی، کنترل‌های مشترک و ذخیرهٔ اصلی را مصرف می‌کند. CSS فقط برای محتوای مصرف‌کننده و داخل main تولید می‌شود؛ فونت اضافی تنها در صورت نیاز همان صفحه بارگذاری می‌شود. صفحه/endpoint/برنامهٔ مستقل Child وجود ندارد.

صفحه‌های فونت، ۲۰۲۶-۱۰-۳۰: ماژول TypographyFields مشترک و lazy برای primary/secondary/loading مصرف می‌شود؛ فرم/registry/runtime موازی ساخته نشده است. نام کلیدهای persian/latin برای سازگاری داده حفظ می‌شود، اما رابط بر پایهٔ نقش اصلی/مکمل و گروه خط نام‌گذاری می‌شود. hash قبلی typography به typography_primary هدایت می‌شود. ذخیرهٔ واحد همچنان تمام values را می‌فرستد و reset صفحه از گروه اصلی مؤثر پیروی می‌کند. [تصمیم رابط](../../scenarios/settings.md).

تکمیل ۲۰۲۶-۱۰-۳۰: نقش‌های link/span به registry و فرم مشترک اضافه شدند؛ والد خانواده/وزن آن‌ها body است، اما CSS مستقل تنها برای مقدار صریح تولید می‌شود تا span خالی از والد واقعی خود ارث ببرد. رنگ‌های body/headings/H1–H6/link/span و link_hover_color خالی یا HEX شش‌رقمی معتبرند؛ ورودی نامعتبر مقدار قبلی را حفظ می‌کند. اندازه‌ها علاوه بر قانون نقش، tokenهای واکنش‌گرای --rdct-size-role دارند تا Child بدون !important یا موتور موازی آن‌ها را مصرف کند. وزن/ارتفاع خط و رنگ نیز از token مشترک خوانده می‌شوند. نقش span به متن داخل p/H1–H6 محدود است و aria-hidden/آیکون‌های رادمان خارج‌اند؛ لینکِ دکمه از قانون عمومی لینک جداست. فرم از ColorSetting و کنترل‌های مشترک استفاده می‌کند؛ چیدمان نقش‌ها در پنل عریض پنج ستون با عرض متناسب خانواده، وزن، اندازه، ارتفاع خط و رنگ دارد؛ container query بر اساس فضای واقعی پنل آن را به سه، دو و یک ستون تبدیل می‌کند. gap و فاصلهٔ نقش‌ها فشرده است؛ کنترل و موتور فونت مشترک تغییر نکرده‌اند. قرارداد نقش‌های PHP، ۹ بررسی Node، تولید CSS در WordPress واقعی بدون نوشتن تنظیمات و build پاس شدند؛ ذخیره از UI و ماتریس کامل Elementor بررسی نشد.

اصلاح بعدی همان روز: طبق درخواست مالک، نمونهٔ شماتیک کناری تنظیمات و تمام CSS چیدمان has-preview حذف شدند؛ توضیح‌های تاریخی زیر دربارهٔ نمایش اندازهٔ دسکتاپ در آن نمونه دیگر رفتار جاری نیستند. نمونهٔ واقعی خانواده داخل FontField باقی است. [مالک رابط](../../engineering/admin-ui.md).

## اصلاح تراز با پنل پیش‌نمایش — ۲۰۲۶-۱۰-۲۹

تصویر بعدی مالک نشان داد صرفاً full-width کردن input/select کافی نبود: قانون عمومی `.rdct-stg__body.has-preview .rdct-stg__field` با specificity بالاتر، فیلدهای تایپوگرافی را دوباره دو ستونی می‌کرد. قانون عمومی اکنون فرزندان مستقیم typography-role را مستثنا می‌کند؛ همان Grid تک‌ستونی برچسب بالا/کنترل پایین، عرض کامل ستون و Grid چهارستونی نقش اعمال می‌شوند. wrapper، !important یا کنترل اختصاصی جدید اضافه نشد. ظاهر فقط از بررسی سورس/CSS و Build نتیجه گرفته شده و مرورگر در این اصلاح اجرا نشده است.

## اندازهٔ responsive و عرض کنترل‌ها — ۲۰۲۶-۱۰-۲۹

تنظیم‌های `ROLE_GROUP_size`، `ROLE_GROUP_tablet_size` و `ROLE_GROUP_mobile_size` برای body/headings/h1 تا h6 و persian/latin اضافه شدند. ورودی عددی ۸ تا ۲۰۰ پیکسل، با مقدار خالی برای بازگشت به پیش‌فرض و validation عدد متناهی/دو رقم اعشار است. پنل با کنترل‌های مشترک و انتخاب دستگاه واحد کار می‌کند؛ مقادیر زبان و دستگاه غیرفعال با hiddenهای بدون کلید تکراری حفظ می‌شوند. الگوی عدد پیکسلی و دستگاه‌های مرجع WoodMart در `controls/typography/class-typography.php` بررسی شد؛ framework یا JS آن منتقل نشد.

خروجی مشترک Typography مقادیر را با مبنای ۱۶ به rem تبدیل می‌کند؛ breakpointها 1024 و 767 هستند. موبایل از تبلت و دسکتاپ، و هر تگ فاقد اندازه از نقش headings استفاده می‌کند. اندازهٔ body جای اندازهٔ پیش‌فرض تیترها نمی‌نشیند. rule خالی و breakpoint فاقد تغییر تولید نمی‌شود. scope عمومی `.rdct-site` حفظ شد؛ scope محتوای Gutenberg با اصلاح ۲۰۲۶-۱۱-۰۱ از تزریق Typography خارج شد؛ `:where` روی تگ‌ها از افزایش specificity بی‌نیاز جلوگیری می‌کند و اندازهٔ صریح عنصر/المنتور اولویت خود را حفظ می‌کند. پیش‌نمایش تنظیمات اندازهٔ دسکتاپ انتخابی را نشان می‌دهد؛ انتخاب دستگاه کنترل فقط مقدار مورد ویرایش را عوض می‌کند.

fieldset تایپوگرافی Grid چهارستونی دارد؛ فیلدهای داخل آن Grid تک‌ستونی و کنترل‌های تمام عرض ستون‌اند تا wrapper در Flex به اندازهٔ متن جمع نشود. در عرض کم یک ستون می‌شود. select عمومی تنظیمات نیز عرض فضای فیلد، با سقف خوانای 36rem دارد؛ این CSS وارد پنل‌های دیگر WordPress یا Elementor نمی‌شود.

Build و lint سه PHP، قرارداد PHP نقش/اندازه و دو تست کوتاه JS شامل حفظ مقادیر دستگاه/زبان، validation/reset و CSS بدون breakpoint تکراری پاس شدند. مرورگر و پذیرش بصری اجرا نشد؛ تنظیمات ذخیره‌شدهٔ سایت تغییر نکردند.

## ورود اندازه با rem — CONFIRMED، ۲۰۲۶-۱۱-۰۱

با تأیید منظور مالک، واحد کنترل اندازه همان rem خروجی است؛ تفاوت نمایش قبلی px با خروجی rem کنار رفت. `typography-size.js` adapter نمایش/ورود است: مقدارهای موجود با تقسیم بر ۱۶ نمایش داده و ورودی rem برای قرارداد ذخیره‌سازی قبلی به مقدار عددی معادل برگردانده می‌شوند. migration یا تفسیر مجدد مقدارهای قدیمی نداریم. حد نمایشی ۰٫۵ تا ۱۲٫۵rem معادل قرارداد قبلی ۸ تا ۲۰۰ است؛ اعشار و مقدار خالیِ ارث‌بری حفظ‌اند. ورودی نمایشی name ذخیره‌سازی ندارد و hidden کنترل فعال، مثل دستگاه/زبان غیرفعال، مقدار canonical را یک‌بار می‌فرستد. draft محلی تایپ اعشار را حفظ می‌کند؛ reset بیرونی و تغییر دستگاه/زبان دوباره با مقدار canonical همگام می‌شوند.

واحد label صریح و راهنمای مشترک به ریشهٔ صفحه اشاره می‌کند. `em` برای اندازهٔ سراسری انتخاب نشده تا بزرگ‌شدن وابسته به والد در تودرتویی رخ ندهد. تبدیل، حساب ساده در تولید CSS/ویرایش تنظیم است؛ هیچ JS دوره‌ای یا query جدیدی روی فرانت اضافه نشده است. ۳ بررسی کوتاه UI/round-trip شامل ۱۷↔۱٫۰۶۲۵ و حفظ کلیدهای فرم، Build و PHP lint پاس شدند؛ رفتار بصری مرورگر یا benchmark سرعت اندازه‌گیری نشد. مرجع معنای واحدها: [MDN font-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-size).

## مرز مستقل ادیتورها — CONFIRMED، ۲۰۲۶-۱۱-۰۱

طبق اصلاح مالک، مجوز قبلی فونت نقش‌های سایت در Gutenberg و Peyda رابط Elementor کنار گذاشته شد. تزریق `block_editor_settings_all` و helper آن، ثبت editor-style والد/Child و hook فونت UI Elementor حذف شدند. سورس و ورودی‌های بی‌مصرف `editor.css` و `admin/elementor-typography.css` نیز حذف شدند؛ selectorهای Gutenberg از CSS تولیدی و `heading-fonts.css` کنار رفتند. نقش‌های فرانت فقط `.rdct-site` را هدف می‌گیرند. دادهٔ مقاله، تنظیمات فونت سایت و استایل صریح محتوای ذخیره‌شده تغییر نکردند.

Peyda مدیریت فقط با enqueue واقعی تنظیمات، سازنده و پیش‌نیازهای خود رادمان می‌آید. Build، lint چهار PHP و قرارداد کوتاه پنل پاس شدند؛ بررسی فقط‌خواندنی WordPress نبود hook/استایل ادیتور، نبود فونت پنل در صفحهٔ نامرتبط و باقی‌ماندن فونت فرانت را تأیید کرد. مرورگر و suite طولانی اجرا نشدند.

## سابقهٔ رفع سرایت به عنوان Gutenberg — ۲۰۲۶-۱۰-۲۸

این بخش سابقهٔ اصلاح قبلی است؛ مجوز فونت محتوایی Gutenberg که پایین شرح داده شده با اصلاح ۲۰۲۶-۱۱-۰۱ لغو شد.

گزارش مالک نشان داد عنوان ویرایش برگه فونت نمایشی H1 را گرفته است. علت، selectorهای عمومی `.editor-styles-wrapper` در `editor.css` و `heading-fonts.css` و CSS نقش‌های ارتفاع خط بود؛ این مورد از Peyda پنل مدیریت نبود. فونت، وزن، رنگ و ارتفاع خط محتوایی اکنون به ناحیهٔ `.block-editor-block-list__layout` در بوم محدودند؛ عنوان سند بیرون آن است. selectorهای فرانت `.rdct-site` و مرز مستقل فونت پنل رادمان حفظ شدند؛ reset سراسری، wrapper یا !important تازه اضافه نشد.

در مرورگر لوکال WordPress 7.1.3، پیش از اصلاح عنوان و بلوک هر دو خانوادهٔ سایت داشتند؛ پس از build، عنوان «درباره ما» دیگر خانوادهٔ Radman CT نداشت و line-height بومی normal بود. صفحهٔ کار مالک reload یا ذخیره نشد؛ بررسی در تب جدا انجام شد. قراردادهای کوتاه typography roles/admin و build پاس شدند و guard محدودهٔ selector و ارتفاع خط اضافه شد. پذیرش تمام نسخه‌های Gutenberg/Classic Editor و همهٔ بلوک‌های ثالث ادعا نمی‌شود. [مرجع رسمی محدودهٔ editor styles](https://github.com/WordPress/gutenberg/blob/trunk/docs/how-to-guides/themes/theme-support.md).

## ارتفاع خط و چیدمان کنترل‌ها — ۲۰۲۶-۱۰-۲۷

تنظیمات `{body|headings|h1..h6}_{persian|latin}_line_height` ارتفاع خط بدون واحد، بین ۰٫۸ و ۴ با دقت دو اعشار یا رشتهٔ خالی‌اند. خالی ظاهر قبلی/ارث‌بری را حفظ می‌کند؛ عدد به خانوادهٔ فونت وابسته نیست. بدنه، تیترها و هر تگ همان زنجیرهٔ وراثت نقش‌ها را دارند. tokenهای `--rdct-line-height-body/h1..h6` و CSS محدود نقش فقط برای مقادیر مؤثر ساخته می‌شوند؛ وزن/ارتفاع صریح کامپوننت با !important اجباراً بازنویسی نمی‌شود. گروه زبان فعال و نبود بارگذاری خانوادهٔ بی‌مصرف حفظ شدند.

رابط هر نقش یک fieldset با سه کنترل native خانواده، وزن و ارتفاع خط است؛ در عرض کم تک‌ستونی می‌شود. پیش‌نمایش، بدنه و H1–H6 را با خانواده/وزن/ارتفاع خط انتخاب‌شده نشان می‌دهد. تب غیرفعال hidden inputهای ارتفاع خط را نیز حفظ می‌کند؛ ذخیرهٔ AJAX از state کامل استفاده می‌کند. reset همان بخش همهٔ این کلیدها را شامل می‌شود. ماژول کنترل‌های تایپوگرافی فقط هنگام بازشدن تب import می‌شود؛ helper زبان ۲۱۳ بایتِ مشترک داخل محدودهٔ حجم قبلی باقی است. قراردادهای وراثت، اعشار، ورودی نامعتبر و مسیرهای فونت موفق شدند؛ ظاهر واقعی تنظیمات میزبان هنوز بررسی نشده است.

## خانواده‌های جدید و انتخاب وزن — ۲۰۲۶-۱۰-۲۷

metadata فایل‌های فعلی با FontTools محلی خوانده شد؛ Dana با وزن‌های ۳۰۰/۴۰۰/۵۰۰/۷۰۰/۸۰۰، Aria با ۴۰۰/۵۰۰/۷۰۰/۸۰۰/۹۰۰ و Hafez FD با ۴۰۰ اضافه شدند. فایل Aria Normal با Regular متفاوت است ولی هر دو در OS/2 وزن ۴۰۰ دارند؛ برای جلوگیری از دو face هم‌وزن مبهم، Normal گزینهٔ مستقل `aria-normal` با یک فایل است. اکنون ۱۲ انتخاب فارسی و دو لاتین وجود دارد. دو پوشهٔ Yekan و IRANYekan فایل‌های همسان با SHA-256 یکسان دارند؛ کلید ذخیره‌شدهٔ `iranyekan` حفظ و مسیر canonical به Yekan منتقل شد، بدون حذف فایل مالک یا ساخت خانوادهٔ تکراری. حروف مسیرهای Pinar/Peste با دیسک تطبیق داده شدند تا Linux نیز معتبر باشد.

`Fonts::weights()` گزینه‌های مجاز را از همان بازه/وزن فایل registry می‌سازد؛ لیست مستقل وزن در JS نداریم. تنظیمات `{body|headings|h1..h6}_{persian|latin}_weight` رشتهٔ عدد معتبر یا خالی‌اند. کنترل native select نام ترجمه‌شده و عدد دارد؛ وراثت خانواده و وزن مستقل‌اند. هنگام تغییر خانواده، وزن صریح ناسازگار پاک می‌شود؛ PHP نیز مستقل اعتبارسنجی می‌کند. وزن ارث‌رسیده برای خانوادهٔ دیگر به نزدیک‌ترین وزن موجود محدود می‌شود. انتخاب قدیمی بدون وزن، ظاهر قبلی را حفظ می‌کند. وزن‌های نقش‌ها از tokenهای `--rdct-weight-body` و `--rdct-weight-h1..h6` به PHP/Elementor می‌رسند، بدون !important یا تغییر کنترل وزن خود ویجت. hidden inputهای تب دیگر و reset بخش، وزن‌ها را نیز پوشش می‌دهند.

اعلان face فقط برای خانواده‌های مؤثر زبان صفحه است؛ معرفی وزن‌های خانوادهٔ منتخب، دانلود اجباری تمام فایل‌ها نیست و مرورگر وزن مصرفی را درخواست می‌کند. preload همچنان اختیاری و حداکثر یک فایل بدنهٔ هر گروه است؛ اگر وزن بدنه مشخص باشد همان وزن به‌جای Regular ترجیح داده می‌شود. بررسی شبکهٔ میزبان/کش و ظاهر واقعی ادیتور در این تغییر اجرا نشده‌اند.

اصلاح Text در ۲۰۲۶-۱۰-۲۶: خانوادهٔ پیش‌فرض h1 تا h6 از متغیر نقش همان عنوان می‌آید؛ خانوادهٔ بدنه نباید آن را بازنویسی کند. قانون اجباری خانواده روی spanهای داخلی حذف شد تا انتخاب مجاز محلی هر segment حفظ شود. خانهٔ مشتری نیز همین نقش‌ها را مصرف می‌کند؛ تأیید دیداری همهٔ ویجت‌ها در نصب میزبان همچنان باز است.

## اصلاح پوشش خانواده — ۲۰۲۶-۱۰-۲۵

قاعدهٔ خانواده در frontend و preview شامل div، تگ‌های Atomic و کلاس‌های متنی شد؛ فونت آیکون‌های دارای کلاس و محدودهٔ کتابخانه مستثنا هستند. پنل والد ادیتور هدف این CSS نیست. سیاست خانواده از تنظیمات قالب حفظ شد؛ تأیید دیداری میزبان باقی است.

## گروه فعال زبان — ۲۰۲۶-۱۰-۲۴

رابط `TypographyFields` همیشه دو گروه انتخاب دارد؛ `fontGroups()` فقط scope اعلان پیش‌نمایش معمول مدیریت است و شرط نمایش انتخاب‌ها نیست. نقش‌های گروه غیرفعال با hidden input کنترل‌شده همچنان در فرم حضور دارند، تا ویرایش هر دو تب پیش از ذخیره حفظ شود. برای مشاهدهٔ فونت گروه دیگر، فقط اعلان همان گروه در مدیریت اضافه می‌شود؛ PHP عمومی، `active_groups()` و preload تغییر نکردند. wrapper و map تک‌عضوی قبلی فیلدها حذف شدند؛ بدنه/تیتر/تگ‌ها همان Field مشترک را مصرف می‌کنند.

`Fonts::primary_group()` زبان جاری معتبر WPML، سپس `font_language` و locale را resolve می‌کند. `active_groups()` به‌صورت پیش‌فرض یک گروه و فقط با `mixed_language_fonts` هر دو گروه را برمی‌گرداند. `Typography::used()`، اعلان CSS و preload همان گروه فعال را رعایت می‌کنند؛ خانواده‌های بی‌مصرف حتی در انتخاب preload حذف می‌شوند. alias بدنه و تگ‌ها از گروه اصلی می‌آیند؛ override زبان داخلی فقط در حالت ترکیبی تولید می‌شود. فهرست فونت Elementor نیز مصرف‌کنندهٔ همین خروجی است. رابط تنظیمات زبان‌های قابل تنظیم را مستقل از بارگذاری عمومی نشان می‌دهد. قرارداد PHP برای تک‌زبان، تعویض زمینهٔ WPML و حالت ترکیبی گسترش یافت؛ اجرای تازهٔ آن به علت نبود PHP و خاموش‌بودن Docker انجام نشد.

## کنترل عمومی Google Fonts — پیاده‌شده، Theme 0.1.45، ۲۰۲۶-۱۰-۲۳

نیاز کلید در [سناریوی فونت](../../scenarios/typography.md) ثبت است. افزونهٔ ارسالی `themes/disable-remove-google-fonts/` نسخهٔ 2.0.3 بررسی شد: `inc/remove-google-fonts.php` حذف URLهای Google از صف stylesheet، حذف resource hint و فیلترهای مشخص افزونه‌ها از جمله Elementor دارد؛ `inc/font-audit.php` audit با loopback و خواندن CSS دارد. نصب یا اجرای افزونه انجام نشد. framework، فهرست بلند سازگاری قالب‌های نامرتبط، تبلیغ و موتور audit/درخواست آن وارد رادمان نشدند.

`block_google_fonts` در Settings با validation بولی، پیش‌فرض true و reset همان بخش پیاده شد. `inc/google-fonts.php` فقط هنگام روشن‌بودن option بارگذاری می‌شود؛ callbackها نیز مقدار جاری را رعایت می‌کنند. تطبیق دقیق hostهای `fonts.googleapis.com`، `fonts.gstatic.com` و `fonts.google.com`، با حروف بزرگ/کوچک، URL بدون scheme و نقطهٔ انتهای host انجام می‌شود؛ دامنهٔ شبیه یا نام Google در مسیر URL مسدود نمی‌شود.

`style_loader_src` منبع را خالی می‌کند و handle/dependency را حذف نمی‌کند؛ رفتار واقعی `WP_Styles` وردپرس 7.1.3 بررسی شد و stylesheet محلیِ وابسته همچنان چاپ می‌شود. `script_loader_tag` tag منبع Google را حذف می‌کند تا script با src خالی تولید نشود؛ resource hint و preload مرتبط حذف و درخواست تازهٔ WordPress HTTP API با `WP_Error` متوقف می‌شود. پاسخ short-circuit قبلی حفظ می‌شود. local registry، فونت آیکون و منابع نامرتبط تغییر نمی‌کنند. شرط Elementor از قبل در adapter موجود است؛ خاموش‌کردن محافظ عمومی آن را به دریافت فونت خارجی وادار نمی‌کند و optionهای افزونه تغییر نمی‌کنند. فعال‌بودن این کنترل دانلود یا تبدیل خودکار فونت خارجی به محلی نیست. فونت دارای مجوز باید از قبل به registry محلی پروژه اضافه شود.

حدود ادعا: فیلترهای WordPress فقط مسیرهای تحت کنترلشان را می‌بندند؛ `@import` داخل CSS دلخواه، link خام، تزریق JavaScript، iframe و نسخهٔ کش‌شده لزوماً از صف WordPress عبور نمی‌کنند. وعدهٔ «قطع قطعی تمام منابع خارجی سایت» از این کلید نتیجه نشود. سیاست مرورگر/CSP در صورت درخواست سخت‌گیرانه نیاز به طراحی جدا و بررسی ناسازگاری دارد؛ CSP سراسری یا output buffering/regex روی کل صفحه پیشنهاد پیش‌فرض نیست. پاک‌سازی کش و بررسی Network/سمت سرور در دامنهٔ واقعی برای پذیرش لازم‌اند.

منابع API بررسی‌شده با Context7: [style_loader_src](https://developer.wordpress.org/reference/hooks/style_loader_src/)، [wp_resource_hints](https://developer.wordpress.org/reference/hooks/wp_resource_hints/)، [pre_http_request](https://developer.wordpress.org/reference/hooks/pre_http_request/). مسیر منع Google و فونت‌های Pro فعلی در [قرارداد Elementor](../../engineering/elementor.md) است.

بررسی کوتاه `tests/google-fonts-contract.php` با PHP 8.4.26، کلاس‌های واقعی WP_Styles/WP_Error تصویر موجود و شبکهٔ خاموش، حفظ CSS وابسته، hostهای دقیق، فونت محلی، hint/preload، درخواست HTTP و حالت خاموش/ورودی نامعتبر را پوشش داد. قراردادهای settings و مرز Elementor نیز پاس شدند؛ مرورگر، Network، CSS/کش واقعی افزونه‌های مشتری و توقف درخواست تمام منابع دلخواه بررسی نشده‌اند.

وضعیت: پیاده‌سازی در ۲۰۲۶-۱۰-۱۹؛ سناریوی محصول و اولویت بر Elementor در [تایپوگرافی](../../scenarios/typography.md) است.

## مرجع واحد

### فونت رابط مدیریت رادمان

اصلاح ۲۰۲۶-۱۱-۰۱ جای override قدیمی MUI در ۲۰۲۶-۱۰-۲۵ را گرفت: فونت UI خود Elementor بومی می‌ماند و stylesheet/hook اختصاصی آن حذف شدند. فونت مدیریت رادمان فقط به صفحه‌های خودش تعلق دارد.

`inc/admin/typography.php` و `src/css/admin/typography.css` فقط وقتی stylesheet تنظیمات، سازنده یا پیش‌نیازهای رادمان enqueue شده باشد فعال‌اند. فونت فارسی `Radman CT Admin Peyda` از همان فایل محلی `persian/Peyda/PeydaWebVF.woff2` با وزن ۱۰۰–۱۰۰۰ و `font-display:swap` اعلان می‌شود. `unicode-range` حروف فارسی/عربی و نویسه‌های اتصال/جهت را پوشش می‌دهد؛ حروف لاتین به stack سیستمی مدیریت (`-apple-system`، `BlinkMacSystemFont`، `Segoe UI` و fallbackهای نصب‌شدهٔ سیستم) می‌روند. نام این fallbackها هیچ stylesheet یا فایل فونت خارجی درخواست نمی‌کند؛ لاتین پنل فایل جدا ندارد.

CSS با کلاس اختصاصی body به `.wrap` همان صفحه محدود است و form controlها ارث می‌برند؛ dashicons، منوی مدیریت، صفحه‌های افزونه‌ها و iframe پیش‌نمایش سایت دستکاری نمی‌شوند. خانوادهٔ فارسی انتخاب‌شده برای سایت و نمونهٔ فونت در پنل همچنان مستقل‌اند. فونت از مسیر قالب والد خوانده می‌شود تا Child Theme به کپی دوباره نیاز نداشته باشد. hookهای `wp_style_is` و `wp_add_inline_style` با مرجع رسمی وردپرس از Context7 تطبیق داده شدند. قرارداد `tests/admin-typography-contract.php` نبود بارگذاری در صفحهٔ نامرتبط، ترتیب dependency و URL محلی/محدودهٔ حروف را بررسی می‌کند؛ درخواست‌های افزونه‌های دیگر و رندر مرورگر بررسی نشده‌اند.

مسیر و وزن Peyda از کلید `peyda` همان registry خوانده می‌شوند؛ فهرست فایل موازی در ماژول مدیریت نداریم. stack لاتین با `wp-admin/css/common.min.css` نسخهٔ محلی وردپرس داخل image توسعه، بدون شبکه، تطبیق داده شد؛ همان font-family سیستمی است و فایل لاتین تازه‌ای لازم ندارد.

`radmanct/inc/font-registry.php` مالک کلید، گروه، نام نمایشی، خانوادهٔ CSS، مسیر و وزن هر فایل است. validation تنظیمات، انتخاب runtime و گزینه‌های پنل همین مرجع را مصرف می‌کنند؛ فهرست موازی داخل React نداریم. registry یک آرایهٔ مشخص است و در هر درخواست پوشه‌های فونت را اسکن نمی‌کند.

گروه `persian` برای انتخاب فارسی و `latin` برای انگلیسی مستقل است. تنظیم قبلی با کلیدهای `iransansx`، `peyda`، `gramophone` و `gt-walsheim` معتبر باقی می‌ماند؛ پیش‌فرض‌ها تغییر نکرده‌اند. انتخاب ناموجود یا متعلق به گروه دیگر، مقدار معتبر قبلی/پیش‌فرض را حفظ می‌کند. فیلتر `radmanct/typography/fonts` نیز همین مرز گروه را رعایت می‌کند.

افزودهٔ ۲۰۲۶-۱۰-۲۰: metadata فایل Manrope با همان ابزار محلی و بدون شبکه خوانده شد؛ نام typographic family برابر Manrope، محور wght برابر ۲۰۰–۸۰۰ با پیش‌فرض ۲۰۰، italicAngle صفر و اندازهٔ فایل ۵۴۳۳۶ بایت است. نام legacy خانواده `Manrope ExtraLight` است؛ ثبت به‌عنوان فونت ثابت ۲۰۰ اشتباه خواهد بود. گزینهٔ `manrope` فقط در گروه لاتین registry واحد ثبت شد؛ انتخاب‌های بدنه/تیتر و preview همان registry را مصرف می‌کنند. قرارداد کوتاه typography-roles انتخاب معتبر، بازهٔ وزن، اعلان یک‌باره، عدم اعلان Walsheimِ بی‌مصرف و خانوادهٔ منتخب Elementor را پوشش می‌دهد؛ پذیرش بصری انجام نشده است.

IRANSansX علاوه بر wght محور DOTS برابر ۰–۸ دارد. دو نسخهٔ پینار محور DSTY حدود ۰–۴٫۹ و KSHD برابر ۱۰۰–۲۰۰ دارند؛ کنترل این محورهای اضافی در پنل ساخته نشده و مقادیر پیش‌فرض خود فایل مصرف می‌شوند. تفاوت ظاهری FD و نحوهٔ اعداد صرفاً از نام آن نتیجه‌گیری نشده است. Gramophone وزن متن عادی ندارد و برای نیاز به Regular مناسب فرض نمی‌شود؛ انتخاب‌های نام‌برده جای بررسی بصری پروژه را نمی‌گیرند.

## بارگذاری و افزودن خانواده

فقط خانواده‌های مؤثر متن بدنه و H1–H6 در CSS سایت `@font-face` می‌گیرند؛ خانوادهٔ یکسان در چند نقش تکرار نمی‌شود. نقش عمومی تیترها اگر توسط تمام تگ‌ها override شده و هیچ مصرف مؤثری نداشته باشد، وارد فهرست نمی‌شود. preview تنظیمات فقط انتخاب‌های جاری خود را اعلان می‌کند تا انتخاب تازه پیش از ذخیره قابل دیدن باشد. اعلام چند وزن از خانوادهٔ منتخب به معنای اجبار مرورگر به دانلود همهٔ وزن‌ها نیست. preload سراسری برای همهٔ فونت‌ها اضافه نشده است. `font-display:swap` حفظ شده؛ Variable با بازهٔ واقعی و Static با وزن دقیق معرفی می‌شود. مسیرهای پوشه‌ای و کاراکترهای خاص نام پینار به‌صورت segment به segment URL-encode می‌شوند؛ نسخهٔ PHP و preview React هر دو همین قاعده را دارند.

### نقش متن، تیتر و تگ‌ها — ۲۰۲۶-۱۰-۱۹

کلیدهای قبلی `persian_font`/`latin_font` برای متن بدنه حفظ‌اند؛ برای هر نقش `headings` و `h1` تا `h6` کلیدهای `{role}_persian_font`/`{role}_latin_font` اضافه شده‌اند. مقدار خالی ارث‌بری است: تیترها از بدنه و هر تگ از تیترها. انتخاب نامعتبر/گروه اشتباه مقدار قبلی را نگه می‌دارد. `Fonts::roles()` فهرست ثابت نقش‌ها را مالک است؛ رابط مدیریت همان فهرست را از PHP می‌گیرد و reset بخش، همهٔ انتخاب‌های فونت را پوشش می‌دهد. تنظیم اندازه/وزن متن در این تغییر بازنویسی نمی‌شود.

`Typography::selections()` یک‌بار تنظیمات را می‌خواند و وراثت را resolve می‌کند؛ `selected()` سازگاری انتخاب قبلی بدنه را حفظ و `used()` خانواده‌های مؤثر یکتا را برمی‌گرداند. متغیرهای هر تگ با ترتیب فارسی/لاتین در scope زبان ساخته می‌شوند؛ تغییر زبان تو‌در‌تو هم همان نقش را حفظ می‌کند. فایل CSS مشترک کوچک `heading-fonts.css` در stylesheet سایت و Gutenberg وارد می‌شود؛ Elementor برای heading و متن داخلی آن متغیر نقش همان تگ را مصرف می‌کند و فونت آیکون همچنان مستثناست. PHP سفارشی، هدر/فوتر و preview از همان CSS/اعلان مرکزی استفاده می‌کنند.

الگوی متن عمومی و primary/title font در `themes/woodmart/inc/admin/settings/typography.php` بررسی شد؛ موتور typography، Google Fonts، advanced rules دلخواه یا framework آن منتقل نشدند. قرارداد `tests/typography-roles-contract.php` وراثت دادهٔ قدیمی، انتخاب مستقل، حذف تکرار فایل، خانوادهٔ overrideشدهٔ بی‌مصرف، URL محلی، حفظ مقدار قبلی نامعتبر، خانواده‌های معرفی‌شده به Elementor و نبود preload خودکار را پوشش می‌دهد. این قرارداد stub است؛ CSS محاسبه‌شدهٔ مرورگر، RTL/LTR بصری و CSS تولیدشده/کش‌شدهٔ افزونه در این مرحله تأیید نشده‌اند.

برای افزودن خانواده، فایل WOFF2 را در پوشهٔ گروه صحیح بگذار، metadata آن را بخوان، یک ورودی معتبر در registry اضافه و بررسی مسیر/گروه/وزن/اعلان CSS را اجرا کن. گزینهٔ پنل و validation از registry می‌آیند و نباید دوباره دستی در JS فهرست شوند. آپلودکنندهٔ فونت، تغییر خودکار فایل یا دانلود CDN اضافه نشده‌اند.

## head و preload محدود

اعلان خانواده‌های منتخب با `wp_add_inline_style` در head و کنار stylesheet رادمان باقی است؛ فایل باینری فونت inline نشده و `font-display:swap` حفظ شده است. preload همهٔ وزن‌ها یا هر دو گروه به‌صورت پیش‌فرض اضافه نشده تا فونت غیرمصرفی با منابع حیاتی رقابت نکند.

برای پروژه‌ای که استفادهٔ بالای صفحهٔ آن مشخص است، فیلتر اختیاری `radmanct/typography/preload` گروه‌های `persian` و/یا `latin` را می‌پذیرد. از خانوادهٔ منتخب هر گروه فقط فایل Regular یا Variable شامل وزن ۴۰۰ انتخاب می‌شود؛ در خانوادهٔ بدون آن وزن، اولین فایل موجود است. URL دقیق همان URL CSS، type برابر `font/woff2` و crossorigin برابر `anonymous` است؛ فهرست preload سایر افزونه‌ها حفظ و تکرار URL را WordPress مدیریت می‌کند. این فیلتر برای کاربرد شناخته‌شده است، نه فعال‌سازی همگانی بدون سنجش.

```php
add_filter( 'radmanct/typography/preload', static function (): array {
    return array( 'persian' );
} );
```

API رسمی [wp_preload_resources](https://developer.wordpress.org/reference/functions/wp_preload_resources/) و راهنمای [بهینه‌سازی فونت](https://web.dev/learn/performance/optimize-web-fonts) بررسی شدند. قرارداد PHP حفظ منابع دیگر، نبود preload بدون اعلام، حداکثر یک فایل برای هر گروه و URL/CORS را بررسی کرد؛ head واقعی وردپرس موقت نیز پاس شد. افزایش سرعت یا کاهش CLS هنوز اندازه‌گیری نشده است.

## شواهد و محدودیت

بررسی محدود PHP، وجود همهٔ مسیرها، انتخاب همهٔ خانواده‌های فارسی، نبود اعلان خانواده‌های انتخاب‌نشده، رد انتخاب میان دو گروه، حفظ تنظیم قبلی و URL متغیر پینار را بررسی می‌کند. Build و بررسی assets/ترجمه جدا ثبت می‌شوند؛ [وضعیت پایه](../../implementation/foundation.md) مالک نتیجهٔ اجراست. نگاشت به API فونت Elementor از همان registry قبلی استفاده می‌کند؛ اجرای تازهٔ مرورگر، کش افزونه و مقایسهٔ بصری همهٔ فونت‌ها در این کار انجام نشده است.
