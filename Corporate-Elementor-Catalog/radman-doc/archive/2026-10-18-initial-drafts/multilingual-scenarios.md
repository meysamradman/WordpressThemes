# سناریوهای RTL، LTR و WPML رادمان

> **آرشیو تاریخی؛ جایگزین‌شده:** این متن مرجع تصمیم جاری نیست. تصمیم قطعی ۲۰۲۶-۱۰-۱۸ در [معماری نهایی](../../engineering/architecture.md) بر تمام وضعیت‌ها و پیشنهادهای این فایل مقدم است. متن قدیمی فقط برای سابقه حفظ شده است.

تاریخ: ۲۰۲۶-۱۰-۱۸ — وضعیت: اصل پشتیبانی تأییدشده؛ جزئیات زیر قرارداد پیشنهادی و معیار پذیرش برای بررسی‌اند.

فعلاً فقط مستندسازی و گفت‌وگو انجام می‌شود. هیچ پیاده‌سازی یا ادعای سازگاری آزمایش‌شده‌ای وجود ندارد.

## سناریوهای محصول

| سناریو | رفتار مورد انتظار |
|---|---|
| پروژه تمام React | همه صفحات می‌توانند React باشند؛ این انتخاب مانع چندزبانه‌شدن با WPML نشود |
| پروژه React با یک صفحه Elementor | مثلاً فقط تماس با ما Elementor باشد؛ تغییر زبان و جهت در هر دو روش درست عمل کند |
| سایت تک‌زبانه فارسی | RTL بدون نیاز به نصب WPML کار کند |
| سایت تک‌زبانه انگلیسی | LTR بدون نیاز به نصب WPML کار کند |
| سایت فارسی/انگلیسی با WPML | هر صفحه، منو و محتوای کاتالوگ زبان جاری را رعایت کند؛ تغییر زبان به ترجمه متناظر هدایت شود |
| هدر/فوتر اختصاصی | متن، لینک، منو و انتخاب layout متناسب با زبان باشند؛ سازنده مستقل از Elementor باقی بماند |
| کاتالوگ چندزبانه | محصول، دسته، توضیح و مشخصات قابل‌ترجمه باشند؛ رابطه ترجمه‌ها حفظ شود |

WPML افزونه ثالث اختیاری برای پروژه چندزبانه است؛ ممنوعیت افزونه همراه اختصاصی رادمان مانع سازگاری با WPML یا Elementor نیست.

## معیارهای پذیرش پیشنهادی

- زبان و جهت صفحه از زمینه معتبر وردپرس/WPML تعیین شوند؛ RTL صرفاً معادل فارسی فرض نشود.
- رندر React، داده‌گیری، جستجو، فیلتر، صفحه‌بندی و لینک‌ها زبان جاری را حفظ کنند. زبان در کلید کش داده و خروجی لحاظ شود تا محتوای زبان‌ها مخلوط نشود.
- تغییر زبان از API/روابط ترجمه WPML استفاده کند؛ URL با جایگزینی دستی رشته ساخته نشود.
- متن‌های ثابت رابط در PHP و JavaScript مسیر ترجمه مشخص داشته باشند؛ متن‌های واردشده توسط مدیر، از جمله متن‌های سازنده، نیز جداگانه قابل‌ترجمه باشند.
- قرارداد داده صفحات React پیش از پیاده‌سازی طوری طراحی شود که متن‌ها و ارجاع‌ها برای WPML قابل‌شناسایی باشند؛ صرف ذخیره یک JSON دلخواه به معنی پشتیبانی ترجمه نیست.
- قواعد ترجمه/کپی/نادیده‌گرفتن فیلدهای کاتالوگ و تنظیمات سازنده پس از تثبیت schema تعیین و از جمله با `wpml-config.xml` مستند شوند؛ شناسه رسانه/منو/محصول با ترجمه متناظر تطبیق یابد.
- CSS، چیدمان، منو، Drawer، آیکون‌های جهت‌دار و تعاملات حرکتی در هر دو جهت بررسی شوند؛ لوگو، عکس و آیکون بی‌جهت خودکار معکوس نشوند.
- پیش‌نمایش سازنده و صفحات React/Elementor در زبان و جهت درست آزمایش شوند.
- متن طولانی ترجمه، محتوای ترکیبی مثل شماره/ایمیل فارسی، موبایل و کیبورد در ماتریس تست باشند.

## جزئیات باز برای گفت‌وگو

- آیا ترجمه‌ها می‌توانند روش نمایش متفاوت داشته باشند؛ مثلاً تماس فارسی React و ترجمه انگلیسی Elementor؟ این آزادی هنوز تأیید نشده است.
- هدر/فوتر همه زبان‌ها چیدمان مشترک با ترجمه متن داشته باشند یا برای هر زبان layout مستقل هم لازم است؟
- نبود ترجمه: لینک زبان پنهان شود، به صفحه اصلی آن زبان برود یا سیاست دیگری داشته باشد؟
- مدل ترجمه مشخصات محصول و امکان بروشور/تصویر متفاوت برای هر زبان چیست؟

اصل پشتیبانی RTL/LTR و WPML باز نیست؛ موارد بالا فقط جزئیات رفتار آن هستند و نیاز به پاسخ یکجای همه پرسش‌ها ندارند.

## مبنای بررسی فنی

مستندات WPML با Context7 بررسی شد. WPML برای نوع محتوا، قواعد فیلدهای سفارشی و تنظیمات تغییر زبان مسیرهای پیکربندی دارد؛ نحوه نگاشت داده اختصاصی رادمان پس از طراحی قرارداد مشخص می‌شود.

- [قواعد ترجمه فیلدهای سفارشی](https://wpml.org/documentation/support/language-configuration-files/custom-fields-translation-options/)
- [ثبت نوع محتوا و taxonomy قابل‌ترجمه](https://wpml.org/documentation/support/language-configuration-files/register-custom-terms-types-taxonomies-as-translatable/)
- [راهنمای سازگاری قالب و افزونه با WPML](https://wpml.org/documentation/support/achieving-wpml-compatibility-for-your-themes-and-plugins/)
