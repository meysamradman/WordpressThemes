# برنامه مرحله‌ای رادمان

> **آرشیو تاریخی؛ جایگزین‌شده:** این متن مرجع تصمیم جاری نیست. تصمیم قطعی ۲۰۲۶-۱۰-۱۸ در [معماری نهایی](../../engineering/architecture.md) بر تمام وضعیت‌ها و پیشنهادهای این فایل مقدم است. متن قدیمی فقط برای سابقه حفظ شده است.

> **برنامه قبلی نیازمند بازنگری است:** افزونه Core حذف شده و پیش از توسعه سازنده باید React فرانت‌اند در کنار Elementor نمونه‌سازی شود. [جهت فعلی](frontend-direction.md) مقدم است؛ جدول قبلی دستور اجرای معماری فعلی نیست.

وضعیت: `PROPOSED`؛ برنامه توسعه است، نه اعلام شروع پیاده‌سازی یا تضمین زمان تحویل.

نسخه اول محصول شامل **شرکتی + کاتالوگ بدون خرید + سازنده اختصاصی هدر/فوتر** است. مرحله اول فنی به‌تنهایی نسخه اول محصول محسوب نمی‌شود.

| مرحله | خروجی قابل بررسی | شرط عبور |
|---|---|---|
| ۰. تصمیم محصول | صفحات، عناصر سازنده، مدل مشخصات و مسیر تماس محصول | نیازهای اصلی با مالک محصول نهایی و موارد باز مشخص شوند |
| ۱. پایه قابل نصب | قالب مستقل، tokens، RTL، برگه/وبلاگ و هدر/فوتر ساده | نصب روی وردپرس تمیز، نبود خطای PHP، محتوای قابل‌ویرایش و بدون صفحه‌ساز اجباری |
| ۲. نمونه قرارداد سازنده | یک هدر با ردیف/ستون و لوگو/منو/دکمه؛ ذخیره و رندر PHP | رفت‌وبرگشت داده، validation، مجوز، revision و فایل‌های شرطی اثبات شوند |
| ۳. سازنده نسخه اول | هدر/فوتر، جابه‌جایی، responsive، پیش‌نمایش و تخصیص | ذخیره/بازکردن مجدد، عدم تداخل دو تب، fallback، تعامل کیبورد و کش صحیح |
| ۴. کاتالوگ | Core، محصول، دسته، گالری، مشخصات، PDF و جستجو/فیلتر توافق‌شده | ایجاد/ویرایش/نمایش؛ صفحه‌بندی؛ داده پس از تعویض قالب قابل‌مدیریت بماند |
| ۵. تکمیل و انتشار | طرح شرکتی واقعی، آزمایش سازگاری، ZIPهای مستقل و راهنمای به‌روزرسانی | معیارهای نسخه اول و گزارش عملکرد و محدودیت‌ها تکمیل شوند |

## کنترل‌های لازم؛ در زمان پیاده‌سازی

- ذخیره سازنده: داده سالم، نوع/مقدار نامعتبر، ارجاع گم‌شده، payload بیش‌ازحد، نسخه schema ناشناخته و کاربر بدون مجوز.
- نگهداری: تغییر tokens، حذف layout تخصیص‌یافته، شکست تولید CSS، import با remap و migration ناموفق.
- محتوا: permalink، آرشیو/جستجو/۴۰۴، کاتالوگ صفحه‌بندی‌شده و انتخاب هدر در صفحه/نوع محتوا/پیش‌فرض.
- تعامل: منوی موبایل با لمس و کیبورد، Escape و Focus، RTL/LTR و کاهش حرکت.
- سازگاری: یک افزونه SEO، یک کش و یک فرم منتخب با نسخه دقیق؛ سازگاری عمومی با همه افزونه‌ها ادعا نشود.
- بسته نصب: فقط کد/دارایی رادمان و وابستگی مجاز لازم؛ نمونه‌ها، docs و محیط توسعه وارد ZIP نشوند.

این بررسی‌ها پس از تولید کد لازم‌اند؛ در مرحله فعلی هیچ‌کدام به‌عنوان تست موفق گزارش نمی‌شوند.

## برنامه اندازه‌گیری سرعت

قبل از افزودن امکانات پیشرفته، صفحه خانه شرکتی، برگه معمولی، آرشیو و محصول کاتالوگی baseline شوند. برای کاتالوگ مجموعه داده پیشنهادی ۵۰۰ محصول است؛ تعداد دسته‌ها، مشخصات و فیلترهای هم‌زمان نیز ثبت شوند.

گزارش باید نسخه‌ها، سخت‌افزار/هاست، داده، مرورگر/شبکه، کش سرد/گرم، CSS/JS انتقالی، تعداد درخواست، TTFB و Queryهای کند را ثبت کند. بودجه عددی CSS/JS از همین baseline تعیین و پیش از توسعه کامل تصویب شود.

هدف پیشنهادی تجربه واقعی: `LCP ≤ 2.5s`، `INP ≤ 200ms` و `CLS ≤ 0.1` در صدک ۷۵، در صورت وجود داده میدانی کافی. تست آزمایشگاهی جای داده واقعی را نمی‌گیرد و امتیاز Lighthouse به‌تنهایی تضمین سرعت نیست.

برای بازبینی فعلی فقط مستندات و سورس مرجع بررسی شده‌اند؛ محیط وردپرس راه‌اندازی و بررسی مرورگری انجام نشده است.
