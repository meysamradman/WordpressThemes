# بررسی اولیه نمونه‌قالب‌ها

> **آرشیو تاریخی؛ جایگزین‌شده:** این متن مرجع تصمیم جاری نیست. تصمیم قطعی ۲۰۲۶-۱۰-۱۸ در [معماری نهایی](../../engineering/architecture.md) بر تمام وضعیت‌ها و پیشنهادهای این فایل مقدم است. متن قدیمی فقط برای سابقه حفظ شده است.

تاریخ: ۲۰۲۶-۱۰-۱۸ — دامنه: بررسی محدود سورس، بدون اجرا یا اندازه‌گیری کارایی

## ورودی‌های موجود

- Hub طبق header فایل `themes/hub/style.css` نسخه `6.0.3` است.
- WoodMart طبق header فایل `themes/woodmart/style.css` نسخه `8.6.1` است.
- `radman-doc/webtalik-framework-spec-v0.1.md` ورودی اولیه نیازمندی‌هاست؛ کامل خوانده شد.
- پوشه `radman/` فعلاً زیرپوشه‌های `css`، `fonts`، `languages` و `templates` دارد و فایل اجرایی در آن مشاهده نشد.
- در ریشه فعلی پوشه `.git` مشاهده نشد؛ مخزن، محیط وردپرس و بسته قابل نصب راه‌اندازی نشده‌اند.

نسخه‌های بالا مشخصات همین کپی محلی‌اند؛ تأیید نسخه رسمی ناشر یا اصالت بسته نیستند.

## شواهد و برداشت برای رادمان

| شاهد سورس | مشاهده | نتیجه پیشنهادی |
|---|---|---|
| `themes/woodmart/inc/modules/header-builder/class-header-builder.php` | تفکیک manager، factory، elements، styles و frontend/backend | جداسازی داده، رندر، استایل و مدیریت مفید است؛ تعداد کلاس‌ها را تقلید نکنیم |
| `themes/woodmart/inc/modules/header-builder/class-styles.php` | تولید CSS بر مبنای داده عناصر و تنظیمات | قرارداد schema و استایل باید هم‌زمان طراحی شود |
| `themes/woodmart/inc/configs/js-libraries.php` | registry کتابخانه‌ها همراه وابستگی و تنظیم استفاده | هر جزء رادمان وابستگی روشن داشته باشد؛ وجود registry اثبات فایل‌های واقعی هر صفحه نیست |
| `themes/woodmart/woocommerce/` | دامنه گسترده templateهای فروشگاهی | برای نسخه بدون خرید رادمان این مجموعه لازم نیست |
| `themes/hub/liquid/liquid-init.php` | راه‌اندازی مرکزی، ساختار صفحات، CSS پویا و ادغام‌ها؛ بخشی مانند WooCommerce شرطی است | هسته راه‌اندازی کوچک و ماژول‌های دارای مرز روشن نگه داریم |
| `themes/hub/liquid/liquid-theme-options-init.php` | اتصال پنل تنظیمات به Redux | چنین framework تنظیماتی نیاز قطعی رادمان نیست |

از این بررسی نمی‌توان گفت همه فایل‌های نمونه‌ها بی‌کاربردند یا در همه صفحات بارگذاری می‌شوند. تعداد فایل‌ها، نام کتابخانه یا اندازه بسته به‌تنهایی عملکرد واقعی صفحه را نشان نمی‌دهد.

## اصلاحات لازم نسبت به سند اولیه

- نام محصول و شناسه‌های جدید به Radman تغییر کنند؛ فایل اولیه برای سابقه حفظ شود.
- کاتالوگ اکنون با پاسخ مالک محصول در نسخه اول تأیید شده؛ فروشگاه همچنان نیاز فعلی نیست.
- سازنده اختصاصی تأیید شده، ولی فهرست بلند امکانات سند اولیه همگی تأیید نشده‌اند.
- ساخت هم‌زمان پنل سازنده، فیلدساز عمومی، ویجت‌های متعدد، انیمیشن و دو زنجیره build دامنه را بی‌دلیل بزرگ می‌کند.
- ترتیب MVP روشن شود: پایه قالب خروجی میانی است؛ محصول نسخه اول باید سازنده و کاتالوگ توافق‌شده را هم داشته باشد.
- «داده با تعویض قالب باقی بماند» با «ظاهر و همه قابلیت‌ها با هر قالبی یکسان کار کنند» متفاوت است؛ مرز Core و قالب مستند شده است.

## استفاده از نمونه‌ها

نمونه‌ها مرجع شناخت رفتار و تجربه ویرایش‌اند. فایل، asset یا الگوریتم اختصاصی آن‌ها وارد رادمان نشده است. برای رادمان کد مستقل نوشته می‌شود؛ هر وابستگی قابل‌بسته‌بندی باید مجوز مشخص خود را داشته باشد.
