# نیازمندی‌های رادمان

> **آرشیو تاریخی؛ جایگزین‌شده:** این متن مرجع تصمیم جاری نیست. تصمیم قطعی ۲۰۲۶-۱۰-۱۸ در [معماری نهایی](../../engineering/architecture.md) بر تمام وضعیت‌ها و پیشنهادهای این فایل مقدم است. متن قدیمی فقط برای سابقه حفظ شده است.

> **اصلاح تأییدشده مالک محصول:** افزونه همراه نمی‌خواهیم؛ قابلیت‌های اختصاصی رادمان داخل قالب باشند. React برای فرانت‌اند خواسته شده، پشتیبانی Elementor لازم است و هدر/فوترساز اختصاصی جدا دارد. پیشنهادهای مخالف در ادامه این نسخه، از جمله Core جدا و عدم بارگذاری React عمومی، نیازمند بازنویسی‌اند و تصمیم جاری نیستند. مرجع: [جهت فعلی فرانت‌اند](frontend-direction.md).

نسخه: `0.2.0-draft` — وضعیت: نیازهای تأییدشده + پیشنهاد قابل‌بررسی

## محدوده پیشنهادی نسخه اول

تمام موارد این بخش `PROPOSED` هستند؛ جزئیات محصول هنوز باید با مالک محصول مشخص شوند.

| بخش | پیشنهاد نسخه اول | معیار پذیرش |
|---|---|---|
| صفحات | خانه، درباره، خدمات، تماس، وبلاگ، جستجو و ۴۰۴ | مدیریت محتوا از وردپرس و نمایش واکنش‌گرا |
| طراحی | پشتیبانی RTL و LTR و سازگاری WPML الزامی است؛ جزئیات طراحی پیشنهادی‌اند | جهت، فاصله، فونت و منوی موبایل در هر دو جهت صحیح باشند |
| تنظیمات | لوگو، رنگ‌ها، فونت محلی، عرض محتوا و فاصله‌ها | یک مرجع مشترک برای استایل سایت و ویرایشگر |
| هدر | ردیف/ستون، لوگو، منو، دکمه، متن، تماس، شبکه اجتماعی و منوی موبایل | جابه‌جایی، ذخیره، بازکردن مجدد و خروجی یکسان |
| فوتر | ردیف/ستون، لوگو، متن، منو، اطلاعات تماس و کپی‌رایت | استفاده مجدد از اجزای مشترک سازنده |
| کاتالوگ | دسته، تصویر، گالری، توضیح، مشخصات و فایل بروشور | آرشیو صفحه‌بندی‌شده و صفحه جزئیات؛ بدون سبد و پرداخت |
| جستجو/فیلتر | جستجوی عنوان و فیلتر دسته؛ برند فقط در صورت نیاز | URL قابل اشتراک و عملکرد با JavaScript خاموش |
| ارتباط محصول | دکمه تماس/درخواست اطلاعات با اشاره به محصول | مقصد و اطلاعات محصول روشن باشد؛ فرم وابسته به تصمیم جداست |

خدمات می‌توانند در شروع برگه باشند. ایجاد نوع محتوای مستقل برای خدمات، پروژه یا اعضای تیم فقط با نیاز واقعی انجام شود.

## مرز سبک‌ماندن

- Elementor، WooCommerce و JetEngine وابستگی اجباری نباشند.
- کتابخانه انیمیشن، اسلایدر، React و آیکون‌فونت روی همه صفحات بارگذاری نشوند.
- هر ماژول مالک کد، تنظیمات و فایل‌های خودش باشد. غیرفعال‌بودن آن باید هزینه عمومی‌اش را حذف کند؛ جز خواندن پیکربندی حداقلی راه‌اندازی.
- از قابلیت‌های موجود وردپرس برای نوشته، برگه، رسانه، کاربر، فهرست و تنظیمات استفاده شود؛ پنل مشابه بی‌دلیل نسازیم.
- فایل‌های ضروری فونت، CSS، JS و آیکون از خود سایت ارائه شوند؛ اتصال خارجی اختیاری نیازمند تعریف جداست.
- سازگاری با افزونه کش/SEO هدف است؛ موتور کش، فشرده‌سازی کل سایت و SEO کامل داخل قالب ساخته نشوند.

## موارد پیشنهادشده برای مراحل بعد (`DEFERRED`)

- فروشگاه و مهاجرت کاتالوگ به WooCommerce.
- ویجت اختصاصی Elementor، مگامنو پیشرفته و جستجوی زنده.
- فیلدساز عمومی شبیه JetEngine، مقایسه، علاقه‌مندی و تنوع محصول.
- GSAP، Three.js، افکت‌های نمایشی، کتابخانه بزرگ دمو و سیستم لایسنس.

## کیفیت و پذیرش

- صفحه و محتوای اصلی از سرور HTML بگیرند؛ تعامل منو JS محدود داشته باشد.
- مجوز کاربر، اعتبارسنجی داده و escaping خروجی در تمام مسیرهای ذخیره/رندر اعمال شوند. Nonce جای مجوز نیست.
- هدر/فوتر با کیبورد قابل استفاده باشند؛ Focus، Escape، بازگشت Focus و کاهش حرکت رعایت شوند.
- غیرفعال‌کردن یا تعویض قالب داده کاتالوگ را حذف نکند. با فعال‌ماندن Core مدیریت آن برقرار بماند.
- برای CSS/JS بودجه عددی پس از نمونه پایه تعیین شود؛ حجم فایل‌های بسته نصب معیار سرعت صفحه نیست.
- هیچ ادعای سرعت، سازگاری یا دسترس‌پذیری پیش از اندازه‌گیری ثبت نشود.
